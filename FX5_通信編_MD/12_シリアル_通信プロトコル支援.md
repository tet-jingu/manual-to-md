## 0. 結論サマリ

- 通信プロトコル支援＝**相手機器のプロトコルをGX Works3に登録しておき、ラダーからはプロトコル番号を指定して実行するだけ**にする機能。
- 命令は **`S(P).CPRTCL`** のみ。**1命令で最大8プロトコルを連続実行**できる。
- **CPUユニット1台で2チャンネルまで**使用可能。
- 1プロトコルにつき **送信パケット1個、受信パケット最大16個**。プロトコル番号は **1〜64**。
- 実行前に **`SD9102`（通信プロトコル準備完了）= 1 を必ず確認する**（0のまま実行すると 7D02H）。
- 完了判定は **完了デバイス `(d)` と完了時状態表示デバイス `(d)+1`** のペア。異常時は `(s)`（実行結果）にエラーコードが入る。

---

## 1. パラメータ設定（GX Works3）

設定場所: 内蔵RS-485→[485シリアルポート]、通信ボード→[拡張ボード]、通信アダプタ→ADP1〜6。

- **プロトコル形式は [通信プロトコル支援] を選択する。**
- 通信プロトコル支援機能は **2チャンネルのみ**設定可能。
- データ長・パリティ・ストップビット・ボーレートなどは相手機器に合わせる（一部項目はパケット設定側で設定）。

---

## 2. プロトコル設定（ラダーを書く前に必須）

GX Works3 の `ツール` → `通信プロトコル支援機能` → `CPU(シリアル)` → `新規作成` で設定する。

手順:

1. **プロトコルの追加** — 通信プロトコルライブラリ（GX Works3に同梱、FREQROLシリーズ等）/ ユーザプロトコルライブラリ / 新規追加 から選ぶ
2. **プロトコルの詳細設定** — プロトコル名、通信タイプ、受信待ち時間、送信監視時間、送信リトライ回数など
3. **パケットの設定** — ヘッダ／局番／コマンド／データ部／誤りチェックコード／ターミネータ等の構成要素を定義
4. **CPUユニットへ書き込み**

### 通信タイプ

| 通信タイプ | 処理内容 | 必要なパケット |
|---|---|---|
| 送信のみ | 送信パケットを1回送信する | 送信パケット1個 |
| 受信のみ | 登録した最大16の受信パケットのうち一致するものがあれば受信する | 受信パケット1個以上 |
| 送信&受信 | 送信パケットを送信後、最大16の受信パケットのうち一致するものがあれば受信する | 送信1個＋受信1個以上 |

### プロトコルの詳細設定でラダー動作に影響する項目

| 項目 | 内容 |
|---|---|
| 受信待ち時間 | 受信待ち状態になってからの待ち時間。**指定時間内に一致するパケットを受信しないと異常**（7D13H）。<br>**0 = 無限待ち** に設定すると、データを受信するまで `S(P).CPRTCL` 命令が完了しない |
| 送信監視時間 | 送信の監視時間。タイムアップで 7D12H |
| 送信リトライ回数 | 送信監視時間内に送信完了しなかったときの再送回数。設定回数送っても完了しなければ異常（7D12H） |

### パケットの制約

- **1パケットのデータ部 最大データ長: 2048バイト**（超過受信で 7D17H）
- パケット設定が「変数未設定」「構成要素なし」「構成要素エラー」の場合、**CPUユニット／SDメモリカードにプロトコルを書き込めない**

## 3. S(P).CPRTCL命令

```
[実行条件]──[ SP.CPRTCL  "U0"  (n1)  (n2)  (s)  (d) ]
ST: ENO := S_CPRTCL(EN, U0, s, n1, n2, d);
    ENO := SP_CPRTCL(EN, U0, s, n1, n2, d);
```

| オペランド | 内容 | 範囲 |
|---|---|---|
| (U) | ダミー。文字列 `"U0"` を入力 | — |
| (n1) | 通信CH | FX5S/FX5UJ: K2〜K4、FX5U: K1〜K4、FX5UC: K1, K3〜K4 |
| (n2) | 連続実行するプロトコルの数 | K1〜8 |
| (s) | コントロールデータ先頭デバイス | **18ワード占有** |
| (d) | 命令実行状態を出力する先頭ビットデバイス | **2点占有** |

> (d) には T, ST, C を使用できない。

### コントロールデータ（18ワード）

| デバイス | 項目 | 内容 | 設定範囲 | セット側 |
|---|---|---|---|---|
| (s)+0 | 実行結果 | 命令の実行結果。複数実行時は**最後に実行したプロトコルの結果**。0: 正常 / 0以外: エラーコード | — | システム |
| (s)+1 | 実行数結果 | 実行したプロトコル数（**エラーが発生したプロトコルも含む**）。設定に誤りがある場合は0 | 0, 1〜8 | システム |
| (s)+2 | 実行プロトコル番号指定1 | 1番目に実行するプロトコル番号 | **1〜64** | ユーザ |
| (s)+3 | 実行プロトコル番号指定2 | 2番目に実行するプロトコル番号 | 0, 1〜64 | ユーザ |
| (s)+4 | 実行プロトコル番号指定3 | 3番目 | 0, 1〜64 | ユーザ |
| (s)+5 | 実行プロトコル番号指定4 | 4番目 | 0, 1〜64 | ユーザ |
| (s)+6 | 実行プロトコル番号指定5 | 5番目 | 0, 1〜64 | ユーザ |
| (s)+7 | 実行プロトコル番号指定6 | 6番目 | 0, 1〜64 | ユーザ |
| (s)+8 | 実行プロトコル番号指定7 | 7番目 | 0, 1〜64 | ユーザ |
| (s)+9 | 実行プロトコル番号指定8 | 8番目 | 0, 1〜64 | ユーザ |
| (s)+10 〜 (s)+17 | 照合一致受信パケット番号1〜8 | 各プロトコルで**照合一致した受信パケット番号**。通信タイプが「送信のみ」の場合、エラー時、実行数に満たない場合は 0 | 0, 1〜16 | システム |

### 完了デバイスの動作

| デバイス | 動作 |
|---|---|
| (d)+0 完了デバイス | 命令が完了したスキャンのEND処理でON、次のEND処理でOFF（1スキャンON） |
| (d)+1 完了時の状態表示デバイス | **正常完了時: OFFのまま変化しない**<br>**異常完了時: 完了スキャンのEND処理でON**、次のEND処理でOFF。このとき `(s)` にエラーコードが格納される |

### 命令レベルの注意事項

1. **複数プロトコル実行中、n番目でエラーが発生するとn+1番目以降は実行されず、命令は異常完了する。**
2. **同一チャンネルに対して同一命令を実行した場合、先に実行中の命令が完了するまで、後の命令は無視され実行されない。**
3. **受信待ち時間を「0: 無限待ち」に設定していると、指定データを受信するまで命令が完了しない。**

## 5. ラダー実装パターン

### 5.1 基本形（CH2でプロトコル4→7→5を連続実行）

```
<<プロトコル番号の設定>>
[ MOV K4 D12 ]   ; 1番目に実行するプロトコル番号
[ MOV K7 D13 ]   ; 2番目
[ MOV K5 D14 ]   ; 3番目

<<命令実行（SD9102=1 のときだけ実行する）>>
X20   [= SD9102 K1]
──┤├────┤├──[ SP.CPRTCL "U0" K2 K3 D10 M0 ]
                    │    │   └ 連続実行数 3
                    │    └ 通信CH2
                    └ コントロールデータ先頭 D10（D10〜D27を占有）

<<完了処理>>
M0  M1(b接点) ──[ SET M101 ]              ; 正常完了フラグ
M0  M1        ──[ SET M102 ]              ; 異常完了フラグ
M1            ──[ MOV D10 D100 ]          ; エラーコードを退避
```

デバイス割付の例:

| デバイス | 内容 |
|---|---|
| X20 | S(P).CPRTCL命令実行トリガ |
| M0 | 完了デバイス `(d)+0` |
| M1 | 完了時の状態表示デバイス `(d)+1` |
| M101 | 正常完了フラグ |
| M102 | 異常完了フラグ |
| D10 | コントロールデータ先頭（(s)+0 実行結果） |
| D11 | (s)+1 実行数結果 |
| D12, D13, D14 | (s)+2〜+4 実行プロトコル番号1〜3 |
| D20〜D27 | (s)+10〜+17 照合一致受信パケット番号1〜8 |
| SD9102 | 通信プロトコル準備完了 |

### 5.2 受信パケットの判別（送信&受信の応答分岐）

```
M0  M1(b接点)
──┤├────┤/├──[ MOV D20 D200 ]     ; (s)+10 = 1番目プロトコルで照合一致した受信パケット番号
; D200 = 1 なら 正常応答(NOR)、2 なら NAK応答(ERR) など、
; プロトコル設定の受信パケット番号に応じて分岐処理を組む
```

### 5.3 プロトコルのキャンセル

```
Xnn(キャンセル指示) ──[ MOV K1 SD9189 ]   ; CH2のプロトコルキャンセル指定に 1（キャンセル要求）
; キャンセル完了で SD9189 は 2（キャンセル実行完了）になる
; 通常実行時は 0
```

| SD916x/918x/920x/922x の値 | 意味 |
|---|---|
| 0 | 通常実行 |
| 1 | キャンセル要求 |
| 2 | キャンセル実行完了 |

**キャンセル時の動作（タイミング依存）**

| 実行中の通信 | キャンセルしたタイミング | 結果 |
|---|---|---|
| 送信 | プロトコル実行開始〜送信開始前（送信待ち） | パケットを送信しない |
| 送信 | 送信開始〜送信完了前（送信処理中） | **パケットを中断せず送信を完了させる** |
| 受信 | 送信完了〜受信開始前（受信データ待ち） | パケットを受信しない |
| 受信 | 受信開始後（受信処理中） | **パケットを中断し破棄する** |

- キャンセルされたプロトコルは**異常完了**になる。複数連続実行中なら、**実行中のプロトコルを終了し以降は実行しない**。
- 実行中のプロトコルがない状態でキャンセル要求すると、無処理でキャンセル完了する。
- **キャンセル要求は定期処理で確認されるため、指示からキャンセル処理までに時間がかかる場合がある。**

### 5.4 送受信データモニタ（デバッグ用）

```
<<モニタ開始（CH2、Rデバイス R0〜R3329 を使用）>>
X21  M21(b接点)
──┤├───┤/├──[ FMOV K0  R0     SD9244 ]   ; モニタエリアをクリア
                 [ MOV  H1  SD9242       ]   ; モニタデータデバイス指定（Rデバイス）
                 [ MOV  K0  SD9243       ]   ; モニタデータ先頭デバイス番号 0
                 [ MOV  HD00 SD9244      ]   ; モニタデータサイズ 3328ワード
                 [ MOV  H1  SD9240       ]   ; モニタ開始（0001H）
                 [ SET  M20 ]
[= SD9240 H2]  ──[ RST M20 ][ SET M21 ]      ; モニタ中（0002H）

<<オプション指定（データエリアフル停止=モニタ停止）>>
X22  M21 ──[ MOV H1 SD9241 ]

<<モニタ停止>>
X23  M21 ──[ MOV H0 SD9240 ][ RST M21 ]
[= SD9240 H1002] ──[ RST M21 ]               ; 自動停止（1002H）
```

**送受信データモニタ機能設定（SD9230等）の値**

| 値 | 内容 |
|---|---|
| 0000H | モニタ停止（書き込むと停止する） |
| 0001H | モニタ開始（書き込むと開始。モニタデータデバイス番号・データ数が初期化される） |
| 0002H | モニタ中（システムが書き込む） |
| 1002H | モニタ停止（データエリアフルまたは1パケット完了による自動停止） |

**オプション設定（SD9231等）**

| ビット | 内容 |
|---|---|
| bit0 | データエリアフル停止指定。OFF: モニタ続行（古いデータを上書き） / ON: モニタ停止 |
| bit1 | 1パケット停止指定。ON: 送信1パケット完了または受信1パケット完了でモニタ停止 |

**モニタデータエリアの構成**

| デバイス | 内容 |
|---|---|
| 先頭+0 | モニタデータデバイス番号（**最古のデータが格納されているデバイス番号**） |
| 先頭+1 | モニタデータ数（0〜モニタデータサイズ） |
| 先頭+2以降 | モニタデータ（1ワード＝下位8bitが送受信データ1バイト、上位8bitがデータ種別／信号モニタ） |

> ⚠ **モニタデータエリアが各チャンネルで重複すると、CH番号が大きい方のデータで上書きされる。** CHごとに別エリアを確保すること。

## 6. プログラム作成上の注意（違反するとバグになる）

1. **`SD9102`（通信プロトコル準備完了）が 1 であることを命令の実行条件に入れる。** 0のまま実行すると 7D02H。
2. コントロールデータは **18ワード連続**で確保する。
3. `(d)` は **2点連続**で確保する。
4. 複数プロトコル連続実行時、**途中でエラーが起きると残りは実行されない**。`(s)+1`（実行数結果）で「どこまで実行できたか」を必ず確認する。
5. **同一CHに同じ命令を重ねて実行しない**（後の命令は無視される）。
6. **受信待ち時間 0（無限待ち）は命令が完了しなくなる**。タイムアウト設計が必要な用途では有限値にする。
7. 受信パケットの判別は `(s)+10`〜`(s)+17`（照合一致受信パケット番号）で行う。
8. 通信プロトコル支援機能は**1台につき2チャンネルまで**。
9. 同一シリアルポートで **RS2命令・インバータ通信命令とは併用できない**。

## 7. トラブルシューティング（シリアル通信プロトコル支援のみ）

### 7.1 エラーフラグ・エラーコード格納先

| CH1 | CH2 | CH3 | CH4 | 名称 |
|---|---|---|---|---|
| SM8500 | SM8510 | SM8520 | SM8530 | シリアル通信エラー |
| SD8500 | SD8510 | SD8520 | SD8530 | シリアル通信エラーコード |

エラーコードは上記に加えて **`S(P).CPRTCL` 命令の実行結果（オペランド `(s)`）にも格納される**。

### 7.2 エラーコード一覧

| コード | 名称 | エラー内容 | エラー処理 |
|---|---|---|---|
| 7D00H | プロトコル番号設定エラー | 連続実行するプロトコル数の設定値が範囲外 | プロトコル番号・実行数の設定値を確認する |
| 7D02H | プロトコル準備未完了エラー | 通信プロトコル準備未完了(SD9102=0)で命令を実行した／プロトコル設定データが異常な状態で実行した | SD9102=1 になってから実行する。プロトコル設定データを再書込みする。それでも発生する場合はCPUユニットを交換 |
| 7D10H | プロトコル未登録エラー | 登録されていないプロトコル番号を指定した／プロトコル設定データ未書込みで実行した | 指定したプロトコル番号と `SD9132`〜`SD9135`（登録有無）を確認し、設定データを書き込んでから実行する |
| 7D12H | 送信監視時間タイムアウトエラー | 送信監視時間がタイムアップ／送信リトライ回数分リトライしても送信できなかった | ケーブルが切断されていないか確認する |
| 7D13H | 受信待ち時間タイムアウトエラー | 受信待ち時間がタイムアップした | ケーブル切断、相手機器の異常を確認する |
| 7D16H | プロトコルキャンセル要求エラー | プロトコル実行中にキャンセル要求を受け付けて異常完了した | `(s)+1`（実行数結果）でキャンセルされたプロトコルを確認し、原因を取り除く |

## 8. ラダー生成前チェックリスト

- [ ] プロトコル形式を[通信プロトコル支援]にしたか（最大2CH）
- [ ] プロトコル設定をCPUユニットに書き込んだか（パケットの変数がすべて設定済みか）
- [ ] 実行条件に `SD9102 = 1` を入れたか
- [ ] コントロールデータ用に18ワード連続を確保したか
- [ ] `(d)` に2点連続の空きビットデバイスを確保したか
- [ ] `(n2)`（連続実行数）と `(s)+2`〜`(s)+9` に設定したプロトコル番号の個数が一致しているか
- [ ] プロトコル番号は 1〜64 の範囲か
- [ ] 異常完了時に `(s)`（実行結果）と `(s)+1`（実行数結果）を退避しているか
- [ ] 受信応答の分岐に `(s)+10`〜`(s)+17`（照合一致受信パケット番号）を使っているか
- [ ] 受信待ち時間を無限待ち(0)にしていないか（するなら完了しないことを織り込んだか）
- [ ] 同一CHで命令を多重駆動していないか
- [ ] モニタ機能を使う場合、CHごとに別のモニタデータエリアを確保したか
