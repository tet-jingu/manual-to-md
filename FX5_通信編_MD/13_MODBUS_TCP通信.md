## 0. 結論サマリ

- FX5のMODBUS/TCPは **スレーブ機能とマスタ機能の両方**に対応。**1台でスレーブとマスタを同時使用できる**。
- **スレーブ局はプログラム不要。** パラメータでMODBUSデバイス割り付けを設定すれば自動応答する。
- **マスタ局は専用命令が用意されていない。** 通信プロトコル支援機能（`SP.ECPRTCL`）でMODBUS標準ファンクションのプロトコルを実行する。
  → マスタのラダーは **`SP.SOCOPEN` → `SP.ECPRTCL` → `SP.SOCCLOSE`** の3段構成になる。
- 対応プロトコルは **MODBUS/TCP（バイナリのみ）**。**合計8コネクション**（他のEthernet通信機能を使うと減る）。
- スレーブのポート番号は **502**（推奨）。

## 1. 通信仕様

| 項目 | 仕様 |
|---|---|
| 対応プロトコル | MODBUS/TCP（**バイナリのみ**） |
| コネクション数 | 合計 **8コネクション**（同時にアクセスできる外部機器は最大8台。他のEthernet通信機能を使うと減少） |
| スレーブ機能 ファンクション数 | 10 |
| ポート局番 | **502**（通信設定から変更可） |

### フレーム仕様（MODBUS/TCP）

```
[交信ID 2byte][プロトコルID 2byte][伝文長 2byte][ユニットID 1byte][ファンクションコード 1byte][データ 0〜252byte]
                                    └─────── 伝文長はこのエリア以降のバイト数 ───────┘
```

| エリア | 内容 |
|---|---|
| 交信ID | マスタがスレーブからの応答伝文のマッチングに使用する |
| プロトコルID | PDU(プロトコルデータ部)のプロトコルを示す。**MODBUS/TCPでは 0** |
| 伝文長 | このエリア以降の伝文サイズ（バイト単位） |
| ユニットID | 他の回線に接続されているスレーブを指定する場合に使用（**FX5は非対応**） |
| ファンクションコード | マスタがスレーブに要求する処理の内容 |
| データ | 要求内容／実行結果 |

### 対応MODBUS標準ファンクション（MODBUSシリアルより2つ多い）

| ファンクションコード | ファンクション名 | 1伝文でのアクセス点数 |
|---|---|---|
| 01H | コイル読出し | 1〜2000点 |
| 02H | 入力読出し | 1〜2000点 |
| 03H | 保持レジスタ読出し | 1〜125点 |
| 04H | 入力レジスタ読出し | 1〜125点 |
| 05H | 1コイル書込み | 1点 |
| 06H | 1レジスタ書込み | 1点 |
| 0FH | 複数コイル書込み | 1〜1968点 |
| 10H | 複数レジスタ書込み | 1〜123点 |
| **16H** | **保持レジスタマスク書込み**（AND/ORマスク） | 1点 |
| **17H** | **複数レジスタ読出し/書込み** | 読出し 1〜125点 / 書込み 1〜121点 |

## 2. スレーブ局として使う（ラダー不要）

### 2.1 ポート番号の設定

`[パラメータ]` → ユニット形名 → `[ユニットパラメータ]` → `[Ethernetポート]` → `[基本設定]` → `[相手機器接続構成設定]` → `<詳細設定>`
→ ユニット一覧の **"MODBUS/TCP接続機器"** をドラッグ＆ドロップ

| 項目 | 設定 |
|---|---|
| シーケンサ ポート番号 | 1〜5548, 5570〜65534（**デフォルト 502**） |

**ポート番号の禁止・推奨**

- **502 を使用することを推奨。** 変更する場合は 1024〜5548, 5570〜61439 を使う。
- **5549〜5569 はシステム使用。指定禁止。**
- 他機能と重複禁止: FTPサーバ **20, 21** / Webサーバ **80**(デフォルト・変更可) / SNTPクライアント **123** / SLMP **61440, 61441** / CC-Link IEフィールドネットワークBasic **61450**

### 2.2 MODBUS/TCP設定

`[基本設定]` → `[MODBUS/TCP設定]`

| 項目 | 設定 | 備考 |
|---|---|---|
| MODBUS/TCP使用有無 | 使用 / 不使用 | 相手機器接続構成設定におけるMODBUS/TCP接続機器の使用状態が表示される |
| デバイス割り付け | §2.3 | 「使用」の場合に設定できる |

### 2.3 MODBUSデバイス割り付け

`[MODBUS/TCP設定]` → `デバイス割り付け` の `<詳細設定>`

| 設定項目 | 内容 |
|---|---|
| 割付1〜16 | 各MODBUSデバイスの割付を1〜16まで設定できる |
| デバイス | 割付デバイスの種類と先頭番号 |
| **先頭MODBUSデバイス番号** | **設定値 = 設定対象MODBUSデバイス番号の下5桁 − 1** |
| 割付点数 | 割り付ける点数 |

**制約（必ず守る）**

- **デバイス番号・割付点数は16の倍数**にする（違反時はGX Works3でパラメータ設定エラー）
- **コイルと入力に同一デバイスは設定できない**
- **入力レジスタと保持レジスタに同一デバイスは設定できない**
- 先頭デバイス番号＋割付点数がデバイス有効範囲を超えるとパラメータ設定エラー
- LCN, LZ などロング型デバイスは**MODBUSデバイスを2点使用**する

**割り付け可能デバイス**

| MODBUSデバイス | 割り付け可能なFX5デバイス |
|---|---|
| コイル（読出し/書込み） | SM, SD, X, Y, M, L, F, B, D, W, TC, TS, TN, STC, STS, STN, CC, CS, CN, LCC, LCS, LCN, SB, SW, S, Z, LZ, R, ER |
| 入力（読出専用） | 同上 |
| 入力レジスタ（読出専用） | SD, D, W, TN, STN, CN, LCN, SW, Z, LZ, R, ER（ビット系デバイスは不可） |
| 保持レジスタ（読出し/書込み） | 同上 |

**初期値（FX5専用パターン・抜粋）**

| MODBUSアドレス | コイル（FX5S/FX5UJ） | コイル（FX5U/FX5UC） | 入力 |
|---|---|---|---|
| 0000H〜03FFH | Y0〜1023 | Y0〜1023 | X0〜1023 |
| 2000H〜3DFFH | M0〜7679 | M0〜7679 | — |
| 5000H〜57FFH | SM0〜2047 | SM0〜2047 | — |
| 5800H〜75FFH | L0〜7679 | L0〜7679 | — |
| B000H〜BFFFH | S0〜4095 | S0〜4095 | — |

| MODBUSアドレス（保持レジスタ） | FX5S/FX5UJ | FX5U/FX5UC |
|---|---|---|
| 0000H〜1F3FH | D0〜7999 | D0〜7999 |
| 5000H〜770FH | SD0〜9999 | SD0〜9999 |
| 7800H〜7BFFH / 7800H〜79FFH | W0〜1023 | W0〜511 |
| A000H〜A3FFH / A000H〜A0FFH | SW0〜1023 | SW0〜511 |

### 2.4 スレーブ機能の動作

- **自動応答**: マスタからの要求に、対応ファンクションコードに応じて自動で応答する
- **MODBUSデバイス割り付け**: MODBUSデバイスへのアクセスを自動でCPUユニットのデバイスアクセスに変換する
- **Ethernet診断**で異常内容を確認できる

> **スレーブ局はプログラムが必要ない。**

## 3. マスタ局として使う（ラダー必要）

FX5のマスタ局は **通信プロトコル支援機能（内蔵Ethernet）** を使う。→ 詳細は **03_Ethernet_通信プロトコル支援.md** を参照。

### 3.1 接続設定

`[基本設定]` → `[相手機器接続構成設定]` → `<詳細設定>` → ユニット一覧の **"Active接続機器"** をドラッグ＆ドロップ

| 項目 | 設定 | 備考 |
|---|---|---|
| **交信手段** | **通信プロトコル** | ← 必須 |
| シーケンサ ポート番号 | 1〜5548, 5570〜65534（5549〜5569は指定禁止） | マスタ局のポート番号 |
| センサ・機器 IPアドレス | 0.0.0.1〜223.255.255.254 | スレーブ局のIPアドレス |
| センサ・機器 ポート番号 | — | スレーブ局のポート番号（通常 502） |

### 3.2 プロトコル設定

`[ツール]` → `[通信プロトコル支援機能]` → `[ファイル]` → `[新規作成]` → `[編集]` → `[プロトコル追加]`

| 項目 | 設定内容 |
|---|---|
| 種別 | **通信プロトコルライブラリ** |
| メーカ | **汎用プロトコル** |
| 型式 | **MODBUS/TCP** |
| プロトコル名 | 下表から選択 |

| プロトコル名 | 対応するMODBUS標準ファンクション |
|---|---|
| 01: RD Coils | 01H コイル読出し |
| 02: RD Discrete Inputs | 02H 入力読出し |
| 03: RD Holding Registers | 03H 保持レジスタ読出し |
| 04: RD IN Registers | 04H 入力レジスタ読出し |
| 05: WR Single Coil | 05H 1コイル書込み |
| 06: WR Single Registers | 06H 1レジスタ書込み |
| 15: WR Multi Coil | 0FH 複数コイル書込み |
| 16: WR Multi Registers | 10H 複数レジスタ書込み |
| 20: RD File Record | 14H ファイル記録読出し（**マスタ局のみ対応**） |
| 21: WR File Record | 15H ファイル記録書込み（**マスタ局のみ対応**） |
| 22: Mask WR Registers | 16H 保持レジスタマスク書込み |
| 23: RD/WR Multi Registers | 17H 複数レジスタ読出し/書込み |

> 追加したプロトコルには、読み書きする内容に合わせて**パケットの変数設定**を行う。
> **FX5のスレーブ局を相手にする場合、変数に指定するデバイスは、相手側でMODBUSデバイスを割り付けたデバイスを使う。**

### 3.3 マスタ局のラダー構成

```
1. コネクション確立   : SP.SOCOPEN  で対象スレーブ局のコネクションをオープン
2. プロトコル実行     : SP.ECPRTCL  で設定したプロトコル（MODBUS標準ファンクション）を実行
3. コネクション切断   : SP.SOCCLOSE でコネクションをクローズ
```

**ラダー例（コネクションNo.1、プロトコル番号1=保持レジスタ読出し）**

```
<<① オープン>>
M1000  SD10680.0(b)  SD10681.0(b)
──┤├─────┤/├────────┤/├──[ MOVP H0 D100 ]
                                   [ SP.SOCOPEN "U0" K1 D100 M100 ]

<<② プロトコル実行>>
[ MOV K1 D12 ]                         ; (s3)+2 実行プロトコル番号1

X20  [= SD10692 K1]  SD10680.0
──┤├──────┤├────────┤├──[ SP.ECPRTCL "U0" K1 K1 D10 M0 ]

M0  M1(b接点) ──[ SET M101 ]            ; 正常完了
M0  M1        ──[ SET M102 ]            ; 異常完了
M1            ──[ MOV D11 D200 ]        ; (s3)+1 完了ステータス退避
M0  M1(b)     ──[ MOV D20 D210 ]        ; (s3)+10 照合一致受信パケット番号
                                         ;  → 正常応答か異常応答かの判別に使う

<<③ クローズ>>
M4000  SD10680.0 ──[ SP.SOCCLOSE "U0" K1 D200 M200 ]
```

> 各命令の詳細は **01_Ethernet_ソケット通信.md**（SOCOPEN/SOCCLOSE）と **03_Ethernet_通信プロトコル支援.md**（ECPRTCL）を参照。

## 5. プログラム作成・設計上の注意

1. **スレーブとして使うだけならラダーは書かない。** パラメータのMODBUSデバイス割り付けだけで動作する。
2. **デバイス番号・割付点数は16の倍数**にする。
3. **先頭MODBUSデバイス番号 = 対象MODBUSデバイス番号の下5桁 − 1**（設定式を間違えやすい）。
4. コイルと入力、入力レジスタと保持レジスタに**同一デバイスを割り付けない**。
5. マスタとして使う場合、コネクションの **交信手段を「通信プロトコル」** にする（ソケット通信用コネクションでは `SP.ECPRTCL` を実行できない）。
6. **`SP.ECPRTCL` はオープン/クローズを行わない。** `SP.SOCOPEN` / `SP.SOCCLOSE` を必ず併用する。
7. コネクションは合計8。**他のEthernet通信機能を使うとMODBUS/TCPに使えるコネクション数は減る**。
8. ポート番号を他機能と重複させない（§2.1）。

## 6. トラブルシューティング（MODBUS/TCP通信のみ）

### 6.1 異常発生時の基本確認

- **MODBUS/TCP通信で異常が発生した場合は、GX Works3の `Ethernet診断` で異常内容を確認する。**
- エラーコードは `SD10130`〜`SD10137`（コネクションNo.1〜8）に格納される。

### 6.2 MODBUS通信エラーコード（TCPで発生するもの）

| コード | エラー詳細 | エラー内容 | 発生局 |
|---|---|---|---|
| 7305H | — | キャラクタオーバーラン（受信データが256バイト以上） | スレーブ |
| 7306H | — | 伝文フォーマット不正（受信バイト数が指定バイト数と不一致） | スレーブ |
| 7307H | — | 未対応ファンクションコードの受信 | スレーブ |
| 7308H | — | 非デバイス割付けMODBUSアドレスへのアクセス発生 | スレーブ |
| 730EH | — | リクエスト伝文データ異常（設定範囲外の値が含まれる） | スレーブ |
| 7311H | — | **ポート番号重複**（使用するポート番号が他機能と重複している） | スレーブ |

> **MODBUS/TCP通信ではスレーブ局のみエラーが発生する。**（マスタ側のエラーは通信プロトコル支援機能のエラーコードとして現れる → 03_Ethernet_通信プロトコル支援.md §8）

### 6.3 スレーブが異常応答を返す場合の読み解き

マスタ側が受け取る異常応答は、**上位バイト＝異常応答ファンクションコード、下位バイト＝異常応答コード**。

**異常応答ファンクションコード（上位バイト）**

| 値 | ファンクション名 |
|---|---|
| 01H | コイル読出しで異常完了 |
| 02H | 入力読出しで異常完了 |
| 03H | 保持レジスタ読出しで異常完了 |
| 04H | 入力レジスタ読出しで異常完了 |
| 05H | 1コイル書込みで異常完了 |
| 06H | 1レジスタ書込みで異常完了 |
| 0FH | 複数コイル書込みで異常完了 |
| 10H | 複数レジスタ書込みで異常完了 |
| 16H | 保持レジスタのマスク書込みで異常完了 |
| 17H | 複数レジスタの読出し/書込みで異常完了 |

**異常応答コード（下位バイト）**

| 値 | 名称 | 詳細 |
|---|---|---|
| 01H | ファンクションコード異常 | 未対応のファンクションコードを受信した |
| 02H | デバイスアドレス異常 | **デバイス割付けされていないMODBUSアドレスにアクセスがあった** |
| 03H | データ異常 | リクエスト伝文のデータ領域で不正があった |

### 6.4 交信相手がMODBUS/TCP対応機器でエラーコードが解消されない場合

シンプルCPU通信でMODBUS/TCP機器と交信していてエラーコード **CFB0H** が解消されない場合:

| 確認項目 | 処置方法 |
|---|---|
| ゲートウェイ機器を介してEthernetユニットとMODBUS RTU/ASCII対応機器間で交信する際に **00H(ブロードキャスト)** を指定していないか | 00H指定では交信のたびにCFB0Hが検出される。オプション(16進数)からMODBUS RTU/ASCII対応機器の局番を指定する。ケーブル・ハブ・ルータなど回線状態を確認する。相手機器のIPアドレスと局番を見直す |

## 7. ラダー生成前チェックリスト

**スレーブとして使う場合**

- [ ] 相手機器接続構成設定に「MODBUS/TCP接続機器」を追加し、ポート番号（502推奨）を設定したか
- [ ] MODBUS/TCP設定の「使用有無」を「使用」にしたか
- [ ] MODBUSデバイス割り付けを16の倍数で設定したか
- [ ] 先頭MODBUSデバイス番号を「下5桁−1」で計算したか
- [ ] コイル/入力、入力レジスタ/保持レジスタで同一デバイスを使っていないか
- [ ] **ラダーを書こうとしていないか**（スレーブはプログラム不要）

**マスタとして使う場合**

- [ ] コネクションの「交信手段」を「通信プロトコル」にしたか
- [ ] 通信プロトコルライブラリから MODBUS/TCP のプロトコルを追加し、パケット変数を設定・書込みしたか
- [ ] `SD10692 = 1`（通信プロトコル準備完了）を実行条件に入れたか
- [ ] `SP.SOCOPEN` → `SP.ECPRTCL` → `SP.SOCCLOSE` の3段構成になっているか
- [ ] オープン完了信号 `SD10680.n` でインタロックしているか
- [ ] コネクション総数8を他のEthernet通信機能と取り合っていないか
