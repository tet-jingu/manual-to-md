> 第6章 SLMP機能(PDF p.96–105) / 第5部 SLMP(PDF p.539–663) / 第46〜47章 トラブルシューティング(PDF p.784–785, 801–802)
> ページ番号はすべて **PDFの通しページ番号**。

## 0. 結論サマリ

- SLMP機能には**2つの役割**がある。**ラダーの要否が真逆**なので最初に切り分ける。

| 役割 | 動作 | ラダー |
|---|---|---|
| **サーバ機能** | 外部機器（GOT・パソコン・他社機器）からSLMP伝文を受信し、FX5のデバイスを読み書きされる | **不要**（パラメータ設定のみで自動応答） |
| **クライアント機能** | FX5から外部機器へSLMP伝文を送信する | **必要**（`SP.SLMPSND` 命令） |

- クライアント機能（`SLMPSND`）は **3Eフレームのみ対応**。
- **コネクションの確立/切断はシステムが行う。ユーザ操作（OPEN/CLOSE命令）は不要。**
- 使用前に **イニシャル処理の正常完了（`SD10683.b0` = ON）** を確認する。

---

## 1. データ交信の手順

1. ケーブルと外部機器を接続する
2. エンジニアリングツールでユニットパラメータを設定する（§2）
3. パラメータをユニットに書き込み、**電源OFF→ONまたはリセット**で有効にする
4. **イニシャル処理の正常完了を確認する**
   - CPUユニット: **イニシャル状態 `SD10683.b0` = ON**
   - インテリジェント機能ユニット: 各ユニットのマニュアル参照
5. SLMP通信
   - サーバ機能: 外部機器からSLMP伝文を受信（自動応答）
   - クライアント機能: `SP.SLMPSND` で外部機器へ伝文を送信

---

## 2. パラメータ設定（GX Works3）

### CPUユニット

1. `[パラメータ]` → ユニット形名 → `[ユニットパラメータ]` → `[Ethernetポート]` → `[基本設定]` → `[自ノード設定]`
   で **「IPアドレス設定」「交信データコード」** を設定する
2. `[基本設定]` → `[相手機器接続構成設定]` → `<詳細設定>` → ユニット一覧の **"SLMP接続機器"** をドラッグ＆ドロップ

| 項目 | 設定 |
|---|---|
| プロトコル | 相手機器に合わせて **TCP** または **UDP** |
| 自局ポート番号 | **1〜5548, 5570〜65534**（5549〜5569はシステム使用・指定禁止） |
| 相手機器IPアドレス | **UDPのみ設定** |

### インテリジェント機能ユニット

`[ユニット情報]` → インテリジェント機能ユニット → `[基本設定]` → `[自ノード設定]` で IPアドレス・交信データコード（FX5-ENET, FX5-ENET/IP, FX5-EIP）を設定し、同様に相手機器接続構成設定でSLMP接続機器を追加する。

### ポート番号の推奨

- **推奨範囲**: 1024〜5548, 5570〜61439（0400H〜15ACH, 15C2H〜EFFFH）
- 1〜1023: WELL KNOWN PORT のため使用しない
- **5549〜5569: システム使用・指定禁止**
- 61440〜65534: 他の通信機能が使用するため使用しない
- SLMP機能自体は **61440(F000H), 61441(F001H)** を使用するため、他機能でこれらを指定しない

## 3. サーバ機能（ラダー不要）

外部機器から **SLMP(3E/1Eフレーム)** でFX5のデバイスデータを読み書きさせる。

- **ラダーは書かない。** パラメータ設定だけで自動応答する。
- 使用可能なフレームは **MCプロトコルの3E/1Eフレームと同様**。
- コマンドの詳細: 3Eフレーム → PDF p.585〜、1Eフレーム → PDF p.648〜

### アクセス範囲の制限（重要）

- **接続しているユニットのみアクセスできる。** その他のユニットへの交信はエラーになる。
- **接続しているユニットを経由して、CC-Linkなどの他局とは交信できない。**

### 接続台数

1台のユニットに同時にアクセスできる外部機器の台数（ソケット通信、MELSOFT接続、SLMPなどを含む）:

| ユニット | 最大台数 |
|---|---|
| CPUユニット | 8台 |
| Ethernetユニット | 32台 |
| CC-Link IE TSNマスタ・ローカルユニット | 8台 |
| EtherNet/IPユニット | 32台 |
| モーションユニット | 8台 |

> MELSOFT接続の1台分は上記に含まれない。SLMPによる接続は **Ethernet構成設定で設定した台数分のみ**同時接続できる。

### セキュリティ

**リモートパスワード機能**で外部からの不正アクセスを防止できる（PDF p.237〜）。

## 4. クライアント機能（ラダー必要）

### 4.1 使用できるユニット

| ユニット | 命令名 |
|---|---|
| **CPUユニット** | **`SP.SLMPSND`** |
| CC-Link IE TSNマスタ・ローカルユニット | `G(P).SLMPSND` |
| EtherNet/IPユニット | `G(P).SLMPSND` |
| モーションユニット | `G(P).SLMPSND` |

> **`SLMPSND` は3Eフレームのみ対応。**
> 命令のオペランド詳細は `MELSEC iQ-F FX5プログラミングマニュアル(命令/汎用FUN/汎用FB編)` を参照。

### 4.2 動作

```
SLMPSND命令に「相手機器」「SLMPのコマンド」などを指定して実行
  → ユニットから相手機器へ 要求伝文（サブヘッダ＋宛先＋コマンド＋データ）を送信
  → 相手機器からの 応答伝文 が、SLMPSND命令で指定したデバイスに格納される
```

- **コネクションの確立/切断はシステムが行う。** `SP.SOCOPEN` / `SP.SOCCLOSE` は不要。
- 完了デバイスの考え方は他のEthernet専用命令と同じ（`(d)+0`: 完了で1スキャンON、`(d)+1`: 異常完了時ON）。

### 4.3 ラダー実装パターン（骨格）

```
<<イニシャル完了を待ってから実行>>
X20  SD10683.0(イニシャル処理正常完了)  M0(b接点)
──┤├─────────┤├───────────────┤/├──[ SP.SLMPSND ... M0 ]

M0  M1(b接点) ──[ SET M101 ]         ; 正常完了
M0  M1        ──[ SET M102 ]         ; 異常完了
M1            ──[ MOV <完了ステータス> D100 ]   ; エラーコード退避
```

**必ず守る点**

- **`SD10683.b0`（イニシャル処理正常完了）でインタロックする**（未完了で実行すると C1BAH）。
- 命令完了まで要求データ・コントロールデータを書き換えない。
- 同一コネクションで命令を多重実行しない。

## 5. リンク時間（性能の目安）

SLMPによる交信の最小処理時間（一括読出し／一括書込み）:

```
Tfs = Ke + (Kdt × Df) + Scr × 処理に要するスキャン回数 + 相手機器のACK処理時間   [ms]
```

| 記号 | 意味 |
|---|---|
| Tfs | 相手機器の要求データを受信してからCPUユニットが処理を完了するまでの時間(ms) |
| Ke, Kdt | 定数（TCP/IP・UDP/IP、ASCII・バイナリのいずれも **Ke=1, Kdt=0.001**） |
| Df | 要求データワード数 ＋ 応答データワード数（アプリケーションデータ部） |
| Scr | スキャンタイム |

**計算例**（TCP/IP、Dデバイス32点をバイナリで読出し、スキャンタイム40ms）

```
Tfs = 1 + (0.001 × 32) + 40 × 1 + 相手機器のACK処理時間 ≒ 41ms + ACK処理時間
```

> ネットワーク負荷率、各機器のウィンドウサイズ、同時使用コネクション数、システム構成により処理時間はさらに長くなる。上式は**コネクション1つのみで交信している場合の目安**。

## 6. 設計上の注意

1. **サーバ用途ならラダーを書かない。** 不要な回路を作らない。
2. **UDPの制限**:
   - 1つのUDPポートに対し、要求伝文を送信して**応答伝文が返るまでの間に新しい要求伝文を送ると、新しい要求は破棄される**。
   - **UDPで同一の自局ポート番号を複数設定しても、1つだけ設定した場合と同じになる。** 複数の相手機器と同じ自局ポート番号で交信する場合は **TCPを使う**。
3. **交信データコード（バイナリ/ASCII）を相手機器と一致させる。** 不一致だと C050H / C06FH。
4. アクセス範囲は接続ユニットのみ。他局への中継はできない。
5. **相手機器側の受信処理はTCPソケットの境界なし特性を考慮する。** 送信側が `send` を1回呼んでも、受信側は `recv` を1回以上呼ぶ必要がある（send と recv は1対1に対応しない）。受信サイズチェック→不足なら継続受信、というループを相手機器側で実装する。

### 相手機器側の推奨受信処理フロー

```
要求伝文・送信処理
  ↓
応答伝文・受信処理
  ├ 受信データを監視タイマ値以内に受信できたか？ ── No → エラー処理
  ├ 受信サイズチェック（不足なら継続受信）
  ├ 応答伝文に対する処理
  ├ 受信伝文をすべて処理したか？ ── No → 継続
  └ TCPコネクションはオープンしているか？ ── No → 終了
```

## 7. トラブルシューティング（SLMPのみ）

### 7.1 LED表示による確認

| "SD/RD" LED表示 | 動作状態 |
|---|---|
| 点滅 | データの送受信を行っている（正常時は**明るく点滅**する） |
| 消灯 | データの送受信ができていない → **配線または通信設定を確認する** |

### 7.2 SLMPによる交信時の異常（PDF p.784）

1. **相手機器接続構成設定は正しいか** → 正しくなければ設定し直す
2. **相手機器からコマンドを送信したか** → 送信していなければ送信側をチェックする
3. **コマンドを送信した機器にレスポンスが返信されているか**
4. **レスポンスの終了コードが "0" か** → 0以外なら終了コード・異常コードの内容に基づいて異常箇所を修復する
5. **IPフィルタ設定で相手機器のIPアドレスを遮断していないか** → 遮断を解除、または透過アドレスとして設定する
6. **コマンドのIPアドレス指定は正しいか** → 修正して再送信する
7. **相手機器との通信プロトコル（TCP/UDP）は一致しているか** → 一致させる

### 7.3 SLMP機能のエラーコード

異常終了時、応答伝文の**終了コード**に格納される。

| コード | 異常内容と原因 | 処置方法 |
|---|---|---|
| C035H | レスポンス監視タイマ値以内に相手機器の生存確認ができなかった | 相手機器の動作・接続ケーブル・生存確認用の各設定値を確認する |
| C050H | 交信データコードが"ASCII"設定時に、バイナリ変換できないASCIIコードのデータを受信した | 交信データコードを"バイナリ"に設定して立ち上げ直す／相手機器の送信データを修正する |
| C051H | 一度に一括読み書きできる最大**ビット**デバイス数が許容範囲外 | 一括書込み/読出しビットデバイス数を修正して再送信する |
| C052H | 一度に一括読み書きできる最大**ワード**デバイス数が許容範囲外 | 一括書込み/読出しワードデバイス数を修正して再送信する |
| C053H | 一度にランダム読み書きできる最大**ビット**デバイス数が許容範囲外 | ランダム書込み/読出しビットデバイス数を修正して再送信する |
| C054H | 一度にランダム読み書きできる最大**ワード**デバイス数が許容範囲外 | ランダム書込み/読出しワードデバイス数を修正して再送信する |
| C056H | 最大アドレスを超える書込み/読出し要求である | 先頭アドレスまたは点数を修正する（最大アドレスを超えないようにする） |
| C057H | SLMP伝文の要求データ長が、キャラクタ部のデータ数と合わない | テキスト部の内容、またはヘッダ部の要求データ長を見直す |
| C058H | ASCII-バイナリ変換後の要求データ長が、キャラクタ部のデータ数と合わない | 同上 |
| C059H | コマンド、サブコマンドの指定に誤りがある／CPUユニットで使用不可のコマンド・サブコマンドである | 要求内容を見直し、使用できるコマンド・サブコマンドを送信する |
| C05BH | 指定デバイスに対してCPUユニットが書込み/読出しできない | 書込み/読出しするデバイスを見直す |
| C05CH | 要求内容に誤りがある（ワードデバイスに対するビット単位の書込み/読出しなど、デバイス指定に関する誤り） | 要求内容（サブコマンドなど）を修正する |
| C05FH | 対象CPUユニットに対して実行できない要求である | ネットワーク番号、要求先局番号、要求先ユニットI/O番号、要求先ユニット局番号、要求内容を修正する |
| C060H | 要求内容に誤りがある（ビットデバイスに対するデータの指定誤りなど） | 要求内容（データ）を修正する |
| C061H | 要求データ長が、キャラクタ部のデータ数と合わない | テキスト部の内容、またはヘッダ部の要求データ長を見直す |
| C06FH | 交信データコードが"バイナリ"設定時に、ASCIIの要求伝文を受信した（**エラー履歴のみ登録され、異常応答は返らない**） | 交信データコードの設定に合った要求伝文を送信する／要求伝文に合った交信データコードに変更する |
| C0D8H | 指定したブロック数が範囲を超えている | ブロック数の指定値を修正する |
| C200H | リモートパスワードに誤りがある | リモートパスワードを見直し、アンロック処理およびロック処理を再実行する |
| C201H | 交信に使用したポートがリモートパスワードのロック状態である | アンロック処理を実行してから交信する |
| C204H | リモートパスワードのアンロック処理を要求した相手機器と異なる | アンロック処理を要求した相手機器からロック処理を要求する |
| C810H | リモートパスワードに誤りがある（認証失敗回数9回以下） | リモートパスワードを見直し、アンロック/ロック処理を再実行する |
| C815H | リモートパスワードに誤りがある（認証失敗回数10回） | 規定時間経過後にアンロック/ロック処理を再実行する |
| C816H | リモートパスワード認証ロックアウト中である | 規定時間経過後にアンロック/ロック処理を再実行する |

## 8. ラダー生成前チェックリスト

**サーバ用途（外部機器からアクセスされる）**

- [ ] 自ノード設定でIPアドレスと交信データコードを設定したか
- [ ] 相手機器接続構成設定に「SLMP接続機器」を追加し、プロトコル(TCP/UDP)とポート番号を設定したか
- [ ] ポート番号が禁止範囲（5549〜5569）や他機能（61440, 61441 等）と重複していないか
- [ ] **ラダーを書こうとしていないか**（サーバ応答は自動）
- [ ] 同時接続台数（CPUユニット8台等）を超えていないか

**クライアント用途（`SP.SLMPSND` を使う）**

- [ ] `SD10683.b0`（イニシャル処理正常完了）でインタロックしたか
- [ ] 3Eフレームのコマンドを指定しているか（1Eフレームは非対応）
- [ ] 完了デバイス2点で正常/異常を判定しているか
- [ ] 命令完了まで要求データを書き換えない構成か
- [ ] UDP使用時、応答が返る前に次の要求を送っていないか（破棄される）
- [ ] 相手機器と交信データコード（バイナリ/ASCII）を一致させたか
