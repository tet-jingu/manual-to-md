## 0. 結論サマリ（最初に読む部分）

- ソケット通信＝**専用命令でTCP/UDPの任意データを送受信する機能**。ラダーが必須。
- CPUユニット内蔵Ethernet: **コネクションNo.1〜8**、命令は `SP.SOC***`（ユニット指定は文字列 `"U0"`）。
- Ethernetユニット/EtherNet/IPユニット: **コネクションNo.1〜32**、命令は `GP.***`（ユニット指定は装着位置番号 `U`）。
- 命令は必ず **オープン完了信号でインタロック**し、**完了デバイス(d)+0 / (d)+1 のペアで結果判定**する。
- **割込みプログラム中でソケット通信命令を実行してはならない**（エラー 3582H）。
- 命令完了までコントロールデータ・送信データを書き換えてはならない。

## 1. 構成の選択

| 使用ユニット | 命令体系 | コネクション数 | ユニット指定オペランド | 状態信号 |
|---|---|---|---|---|
| CPUユニット内蔵Ethernet | `SP.SOCOPEN` / `SP.SOCCLOSE` / `SP.SOCRCV` / `SP.SOCSND` / `SP.SOCCINF` / `S(P).SOCRDATA` | 1〜8 | 文字列 `"U0"`（ラベル不可） | SD10680〜SD10683 |
| FX5-ENET等 Ethernetユニット / EtherNet/IPユニット | `GP.OPEN` / `GP.CLOSE` / `GP.SOCRCV` / `GP.SOCSND` | 1〜32 | 装着位置番号 `U`（FX5UJ: 1H〜8H、FX5U/FX5UC: 1H〜10H） | Un\G152〜159 |

> `SP.SOCCINF` と `S(P).SOCRDATA` は **CPUユニット専用**。Ethernetユニットには相当命令がない。

## 2. 事前に決める設定（パラメータ）

GX Works3 のパラメータで「相手機器接続構成設定」にコネクションを登録する。

- **CPUユニット**: ナビゲーションウィンドウ → [パラメータ] → ユニット形名 → [ユニットパラメータ] → [Ethernetポート] → [基本設定] → [相手機器接続構成設定] → [詳細設定]
- **Ethernetユニット**: ナビゲーションウィンドウ → [パラメータ] → [ユニット情報] → [Ethernetユニット] or [EtherNet/IPユニット] → [基本設定] → [相手機器接続構成設定] → [詳細設定]

ユニット一覧からドラッグ＆ドロップする接続機器の種類:

| 通信形態 | 選択する接続機器 | シーケンサ側ポート番号 | 相手機器IP/ポート |
|---|---|---|---|
| TCP Active | Active接続機器 | 1〜5548, 5570〜65534 | 必須 |
| TCP Unpassive | Unpassive接続機器 | 同上 | 設定なし（任意の相手を許可） |
| TCP Fullpassive | Fullpassive接続機器 | 同上 | 必須（一致した相手のみ許可） |
| UDP | UDP接続機器 | 同上 | 必須 |

### ポート番号の禁止・推奨（必ず守る）

- **推奨範囲**: 1024〜5548, 5570〜61439（0400H〜15ACH, 15C2H〜EFFFH）
- 1〜1023: WELL KNOWN PORT のため使用しない
- **5549〜5569 (15ADH〜15C1H): システム使用。指定禁止**
- 61440〜65534 (F000H〜FFFEH): 他の通信機能が使用するため使用しない
- 他機能と重複禁止のポート: FTPサーバ **20, 21** / Webサーバ **80**(デフォルト・変更可) / SNTPクライアント **123** / SLMP **61440, 61441** / CC-Link IEフィールドネットワークBasic **61450**
- iQ Sensor Solution対応機能使用時は **45237 (B0B5H)** と 61440〜65534 を指定しない

### Ethernetユニットの「オープン方法の設定」

[基本設定] → [自ノード設定] で選ぶ。ラダーの構成が変わる。

| 設定 | TCP Passive時の動作 | UDP時の動作 | ラダー |
|---|---|---|---|
| プログラムでOPENしない | 常にオープン待ち。相手のActiveオープンで確立 | 立上げ完了後に自動オープン | **OPEN/CLOSE命令不要** |
| プログラムでOPENする | `GP.OPEN` 実行でオープン待ちにする必要あり | `GP.OPEN`/`GP.CLOSE` が必要 | OPEN/CLOSEを実装 |

> ⚠ 「プログラムでOPENしない」設定で専用命令によりクローズすると、該当コネクションは**オープン要求待ち状態に戻らない**。以降のオープン/クローズはすべてプログラムで行う必要がある。
>
> ⚠ コネクションの設定を変更する場合は、`GP.OPEN` 実行**前**に変更する。オープン処理実行後、完了前にオープン要求は中止できない（完了後に `GP.CLOSE` すること）。

## 4. 命令一覧

### CPUユニット専用命令

| 命令 | 内容 | 本書内参照 |
|---|---|---|
| `SP.SOCOPEN` | コネクションを確立する | §5.1 |
| `SP.SOCCLOSE` | コネクションを切断する | §5.2 |
| `SP.SOCRCV` | 受信データを読み出す（END処理読出し） | §5.3 |
| `SP.SOCSND` | データを送信する | §5.4 |
| `SP.SOCCINF` | コネクション情報を読み出す | §5.5 |
| `S(P).SOCRDATA` | ソケット通信受信データエリアのデータを読み出す | §5.6 |

### Ethernetユニット / EtherNet/IPユニット専用命令

| 命令 | 内容 |
|---|---|
| `GP.OPEN` | コネクションを確立する |
| `GP.CLOSE` | コネクションを切断する |
| `GP.SOCRCV` | 受信データを読み出す |
| `GP.SOCSND` | データを送信する |

### 全命令共通の制約（必ず適用）

1. **完了デバイスのある命令は、実行完了までコントロールデータ・要求データを変更しない。**
2. **割込みプログラム中で実行しない。**
3. 完了デバイス `(d)` に **T, ST, C は使用できない**。
4. `"U0"` を指定するCPU専用命令は、**言語によらず文字列で直接指定**する（ラベル指定不可）。
5. 完了デバイスの使い方は全命令共通:
   - `(d)+0`: 命令完了スキャンのEND処理でON、次のEND処理でOFF（**1スキャンON**）
   - `(d)+1`: **異常完了時のみ**同じタイミングでON。正常完了時はOFFのまま変化しない
   - → 判定回路は `(d)+0` と `(d)+1` のa接点／b接点の組合せで正常・異常を分岐させる

## 5. 命令仕様

### 5.1 コネクションの確立

#### SP.SOCOPEN（CPUユニット専用）

```
[実行条件]──[ SP.SOCOPEN  "U0"  (s1)  (s2)  (d) ]
ST: ENO := SP_SOCOPEN(EN, U0, s1, s2, d);
```

| オペランド | 内容 | 範囲 | データ型 |
|---|---|---|---|
| (U) | ダミー。文字列 `"U0"` を入力 | — | 文字列 |
| (s1) | コネクション番号 | 1〜8 | 符号なしBIN16 |
| (s2) | コントロールデータ先頭デバイス | 10ワード使用 | ワード |
| (d) | 完了デバイス先頭 | 2点使用 | ビット |

**コントロールデータ（10ワード）**

| デバイス | 項目 | 内容 | 設定範囲 | セット側 |
|---|---|---|---|---|
| (s2)+0 | 実行タイプ/完了タイプ | `0000H`: パラメータ「相手機器接続構成設定」の内容でオープン / `8000H`: (s2)+2〜+6 の内容でオープン | 0000H, 8000H | ユーザ |
| (s2)+1 | 完了ステータス | 0000H: 正常完了 / 0000H以外: エラーコード | — | システム |
| (s2)+2 | 使用用途設定エリア | 下記ビット構成 | — | ユーザ |
| (s2)+3 | 自局ポート番号 | 1〜5548, 5570〜65534 | — | ユーザ |
| (s2)+4,+5 | 相手機器IPアドレス（32bit） | 1〜3758096382 (00000001H〜DFFFFFFEH) | — | ユーザ |
| (s2)+6 | 相手機器ポート番号 | 1〜65534 (0001H〜FFFEH) | — | ユーザ |
| (s2)+7〜+9 | 使用禁止 | — | — | システム |

**(s2)+2 使用用途設定エリアのビット構成**

| ビット | 項目 | 値 |
|---|---|---|
| b15 | 通信方式(プロトコル) | 0: TCP/IP、1: UDP/IP |
| b14 | ソケット通信機能の手順有無 | 0: 通信プロトコル、1: ソケット通信(無手順) |
| b13 | 通信プロトコル設定 | 0: 通信プロトコル機能を使用しない(ソケット通信)、1: 使用する |
| b9, b8 | オープン方式 | `00`: Active または UDP/IP、`10`: Unpassive、`11`: Fullpassive |
| その他 | — | 0 |

> Unpassiveオープン時は **相手機器のIPアドレスとポート番号は無視される**。
> 代表値: `H200` = TCP/IP・ソケット通信(無手順)・Activeオープン。

**エラー（SD0/SD8067に格納）**

| コード | 内容 |
|---|---|
| 3405H | (s1) のコネクション番号が1〜8以外 |
| 2820H | (s2), (d) のデバイス番号がデバイス点数の範囲を超えた |
| 2822H | 指定できないデバイスを指定した |
| 3582H | 割込みルーチンプログラムで使用できない命令を使用した |

**プログラム例（パラメータ設定値でオープン）**

```
M1000  SD10680.0(b)  SD10681.0(b)
──┤├─────┤/├────────┤/├──[ MOVP  H0  D100 ]     ; 実行タイプ/完了タイプ=0000H
                                   [ SP.SOCOPEN "U0" K1 D100 M100 ]
M100  M101(b接点) ──[ SET M150 ]   ; 正常完了表示
M100  M101        ──[ SET M151 ]   ; 異常完了表示
```

**プログラム例（コントロールデータでオープン: TCP/Active, 自局4096, 相手10.97.79.14:4096）**

```
[ MOVP  H8000      D100 ]   ; 実行タイプ/完了タイプ
[ MOVP  H200       D102 ]   ; 使用用途設定(TCP/IP, 無手順, Active)
[ MOVP  H1000      D103 ]   ; 自局ポート番号 4096
[ DMOVP H0A614F0E  D104 ]   ; 相手IP 10.97.79.14
[ MOVP  H1000      D106 ]   ; 相手ポート番号 4096
[ SP.SOCOPEN "U0" K1 D100 M100 ]
```

> パラメータ上で設定していないコネクション（プロトコル欄が空欄）も、(s2)+0 に `8000H` を設定すればオープンして使用できる。

#### GP.OPEN（Ethernetユニット/EtherNet/IPユニット専用）

```
[実行条件]──[ GP.OPEN  U  (s1)  (s2)  (d) ]
ST: ENO := GP_OPEN(EN, U, s1, s2, d);
```

`SP.SOCOPEN` との差分:

| 項目 | GP.OPEN |
|---|---|
| (U) | 装着位置番号。FX5UJ: 1H〜8H、FX5U/FX5UC: 1H〜10H |
| (s1) | コネクション番号 **1〜32** |
| (s2)+2 のビット | b15: 通信方式、**b9,b8: オープン方式**（「手順有無」ビットは無い） |
| コントロールデータ長 | 10ワード（同じ） |

**GP.OPEN の完了ステータスエラーコード ((s2)+1)**

| コード | 内容 |
|---|---|
| 1D80H | 実行可能な専用命令番号以外の命令が指定された |
| 1D83H | CPUユニットから専用命令要求データのサイズが異常のため棄却された |
| 1D84H | CPUユニットからの専用命令要求データが正常に入力できなくなった |
| 1D85H | 専用命令応答データでタイムアウトエラーが発生してデータが棄却された |
| C029H | コントロールデータの内容がおかしい |
| C1A6H | 1〜32以外のコネクション番号が指定された |

> インタロックには `Un\G152`/`Un\G153`（オープン完了）、`Un\G154`/`Un\G155`（オープン要求）、`Un\G158.b0`（イニシャル正常完了）を使う。

### 5.2 コネクションの切断

#### SP.SOCCLOSE（CPUユニット専用） / GP.CLOSE（ユニット専用）

```
[実行条件]──[ SP.SOCCLOSE  "U0"  (s1)  (s2)  (d) ]
[実行条件]──[ GP.CLOSE      U    (s1)  (s2)  (d) ]
```

| オペランド | 内容 | 範囲 |
|---|---|---|
| (s1) | コネクション番号 | SP: 1〜8 / GP: 1〜32 |
| (s2) | コントロールデータ先頭（**2ワード**） | (s2)+0: システムエリア、(s2)+1: 完了ステータス |
| (d) | 完了デバイス先頭（2点） | — |

> ⚠ **最重要**: **Passiveオープンのコネクションに対してCLOSE命令を実行しないこと。** 実行するとオープン完了信号・オープン要求信号がOFFになりクローズされるため、以後**送受信できなくなる**。再開にはOPEN命令が必要。UDPのコネクションも同様にCLOSE命令を実行しない。

**エラー（SP.SOCCLOSE, SD0/SD8067）**: 3405H / 2820H / 2822H / 3582H（内容は §5.1 と同じ）
**エラー（GP.CLOSE, (s2)+1）**: 1D80H / 1D83H / 1D84H / 1D85H / C029H / C1A6H

**プログラム例（自発クローズ＋相手切断検出）**

```
M2000(クローズ指示) ──[ SET M210 ]             ; 実行中フラグ
SD10680.0 の立下り  ──[ PLS M161 ]             ; 相手からの切断検出
M161                ──[ SET M210 ]

M210  SD10680.0 ──[ SP.SOCCLOSE "U0" K1 D200 M200 ]
M200  M201(b接点) ──[ SET M202 ]               ; 正常完了
M200  M201        ──[ SET M203 ]               ; 異常完了
M200              ──[ RST M210 ]               ; 実行中フラグ解除
```

### 5.3 受信データの読出し

#### SP.SOCRCV（CPUユニット専用） / GP.SOCRCV（ユニット専用）

```
[実行条件]──[ SP.SOCRCV  "U0"  (s1)  (s2)  (d1)  (d2) ]
[実行条件]──[ GP.SOCRCV   U    (s1)  (s2)  (d1)  (d2) ]
```

| オペランド | 内容 |
|---|---|
| (s1) | コネクション番号（SP: 1〜8 / GP: 1〜32） |
| (s2) | コントロールデータ先頭（2ワード）。(s2)+1 に完了ステータス |
| (d1) | 受信データ格納先頭。**(d1)+0 = 受信データ長（バイト数, 0〜2046）**、(d1)+1以降に受信データ |
| (d2) | 完了デバイス先頭（2点） |

**動作**

- 命令実行後の **END処理** でソケット通信受信データエリアから読み出す → **スキャンタイムが延びる**。
- 奇数バイト受信時、最後のワードの**上位バイトには無効データが入る**。
- 受信起動条件は **受信状態信号**（CPU: `SD10682.n` / ユニット: `Un\G156.n`, `Un\G157.n`）のON。

**エラー（SP.SOCRCV, SD0/SD8067）**

| コード | 内容 |
|---|---|
| 3405H | (s1) のコネクション番号が1〜8以外 |
| 2820H | **受信データが格納先デバイスサイズを超えた** / (s2),(d1),(d2)がデバイス点数超過 |
| 2822H | 指定できないデバイスを指定した |
| 3582H | 割込みルーチンプログラムで使用できない命令を使用した |

**エラー（GP.SOCRCV, (s2)+1）**: 1D80H / 1D83H / 1D84H / 1D85H / C029H / C1A6H

**プログラム例（連続受信対応）**

```
M5000  SD10680.0  SD10682.0  M450(b接点)
──┤├────┤├───────┤├───────┤/├──[ SP.SOCRCV "U0" K1 D5000 D500 M450 ]
M450  M451(b接点) ──[ SET M452 ]   ; 正常完了
M450  M451        ──[ SET M453 ]   ; 異常完了
```

> **定石**: 完了デバイス `(d2)+0` を **b接点** で実行条件に直列に入れると、データを連続受信しても連続して読み出せる。

### 5.4 データ送信

#### SP.SOCSND（CPUユニット専用） / GP.SOCSND（ユニット専用）

```
[実行条件]──[ SP.SOCSND  "U0"  (s1)  (s2)  (s3)  (d) ]
[実行条件]──[ GP.SOCSND   U    (s1)  (s2)  (s3)  (d) ]
```

| オペランド | 内容 |
|---|---|
| (s1) | コネクション番号（SP: 1〜8 / GP: 1〜32） |
| (s2) | コントロールデータ先頭（2ワード）。(s2)+1 に完了ステータス |
| (s3) | 送信データ先頭。**(s3)+0 = 送信データ長（バイト数, 1〜2046）**、(s3)+1以降が送信データ |
| (d) | 完了デバイス先頭（2点） |

**注意**

- TCPの場合、**送信データ長は相手機器の最大ウィンドウサイズ（TCP受信バッファ）以下**にする。超えるデータは送信できない。
- **完了デバイスON後も送信が続く場合がある**（完了＝相手の受信完了ではない）。

**エラー（SP.SOCSND, SD0/SD8067）**: 3405H / 2820H / 2822H / 3582H
**エラー（GP.SOCSND, (s2)+1）**: 1D80H / 1D83H / 1D84H / 1D85H / **C020H**(最大データ長超過) / **C027H**(伝文送信失敗) / C029H / C1A6H

**プログラム例（6バイト送信）**

```
M3000  SD10680.0
──┤├────┤├──[ MOV K6      D300 ]   ; 送信データ長 6バイト
                 [ MOV K1234   D301 ]
                 [ MOV K5678   D302 ]
                 [ MOV K8901   D303 ]
                 [ SP.SOCSND "U0" K1 D3000 D300 M300 ]
M300  M301(b接点) ──[ SET M302 ]
M300  M301        ──[ SET M303 ]
```

### 5.5 SP.SOCCINF（コネクション情報の読出し・CPUユニット専用）

```
[実行条件]──[ SP.SOCCINF  "U0"  (s1)  (s2)  (d) ]
```

| オペランド | 内容 |
|---|---|
| (s1) | コネクション番号 1〜8 |
| (s2) | コントロールデータ先頭（2ワード）。(s2)+1 に完了ステータス |
| (d) | コネクション情報格納先頭（**5ワード**） |

**格納されるコネクション情報**

| デバイス | 項目 | 範囲 |
|---|---|---|
| (d)+0, (d)+1 | 相手機器IPアドレス | 1〜3758096382 |
| (d)+2 | 相手機器ポート番号 | 1〜65534 |
| (d)+3 | 自局ポート番号 | 1〜5548, 5570〜65534 |
| (d)+4 | 使用用途設定エリア | b15: 0=TCP/1=UDP、b14: 1=無手順、b9/b8: 00=Active or UDP, 10=Unpassive, 11=Fullpassive |

- **オープンされていないコネクションで実行した場合は 0 が返る。**
- 用途: Unpassive/UDPで**接続してきた相手のIPアドレス・ポート番号を特定する**。

**エラー（SD0/SD8067）**: 3405H / 2820H / 2822H

```
M5000 ──[ SP.SOCCINF "U0" K1 D500 D5000 ]
```

### 5.6 S(P).SOCRDATA（受信データエリアの直接読出し・CPUユニット専用）

```
[実行条件]──[ S.SOCRDATA   "U0"  (s1)  (s2)  (d)  (n) ]
[実行条件]──[ SP.SOCRDATA  "U0"  (s1)  (s2)  (d)  (n) ]
```

| オペランド | 内容 |
|---|---|
| (s1) | コネクション番号 1〜8 |
| (s2) | コントロールデータ先頭（2ワード）。(s2)+1 に完了ステータス |
| (d) | 読出しデータ格納先頭 |
| (n) | 読出しデータ数 **1〜1024ワード**（0のときは無処理） |

**特性（重要）**

- **受信データエリアはクリアされず、受信状態信号も変化しない** → この命令だけでは次の受信データが入らない。
- 受信データを更新したい場合は必ず `SP.SOCRCV` を使う。
- **定石**: `(n)=K1` で読むと **受信データ長だけを先読み**できる。これにより `SP.SOCRCV` 実行前に格納先デバイスを切り替えられる。

**エラー（SD0/SD8067）**: 3405H / 2820H / 2822H

```
M4000  SD10680.0  SD10682.0
──┤├────┤├───────┤├──[ S.SOCRDATA "U0" K1 D400 D4000 K1 ]
```

## 6. ラダー実装パターン

### 6.1 TCP・Activeオープン（自局がクライアント）

処理の流れ: **オープン(OPEN) → 送信(SOCSND)/受信(SOCRCV) → クローズ(CLOSE)**

```
<<コネクションNo.1 オープン処理(Active)>>
M1000  SD10680.0(b)  SD10681.0(b)
──┤├─────┤/├────────┤/├──[ MOVP H0 D100 ]
                                   [ SP.SOCOPEN "U0" K1 D100 M100 ]
M100 M101(b) ─[ SET M1002 ]   ; オープン正常完了表示
M100 M101    ─[ SET M1003 ]   ; オープン異常完了表示

<<データ送信処理>>
M3000  SD10680.0
──┤├────┤├──[ MOVP K6 D300 ][ MOVP H3412 D301 ][ MOVP H7856 D302 ][ MOVP HBC9A D303 ]
                 [ SP.SOCSND "U0" K1 D3000 D300 M300 ]
M300 M301(b) ─[ SET M3002 ]
M300 M301    ─[ SET M3003 ]

<<データ受信処理>>
SD10680.0  SD10681.0  SD10682.0  M400(b)
────┤├──────┤├───────┤├───────┤/├──[ SP.SOCRCV "U0" K1 D5000 D500 M400 ]
M400 M401(b) ─[ SET M5002 ]
M400 M401    ─[ SET M5003 ]

<<コネクションNo.1 クローズ処理>>
SD10680.0 の立下り ──[ PLS M4001 ]              ; 相手側からの切断を検出
M4000(クローズ指示) または M4001 ──[ SET M410 ] ; クローズ実行中フラグ
M410  SD10680.0 ──[ SP.SOCCLOSE "U0" K1 D200 M200 ]
M200 M201(b) ─[ SET M4002 ]
M200 M201    ─[ SET M4003 ]
M200         ─[ RST M410 ]
```

**インタロックの必須要件**: オープン完了信号(`SD10680.n` / `Un\G152.bn`, `Un\G153.bn`)とオープン要求信号(`SD10681.n` / `Un\G154.bn`, `Un\G155.bn`)を**必ず**回路に組み込む。

信号のON/OFFタイミング:

- 自局からクローズ: OPEN命令でON → CLOSE命令実行 → ユニットからTCP接続切断要求 → 相手の応答で切断完了 → OFF
- 相手からクローズ: 相手からTCP接続切断要求 → ユニットの応答で切断完了 → オープン完了信号OFF（この立下りを検出してクローズ処理へ）

### 6.2 TCP・Passiveオープン（自局がサーバ）

処理の流れ: **Passiveオープンで接続待ち → 送受信**（OPEN/CLOSE命令はプログラムに書かない）

```
<<交信相手確認処理（任意）>>
SD10680.0 ──[ SP.SOCCINF "U0" K1 D6000 D6010 ]   ; 接続してきた相手のIP/ポートを取得

<<データ送信処理>>
M3000  SD10680.0
──┤├────┤├──[ MOVP K6 D300 ] …  [ SP.SOCSND "U0" K1 D3000 D300 M300 ]

<<データ受信処理>>
SD10680.0  SD10682.0  M400(b)
────┤├──────┤├───────┤/├──[ SP.SOCRCV "U0" K1 D5000 D500 M400 ]
```

**Passive固有の注意**

- **プログラム内でCLOSE命令を実行しない**（実行すると送受信不能になる）。
- TCPは1コネクション＝相手1台。**同一自局ポートで複数台と接続するには台数分のコネクションを用意**する。超過した接続要求は即切断される。
- ユニット立上げ完了〜オープン待ち状態になるまでに来たTCP接続要求はエラーになり、相手へ強制クローズを返す。相手側で時間をおいてリトライさせる。
- Unpassiveは相手を制限しない。相手を限定するなら Fullpassive（指定IP/ポート以外は交信前に自動切断）。

### 6.3 UDP

```
<<データ送信処理>>
M3000  SD10680.0
──┤├────┤├──[ MOVP K6 D300 ] …  [ SP.SOCSND "U0" K1 D3000 D300 M300 ]

<<データ受信処理>>
SD10680.0  SD10682.0  M400(b)
────┤├──────┤├───────┤/├──[ SP.SOCRCV "U0" K1 D5000 D500 M400 ]
        └─ 必要なら [ SP.SOCCINF "U0" K1 D450 D460 ] で相手機器情報を取得
```

**UDP固有の注意**

- UDPコネクションの **オープン完了信号・オープン要求信号は常時ON**。
- **CLOSE命令を実行しない**（実行すると送受信不能になる）。
- データの消失・到着順序の入れ替わりが起こりうる。問題がある場合はTCPを検討する。
- 回線が断線していても**送信処理が正常終了することがある**ため、**ユーザ側で交信手順（アプリ層のACK等）を設けることを推奨**。

## 7. プログラム作成上の必須ルール（違反するとバグになる）

1. **インタロック**: 全命令をオープン完了信号（＋必要に応じオープン要求信号）で修飾する。
2. **完了判定**: `(d)+0` のONで完了、同時に `(d)+1` がONなら異常。異常時は `(s2)+1` の完了ステータスを退避してから次処理へ。
3. **命令実行中はコントロールデータ／送信データを書き換えない。**
4. **割込みプログラム中でソケット通信命令を実行しない。**
5. **受信データは溜めない**: 受信状態信号がONしたら速やかに `SOCRCV` で読み出す。多くの受信データが読み出されない状態が続くと**ユニットの交信に影響**する。
6. **相手機器から受信した全データを読み出すまで CLOSE命令を実行しない。**
7. RUN→STOP時に**受信データはクリアされる**。
8. **TCPは境界のないストリーム**: 連続送信したデータが結合されたり、一括送信したデータが分割されたりする。受信側は **受信データ長を必ず確認**し、不足なら残りを受信するループ処理を作る。
9. **再接続は500ms以上あける**: 同一の(相手IP, 自局ポート, 相手ポート)でクローズ直後に再接続する場合は500ms以上待つ。待てない場合はActiveオープン側の自局ポート番号を変更する。
10. **TCPの同時接続条件**: 「自局IP・自局ポート・相手IP・相手ポート」の4要素が同一の接続は同時に1つしか作れない。複数同時接続時はいずれかを変える。
11. TCPが自動的にクローズする条件: 相手からのクローズ要求のほか、**生存確認機能のタイムアウト**、**相手機器からの強制クローズ受信**。
12. ルータ経由でアクセスする場合は、サブネットマスクパターンとデフォルトゲートウェイIPアドレスも設定する。

### 受信側の推奨処理フロー（TCP）

```
受信開始
  ├ 受信データを監視タイマ値以内に受信できたか？ ── No → エラー処理
  ├ 受信サイズチェック（受信サイズが不足していないか？）
  │     └ 不足 → 残りの受信伝文を受信
  ├ 受信伝文に対する処理
  ├ 受信伝文をすべて処理したか？ ── No → 継続
  └ TCPコネクションはオープンしているか？ ── No → 終了（クローズ処理）
```

## 8. トラブルシューティング（ソケット通信・Ethernet交信）

### 8.1 データ交信が行えないときの確認フロー（PDF p.782）

1. CPUユニットに処理を停止するエラーが発生していないか → 発生時はエラーコードを確認して復旧
2. Ethernet搭載ユニットにエラーが発生していないか → FX5ユーザーズマニュアルのトラブルシューティング参照
3. イニシャル処理は正常完了しているか（`SD10683.b0` / `Un\G158.b0`）→ 未完了ならパラメータを確認し、修正したものをダウンロード
4. 接続ケーブルは確実に接続・ロックされているか
5. 交信データのデータコード（バイナリ/ASCII）設定が送信ノードと受信ノードで一致しているか → [ユニットパラメータ]-[自ノード設定]-[交信データコード]を修正
6. エラーコードを確認して異常箇所を修復

> データコードが送信ノードと受信ノードで異なると、コマンドを正常に解読できず送受信できない。

### 8.2 補足事項（PDF p.783）

- GX Works3 の **Ethernet診断** でエラー状態を確認できる。
- 異常でユニットを交換したときは、**交信していた全ての相手機器を再立上げ**する（相手がMACアドレスを保持していると継続交信できない）。
- 相手機器（パソコンなど）を交換した場合も、**CPUユニットの電源OFF→ONまたはリセット**を行う。
- 相手機器からの送信伝文を受信できないことが多発する場合、Ethernet回線の高負荷が考えられる。ネットワーク分離・送信回数削減などで負荷を軽減する。
- **ユニットのアース端子が未接地だと、ノイズの影響で通信回線がクローズ（切断）される**ことがある。

### 8.3 ソケット通信に関係する主なエラーコード

格納先: 命令自体のエラーは `SD0`/`SD8067`、交信エラーは `SD10130`〜`SD10137`（コネクション1〜8）、Ethernetユニットは `Un\G108`〜`Un\G139`。

| コード | 異常内容と原因 | 処置方法 |
|---|---|---|
| C012H | 相手機器とのオープン処理に失敗した（すでにオープン完了のコネクションと同一の組合せ、など） | コネクションの設定・相手機器の状態を確認する |
| C013H | 相手機器とのオープン処理に失敗した（オープン完了のコネクションで使用中のポート番号の重複など） | ポート番号・オープン方式を見直す |
| C015H | オープン処理時の相手機器のIPアドレス指定に誤りがある | IPアドレス指定を見直す |
| C017H | TCPコネクションのオープン処理でタイムアウト／失敗した | 相手機器の状態・回線を確認する |
| C020H | 送受信データ長が許容範囲（1〜2046バイト）を超えている | 送信データ長／受信格納先サイズを見直す |
| C024H | 交信手段が通信プロトコル以外のコネクションで通信プロトコル命令を実行した | 使用用途設定とコネクションの用途を一致させる |
| C025H | コントロールデータの内容に誤りがある | コントロールデータを見直す |
| C027H | ソケット通信の伝文送信に失敗した | 相手機器の状態・回線を確認して再実行する |
| C029H | コントロールデータの内容がおかしい | コントロールデータを見直す |
| C035H | レスポンス監視タイマ値以内に相手機器の生存確認ができなかった | 相手機器の動作と接続ケーブルを確認する |
| C0DEH | ソケット通信の伝文受信に失敗した | 相手機器の状態・回線を確認する |
| C1AFH | ポート番号の指定に誤りがある | 使用可能なポート番号範囲を確認する |
| C1B0H | 指定されたコネクションは既にオープンされている | オープン状態を確認し、多重オープンしない |
| C1B1H | 指定されたコネクションはオープンされていない | オープン完了信号でインタロックする |
| C1BAH | イニシャル未完了状態で専用命令を実行した | `SD10683.b0` / `Un\G158.b0` でインタロックする |
| C1D3H | コネクションの交信手段に対応していない命令を実行した | コネクションの用途設定と命令を一致させる |
| CFB2H | 指定された自局ポート番号が重複して使用されている | ポート番号が重複しないよう見直す |
| 1134H | TCP/IPの交信で相手機器からACKが返ってこない | 相手機器・回線の状態を確認する |
| 2160H | IPアドレスの重複を検出した | ネットワーク上のIPアドレスを見直す |

> 上記はソケット通信で発生しやすいものを抜粋。Ethernet全体のエラーコード一覧は本マニュアルPDF p.796〜807 を参照。

## 9. ラダー生成前チェックリスト

- [ ] 使用ユニットを確定したか（内蔵Ethernet → `SP.*` / Ethernetユニット → `GP.*`）
- [ ] コネクション番号は範囲内か（内蔵1〜8 / ユニット1〜32）
- [ ] 自局ポート番号は推奨範囲か（5549〜5569、1〜1023、61440〜65534を避けたか）
- [ ] オープン方式（Active / Unpassive / Fullpassive / UDP）を決め、パラメータと一致させたか
- [ ] Passive・UDPでCLOSE命令を書いていないか
- [ ] 全命令にオープン完了信号のインタロックを入れたか
- [ ] 完了デバイスを2点連続で確保し、`(d)+1` で異常判定しているか
- [ ] 送信データ長（1〜2046バイト）／受信格納デバイスのサイズは足りているか
- [ ] 受信は受信状態信号 + 完了デバイスb接点で連続読出しにしたか
- [ ] コントロールデータ用に必要ワード数を確保したか（OPEN: 10ワード、他: 2ワード、SOCCINF出力: 5ワード）
- [ ] 割込みプログラム内に命令を置いていないか
