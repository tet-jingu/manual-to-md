# 命令とデータの書き方 — 共通ルール（iQ-R）

> **出典**: 三菱電機 MELSEC iQ-R プログラミングマニュアル（CPUユニット／汎用FUN／汎用FB）
> 第1部 命令概要（PDF p.34–70）
> **ページ表記**: 本文ノンブル + 2 = PDF通しページ。
>
> **このファイルの用途**: 命令を書く前に必ず押さえるルール。**オペランドの意味・データ型・実行条件・
> 範囲チェックの落とし穴**をまとめている。個々の命令は `00_索引_命令一覧.md` で探す。

## 0. 結論サマリ

- 命令は **命令部 ＋ オペランド部**。オペランドは **ソース(s)／ディスティネーション(d)／数値(n)** に分類される。
- **`(d)` は「格納先」だが、命令によっては実行前にデータを入れておく必要がある**（加算命令の2オペランド形式など）。
- ⚠ **デバイス・ラベルの範囲チェックは、原則として行われない。** 範囲を超えても異常を検出せず、**隣のデバイスを破壊する**。演算結果が範囲内に収まるプログラムを書くのは設計者の責任。
- ⚠ **1スキャン中に同一デバイスの OUT／PLS／PLF を複数回実行してはならない。** 意図しないON/OFFになる。
- 実行条件は5種類（ON時／立上り／OFF時／立下り／常時）。**ST・FBD/LD では `EN` が実行条件**になる。

## 1. 命令の構成

```
[命令部] [オペランド部]
   │         └ 命令で使用するデータ
   └ その命令の機能
```

| オペランド | 記号 | 内容 |
|---|---|---|
| ソース | `(s)`, `(s1)`, `(s2)` … | **演算で使用するデータ**。定数／デバイス／ラベルを指定する |
| ディスティネーション | `(d)`, `(d1)`, `(d2)` … | **演算後のデータが格納される**。必ず格納用のデバイス／ラベルを指定する |
| 数値 | `(n)`, `(n1)`, `(n2)` … | デバイス数・転送数・データ数・文字列数など |

### ソース (s) に指定できるもの

| 種類 | 内容 |
|---|---|
| 定数 | 演算で使用する数値。**プログラム実行中に変更できない**。可変にしたい場合はインデックス修飾する |
| デバイス／ラベル | データの格納先を指定する。**演算を実行するまでにデータを格納しておく必要がある**。実行中に値を変えれば使用データを変えられる |

### ディスティネーション (d) の注意

- 通常は**演算結果のみが格納される**。
- ただし **命令によっては演算前に (d) にデータを格納しておく必要がある**。
  例: BIN16ビット加算命令の2オペランド形式 `[+ (s) (d)]` は **(d) = (d) + (s)** となるため、(d) に加算前の値を入れておく。
  3オペランド形式 `[+ (s1) (s2) (d)]` は (d) = (s1) + (s2) で (d) は結果のみ。

### 数値 (n) の注意

- 設定範囲は **0〜65535** または **0〜4294967295**（命令により異なる。各命令のページを参照）。
- **(n) が 0 の場合、その命令は無処理**になる。
- デバイスメモリ容量やファイル格納容量によっては、上限値未満に制限される。
- ⚠ **転送数などに大きい値を使うとスキャンタイムが遅くなる。**

## 2. 扱えるデータの種類

| 分類 | データ |
|---|---|
| ビットデータ | ビットデータ |
| 16ビットデータ（ワード） | 符号付きBIN16ビット／符号なしBIN16ビット |
| 32ビットデータ（ダブルワード） | 符号付きBIN32ビット／符号なしBIN32ビット |
| 実数データ（浮動小数） | 単精度実数／倍精度実数 |
| BCDデータ | BCD4桁／BCD8桁／BCD16桁 |

### データ型ごとの指定可能デバイス／定数

| データ型 | 指定可能デバイス／定数 |

| ビット | ビットデバイス／**ワードデバイスのビット指定** |

| ダブルワード、符号付き/なしBIN32ビット | ワードデバイス／ダブルワードデバイス／**ビットデバイスの桁指定(K1〜K8)**／10進定数／16進定数 |

| 単精度実数／倍精度実数 | ワードデバイス／ダブルワードデバイス／**実数定数**（ビットデバイスは不可） |
| 文字列／Unicode文字列 | ワードデバイス／文字列定数 |
| デバイス名 | 使用可能デバイスで対応のデバイス名を直接指定 |

## 3. ビットデータの指定

| 対象 | 扱い |
|---|---|
| ビットデバイス／ビット型ラベル | 1点＝1ビット |
| ワードデバイス | **ビットNo.指定**で任意ビットを扱える |
| ワード型ラベル | **ラベル名.ビットNo.** で任意ビットを扱える |

### ワードデバイスのビット指定

- 表記: **`ワードデバイス番号.ビットNo.`**
- ビットNo.は **16進数で 0〜F**。
- 例: `D0.5` = D0 の b5 ／ `D0.A` = D0 の b10

**ビット指定が可能なデバイス**

- データレジスタ `D`
- リンクレジスタ `W`, `J\W`
- リンク特殊レジスタ `SW`, `J\SW`
- ファンクションレジスタ `FD`
- 特殊レジスタ `SD`
- ユニットアクセスデバイス `U\G`
- CPUバッファメモリアクセスデバイス `U3E\G`, `U3E\HG`
- ファイルレジスタ `R`, `ZR`
- ユニットリフレッシュ用レジスタ `RD`

（安全デバイス: `SA\D`, `SA\W`, `SA\SD` — 表記は `SA\D0.5` のように同じ）

### ワード型ラベルのビット指定

- 表記: `L_INT.0` ／ 配列 `L_INT[1].0` ／ 構造体 `L_STRUCT[1].S_INT.0`
- ビット指定が可能なデータ型:
  - ワード[符号付き]（INT型）
  - ワード[符号なし]/ビット列[16ビット]（WORD型）
  - タイマ／積算タイマ／カウンタ型の現在値(N) — **ラダーでは指定できない**

## 4. 桁指定（ビットデバイスをワードとして扱う）

| 対象 | 表記 | 例 |
|---|---|---|
| ビットデバイス | `K<桁数><ビットデバイス先頭番号>` | `K4X10`, `K2M113` |
| リンクダイレクトデバイス | `J<NW番号>\K<桁数><先頭番号>` | `J1\K3B10`, `J10\K2Y10` |
| 安全デバイス | `SA\K<桁数><先頭番号>` | `SA\K4X10`, `SA\K2M113` |
| ビット型配列ラベル | `K<桁数><ラベル名>`（**要素指定なし**） | `K1L_BOOL` |

桁数は 16ビットデータなら **K1〜K4**、32ビットデータなら **K1〜K8**。

### 桁指定の範囲

| 桁指定 | 10進表記 | 16進表記 |
|---|---|---|
| K1 | 0〜15 | 0H〜FH |
| K2 | 0〜255 | 00H〜FFH |
| K3 | 0〜4095 | 000H〜FFFH |
| K4 | 符号付き: -32768〜32767 ／ 符号なし: 0〜65535 | 0000H〜FFFFH |

対象点数の例（X0を桁指定した場合）:

| 指定 | 対象 |
|---|---|
| `K1X0` | X0〜X3（4点） |
| `K2X0` | X0〜X7（8点） |
| `K3X0` | X0〜XB（12点） |
| `K4X0` | X0〜XF（16点） |

### 桁指定の重要な挙動

- **ソース(s)側に桁指定したビットデバイスを指定した場合**
  → ディスティネーション側ワードデバイスの、**桁指定したビットより上位のビットには 0 が格納される**。
- **ディスティネーション(d)側に桁指定がある場合**
  → 桁指定による点数だけが対象。**それより上位のビットデバイスは変化しない**（前の値が残る）。

## 5. 実数データ

| データ名称 | サイズ | 値の範囲 |
|---|---|---|
| 単精度実数 | 32ビット（2ワード） | 正: 2⁻¹²⁶ ≦ 実数 < 2¹²⁸ ／ 0 ／ 負: -2¹²⁸ < 実数 ≦ -2⁻¹²⁶ |
| 倍精度実数 | 64ビット（4ワード） | 正: 2⁻¹⁰²² ≦ 実数 < 2¹⁰²⁴ ／ 0 ／ 負: -2¹⁰²⁴ < 実数 ≦ -2⁻¹⁰²² |

- 実数データは**ビットデバイス以外のデバイス**、または単精度/倍精度実数型ラベルにのみ格納できる。
- ⚠ **実数データで「-0」（最上位ビットのみ1）は指定しない。** -0 で実数演算を行うと**演算エラー**になる。
- 「0」を表すときは全ビット（単精度 b0〜b31 ／ 倍精度 b0〜b63）を 0 にする。

### エンジニアリングツールからの入力値の丸め

| 種類 | 有効桁数 | 丸め |
|---|---|---|
| 単精度実数 | 約7桁 | 8桁目を四捨五入 |
| 倍精度実数 | 約15桁 | 16桁目を四捨五入 |

入力可能範囲（超えると変換エラー）:

- 単精度 小数表現: 0.0000000001 ≦ |実数| ≦ 999999900000.0
- 単精度 指数表現: 1.175494351E-38 ≦ |実数| ≦ 3.402823466E+38
- 倍精度 小数表現: 0.00000000000000000001 ≦ |実数| ≦ 999999999999999000000.0
- 倍精度 指数表現: 2.22507385850721E-308 ≦ |実数| ≦ 1.79769313486231E+308

> 例: 入力値 `2147483647` は8桁目の「6」を四捨五入して **2147484000** として扱われる。四捨五入後の値が -2147483648〜2147483647 を超えると意図した値にならない。

## 6. 文字列データ

- **NULLコードで終わる文字コード列**を文字列として扱う。
- デバイス番号／配列の要素番号の**下位から上位に向かって**格納される。

| 言語 | 文字列(STRING) | Unicode文字列(WSTRING) |
|---|---|---|
| ラダー | `"ABC"` — ダブルクォーテーションで囲む | `"ABC"` |
| ST / FBD-LD | `'ABC'` — シングルクォーテーションで囲む | `"ABC"` — ダブルクォーテーションで囲む |

| 種類 | 最大文字数（ラベル／文字列定数とも） |
|---|---|
| 文字列 | 半角255文字（終端NULLを含まない） |
| Unicode文字列 | 255文字（終端NULLを含まない） |

### 格納に必要なワード数

| 文字列のバイト数 | 文字列 | Unicode文字列 |
|---|---|---|
| 0バイト | 1ワード | 1ワード |
| 奇数バイト | (バイト数+1) ÷ 2 ワード | （1文字が偶数バイトのため）文字数+1 ワード |
| 偶数バイト | (バイト数 ÷ 2) + 1 ワード | 文字数+1 ワード |

> 例: `"ABC"`（3バイト）を D0 から格納 → D0 に `A`,`B` ／ D1 に `C`,`NULL` の **2ワード**。
> `"ABCD"`（4バイト）→ D0 に `A`,`B` ／ D1 に `C`,`D` ／ D2 に `NULL` の **3ワード**。

## 7. 実行条件

| 実行条件 | 説明 |
|---|---|
| **ON時実行** | 前条件がONの間だけ実行する。OFFなら実行せず、処理しない |
| **立上り実行** | 前条件の立上り(OFF→ON)だけ実行。以降ONでも実行しない |
| **OFF時実行** | 前条件がOFFの間だけ実行する |
| **立下り実行** | 前条件の立下り(ON→OFF)だけ実行。以降OFFでも実行しない |
| **常時実行** | 前条件のON/OFFに関係なく常に実行する。OFFの場合は「OFFという処理」を行う |

### ST言語・FBD/LD言語の場合

- **命令中の `EN` が命令の前条件（実行条件）になる。** `EN` が TRUE の場合のみ実行する。
- **`ENO` は `EN` と同じ状態**になる。
- 汎用ファンクション／ファンクションブロックは **EN の有無で実行条件が異なる**。**EN無しの場合は常時実行**。

> パルス実行させたい場合は命令記号末尾に `P` を付ける（`MOV` → `MOVP`）。`P` 付きは立上り実行。

## 8. サブセット処理（処理時間の高速化）

- サブセット処理＝**オペランドが特定条件を満たすとき、ステップ数が減り処理時間が速くなる**仕組み。
- **命令記号やオペランドの数は変わらない**（書き方は同じ）。
- 命令ごとの可否は、原典 **p.1584（PDF 1586）「基本ステップ数とサブセット処理の可否」** を参照。
- ラベルエリア／ラッチラベルエリアに割り付けたラベルを指定した場合、**サブセット処理が可能な命令なら、データ型に関係なくサブセット処理になる**（ビットNo.指定・桁指定を含む）。
- ビットNo.指定・桁指定・間接指定・インデックス修飾したデバイスも条件の対象に含まれる。

## 10. ⚠ デバイス・ラベルの範囲チェック（最大の落とし穴）

### 原則: 範囲チェックは行われない

命令でデバイス／ラベルを指定しても、**下記のデバイスを除いて範囲チェックは行われない。**

**範囲チェックを行うデバイス（＝異常を検出できる）**

- リフレッシュデータレジスタ
- リンクダイレクトデバイス
- CPUバッファメモリアクセスデバイス
- インデックスレジスタ
- ファイルレジスタ

**それ以外は、範囲を超えても異常を検出せず、他のデバイス／ラベルに値が書き込まれる。**
**インデックス修飾したデバイスを指定する場合も同様。**

> **演算結果が該当するデバイス・ラベルの範囲内で収まるようなプログラムを作成すること。**

### 例外的に範囲外を検出する場合

- 命令で指定したデバイス／ラベルが、**デバイス・ラベルメモリの各エリアを超える**
- **インデックス修飾したデバイスがインデックス修飾でアクセスできる範囲を超える**
- ファイルレジスタ指定時、**ZR の範囲を超える**
- ファイルレジスタ指定時、**R で使用するブロックNo.のファイルレジスタ範囲を超える**

### 実際に起こる破壊の例

```
デバイス/ラベルメモリの割付けで、グローバルデバイスの D1023 の次が W0 になっている場合

[ BMOV D0 D1023 K10 ]
→ 転送先は D1023〜D1032 に該当する範囲。
  D1024〜D1032 が存在しなくてもデータが書き込まれ、W0〜W0008 のデータが上書きされる。
```

```
ローカルデバイスを M0〜M63、D0〜D11 の範囲で設定している場合

[ BMOV D0 K4#M48 K12 ]
→ 転送先は #M48〜#M239 に該当する範囲。
  #M64〜#M239 が存在しなくてもデータが書き込まれ、#D0〜#D10 のデータが上書きされる。
```

> CPUパラメータのRAS設定で「デバイス範囲異常(Qシリーズ互換)」を**「検出する」**に設定すると、グローバルデバイスは一部を除き範囲チェックが行われるようになる。

## 11. ⚠ 同一デバイスの OUT／SET／RST／PLS／PLF

### OUT命令

> **1スキャン中に同一デバイスのOUT命令を複数回実行しないこと。**

- 各OUT命令の実行時点で、そこまでの演算結果により指定デバイスがON/OFFする。
- そのため **1スキャン中にON/OFFを繰り返す**ことがある。
- OUT命令で出力(Y)を指定した場合、**1スキャンの最後に実行したOUT命令のON/OFF状態が出力される**。

```
X0 ──( M0 )      ; X0がON  → M0 ON
X1 ──( M0 )      ; X1がOFF → M0 OFF   ← 直前のONが打ち消される
```

### SET命令 / RST命令

- **SET**: 実行指令がONのとき指定デバイスをON、OFFのときは**無処理**。
  → 同一デバイスのSETを1スキャンに複数回実行した場合、**1つでも実行指令がONなら指定デバイスはON**になる。
- **RST**: 実行指令がONのとき指定デバイスをOFF、OFFのときは**無処理**。
  → 同様に、1つでもONならOFFになる。

> SET/RST は「無処理」があるため OUT よりは扱いやすいが、1スキャン内に SET と RST が両方あると**後から実行された方**が結果になる。

### PLS命令

- 実行指令の **OFF→ON 時に指定デバイスをON**。それ以外（OFF→OFF、ON→ON、ON→OFF）では**指定デバイスをOFF**にする。
- そのため同一デバイスのPLSを1スキャンに複数回実行すると、**PLS命令でONしたデバイスが1スキャンONしないことがある**。

```
X0 ──[ PLS M0 ]   ; X0が OFF→ON → M0 ON
X1 ──[ PLS M0 ]   ; X1が OFF→ON 以外 → M0 OFF  ← 1スキャンONにならない
```

- PLS命令で出力(Y)を指定した場合、**1スキャンの最後に実行したPLS命令のON/OFF状態が出力される**。

### PLF命令

- 実行指令の **ON→OFF 時に指定デバイスをON**。それ以外（OFF→OFF、OFF→ON、ON→ON）では**指定デバイスをOFF**にする。
- PLSと同様、同一デバイスを複数回使うと**1スキャンONしないことがある**。

## 12. ロングタイマ／ロング積算タイマの一括転送

デバイスの構成:

| デバイス | 構成 |
|---|---|
| タイマ(T)／積算タイマ(ST)／カウンタ(C) | 現在値・接点・コイル |
| **ロングタイマ(LT)／ロング積算タイマ(LST)** | **現在値・FRT前回値・接点・コイル**（現在値が32ビット幅を超えるため、前回値と接点・コイルの領域も使う） |
| ロングカウンタ(LC) | 現在値・接点・コイル |

| 転送方法 | 挙動 |
|---|---|
| **BMOV命令** | **現在値のみの一括転送はできない。** 現在値・接点・コイルを一括転送し、転送後のデータから現在値のみを使う |
| **DMOV命令** | 現在値のみを転送できる。**FOR〜NEXT で繰り返して**現在値を転送する |

## 13. ファイルレジスタ使用時の制約（リフレッシュデバイス指定時）

| 状況 | 挙動と対策 |
|---|---|
| **プログラム名と同一のファイルレジスタを指定した** | 正しくリフレッシュできない。プログラム設定で**最後の番号に設定したプログラム名と同一のファイルレジスタ**にリフレッシュされる。→ `QDRSET` 命令で該当ファイルレジスタに切り換えてから指定する |
| **QDRSET命令でファイル名やドライブNo.を変更した** | **リフレッシュ直前での設定ファイル**にリンクリフレッシュされる。→ リフレッシュ直前での設定ファイルを指定する |
| **RSET命令でブロックNo.を切り換えた** | 切り換えたブロックNo.のファイルレジスタ(R)、および**リフレッシュ直前でのブロックNo.のファイルレジスタ(R)**にリフレッシュされる。→ リフレッシュ直前でのブロックNo.を指定する |
