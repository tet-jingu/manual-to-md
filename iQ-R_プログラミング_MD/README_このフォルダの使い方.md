## AIがラダーを書くときの参照手順

```
① 00_索引_命令一覧.md      で命令を探す（やりたい処理 → 命令記号 → 参照ページ）
        ↓
② 01_共通ルール_….md       でオペランド・データ型・実行条件・落とし穴を確認
        ↓
③ 02〜05 の該当ファイル     で命令の設定データ・機能・注意事項・エラーを確認
        ↓
④ 必要なら原典PDFの該当ページ  でラダー図・タイミングチャート・プログラム例を確認
```

## 各命令ファイルの構成

```
## 命令のグループ名（例: BIN16ビットデータ比較出力）

### `CMP(P)(_U)`            ← 命令記号。(P)=パルス形式あり、(_U)=符号なし形式あり

  概要文
  | ラダー | ST |           ← ST言語の記述形式
  **実行条件**
  **設定データ** / **内容，範囲，データ型**
      | オペランド | 内容 | 範囲 | データ型 | データ型(ラベル) |   ← ラダーを書くときはここ
  **使用可能デバイス**       ← 表が大きいため省略（原典参照）
  **機能**                  ← 動作の説明
  **注意事項**              ← やってはいけないこと・制約
  **エラー**                ← その命令の演算エラー
```

**実行条件の読み方**: 命令記号に `P` が付く形式（`CMPP` など）は**立上り実行**、付かない形式は**ON時実行**。
ST・FBD/LD では `EN` が実行条件になる。

### プログラム例について

原典のプログラム例・ラダー図・タイミングチャートは**すべて画像（図）**であり、
テキスト抽出ではデバイス名と命令記号が断片的に並ぶだけで、回路構成は再現できない。

そのため `02`〜`05` のファイルには `**例**` 見出しだけが残り、回路は入っていない。
**代わりに、ラダー図を画像として読み取り、ニモニック（命令リスト）に書き起こしたものを
`06_プログラム例_ニモニック.md` に収録した。**

対象範囲（PDF p.156–612）を走査した結果、ラダー回路の図があるのは **31ページ**、
残り61ページは**データ遷移の図**（ビット並び・変換イメージ）で回路ではない。
内訳は `06_プログラム例_ニモニック.md` の末尾に記載している。

`06` に収録した命令群: `OUT T` / `OUT LT` / `RST F` / `SFT(P)` / `LDP,LDF` / `EGP,EGF` /
`SET` / `RST` / `PLS` / `DELTA(P)` / `MC,MCR` / `CJ,SCJ,JMP` / `CALL(P)` / `FCALL(P)` /
`FOR,NEXT` / `DI,EI` / `ECALL(P),EFCALL(P),XCALL`

同様に、**使用可能デバイスの対応表**（オペランド × デバイス種別の○×マトリクス）も
チェックマークが図形のため抽出できないため省略している。デバイス種別の可否は原典を参照する。

## 特に注意すべき落とし穴（`01_共通ルール` より抜粋）

1. **デバイス・ラベルの範囲チェックは原則行われない。** 範囲を超えても異常を検出せず、隣のデバイスを破壊する。
   （範囲チェックされるのはリフレッシュデータレジスタ／リンクダイレクトデバイス／CPUバッファメモリアクセスデバイス／インデックスレジスタ／ファイルレジスタのみ）
2. **1スキャン中に同一デバイスの OUT／PLS／PLF を複数回実行しない。** 意図しないON/OFFになる。
3. **`(d)` に実行前のデータ格納が必要な命令がある**（2オペランド形式の演算命令など）。
4. **桁指定の (d) 側は、指定点数より上位のビットデバイスが変化しない**（前の値が残る）。
5. **実数データで `-0` を指定すると演算エラー**になる。
6. **ロングタイマ／ロング積算タイマの現在値は BMOV で単独転送できない**（DMOV + FOR〜NEXT を使う）。
7. **(n) が 0 の命令は無処理**になる。転送数に大きい値を使うとスキャンタイムが延びる。
