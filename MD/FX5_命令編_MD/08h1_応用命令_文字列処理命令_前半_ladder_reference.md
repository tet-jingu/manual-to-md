### LD$□，AND$□，OR$□ (8.9 / 原本 p.585-587)

対応機種: FX5S / FX5UJ / FX5U / FX5UC

(s1)で指定されたデバイス番号以降に格納されている文字列データと，(s2)で指定されたデバイス以降に格納されている文字列データをa接点扱いで比較演算を行います。

#### 機能 (8.9 / 原本 p.586-587)

- (s1)で指定された文字列データと，(s2)で指定された文字列データを，a接点扱いで比較演算を行います。
- 比較演算は，文字列のアスキーコードを文字列の最初から1文字ずつ比較を行います。
- (s1)，(s2)の文字列は，指定されたデバイス番号から00Hが格納されているデバイス番号までが対象となります。
  - すべての文字列が一致した場合に，比較結果が一致となります。

| (s1)+1 | 44H (D) | 43H (C) |
| (s1)+2 | 00H | 45H (E) |
| (s2) | 42H (B) | 41H (A) |
| (s2)+1 | 44H (D) | 43H (C) |
| (s2)+2 | 00H | 45H (E) |

| □内命令記号 | 比較演算結果 |
|---|---|
| $= | 導通状態 |
| $<> | 非導通状態 |
| $> | 非導通状態 |
| $<= | 導通状態 |
| $< | 非導通状態 |
| $>= | 導通状態 |

#### 注意事項 (8.9 / 原本 p.587)

- 文字列データ比較演算では，該当デバイスの範囲に”00H”が存在しないときは，該当デバイスの最終番号までの値を取得します。このため，該当デバイスの範囲に”00H”が存在しないときでも，取得した文字列内で文字の不一致を検出すると，比較演算結果が出力されます。

**例**

```
     LD$=  D7998 D10        (s1)=D7998, (s2)=D10
     OUT   M0
```

(s1)のデータ

| デバイス | 上位バイト(b15〜b8) | 下位バイト(b7〜b0) |
|---|---|---|
| D7998 | 42H(B) | 41H(A) |
| D7999 | 44H(D) | 43H(C) |

(s2)のデータ

| デバイス | 上位バイト(b15〜b8) | 下位バイト(b7〜b0) |
|---|---|---|
| D10 | 5A(Z) | 41H(A) |
| D11 | 00H | 43H(C) |

> 要確認: 原本図では D10 上位バイトが「5A(Z)」と表記されています(他の値は「〜H」付き)。5AH の H 脱落と思われますが原文のまま転記しています。

- (s1)と(s2)のデータが上記の場合，(s1)の2 文字目が(s2)と異なるため演算結果は非導通となります。

(2): 小数部桁数

(2): 自動的に付加します。

(1): 自動的に付加します。

【図】(s1)=8, (s1)+1=1, BIN16=-123 ⇒ `-␣␣␣12.3`(符号の後の3つの␣が(1))

(1): 20H(スペース)になります。

  - 変換した文字列の最後には，自動的に00Hを格納します。
  - 総桁数が偶数桁の場合は，最終文字を格納するデバイスの次のデバイスに“0000H”を格納します｡また，奇数桁の場合は，最終文字を格納するデバイスの上位バイト(8ビット)に“00H”を格納します。
