## 15.3 MODBUS命令 (15.3 / 原本 p.1081-1084)

### ADPRW[オペランドが6個の場合] (15.3 / 原本 p.1081-1082)

対応機種: FX5S / FX5UJ / FX5U / FX5UC

MODBUSマスタが対応するスレーブと通信(データの読出し/書込み)をするための命令です。
マスタ局が1chのみの場合に使用します。(ADPRW[オペランドが8個の場合]とは併用できません。)

#### 書式 (15.3 / 原本 p.1081)

| 言語 | 記述 |
|---|---|
| ラダー | 【図】命令ボックス `□ (s1) (s2) (s3) (s4) (s5)/(d1) (d2)`(□に ADPRW) |
| ST | ENO:=ADPRW(EN,s1,s2,s3,s4,s5d1,d2); |
| FBD/LD | 【図】EN・s1・s2・s3・s4・s5d1 入力、ENO・d2 出力のボックス |

#### 設定データ (15.3 / 原本 p.1081)

■内容，範囲，データ型

| オペランド | 内容 | 範囲 | データ型 | データ型(ラベル) |
|---|---|---|---|---|
| (s1) | スレーブ局番 | 0～F7H*1 | 符号付きBIN16ビット | ANY16 |
| (s2) | ファンクションコード | 01H～06H，0FH，10H | 符号付きBIN16ビット | ANY16 |
| (s3) | ファンクションコードに応じたファンクションパラメータ | 0～FFFFH | 符号付きBIN16ビット | ANY16 |
| (s4) | ファンクションコードに応じたファンクションパラメータ | 1～2000 | 符号付きBIN16ビット | ANY16 |
| (s5)/(d1) | ファンクションコードに応じたファンクションパラメータ | — | ビット/符号付きBIN16ビット | ANY_ELEMENTARY*2 |
| (d2) | 命令実行状態を出力する先頭のビットデバイス番号 | — | ビット | ANYBIT_ARRAY<br>(要素数：3) |
| EN | 実行条件 | — | ビット | BOOL |
| ENO | 実行結果 | — | ビット | BOOL |

*1 FX5マスタ局で指定可能なスレーブ局番はバージョンにより異なります。(→1422ページ 機能の追加と変更)
*2 ビット型ラベルの桁指定は使用できません。

#### 機能 (15.3 / 原本 p.1082)

- ファンクションコード(s2)は，スレーブ(s1)上でパラメータ(s3)，(s4)，(s5)/(d1)に従って動作します。ブロードキャストの場合は，スレーブ局番に0を指定してください。詳細は，→MELSEC iQ-F FX5ユーザーズマニュアル(通信編)を参照してください。
- 通信実行状態(d2)は，ADPRW命令の通信実行中/正常完了/異常完了の各状態に応じて出力します。

#### 注意事項 (15.3 / 原本 p.1082)

(d2)に指定したデバイスを先頭に3点占有します。他の制御で使用しているデバイスと重複しないように注意してください。

#### エラー (15.3 / 原本 p.1082)

| エラーコード<br>(SD0/SD8067) | 内容 |
|---|---|
| 1810H | 命令で使用するCHが，他の命令で使用されているとき。 |
| 3600H | 命令をスレーブで使用しているとき。 |
| 2822H | 命令で使用できないデバイスを指定しているとき。 |
| 3405H | 指定可能な範囲外のデータを入力したとき。 |
| 2820H | 指定したデバイスが該当デバイスの範囲を超えるとき。 |
| 3100H | 使用できない組合せの命令が同時にプログラムされているとき。 |

通信エラーについては，→MELSEC iQ-F FX5ユーザーズマニュアル(通信編)を参照してください。

#### 機能 (15.4 / 原本 p.1087)

エンジニアリングツールで登録したプロトコルを実行します。(n1)で指定されたCHを使用し，実行するプロトコルは，(s)で指定されたデバイス以降のコントロールデータに従います。1回の命令実行で，(n2)に指定したプロトコル数(最大8)を連続実行します。
プロトコルを実行した数は，(s)+1(実行数結果)に格納します。
S(P).CPRTCL命令完了の確認は，完了デバイス(d)+0および(d)+1で行うことができます。

- 完了デバイス(d)+0：S(P).CPRTCL命令が完了したスキャンのEND処理でONし，次のEND処理でOFFします。
- 完了デバイス(d)+1：S(P).CPRTCL命令が完了したときの状態により，ONまたはOFFします。

| 状態 | 内容 |
|---|---|
| 正常完了時 | OFFのまま変化しません。 |
| 異常完了時 | S(P).CPRTCL命令が完了したスキャンのEND処理でONし，次のEND処理でOFFします。 |

【図】タイミングチャート(原本 p.1087)
- プログラム: END処理が3回並ぶ(1回目・2回目・3回目)。
- S(P).CPRTCL命令: 1回目のEND処理の前にONパルス(S(P).CPRTCL命令実行)。
- 命令実行後、「プロトコル実行」が行われる(1回目のEND処理以降、2回目のEND処理の直前まで)。
- 完了デバイス(d)+0: OFF → 命令が完了したスキャンのEND処理(2回目のEND処理)でON → 次のEND処理(3回目)でOFF。ON期間は「1スキャン」。
- 完了デバイス(d)+1: OFF。異常完了時は(d)+0と同じタイミング(2回目のEND処理でON、3回目のEND処理でOFF)でON(破線)。正常完了時はOFFのまま。

詳細は，→MELSEC iQ-F FX5ユーザーズマニュアル(通信編)を参照してください。

#### 注意事項 (15.4 / 原本 p.1087)

- 複数のプロトコルを実行する場合において，m番目のプロトコルでエラーが発生すると，m+1番目以降のプロトコルは実行せずに，命令を異常完了します。
- S(P).CPRTCL命令が実行可能な通信CHは，通信プロトコルが「通信プロトコル支援」に設定されたCHのみです。
- 複数のプロトコルを連続実行中，m番目のプロトコル実行中にキャンセル要求を受けた場合，(s)に下記を格納します。

| デバイス | 項目 | 格納内容 |
|---|---|---|
| (s)+0 | 実行結果 | エラーコード |
| (s)+1 | 実行数結果 | 実行したプロトコル数 |
| (s)+10 | 照合一致受信パケット番号1 | 実行済みプロトコルの照合一致した受信パケット番号 |
| ⋮ | ⋮ | 実行済みプロトコルの照合一致した受信パケット番号 |
| (s)+m+8 | 照合一致受信パケット番号m-1 | 実行済みプロトコルの照合一致した受信パケット番号 |

(格納内容「実行済みプロトコルの照合一致した受信パケット番号」は原本では (s)+10～(s)+m+8 の結合セル)

- 同一CHに対して同一命令を実行した場合，先に実行中の命令が完了するまで，あとの命令は無視され実行されません。

その他の注意事項については，→MELSEC iQ-F FX5ユーザーズマニュアル(通信編)を参照してください。
