## 文字列→BIN16ビットデータ変換 (7.5 / 原本 p.365-367)

### VAL(P)(_U) (7.5 / 原本 p.365-367)

対応機種: FX5S / FX5UJ / FX5U / FX5UC

(s)で指定されたデバイス番号以降に格納されている文字列を，BIN16ビットデータに変換して，桁数を(d1)に，BINデータを(d2)に格納します。

#### 書式 (7.5 / 原本 p.365)

#### 機能 (7.5 / 原本 p.366)

- (s)で指定されたデバイス番号以降に格納されている文字列を，BIN16ビットデータに変換して，桁数を(d1)に，BINデータを(d2)に格納します。文字列→BIN変換では，(s)で指定されたデバイス番号から，00Hが格納されているデバイス番号までのデータを，文字列として処理します。
- (d1)に格納する全桁数は，数値を表すすべての文字(符号，小数点を含む)の数を格納します。(d1)+1に格納する小数部桁数は，2EH(.)以降の小数部を表す文字数を格納します。(d2)に格納するBIN16ビットデータは，小数点を無視した文字列をBIN値に変換して格納します。

【図】(s)の構成と格納先

| デバイス | 上位バイト(b15〜b8) | 下位バイト(b7〜b0) |
|---|---|---|
| (s) | ASCII 1 | ASCII S |
| (s)+1 | ASCII 3 | ASCII 2 |
| (s)+2 | ASCII 5 | ASCII 4 |
| (s)+3 | ASCII 7 | ASCII 6 |
| (s)+4 | | 00H(文字列の最終を示します。) |

- 文字列: 符号，1文字目，2文字目，…，7文字目 → (d1): 全桁数，(d1)+1: 小数部桁数，(d2): 小数点を無視した整数値(BIN16)

**例**
(s)以降に「-123.45」の文字列が指定された場合(符号付きを指定した場合)

| デバイス | 上位バイト(b15〜b8) | 下位バイト(b7〜b0) |
|---|---|---|
| (s) | 31H (1) | 2DH (-) |
| (s)+1 | 33H (3) | 32H (2) |
| (s)+2 | 34H (4) | 2EH (.) |
| (s)+3 | 00H | 35H (5) |

→ (d1) = 7，(d1)+1 = 2，(d2) = -12345

- (s)で指定する文字列の全文字数は，2～8文字です。
- (s)で指定する文字列のうち，小数部となる文字数は，0～5文字です。ただし，「全桁数-3」以下で指定してください。
- BIN値に変換できる数値の文字列の範囲は，小数点を無視した値で符号付きを指定した場合は-32768～+32767，符合なしを指定した場合は0～65535となります。また，符号と小数点を除く数値の文字列は，30H～39Hの範囲内のみ指定できます。(小数点を無視した値…「-12345.6」の場合は，「-123456」となります。)
- 符号には，正の数値を表す場合は20Hを設定し，負の数値を表す場合は2DHを設定します。
- 小数点には，2EHを設定します。
- (s)で指定された文字列で，符号と最初の0以外の数値との間に，20H(スペース)か30H(0)が存在する場合は，20H，30Hを無視してBIN値に変換します。

**例**
符号と最初の0以外の数値との間に20Hが存在する場合(符号付きを指定した場合)
- 「-␣123.45」(␣は無視します。) → 全桁数 8，小数部桁数 2，BIN16 -12345

**例**
符号と最初の0以外の数値との間に30Hが存在する場合
- 「␣0.0012」(符号␣，符号直後の0は無視します。) → 全桁数 7，小数部桁数 4，BIN16 12

- (s)の最終文字には，2EH(.)を設定しないでください。(例：1234.)

#### 注意事項 (7.5 / 原本 p.367)

- 符号データ“スペース(20H)”または“- (2DH)”は，必ず1バイト目((s)に設定した先頭デバイスの下位8ビット)に格納する必要があります。また，(s)の2バイト目以降から文字列最終｢00H｣までのアスキーデータは，“0(30H)”～“9(39H)”，“スペース(20H)”および小数点“. (2EH)”のみ格納できます。2バイト目以降に“- (2DH)”を格納した場合は，演算エラーとなります。

#### プログラム例 (7.5 / 原本 p.367)

X0をONしたとき，D20～D22に格納されている文字列データをBIN16ビットデータに変換し，D0に格納するプログラムです。

```
LD     X0
VALP   D20 D10 D0
```

【図】データの動き

| デバイス | 上位バイト(b15〜b8) | 下位バイト(b7〜b0) |
|---|---|---|
| D20 | 31H (1) | 2DH (-) |
| D21 | 2EH (.) | 36H (6) |
| D22 | 34H (4) | 35H (5) |
| D23 | | 00H(00Hとします｡) |

→ D0 = -1654，D10 = 6(全桁数)，D11 = 2(小数部桁数)

#### エラー (7.5 / 原本 p.367)

| エラーコード<br>(SD0/SD8067) | 内容 |
|---|---|
| 2820H | (d1)で指定したデバイスが該当デバイスの範囲を超えるとき。 |
| 2820H | (s)で指定したデバイス番号以降の該当デバイス範囲に“00H“が設定されていないとき。 |
| 3401H | (s)で指定する文字列の文字数が，2～8以外のとき。 |
| 3401H | (s)で指定する文字列の小数部文字数が，0～5以外のとき。 |
| 3401H | (s)で指定する全文字数と，小数部文字数の関係が，下記以外のとき。<br>全文字数-3≧小数部文字数 |
| 3401H | VAL(P)命令使用時，符号に20H，2DH以外のアスキーコードが設定されている。 |
| 3401H | VAL(P)_U命令使用時，符号に20H以外のアスキーコードが設定されている。 |
| 3401H | 各数字の桁に30H～39H，および2EH(小数点)以外のアスキーコードが設定されているとき。 |
| 3401H | 小数点が複数設定されているとき。 |
| 3401H | 変換したBIN値の値が，各命令で変換できる範囲を超えたとき。<br>符号付き演算: -32768～+32767，符号なし演算: 0～65535 |

**例**
(s)以降に「-12345.678」の文字列が指定された場合(符号付きを指定した場合)

| デバイス | 上位バイト(b15〜b8) | 下位バイト(b7〜b0) |
|---|---|---|
| (s) | 31H (1) | 2DH (-) |
| (s)+1 | 33H (3) | 32H (2) |
| (s)+2 | 35H (5) | 34H (3) |
| (s)+3 | 36H (6) | 2EH (.) |
| (s)+4 | 38H (8) | 37H (7) |
| (s)+5 | 00H(ワード全体) | |

→ (d1) = 10，(d1)+1 = 3，(d2)+1,(d2) = -12345678

> 要確認: (s)+2の下位バイトは原本で「34H (3)」と印字されています(34Hは「4」)。「-12345.678」の並びからは「34H (4)」が正しいと考えられます。

- (s)で指定する文字列の全文字数は，2～13文字です。
- (s)で指定する文字列のうち，小数部となる文字数は，0～10文字です。ただし，「全桁数-3」以下になるようにしてください。
- BIN値に変換できる数値の文字列の範囲は，小数点を無視した値で符号付きを指定した場合は，-2147483648～+2147483647，符合なしを指定した場合は，0～4294967295となります。また，符号と小数点を除く数値の文字列は，30H～39Hの範囲内のみ指定できます。(小数点を無視した値…「-12345.6」の場合は，「-123456」となります。)
- 符号には，正の数値を表す場合は20Hを設定し，負の数値を表す場合は2DHを設定します。
- 小数点には，2EHを設定します。

**例**
符号と最初の“0”以外の数値との間に20Hが存在する場合(符号付きを指定した場合)
- 「-␣␣␣␣6543.21」(␣は無視します。) → 全桁数 12，小数部桁数 2，BIN32 -654321

**例**
符号と最初の“0”以外の数値との間に30Hが存在する場合
- 「␣0.00054321」(符号␣，符号直後の0と小数点直後の0は無視します。) → 全桁数 11，小数部桁数 8，BIN32 54321

- (s)の最終文字には，2EH(.)を設定しないでください。(例： 1234.)

#### 注意事項 (7.5 / 原本 p.370)

- 符号データ“スペース(20H)”または“-(2DH)”は，必ず1バイト目((s)に設定した先頭デバイスの下位8ビット)に格納する必要があります。また，(s)の2バイト目以降から文字列最終｢00H｣までのアスキーデータは，“0(30H)”～“9(39H)”，“スペース(20H)”および小数点“. (2EH)”のみ格納できます。2バイト目以降に“-(2DH)”を格納した場合は，演算エラーとなります。

#### プログラム例 (7.5 / 原本 p.370)

```
LD     X0
DVALP  D20 D10 D0
```

【図】データの動き

| デバイス | 上位バイト(b15〜b8) | 下位バイト(b7〜b0) |
|---|---|---|
| D20 | 37H (7) | 20H (スペース) |

- (d)で指定されたBIN16ビットデバイスの符号を反転して，(d)で指定されたデバイスに格納します。
- 正負の符号を反転するときに使用します。

【図】
- 実行前 (d): 1010 1010 1010 1010(b15〜b0) … -21846
- 符号変換: 1 0000 0000 0000 0000 − 1010 1010 1010 1010
- 実行後 (d): 0101 0101 0101 0110 … 21846

#### 注意事項 (7.5 / 原本 p.372)

連続実行形(NEG)命令では各演算周期ごとに反転されますので注意してください。

#### プログラム例 (7.5 / 原本 p.372)

負のBIN16ビットデータに対する絶対値を得るプログラム例です。

- NEG命令による負数の絶対値化

```
LD     SM400             RUNモニタ
BON    D10 M0 K15        BON(ONビット判定)命令は，D10の15ビット目(b0～b15のb15)が1のときにM0がON
LD     M0
NEGP   D10               D10(反転)→D10  M0がONしたときのみD10にNEGP命令を実行
```

- SUB(減算)命令による絶対値処理

NEG命令(補数演算)を使用しなくても(D30)は常に差の絶対値を格納します。

```
LD     X0
MPS
CMP    D10 D20 M10       (D10)>(D20) M10=ON / (D10)=(D20) M11=ON / (D10)<(D20) M12=ON
MRD
LD     M10
OR     M11
ANB
SUB    D10 D20 D30       (D10)≧(D20) のときは，(D10)-(D20)→(D30)
MPP
AND    M12
SUB    D20 D10 D30       (D10)<(D20) のときは，(D20)-(D10)→(D30)
```

(ラダー図: X0 から3分岐。M10 と M11 は並列接続。ニモニックのMPS/MRD/MPP/ANBは分岐を表すための書き起こしです。)

#### エラー (7.5 / 原本 p.372)

演算エラーはありません。
