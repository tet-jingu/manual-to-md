## Unicode文字列→シフトJIS文字列変換 (8.9 / 原本 p.623-625)

### WS2SJIS(P) (8.9 / 原本 p.623-625)

対応機種: FX5S / FX5UJ / FX5U / FX5UC

Unicode文字列をシフトJIS文字列に変換します。

#### 書式 (8.9 / 原本 p.623)

| 言語 | 記述 |
|---|---|
| ラダー | 【図】命令ボックス `□ (s) (d)`(□に WS2SJIS, WS2SJISP) |
| ST | ENO:=WS2SJIS(EN,s,d);<br>ENO:=WS2SJISP(EN,s,d); |
| FBD/LD | 【図】EN・s 入力、ENO・d 出力のボックス |

#### 設定データ (8.9 / 原本 p.623)

■内容，範囲，データ型

| オペランド | 内容 | 範囲 | データ型 | データ型(ラベル) |
|---|---|---|---|---|
| (s) | 変換するUnicode文字列(最大255文字)または，Unicode文字列が格納されている先頭デバイス | — | Unicode文字列 | ANYSTRING_DOUBLE |
| (d) | 変換後のシフトJIS文字列を格納する先頭デバイス | — | 文字列 | ANYSTRING_SINGLE |
| EN | 実行条件 | — | ビット | BOOL |
| ENO | 実行結果 | — | ビット | BOOL |

■使用可能デバイス

| オペランド | ビット | ワード | U□￥G□ | Z | LC | LZ | 間接指定 | K，H | E | $ | その他 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| (s) | — | ○ | — | — | — | — | ○ | — | — | ○ | — |
| (d) | — | ○ | — | — | — | — | ○ | — | — | — | — |

#### 機能 (8.9 / 原本 p.623-624)

- (s)で指定したUnicode文字列をシフトJIS文字列に変換し，(d)へ格納します。
- (s)のUnicode文字列は，リトルエンディアンで指定してください。

例
Unicode文字列の「6587H」を指定します。

【図】「65」「87」→ b15～b8 に 65H、b7～b0 に 87H を格納

- (d)のシフトJIS文字列は，ビッグエンディアンで格納します。

例
シフトJIS文字列の「95B6H」は，「B695H」で指定します。

【図】「95」「B6」→ b15～b8 に B6H、b7～b0 に 95H を格納

- バイトオーダーマークがない場合，Unicode→シフトJIS変換の動作は下記になります。

```
     LD     SM402
     $MOVP_WS "文字列ABC" D0
     LD     M0
     WS2SJISP D0 D100          (s)=D0 (d)=D100
```

【図】(s)(b15～b0) → (d)(上位バイト / 下位バイト)
- D0=6587H(文)、D1=5B57H(字)、D2=5217H(列)、D3=0041H(A)、D4=0042H(B)、D5=0043H(C)、D6=0000H
- D100=B6H / 95H(文)、D101=9AH / 8EH(字)、D102=F1H / 97H(列)、D103=42H / 41H(BA)、D104=00H / 43H(C)

- バイトオーダーマーク(FEFFH)が付加されている場合，Unicode→シフトJIS変換の動作は下記になります。

```
     LD     SM402
     $MOVP_WS "文字列123" D0
     LD     M0
     WS2SJISP D0 D100          (s)=D0 (d)=D100
```

【図】(s)(b15～b0) → (d)(上位バイト / 下位バイト)
- D0=FFFEH(バイトオーダーマーク)、D1=6587H(文)、D2=5B57H(字)、D3=5217H(列)、D4=0031H(1)、D5=0032H(2)、D6=0033H(3)、D7=0000H
- D100=B6H / 95H(文)、D101=9AH / 8EH(字)、D102=F1H / 97H(列)、D103=32H / 31H(21)、D104=00H / 33H(3)

> 要確認: 本文は「バイトオーダーマーク(FEFFH)」ですが、図のD0の値は「FFFEH」と記載されています(原本のまま転記)。

#### 注意事項 (8.9 / 原本 p.625)

- (s)で指定されたUnicode文字列の中に変換できない文字コードが含まれる場合，(d)で指定されたデバイス番号にエラー発生文字まで書込みます。
- 32ビットUnicode文字列はシフトJIS変換できません。
- (s)，(d)で指定したデバイス範囲が重複した場合，重複を事前に検出できるときがあります。デバイス範囲重複時の各動作は下記です。

[事前に検出した場合]
【図】(s+0)から「A B C D E …」、(d+0)は(s+0)の3ワード後ろから始まり「D E …」と重なっている。実行後は(d+0)に「BA C」が書き込まれ、(s+3)の「D E」部分(網掛け)は変換されない。
事前にデバイス範囲の重複を検出した場合，重複位置までは文字列変換と(d)への書込みを行います。
(s+3)でのデバイス範囲の重複が事前に判明しているため，(s+0)～(s+2)を文字列変換し，(d+0)，(d+1)に書き込みます。
重複エラー (2821H)となります。

[事前に検出できない場合(異常完了)]
【図】(d+0)の3ワード後ろに(s+0)があり「α β γ δ ε …」。実行後は(d+0)から「α β γ δ α β γ δ ε(網掛け)」となる。
(s+3)を文字列変換した時点でデバイス範囲が重複するため，次の格納先がありません。
重複エラー (2821H)となります。

[事前に検出できない場合(正常完了)]
【図】(d+0)の3ワード後ろに(s+0)があり「a b c d e …」。実行後は(d+0)から「ba dc e」が格納され、(s+0)以降は「a b c d e」のまま。
文字列変換した結果，デバイス範囲が重複しないため正常完了します。

#### エラー (8.9 / 原本 p.625)

| エラーコード<br>(SD0/SD8067) | 内容 |
|---|---|
| 2820H | (s)で指定したデバイス番号以降，デバイス/ラベルメモリの各設定エリアの間に0000Hが存在しないとき。 |
| 2821H | (s)，(d)で指定した範囲が重複しているとき。 |
| 3401H | (s)で指定した文字列に，バイトオーダーマークのFEFFH(ビッグエンディアン)が付加されているとき。 |
| 3401H | (s)で指定した範囲に，変換できない文字コードが含まれているとき。 |
| 3405H | (s)で指定した文字列が，512文字を超えるとき。*1 |
| 3406H | (d)で指定したデバイス番号以降，該当デバイス/ラベルメモリ各設定エリアの最終番号までの点数に変換したシフトJIS(ASCII)文字列がすべて格納できないとき。 |

*1 漢字などのシフトJISコードで表現した場合に2バイトデータになる文字は，1文字あたり2とカウントしてください。

#### 機能 (8.9 / 原本 p.626-627)

- (s)で指定したシフトJIS文字列をUnicode文字列に変換し，(d)へ格納します。
- (s)のシフトJIS文字列は，ビッグエンディアンで指定してください。

シフトJIS文字列の「95B6H」は，「B695H」で指定します。

【図】「95」「B6」→ b15～b8 に B6H、b7～b0 に 95H を格納

- (d)のUnicode文字列は，リトルエンディアンで格納されます。

例
Unicode文字列の「6587H」を指定します。

【図】「65」「87」→ b15～b8 に 65H、b7～b0 に 87H を格納

- SJIS2WS(P)命令では，(d)の先頭にバイトオーダーマークを付加しません。バイトオーダーマークを付加したい場合は，SJIS2WSB(P)命令を使用してください。
  (→627ページ SJIS2WSB(P))
- シフトJIS→Unicode変換の動作は下記になります。

```
     LD     SM402
     $MOVP  "文字列123" D0
     LD     M0
     SJIS2WSP D0 D100          (s)=D0 (d)=D100
```

【図】(s)(上位バイト / 下位バイト) → (d)(b15～b0)
- D0=B6H / 95H(文)、D1=9AH / 8EH(字)、D2=F1H / 97H(列)、D3=32H / 31H(21)、D4=00H / 33H(3)
- D100=6587H(文)、D101=5B57H(字)、D102=5217H(列)、D103=0031H(1)、D104=0032H(2)、D105=0033H(3)、D106=0000H

#### 注意事項 (8.9 / 原本 p.627)

- (s)で指定されたASCII(シフトJIS)文字列のデータ長が0の場合，(d)+0に終端NULLの1文字分(1ワード)のみ書き込みます。
- (s)で指定されたASCII(シフトJIS)文字列の中に変換できない文字コードが含まれる場合，(d)で指定されたデバイス番号にエラー発生文字まで書込みます。
- (s)，(d)で指定したデバイス範囲が重複した場合，重複を事前に検出できるときがあります。デバイス範囲重複時の各動作は下記です。

[事前に検出した場合]
【図】(s+0)から「AB C D E F …」、(d+0)は(s+0)の3ワード後ろから始まり「E F …」と重なっている。実行後は(d+0)から「B A C D」が書き込まれ、(s+3)以降の「E F」部分(網掛け)は変換されない。
事前にデバイス範囲の重複を検出した場合，重複位置までは文字列変換と(d)への書込みを行います。
(s+3)でのデバイス範囲の重複が事前に判明しているため，(s+0)～(s+2)を文字列変換し，(d+0)～(d+3)に書き込みます。
重複エラー (2821H)となります。

[事前に検出できない場合(異常完了)]
【図】(d+0)の3ワード後ろに(s+0)があり「AB C D E F …」。実行後は(d+0)から「B A C D AB C D E(網掛け) F(網掛け)」となる。
(s+2)を文字列変換した時点でデバイス範囲が重複するため，次の格納先がありません。
重複エラー (2821H)となります。

[事前に検出できない場合(正常完了)]
【図】(d+0)の3ワード後ろに(s+0)があり「α β γ …」。実行後は(d+0)から「α β γ」が格納され、(s+0)以降は「a β γ」と表示されている。
文字列変換した結果，デバイス範囲が重複しないため正常完了します。

> 要確認: 正常完了の図で実行後の(s+0)の1文字目が「a」と読める表記になっています(実行前は「α」)。原本 p.627 参照。

[事前に検出した場合]
【図】(s+0)から「AB C D E F …」、(d+0)は(s+0)の3ワード後ろから始まり「E F …」と重なっている。実行後は(d+0)から「B A C D」が書き込まれ、(s+3)以降の「E F」部分(網掛け)は変換されない。

(s+3)でのデバイス範囲の重複が事前に判明しているため，(s+0)～(s+2)を文字列変換し，(d+0)～(d+3)に書き込みます。

[事前に検出できない場合(正常完了)]
【図】(d+0)の3ワード後ろに(s+0)があり「α β γ …」。実行後は(d+0)から「α β γ」が格納され、(s+0)以降は「a β γ」と表示されている。
