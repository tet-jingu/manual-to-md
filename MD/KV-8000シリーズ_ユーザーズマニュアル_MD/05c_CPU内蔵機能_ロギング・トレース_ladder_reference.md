## ロギング機能/トレース機能の概要

(5-5 / 原本 p.433-434 / 5-57〜5-58)

### ● ロギング機能

(5-5 / 原本 p.433 / 5-57)

ロギング機能とは、指定したデバイスの状態や値を任意のタイミング（トリガ）で取り込む機能です。取り込んだデータは、CSVファイル形式でメモリカードまたはCPUメモリ（ユーザメモリ）に自動保存されます。取り込むデバイスやトリガなどは《KV STUDIO》で簡単に設定できます。

ロギング・トレースデータはCSV形式で保存されるため、Microsoft Excelなどの表計算ソフトでそのまま使用できます。CSV形式で保存されたデータは以下の方法で読み出せます。
- メモリカードを抜き出してパソコンで読み出す
- ストレージ転送ツールや、FTP機能を使用してPLC経由で読み出す
- リアルタイムチャートモニタを使用して読み出す

【図】ロギング機能の構成図 (原本 p.433)
- CPUユニット内の「PLC デバイスデータ」→(ロギング)→「メモリカード」(参照:「メモリカード」(5-3ページ)) または「CPU メモリ」(参照:「CPUメモリ（ユーザメモリ）」(5-27ページ))
- メモリカード/CPUメモリ →(読み出し)→ パソコン (Microsoft Excelなど)

【図】ロギング動作タイミングチャート (原本 p.433)
- ロギング開始 LOGE命令実行: 1パルス
- ロギングトリガ: LOGE実行後、周期的にパルス(図では6回)
- 実行リレー / 動作中リレー / 任意ロギング動作中リレー / メモリカード使用中リレー: LOGE命令実行でON、LOGD命令実行でOFF
- メモリカード使用中リレーのON時点が「ファイルオープン」、OFF時点が「ファイルクローズ」
- ロギング終了 LOGD命令実行: 1パルス(このパルス後に各リレーOFF)
- ※オプション設定により各リレーの挙動は変わります。

> **参考**
> - ファイルが存在しない状態でロギング・トレースを開始すると自動でファイルを新規作成します。
> - ロギング・トレース機能とストレージ命令は同時使用可能です。優先順位はストレージ命令 > ロギング・トレース機能となります。

### ● トレース機能

(5-5 / 原本 p.434 / 5-58)

ロギング機能と同様にデバイスの状態や値をバッファメモリ上に記憶します。ファイル保存のタイミングで、その前後の指定したデータ数のみを抽出してメモリカードやCPUメモリ（ユーザメモリ）、または内部メモリに記録します。

例えば、装置の異常時にファイル保存するようにトリガ設定すると、異常発生前後のみのデータが自動保存されるので、異常解析に役立ちます。

【図】トレース機能の概念図 (原本 p.434)
- SRAM上のバッファに「日付 時刻 DM11 DM12 DM13」の行が時間とともに常時ロギングされる
- ファイル保存トリガの発生行を境に、その前の「トリガ前データ」と後の「トリガ後データ」が抽出される
- 抽出データは メモリカード(CSVファイルとして自動保存) / CPUメモリ（ユーザメモリ）(CVSファイルとして自動保存 ※原本表記のまま) / 内部メモリ(※データのみ記録) に記録される

> **参考**
> ファイル保存先を「内部メモリ」にして保存したデータは、《KV STUDIO》の「リアルタイムチャートモニタ」上に読み出すことができます。

【図】トレース動作タイミングチャート (原本 p.434)
- トレース開始 LOGE命令実行: 1パルス
- ロギングトリガ: 周期的にパルス
- 実行リレー / 動作中リレー: LOGE命令実行でON、データ取得完了の時点でOFF
- ファイル保存トリガ: 1パルス。その前が「トリガ前データ」、後が「トリガ後データ」の範囲
- ファイル保存トリガモニタ: ファイル保存トリガ発生後にONし、ON保持
- データ取得完了: トリガ後データの取得が終わった時点でONし、ON保持
- ファイル書き込み完了: データ取得完了と同じタイミングでONし、ON保持
- トレース終了 LOGD命令実行: データ取得完了後に1パルス
- 任意ロギング動作中リレー / メモリカード使用中リレー: LOGD命令実行時に短時間ONパルス(トレース中はOFF)

> **ポイント**
> トレース機能で取得したデータをメモリカードに保存する場合はデータ取得完了をトリガにしてLOGD命令を実行してください。
> データ取得完了前にLOGD命令を実行してもファイルは生成されません。

## 使用手順

(5-5 / 原本 p.435 / 5-59)

ロギング・トレース機能の使用手順は次のとおりです。

1. ① デバイスやトリガを設定 — 【ツール（T）】－【ロギング/トレース設定（L）】 (参照:「設定」（5-60ページ）)
2. ② ラダープログラム作成 — 「LOGE」「LOGD」「TRGD」命令 (参照:「ロギング命令」（5-73ページ）)
3. ③《KV-8000》への転送 — 【モニタ/シミュレータ（N）】－【PLC転送→モニタ（C）】
4. ④ ロギング・トレースの実行 — LOGE命令を実行するとロギング実行中になります。ロギング実行中に、ロギングトリガ（トレース使用時はファイル保存トリガも必要）を発生するとデータをファイルに書き込んでいきます。LOGD命令を実行してファイルをクローズします。

- データ保存先
- 保存するファイル名の設定
- 機能（ロギング/トレース）の選択

- トリガの設定

割り込みプログラムや定周期モジュール/ユニット間同期モジュール内にも記述できます。

※4 **保存先がメモリカードの場合**
ロギング実行中はファイルがオープンされたままになります。ファイルがオープンされた状態で電源がOFFすると、ロギングした結果がメモリカードに残りません。電源OFFする前に必ずLOGD命令を実行してください。
「トリガ毎にCSVファイル保存を行う」にチェックすると、ロギング実行中でもトリガ後の書込みさえ終了していれば、電源がOFFしてもロギングの結果が残ります。ただし、メモリカードに書込み中に電源がOFFするとメモリカードの内容が失われる危険があります。
また、トリガ毎にメモリカードへの書込みが発生するため、メモリカードにアクセスする時間が長くなります。そのため、バッファオーバーフローが発生しやすくなります。トリガの間隔が短い場合は、「トリガ毎にCSVファイル保存を行う」チェックを外してください。

**保存先がCPUメモリの場合**

**チェックが入っている場合**
トリガ毎にCPUメモリに保存されるため、電源をOFFしてもCPUメモリにファイルは残ります。ただし、アクセスする時間が長くなります。

**チェックを外した場合**
RAM上にデータを作成するため高速でロギングできます。ただし、電源OFF時にRAMモードで作成したデータはクリアされるため、電源をOFFする前にCR3200をONし、CPUメモリの保存処理要求を実行する必要があります。

### LOGE / LOGD — ロギング・トレース許可 / ロギング・トレース禁止

(5-5 / 原本 p.450-451 / 5-74〜5-75)

| 命令 | 記号 | 名称 | 概要 |
|---|---|---|---|
| LOGE | [LOGE] | ロギング・トレース許可 | 指定したIDのロギング・トレースを実行許可／禁止状態にします。 |
| LOGD | [LOGD] | ロギング・トレース禁止 | (同上) |

**書式(ラダープログラム / 入力方法)**

```
実行条件 ─┤├─ [LOGE n]      入力方法: L O G E ␣ n ↵
実行条件 ─┤├─ [LOGD n]      入力方法: L O G D ␣ n ↵
```

**オペランド**

| オペランド | 説明 | 占有サイズ |
|---|---|---|
| n | ロギング・トレースID（0～9）を指定します。※1 ※2 | 16ビット |

(原本の表 1行 → md 1行)

※1 “$”での指定はできません。
※2 n にビットデバイスを指定した場合、連続した16ビットを占有します。
ワードデバイスを指定した場合は1ワードを占有します。

**動作説明**

- **LOGE**: 実行条件がONすると、n で指定したIDのロギング・トレースを実行許可状態にします。
  命令実行時、指定したIDのCPUユニットバッファがクリアされ、ロギング・トレース実行リレーがセットされます。トリガが発生すると、ロギング・トレースが実行されます。
  LOGE命令の実行条件の状態に関係なくLOGD命令が実行されるまで実行許可状態を継続します。
  すべてのロギングIDのロギング・トレースを同じ実行条件で実行許可状態にできます。
- **LOGD**: 実行条件がONすると、n で指定したIDのロギング・トレースを実行禁止状態にします。
  命令実行後、IDごとのロギング・トレース実行リレーがリセットされ、ロギング・トレースが停止します。それまでのロギング内容がメモリカードまたはCPUメモリに出力されます。

|---|---|
| 0 | CR000 |
| 1 | CR100 |
| 2 | CR200 |
| 3 | CR300 |
| 4 | CR400 |
| 5 | CR500 |
| 6 | CR600 |
| 7 | CR700 |
| 8 | CR800 |
| 9 | CR900 |

(原本の表 10行 → md 10行)

**ロギング・トレースのタイムチャート** (原本 p.451 / 5-75)

【図】トリガ(ビットデバイス)の場合 (原本 p.451)
- スキャン: 等間隔の縦線(各スキャンのEND処理)
- ロギング・トレース実行リレー: 途中でONし、しばらく後にOFF
- トリガ(ビットデバイス): 実行リレーON中に4回ON(うち1回は複数スキャンにわたる長いON)、実行リレーOFF後にさらに1回ON
- ロギング・トレース実行: 短いトリガON(1スキャン分)の各回はトリガON中のEND処理で1回「実行」。長いONの回はON中の各スキャンで連続して「実行」(網掛けが複数スキャン幅)。実行リレーOFF後のトリガONでは実行されない

【図】トリガ(周期)の場合 (原本 p.451)
- ロギング・トレース実行リレー: 途中でONし、しばらく後にOFF
- トリガ(周期): 一定間隔の短いパルス(実行リレーON中に4回、OFF後に1回)
- ロギング・トレース実行: 実行リレーON中の各トリガパルス後のスキャンで「実行」(4回)。実行リレーOFF後のトリガでは実行されない

### ■ 各デバイスの詳細

(5-5 / 原本 p.455-457 / 5-79〜5-81)

#### ● ロギング・トレース実行リレー

(5-5 / 原本 p.455 / 5-79)

ロギング・トレース実行の許可、禁止を行います。ロギング・トレース命令（LOGE）実行時、またはKV STUDIOでロギング・トレースを開始時にセットされますので、通常は直接操作する必要はありません。
このリレーがONすると、同じロギング/トレースIDのすべての状態リレーを一度OFFします。
エラーが発生した場合、リセットします。

#### ● ロギング・トレース動作中リレー

(5-5 / 原本 p.455 / 5-79)

実際にロギング・トレースが実行している間ONします。

#### ● ロギング・トレースファイル書き込み完了リレー

(5-5 / 原本 p.455 / 5-79)

ロギング使用時 : ファイル毎に指定したファイル容量上限値のデータを書き終えたときにONします。
トレース使用時 : ファイルまたは内部メモリにデータを書き終えたときにONします。
このリレーがONした場合ロギング・トレースは終了し、ロギング・トレース実行リレーがOFFします。
ロギング・トレースファイル書き込み完了リレーは、次回のLOGE命令実行時にOFFします。
参照:「ファイル容量上限設定オーバー時の処理について」（5-84ページ）

#### ● ロギングバッファ50%未満警告リレー

(5-5 / 原本 p.455 / 5-79)

トリガ発生の頻度がファイル書き込み速度よりも速いために、バッファの空き容量が50%未満になったときにONします。ファイル毎に指定したファイル容量上限値のデータを書き終えたときにONします。

#### ● バッファオーバーフローリレー

(5-5 / 原本 p.455 / 5-79)

メモリカードまたはCPUメモリへのデータの書き込みが追いつかず、ロギング・トレース用のバッファがオーバーフローしたことを示します。
このリレーがONしたときは、データの取りこぼしが発生しています。データ番号を見れば、いつデータを取りこぼしたか確認できます。
オーバーフローが発生しても、メモリカードへの書き込みは継続されます。
バッファオーバーフローが発生するときは、
- メモリカードまたはCPUメモリへのアクセスを減らす
- データ量やトリガの頻度を下げる
- スキャンタイムを長くすることで軽減できます。

#### ● ロギング・トレース実行中RUN中書込みありリレー

(5-5 / 原本 p.455 / 5-79)

ロギング・トレース実行中にRUN中書き込みがあったときONします。
RUN中書き込み時、ロギング・トレースは動作を続けますが、メモリカードまたはCPUメモリへの書き込みが遅くなるため、バッファオーバーフローが発生しやすくなります。

#### ● ロギング・トレースエラーリレー

(5-5 / 原本 p.455 / 5-79)

ロギング・トレースが、メモリカードのエラーで終了したとき、ONしロギング・トレースは終了します。
各種エラーリレーがONしていないか確認してください。このときバッファに残っているデータは無くなります。エラークリアは次回の「LOGE命令」実行時に行われます。

#### ● メモリ容量なしエラーリレー

(5-5 / 原本 p.456 / 5-80)

メモリカードまたはCPUメモリに十分な空き容量がないときにONします。
このリレーがONしたときは、ロギング・トレースは終了します。ロギング・トレースエラーリレーがONし、ロギング・トレース実行リレーがOFFします。このときバッファに残っているデータは無くなり、ロギングファイルは作成されません。エラークリアは次回の「LOGE命令」で行われます。

#### ● デバイス・トリガ設定異常リレー

(5-5 / 原本 p.456 / 5-80)

ロギング・トレースのデバイス設定、トリガ設定、その他設定が異常な場合にONします。
このリレーがONしたときは、ロギング・トレースが終了します。ロギング・トレースエラーリレーがONし、ロギング・トレース実行リレーがOFFします。

#### ● トレースファイル保存トリガモニタリレー

(5-5 / 原本 p.456 / 5-80)

トレース機能使用時に、ファイル保存トリガが発生するとONします。
次回のLOGE命令実行時にOFFします。

#### ● トレースデータ取得完了リレー

(5-5 / 原本 p.456 / 5-80)

トレース機能使用時に、ファイル保存トリガ後データ量で設定されたデータ量を取得し終わるとONします。

#### ● バッファ空き容量（KB単位）

(5-5 / 原本 p.456 / 5-80)

現在のバッファの空き容量がKB単位で格納されています。KV-8000シリーズのバッファ容量は10240KBです。

トレース使用時 : ファイル保存トリガ発生前は、バッファ全体の容量を表します。ファイル保存トリガ発生後は、トレース完了までに取得する残りのデータ量を表します。

他の機能を使用するときに、メモリカードへのロギング・トレースが動作しているかどうか確認するために用います。

#### ● メモリカード使用中リレー

(5-5 / 原本 p.457 / 5-81)

メモリカードを使用しているときにONします。ロギング・トレース機能に限らず何らかの機能がメモリカードを使用している間ONします。

#### ● メモリカード認識完了リレー

(5-5 / 原本 p.457 / 5-81)

メモリカードが挿入され、メモリカードスロットカバーが閉まっており、かつ初期化が完了し利用可能な状態になっているときにONします。

#### ● メモリカードありリレー

(5-5 / 原本 p.457 / 5-81)

メモリカードが挿入されており、かつメモリカードスロットカバーが閉まっている場合にONします。

#### ● メモリカードライトプロテクトリレー

(5-5 / 原本 p.457 / 5-81)

メモリカードが挿入されており、かつライトプロテクトがかかっている場合にONします。

(5-5 / 原本 p.457 / 5-81)

収集しているデバイス数、またはサンプリング頻度を減らすことで軽減できます。

## ロギング・トレース機能の注意事項

(5-5 / 原本 p.458-460 / 5-82〜5-84)

ロギング・トレース機能を使用する上での注意事項を以下に示します。
「CPUユニットで使用する」（5-8ページ）、「使用上の注意事項」（5-9ページ）もあわせてお読みください。

### ● 保存速度

(5-5 / 原本 p.458 / 5-82)

- ロギング・トレース実行時のスキャンタイムは、最大で20µs×使用しているIDの数まで延びます。
- 複数のトリガが同時に発生する場合、メモリカードやCPUメモリに対するアクセス量が多くなるためスキャンタイムが延びたり、バッファオーバーフローが発生しやすくなります。

> **参考**
> データの取りこぼしが発生する場合に、一定スキャンタイム運転やEND処理時間の設定を使用して改善することができます。
> 「一定スキャンタイム運転」（4-90ページ）
> 「END処理時間の設定」（4-92ページ）

### ● ストレージへのアクセスの優先順位

(5-5 / 原本 p.458 / 5-82)

- ロギング・トレース中、ストレージへのアクセスの優先順位は、以下の通りです。
  ストレージ命令 ＞ ロギング・トレース命令 ＞ FTPサーバ機能、FTPクライアント機能、アクセスウィンドウのファイル操作、KV-XD02からのアクセス
  このため、ロギング・トレースのトリガが大量に発生している場合、他の機能がストレージを使用できないことがあります。

### ● 電源断、カード抜き差し

(5-5 / 原本 p.458 / 5-82)

メモリカードは、本体の電源をONしたまま、メモリカードアンマウント要求リレーをONし、メモリカード認識完了リレーがOFFになるのを確認して取り出してください。ロギング・トレース実行時は、この手順でメモリカードを取り出さないとデータが保存されません。

**メモリカードスロットカバーの扱い**
- メモリカードスロットカバーが閉まっていないときは、ロギング・トレースは開始されません。
- メモリカードスロットカバーを開くと、実行中の処理は継続されますが、それ以後の処理はメモリカードの処理を受け付けません。

**電源断時、カードの抜き差しの注意**
- メモリカードアクセス中LEDが点灯中（カードへのデータの読み込み・書き込み）は、絶対にカードを抜いたり、本体の電源を切らないでください。カード内のデータが破壊されることがあります。
- ロギング・トレース実行中に電源がOFFした場合、データはメモリカードに保存されません。
- CPUメモリアンマウント要求リレーONし、CPUメモリ認識完了リレーがOFFするのを待って電源をOFFしてください。アンマウントとは、メモリカードを安全に取り外し可能な状態にすることです。
- RAMモードで使用している場合、必要なデータは電源断を実行する前にCPUメモリ保存要求リレーをONし、CPUメモリ保存完了リレーがONになったのを確認して電源をOFFしてください。

**カードの交換**
- カード交換は、必ず手順にそって行ってください。
  「CPUユニットで使用する」（5-8ページ）
- 《KV STUDIO》のロギング・トレース設定で「メモリカード挿入によるロギング・トレース自動再開」を設定すると、ロギング・トレース実行中にメモリカードを抜いた場合、次回メモリカードを挿入するまで本体バッファにロギング・トレースデータを蓄積し、メモリカードが挿入されると、蓄積していたデータをメモリカードに書き込みます。このとき、ロギング・トレースエラーリレーはONしません。メモリカード挿入までの時間が長かったり、トリガ発生回数が多かったりすると、バッファオーバーフローが発生してデータが欠落することがあります。
  「メモリカード挿入によるロギング・トレース自動再開」を設定していない場合、ロギング・トレース実行中にメモリカードを絶対に抜かないでください。カード内のデータが破壊されることがあります。

### ● RUN中書き換え中の動作

(5-5 / 原本 p.459 / 5-83)

- RUN中書換えを行っているとき、ロギング・トレースの実行が非常に遅くなります。このため、バッファオーバーフローが発生しやすくなります。
- ロギング・トレース設定をRUN中書き込みできますが、設定が有効になるのは次回ロギング・トレース動作開始時です。

### ● RUN/PRGモード切換時の動作

(5-5 / 原本 p.459 / 5-83)

- ロギング・トレース機能はRUN状態のときのみ動作します。RUN→PRG切換を行うとすべてのロギング・トレースが停止します。
  LOGD命令が実行された場合と同様、それまでのロギング・トレース内容がメモリカード（またはCPUメモリ）に出力されます。
  また、PRG→RUN切換したときには、ロギング・トレースはすべて停止状態なので、開始するためにLOGE命令を実行する必要があります。

### ● ロギング・トレース開始時の処理について

(5-5 / 原本 p.459 / 5-83)

電源を投入してロギング・トレース許可されたとき、指定されたファイル番号がすでに存在していると次のような動作になります。

**ファイル番号の指定方法が「自動連番」のとき**
- 「ファイル新規作成」で空き番号が無い場合の動作は「ファイル容量上限設定オーバー時の処理について」を参照してください
- 「最新のファイルに追記」で最新のファイルがファイル容量上限設定で設定した上限値を超えた場合 : 次の空き番号のファイルを使用します。空き番号が無い場合の動作は「ファイル容量上限設定オーバー時の処理について」を参照してください。
  ファイル容量上限設定をしていない場合は追記し続けます。

「ファイル容量上限設定オーバー時の処理について」は次ページを参照してください。

**ファイル番号の指定方法が「固定/デバイス値」のとき**
- 「同一ファイル存在時」に「古いファイルを上書き」を選択している場合 : 古いデータを削除し、同一ファイル名で上書きします。
- 「同一ファイル存在時」に「追記」を選択している場合 : 指定されたファイルにデータを追記します。存在するファイルがすでにファイル容量上限設定で設定した上限値を超えているときにロギング・トレースを開始すると、ロギング・トレースエラーリレーがONし、ロギング・トレースを停止します。

参照:「ロギング・トレース用デバイス一覧」（5-78ページ）

### ● ファイル容量上限設定オーバー時の処理について

(5-5 / 原本 p.460 / 5-84)

ファイル容量の上限値を超えたときの動作は、ファイル番号の指定方法によって異なります。
ファイル容量上限値設定については、「オプション」（5-67ページ）参照

**ファイル番号の指定方法が「自動連番」のとき**
ファイル番号に空きがある場合は、次のファイル番号で新たなファイルを作成します。
ファイル番号がすべて使用済みの状態で、最後のファイルが容量オーバーしたとき
- 「空き番号がない場合」に「古いファイルから上書き」を選択している場合 : 最も古いデータを削除し、同一ファイル番号でファイルを新規作成します。
- 「空き番号がない場合」に「ロギング・トレース停止」を選択している場合 : ロギング・トレース開始時にロギング・トレースエラーリレーがONし、ロギング・トレースを停止します。

**ファイル番号の指定方法が「固定/デバイス」のとき**
「同一ファイル存在時」に「古いファイルを上書き/追記」どちらを選択している場合も、ロギング・トレースを停止します。

> **参考**
> FTPクライアント機能で「ロギング/トレース転送設定」を設定している場合、LOGD命令を実行していなくても、ファイル容量上限設定オーバーで生成されたファイルは都度FTPアップロードされます。
