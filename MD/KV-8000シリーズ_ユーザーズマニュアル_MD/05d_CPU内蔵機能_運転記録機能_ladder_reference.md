## 5-6 運転記録機能

(5-6 / 原本 p.462-486 / 5-86〜5-110)

### 運転記録の概要

(5-6 / 原本 p.462 / 5-86)

運転記録機能を使用すると任意のタイミング（トリガ）前後のPLCの運転記録を保存できます。運転記録で保存できるデータは以下のとおりです。

保存した運転記録は、《KV STUDIO》または《KV REPLAY VIEWER》で再生できます。トラブル発生前後のビットデバイスのON/OFF状態やワードデバイスの値、カメラで撮影した映像※1をラダープログラム、リアルタイムチャートモニタ、リプレイVTビューワ※2で確認できます。時系列のデータとして再生・停止・巻き戻し・コマ送りなどを行いながら確認できるため、センサがチャタリングしていた、チャック前に完全に停止していなかったためにチャックミスが起こったなど、後からの確認が難しかったトラブル要因の解析に活用できます。

※1 小型標準カメラ《KV-CA1H》もしくは広視野・高解像度カメラ《KV-CA1W》およびカメラ入力ユニット《KV-CA02》が必要です。
※2 運転記録のデバイスデータをタッチパネルの画面データを使用してPC上でシミュレートする機能です。VT STUDIO Ver.7.10以降が必要です。

運転記録はCPUユニットに挿入したメモリカードまたはCPUメモリに保存でき、CPUユニット経由で読み出したり、パソコンなどにコピーしたファイルを開いたりすることで内容を確認できます。

【図】運転記録の保存・読み出し構成 (原本 p.462)
- CPUユニットが 運転記録(・デバイス ・カメラ ・イベント / エラー ・プロジェクトデータ)を CPUメモリ または メモリカード に「保存」
- パソコン(KV STUDIO) が CPUユニット経由で「読み出し」
- 参照: 「メモリカード」（5-3ページ）、「CPUメモリ（ユーザメモリ）」（5-27ページ）

| 種類 | 詳細 |
|---|---|
| デバイス | トリガ条件成立前後のPLCのデバイス、変数、拡張ユニットのバッファメモリの、スキャンタイムごとのデータ |
| カメラ | トリガ条件成立前後のフレームレートごとにKV-CA02で撮影した映像データ |
| イベント/エラー | トリガ条件成立前後のエラーやデバイス値変更などのイベント履歴 |
| プロジェクトデータ | トリガ条件成立時のプロジェクトデータ |

(原本の表 4行 → md 4行)

> **ポイント**
> 運転記録機能は《KV-8000》でのみ使用できる機能です。

> **ポイント**
> - 保存した運転記録は《KV STUDIO》のリプレイモード、または《KV REPLAY VIEWER》で内容を確認できます。リプレイモードの詳細は『KV STUDIO ユーザーズマニュアル』を参照してください。
> - カメラの映像データはカメラ入力ユニット《KV-CA02》に記録され、トリガ条件成立時にCPUユニットに保存されます。詳細は『KV-CA02ユーザーズマニュアル』を参照してください。
> - データ活用ユニット《KV-XD02》を使用すると、運転記録の内容を分析し、トラブル要因となった可能性が高いデバイス/変数を表示することができます。詳細は『KV-XD02ユーザーズマニュアル』を参照してください。

### 使用手順

(5-6 / 原本 p.463 / 5-87)

運転記録機能の使用手順は以下のとおりです。

1. **① 保存するデータとトリガの設定**
   【運転記録/リプレイ(R)】－【運転記録設定(P)】
   運転記録として保存するデータの種類と、保存する条件、期間を設定します。保存するデータはユニット設定やラダープログラムの内容から自動で設定され、手動で追加・削除することも可能です。
   「設定」（5-88ページ）
2. **② カメラ入力ユニットの設定**
   カメラの設定
   カメラの映像を記録する場合のみ必要です。
   詳細は 『KV-CA02ユーザーズマニュアル』を参照してください。
3. **③ 運転記録の収集、保存**
   設定をPLCに転送します。設定したファイル保存トリガの条件が成立すると、CPUユニットに運転記録が保存されます。
4. **④ 運転記録の再生**
   保存した運転記録を《KV STUDIO》のリプレイモードで、または《KV REPLAY VIEWER》で再生します。リプレイモードの使用方法は、『KV STUDIO ユーザーズマニュアル』を参照してください。

### 設定

(5-6 / 原本 p.464-465 / 5-88〜5-89)

運転記録機能を使用するためには、《KV STUDIO》で以下の設定を行います。
- データ保存先
- データの取得方法
- ファイル保存トリガ
- データの収集時間
- データの収集開始タイミング
- 記録対象

運転記録設定は最大4個（ID0～ID3）まで作成できます。IDごとに運転記録設定を行います。

#### ■「ファイル保存トリガ前後」と「開始リレー」の動作

(5-6 / 原本 p.467 / 5-91)

**●「ファイル保存トリガ前後」を選択した場合**

運転記録設定の各IDに割り当てたバッファ容量分のデータを常に収集します。ファイル保存トリガの条件が成立しトリガ後収集期間が経過すると、データの収集を停止し、トリガ前収集時間とトリガ後収集時間分のデータを運転記録として保存します。トリガ前収集時間以前のデータは保存されません。
エラーリレーの立ち上がり前後の運転記録を確認する場合などに選択します。

【図】ファイル保存トリガ前後の保存範囲 (原本 p.467)
- バッファ容量全体のうち、古い側が「保存されないデータ」、新しい側が「運転記録として保存」
- 「運転記録として保存」= トリガ前収集時間 + トリガ後収集時間。その境界がファイル保存トリガ

> **ポイント**
> - トリガ前収集時間で指定した時間分のデータを収集していない状態でファイル保存トリガの条件が成立した場合、収集できたデータのみを運転記録として保存します。
> - バッファ容量分のデータを収集すると、先頭に保存したデータから順番に上書きされていきます。

**●「開始リレー」を選択した場合**

開始リレーで指定したデバイスがONすると、データの収集を開始し、設定した収集時間が経過するとデータの収集を停止します。完了信号、または次の開始リレーがONするまでの時間が一定時間を超えたことをファイル保存トリガの条件としておくと、ファイル保存トリガの条件が成立し、収集時間分のデータを運転記録として保存します。
設備が無応答で停止した場合など、エラーリレーとして検出できないような場合に選択します。

【図】開始リレー方式の保存範囲 (原本 p.467)
- 開始リレーから「収集時間」の間「収集したデータ」を取得
- 収集終了から「一定時間経過」後にファイル保存トリガ → 「収集したデータを運転記録として保存」

> **参考**
> 運転記録バッファ領域全保存モード（ID0：CR5614）がONしている状態でファイル保存トリガが成立するとバッファ容量分の全デバイスデータを保存できるため、収集期間以外のデバイスデータも確認できます。

> **ポイント**
> - 開始リレーがONした時点で収集したデータが存在する場合、収集したデータを破棄してからデータの収集を開始します
> - 収集したデータが存在しない状態でファイル保存トリガの条件が成立した場合、運転記録は保存されません。
> - 開始リレーのON後、収集時間が経過する前にファイル保存トリガが成立した場合、収集時間分のデータを収集してから運転記録を保存します。

#### ■ 各デバイスの詳細

(5-6 / 原本 p.475-476 / 5-99〜5-100)

**● 運転記録保存要求リレー**
運転記録保存要求リレーがOFF→ONするとCPUユニットは収集したデータを運転記録として保存します。運転記録機能でファイル保存トリガを設定していない場合でも、運転記録保存要求リレーをOFF→ONすると運転記録を保存できます。ラダープログラムから実行する場合はSET命令を使用してください。

**● 運転記録動作中リレー**
運転記録機能が動作している間ONします。

**● 運転記録保存トリガモニタリレー**
運転記録動作中にファイル保存トリガが発生すると、ONします。運転記録の保存が完了、または失敗すると、OFFします。

**● 運転記録保存中リレー**
運転記録の収集が完了し、保存を開始するとONします。運転記録の保存が完了、または失敗すると、OFFします。

**● 運転記録収集中リレー**
運転記録を収集している間、ONします。

**● 運転記録設定異常リレー**
運転記録機能の設定値が範囲外のときにONします。

**● 運転記録保存完了リレー**
運転記録の保存が完了するとONします。次のファイル保存トリガがONすると、OFFします。
KV-XD02のいつもと違う分析が動作している場合は、運転記録の保存完了後、いつもと違う分析が完了したタイミングでONします。

**● 運転記録保存エラーリレー**
運転記録の保存が失敗するとONします。次のファイル保存トリガがONすると、OFFします。

**● デバイス記録バッファ不足リレー**
バッファ容量が不足し、設定した収集時間分のデータを収集できないときにONします。

**● 運転記録バッファ領域全保存モードリレー**
このリレーをONした状態で運転記録の保存を開始すると、設定した収集時間分だけではなく、バッファに存在するすべてのデータを保存します。

> **ポイント**
> - CRにBOOLの配列型変数を割り当てた場合、配列の要素番号は数値で指定してください。デバイスや変数で指定した場合、SET命令が正しく動作しません。

**● デバイス記録平均サンプリング周期**
デバイス記録のサンプリング周期（単位：μs）の平均値が格納されます。

**● デバイス記録平均変化デバイス数**
デバイスの状態に変化があったデバイスの数（ワード数）の平均値が格納されます。

**● デバイス記録最大収集期間**
現在の設定で収集可能な期間（単位：秒）が格納されます。収集するデバイスの状態が変化すると収集可能な期間は短くなるため、同じ設定でもモニタ中に値が変化することがあります。

**● 運転記録保存完了コード**
運転記録の保存が完了すると、値が格納されます。保存完了時には0が格納され、保存失敗時には失敗要因に関する完了コードが格納されます。完了コードの内容は 「運転記録保存完了コード」（5-103ページ）を参照してください。

**● 運転記録保存カウンタ**
運転記録の保存が完了すると、1ずつ加算されます。0～65535の範囲で加算され、65535の次は0になります。電源断時にも値が保持されます。リセットする場合は、0を格納します。

**● 運転記録保存進捗詳細1**
保存実行中のファイル種別が格納されます。番号とファイル種別の関係は以下のとおりです。

| 番号 | ファイル種別 | 内容 |
|---|---|---|
| 0 | なし | 保存中ではありません。 |
| 1 | CPU履歴 | CPUのイベント/エラー履歴です。 |
| 2 | ラダープロジェクト | 保存時にCPUユニットで実行していたプロジェクトです。 |
| 3 | デバイス記録 | 運転記録設定で設定したデバイスデータです。 |
| 4 | カメラ記録 | KV-CA02で撮影した映像データです。 |
| 5 | Savelog.txt | トリガ種別、時刻、フォルダ作成日時、ファルダ名、データサイズを記載したテキストファイルです。運転記録の保存に失敗した場合、Savelog.txtは保存されません。 |

(原本の表 6行 → md 6行)

**● 運転記録保存進捗詳細2**
運転記録保存の進捗がファイル種別ごとに0～100の範囲で格納されます。

**● 運転記録保存進捗**
運転記録保存の進捗が0～100の範囲で格納されます。

**● 運転記録保存パス**
運転記録の保存先のパスが格納されます。

### 運転記録保存時のデバイスの動作

(5-6 / 原本 p.477-478 / 5-101〜5-102)

収集期間の指定方法で「ファイル保存トリガ前後」を選択した場合と「開始リレー」を選択した場合とで、使用するデバイスや作成するラダープログラムが一部異なります。

#### ●「ファイル保存トリガ前後」を選択した場合

(5-6 / 原本 p.477 / 5-101)

【図】タイミングチャート(ファイル保存トリガ前後) (原本 p.477)
- 運転記録動作中(CR5601): 運転開始でON、2回の保存サイクルを通してON、最後にOFF
- ファイル保存トリガ: 短いパルスが2回
- 運転記録収集中(CR5604): CR5601と同時にON → 「トリガ後収集時間」経過でOFF(保存中はOFF) → 保存完了で再ON → 2回目も同様 → 2回目の保存終了で再ON → CR5601のOFFでOFF
- 運転記録保存トリガモニタ トリガ発生(CR5602): トリガでON、「トリガ後収集時間」+「保存中」の間ON、保存完了/失敗でOFF
- 運転記録保存中(CR5603): トリガ後収集時間の経過でON、「保存中」の区間ON、保存終了でOFF
- 運転記録保存完了(CR5607): 1回目の保存完了でON、次のファイル保存トリガでOFF、2回目(失敗)の終了で再ON
- 運転記録保存エラー(CR5608): 2回目の保存(失敗)の終了でON
- 運転記録保存完了コード(CM6000): 1回目保存完了で 0、2回目(失敗)でエラーコード

① 運転記録機能が動作中になると、運転記録動作中リレー（CR5601）と運転記録収集中（CR5604）がONし、CPUユニットがデータ収集を開始します。
② ファイル保存トリガの条件が成立すると、運転記録保存トリガモニタ（CR5602）がONし、トリガ後収集時間が経過するまでデータを収集します。
③ トリガ後収集時間が経過すると、CPUユニットが運転記録の保存を開始し、運転記録保存中リレー（CR5603）がONします。運転記録保存中リレーがONしている間は運転記録収集中リレーはOFFし、CPUユニットはデータの収集を停止します。
④ 運転記録の保存が完了すると、運転記録保存トリガモニタリレーと運転記録保存中リレーがOFFし、運転記録保存完了リレー（CR5607）がONします。運転記録保存完了コード（CM6000）に0が格納されます。
⑤ ファイルの保存に失敗した場合、運転記録保存トリガモニタ発生リレーと運転記録保存中リレーがOFFし、運転記録保存完了リレーと運転記録保存エラーリレー（CR5608）がONします。運転記録保存完了コードにはエラーコードが格納されます。

> **参考**
> - 運転記録機能が動作中になるのはCPUユニットがPROGモードからRUNモードに切り換わったタイミングです。
> - 運転記録機能に関連するCRおよびCMはCPUユニットが自動で制御するため、ラダープログラムから操作する必要はありません。

> **ポイント**
> 運転記録保存完了リレーは、KV-XD02のいつもと違う分析が動作している場合、運転記録の保存完了後、いつもと違う分析が完了したタイミングでONします。

#### ●「開始リレー」を選択した場合

(5-6 / 原本 p.478 / 5-102)

【図】タイミングチャート(開始リレー) (原本 p.478)
- 運転記録動作中(CR5601): 運転開始でON、最後にOFF
- 開始リレー: 短いパルスが2回

① 運転記録機能が動作中になると、運転記録動作中リレー（CR5601）がONします。
② 運転記録設定で開始リレーに指定したデバイスをONすると、運転記録収集中（CR5607）がONし、CPUユニットがデータの収集を開始します。収集時間が経過するとデータの収集を終了し、運転記録収集中はOFFします。

運転記録保存完了コードにはエラーコードが格納されます。

### 運転記録機能の注意事項

(5-6 / 原本 p.484-485 / 5-108〜5-109)

運転記録機能を使用する上での注意事項を以下に示します。

**● 保存速度**
- 運転記録の収集時はスキャンタイムが延びます。実際のスキャンタイムはスキャンタイムモニタで確認できます。
- 運転記録保存中はデータ収集が停止するため、スキャンタイムは延びません。

> **参考**
> スキャンタイムのばらつきが問題になる場合に、一定スキャンタイム運転やEND処理時間の設定を使用して改善することができます。
> 「一定スキャンタイム運転の設定」（4-91ページ）
> 「END処理時間の設定」（4-92ページ）

**● ストレージへのアクセスの優先順位**
ストレージへのアクセスの優先順位は以下のとおりです。
ストレージ命令 > ロギング・トレース命令 > 運転記録機能、FTPサーバ機能、FTPクライアント機能、アクセスウィンドウのファイル操作
このため、運転記録機能のファイル保存トリガが大量に発生している場合、他の機能がストレージを使用できないことがあります。

**● 電源断、カード抜き差し**
メモリカードは、本体の電源をONしたまま、メモリカードアンマウント要求リレーをONし、メモリカード認識完了リレーがOFFになることを確認してから取り出してください。運転記録の保存中はメモリカードを抜き出したり、メモリカードスロットカバーを開けたりしないでください。

メモリカードスロットカバーの扱い
- メモリカードスロットカバーが閉まっていないときは、運転記録は保存できません。
- メモリカードスロットカバーを開くと、実行中の処理は継続されますが、それ以後の処理は受け付けません。

電源断時、カードの抜き差しの注意
運転記録の保存中は保存が完了するまで保存が中断されるような操作をしないでください。保存が完了する前に保存を中断すると、運転記録は正しく保存されません。保存が中断される動作は以下のとおりです。
- CPUユニットの電源断
- メモリカードアンマウント要求リレー、CPUメモリアンマウント要求リレーをONしてストレージをアンマウントする
- メモリカードスロットカバーを開く（ファイル保存先がメモリカードの場合）

**● RUN/PRGモード切換時の動作**
運転記録機能はCPUユニットがRUNモードのときのみ動作します。RUN→PRG切換を行うとすべての運転記録機能が停止します。PRG→RUN切換を行うと、運転記録機能は自動で再開します。

**● 運転記録保存時の処理について**

(5-6 / 原本 p.485 / 5-109)

運転記録の保存が実行されたとき、指定したフォルダ番号がすでに存在していると以下の動作になります。

フォルダ番号の指定方法が「自動連番」のとき
- 「空き番号がない場合」で「上書き」を選択している場合は、最も古いフォルダを削除し、同一フォルダ名で上書きします。
- 「空き番号がない場合」で「停止」を選択している場合は、保存に失敗し、運転記録の収集を再開します。

フォルダ番号の指定方法が「固定/デバイス値」のとき
すでに存在している番号のフォルダ削除し、同一フォルダ名で上書きします。

**● データ保存先パスで使用できない文字**
以下の文字はデータ保存先パスのコメントおよびトリガコメントに使用できません。
- 半角12文字* / < > ? ￥ ｜ % , : ; "
- 全角7文字／　：　？　￥　＊　［　］
- NEC特殊文字（8740H～879CH）①、㌢、℡、㍻、など
- NEC選定IBM拡張文字（ED40H～EEFCH）
- IBM選定IBM拡張文字（FA40H～FC4BH）
