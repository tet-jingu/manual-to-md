### FB / FEND / FUN

(4-10 / 原本 p.246-248 / 4-148〜4-150)

| 命令 | 名称 | 機能概要 |
|---|---|---|
| FB | ファンクションブロック呼び出し | 指定したファンクションブロックを呼び出します。 |
| FEND | ファンクションブロックエンド | ファンクションブロックの実行を停止します。（ファンクションブロック内に記述） |
| FUN | ファンクション呼び出し | 指定したファンクションを呼び出します。 |

(原本の表 3行 → md 3行)

**書式(ラダープログラム / 入力方法)** (原本 p.246)

【図】ラダーシンボル (原本 p.246)
- FB: 実行条件(a接点) → 箱形シンボル(上段に `S`、左側ピン例 Input1 / InOut1 / UnitNo、右側ピン例 Output1 / InOut1)
- FEND: 実行条件(a接点) → `FEND` 出力シンボル
- FUN: 実行条件(a接点) → 箱形シンボル(FBと同形。上段に `S`、左側ピン例 Input1 / InOut1 / UnitNo、右側ピン例 Output1 / InOut1)

入力方法:

```
FB␣S〔␣引数1␣引数2…〕↵      ※1※2
FEND↵
FUN␣S〔␣引数1␣引数2…〕↵     ※1※2
```

| オペランド | 説明 | 占有サイズ |
|---|---|---|
| S | ファンクションブロック・ファンクション名を指定します。※3 | ー |

(原本の表 1行 → md 1行)

※1 ファンクションブロック・ファンクション名称以外のオペランドの個数や、指定できるデータは、実行するファンクションブロック・ファンクションに設定されている引数設定によって以下のとおり異なります。
- IN ：デバイス、変数、ラベル、定数を指定できます。
- OUT ：デバイス、変数、ラベルを指定できます。定数は指定できません。
- IN-OUT ：デバイス、変数、ラベルを指定できます。定数は指定できません。
- ユニット ：デバイス、変数、ラベル、定数を指定できます。

※2 IN-OUT引数にT、C、TIMER型変数、COUNTER型変数を指定した場合、ファンクションブロック・ファンクション内で使用する命令語によって扱いが異なります。

※3 ""、#、$は使用できません。KV STUDIOで設定してファンクションブロック・ファンクション名称を直接入力してください。半角英数字の場合は12文字、全角の場合は6文字まで指定できます。ただし、KV-8000/7000シリーズの場合は全角でも12文字まで指定できます。

> **ポイント**
> FB命令、FEND命令、FUN命令は、KV-8000シリーズCPUユニットおよびCPU機能バージョン2.0以降のKV-7000シリーズCPUユニットで使用できます。
> 「KV-8000(A)　CPU機能バージョンについて」（1ページ）

#### 動作説明

(4-10 / 原本 p.247 / 4-149)

- **FB** 実行条件がONのとき、S で指定したファンクションブロックを起動します。
  指定したファンクションブロックは、実行条件がOFFからONになったスキャンから実行を開始します。
  一旦実行を開始すると、実行条件がOFFでもファンクションブロックを実行し続けます。
- **FEND** 実行条件がONのとき、FEND命令が記述されているファンクションブロックを停止します。
- **FUN** 実行条件がONのとき、S で指定したファンクションを実行します。

プログラムの設定により、停止時のOFF処理の動作が異なります。詳細は「停止時の動作」（4-125ページ）を参照ください。

> **ポイント**
> - FB命令の呼び出し個数や順序を変更すると、RUN中書き込みできません。
> - ファンクションブロックは以下の場合に停止します。
>   - 読み出し元のプログラムが停止した場合
>   - ファンクションブロック内でFEND命令を実行した場合
> - FB命令の実行条件がONのままの場合には、FEND命令は無視されます。
> - FEND命令は、モジュール内やファンクション内に記述できません。
> - FEND命令で他のファンクションブロックを停止することはできません
> - ファンクションブロック内の微分実行型命令の前回状態は、ファンクションブロックの実行開始時に毎回初期化されます。（立ち上がり微分：ON、立ち下がり微分：OFF）
> - ファンクション内では、微分実行型命令・タイマ命令は使用できません。
> - 以下の場合、各モジュール・ファンクションブロックが停止もしくは各命令間の実行条件がOFFしたとき、実行中のファンクションブロック・ファンクションは停止します。
>   - FB/FUN命令をモジュール・ファンクションブロックに記述した場合
>   - FB/FUN命令をマスターコントロール（MC～MCR命令間）に記述した場合
>   - FUN命令をステージ（STG～JMP命令間）に記述した場合
> - 以下の場合、各命令間の実行条件がOFFしたとき、実行中のファンクションブロック・ファンクションは中断します。次に各命令間が実行されたときにファンクションブロックの実行を再開します。このときファンクションブロック内の微分実行型命令の前回状態は、初期化されません。（初期化モジュール内に記述した場合は、運転開始時1スキャンのみ実行します。）
>   - FB/FUN命令をサブルーチン（SBN～RET命令間）に記述したとき
>   - FB/FUN命令を条件分岐（CJ/NCJ～LABEL命令間）に記述したとき
>   - FB/FUN命令をステップ（STP～STE命令間）に記述したとき
>   - FB/FUN命令を割り込み（INT～RETI命令間）に記述したとき
>   - FB命令をステージ（STG～JMP命令間）に記述したとき
> - ファンクション内で、FB命令は使用できません。
> - マクロ内でFB/FUN命令は使用できません。
> - ファンクションブロック・ファンクション内に、そのファンクションブロック・ファンクション自身を呼び出すFB/FUN命令は使用できません。
> - ファンクションブロック・ファンクション内でサブルーチンプログラムを使用できますが、割り込みプログラムは使用できません。
> - プロジェクト内で同じファンクションブロック・ファンクションを複数回実行する場合、ファンクションブロック・ファンクション内でOUT/OUB命令にグローバルデバイス/グローバル変数を使用すると、2重コイルになります。

#### 動作説明

(4-10 / 原本 p.249 / 4-151)

- **FBCALL** 実行条件がONのとき、S1、S2 で指定したファンクションブロックのインスタンスを第3オペランド以降で指定した引数で実行します。
  指定したファンクションブロックは、OFF→ONになったスキャンから実行を開始します。
  一旦実行を開始すると、実行条件がON中は常にファンクションブロックを実行し続けます。
  実行条件がOFFすると、ファンクションブロックの実行を停止します。
- **FBSTRT** 実行条件がONのとき、S1、S2 で指定したファンクションブロックのインスタンスを第3オペランド以降で指定した引数で実行します。

  一旦実行を開始すると、実行条件がOFFでもファンクションブロックを実行し続けます。
  ファンクションブロックを停止する場合はファンクションブロック内でFEND命令を実行します。

詳細は「停止時の動作」（4-125ページ）を参照してください。

## ファンクションブロックとマクロの違い

(4-10 / 原本 p.273-274 / 4-175〜4-176)

ファンクションブロックはマクロと同様に、ラダー回路を1つのラダー命令語のようにまとめる機能です。ファンクションブロックの動作をマクロの動作と比較して説明します。
マクロについての詳細は、「マクロ」（4-178ページ）を参照してください

### 実体の生成

(4-10 / 原本 p.273 / 4-175)

【ファンクションブロック】
- プログラムの種類：ファンクションブロックの場合
  インスタンスの個数だけ実体が生成されます。
- プログラムの種類：ファンクションの場合
  プログラム内で呼び出す数によらず、1つの同じ実体が生成されます。

【マクロ】
- プログラム内で呼び出すごとに、同じ数の実体が生成されます。

### 呼び出せる箇所

(4-10 / 原本 p.273 / 4-175)

【ファンクションブロック】
- プログラムの種類：ファンクションブロックの場合
  モジュール、ファンクションブロックから呼び出せます。
- プログラムの種類：ファンクションの場合
  モジュール、ファンクションブロック、ファンクションから呼び出せます。
- 最大8段までネストできます。
  「ファンクションブロックのネスト」（4-140ページ）

【マクロ】
- モジュールから呼び出せます。マクロからマクロを呼び出すことはできません。

### 引数タイプ

(4-10 / 原本 p.273 / 4-175)

【ファンクションブロック】
- IN ：実行開始時、デバイスの値を引数に格納します。
- OUT ：実行完了時、引数の値をデバイスに格納します。
- IN-OUT ：実行開始時、デバイスへの参照を格納します。

【マクロ】
- P ：実行開始時、デバイスへの参照を格納します。
- V ：実行開始時、デバイスの値を引数に格納します。

### 引数に指定できる変数の種類

(4-10 / 原本 p.273 / 4-175)

以下の変数はファンクションブロックのみで指定でき、マクロでは指定できません。
- IN、OUT引数 ：固定長配列、構造体、固定長文字列
- IN-OUT引数 ：固定長配列、可変長配列、構造体、固定長文字列、可変長文字列

> **参考**
> KV-8000シリーズで新規のプログラムを作成する際は、マクロではなくファンクションブロックでの作成を推奨します。
