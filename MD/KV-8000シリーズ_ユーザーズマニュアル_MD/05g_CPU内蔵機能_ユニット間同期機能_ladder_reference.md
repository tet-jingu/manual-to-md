## 5-10 ユニット間同期機能

(5-10 / 原本 p.545 / 5-169)

### ユニット間同期とは

(5-10 / 原本 p.545 / 5-169)

ユニット間同期機能は，複数ユニット間の制御タイミングを合わせる機能です。本機能を使用すると，同期対象のユニットがユニット間同期周期に入力または出力タイミングを合わせることができます。
ユニット間同期周期とは，ユニット間同期機能の定周期間隔です。
この機能を使用することで、複数のユニット間での同時サンプリング、同時位置決めなどが実現できます。

**ユニット間同期の動作イメージ**

【図】ユニット間同期機能を使用しない場合の動作 (原本 p.545)
- CPUユニット: 「ラダープログラム」→「END処理」→「ラダープログラム」→「END処理」→「ラダープログラム」→「END処理」を繰り返す。
- 拡張ユニット1・拡張ユニット2: それぞれが独自の「内部周期」で動作し、内部周期の中で「実行」が行われる。拡張ユニット1と拡張ユニット2の内部周期の区切り位置・「実行」の位置は互いにずれている。
- CPUユニットの各END処理のタイミングで、CPUユニットと拡張ユニット1・拡張ユニット2の間でデータのやり取り(上下の矢印)が行われる。

【図】ユニット間同期を使用する場合の動作 (原本 p.545)
- CPUユニットは「通常スキャン」(ラダープログラム、END処理)と「ユニット間同期」の2段で表される。
- 「ユニット間同期」処理は一定間隔で3回描かれ、その間、通常スキャンのラダープログラムは中断(点線枠)されている。
- 各「ユニット間同期」処理のタイミングで、CPUユニットと拡張ユニット1・拡張ユニット2の間でデータのやり取り(矢印)が行われる。
- 拡張ユニット1・拡張ユニット2の内部周期は、ユニット間同期のタイミングに開始位置がそろえられ、両ユニットの「実行」が同じタイミングで行われる。

各拡張ユニットの内部周期を調整して内部周期の開始タイミングを調整するため、拡張ユニット間でばらつき1µs以下の同時制御、同時サンプリングができます。
開始タイミング、サンプリングタイミングの調整方法については各ユニットにより異なります。
詳細については各ユニットのユーザーズマニュアルを参照してください。

> **ポイント**
> - ユニット間同期に対応しているユニットはKV-8000/7000シリーズ用拡張ユニット（S-Unit、X-Unit）のみです。KV-5000/3000シリーズ用の拡張ユニットは対応していません。
> - ユニット間同期機能ではユニット間同期周期後に出力制御が実行されます。実行時高速で出力したい場合などはユニット間同期機能ではなく、ダイレクトリフレッシュ命令を使用してください。
> - 「CPUシステム設定」の「スキャンタイム関連の設定」でユニット間同期モジュールか、毎スキャンモジュール（待機モジュール）を同期するかを選択できます。

### ユニット間同期モジュール

(5-10 / 原本 p.546 / 5-170)

ユニット間同期モジュールはユニット間同期実行開始時に各ユニットに対して出力リフレッシュと、入力リフレッシュを実行します（設定により実施しない場合もあります）。その後ユニット間同期モジュール内のラダープログラムを実行します。
ダイレクトリフレッシュ命令を使用しない場合、ユニット間同期モジュールで変更した内容は次回のユニット間同期実行時に反映されます。
動作指令などはユニット間同期の開始タイミングを基準にタイミングをそろえて実行されます。

【図】ユニット間同期モジュールのタイミングチャート (原本 p.546)
- 「同期開始タイミング」(点線)から次の同期開始タイミング(点線)までの間隔が「ユニット間同期周期」。
- 各ユニット間同期周期の先頭で、CPUユニットは「入力リフレッシュ」→「出力リフレッシュ」→「ユニット間同期モジュール」の順に処理する。
- 信号の段(上から):
  - CPUユニット: 拡張ユニット1用 出力リレー・出力DM／リフレッシュデバイス(W)／CPUデバイス読み出し
  - CPUユニット: 拡張ユニット1用 入力リレー・入力DM／リフレッシュデバイス(R)／CPUデバイス書き込み
  - CPUユニット: 拡張ユニット2用 出力リレー・出力DM／リフレッシュデバイス(W)／CPUデバイス読み出し
  - CPUユニット: 拡張ユニット2用 入力リレー・入力DM／リフレッシュデバイス(R)／CPUデバイス書き込み
  - 拡張ユニット1: ユニット1 出力バッファ / ユニット1 入力バッファ
  - 拡張ユニット2: ユニット2 出力バッファ / ユニット2 入力バッファ
- ユニット1入力バッファ・ユニット2入力バッファは、同期開始タイミング(点線上)で値が切り換わる。
- 入力リフレッシュ区間で、ユニット1入力バッファ→CPU側「拡張ユニット1用 入力リレー・入力DM…」、ユニット2入力バッファ→CPU側「拡張ユニット2用 入力リレー・入力DM…」へ矢印が伸び、CPU側の値がその時点で切り換わる。
- 出力リフレッシュ区間で、CPU側「拡張ユニット1用 出力リレー・出力DM…」→ユニット1出力バッファ、「拡張ユニット2用 出力リレー・出力DM…」→ユニット2出力バッファへ矢印が伸び、出力バッファの値が切り換わる。
- CPU側の出力リレー・出力DM等の値は、ユニット間同期モジュール実行中(周期の途中)に変化し、その値は次の同期周期の出力リフレッシュで出力バッファへ書き込まれる。

> **ポイント**
> - 入力リフレッシュのタイミングで読み出す値は、同期開始タイミングを基準にユニット間で同じタイミングのデータを読み出しできます。読み出すタイミングはユニットごとに異なるため、拡張ユニットのマニュアルを参照してください。
> - 出力リフレッシュのタイミングで書き込んだ値（指令）は同期開始タイミングを基準に同じタイミングで実行されます。
> - ユニット間同期モジュールの入力リフレッシュ、出力リフレッシュでリフレッシュされるデータは、ユニットごとに異なります。拡張ユニットによって、リフレッシュデバイス（ユニット間同期リフレッシュ）、CPUデバイス書き込み／読み出し機能がないユニットがあります。詳細については、拡張ユニットのマニュアルを参照してください。
> - ユニット間同期機能のリフレッシュタイミングを「一括（END処理）」に設定した場合、ユニット間同期の入出力リフレッシュ時はリフレッシュされません。ただし、リフレッシュタイミングを「一括（END処理）」に設定した場合でも、リフレッシュデバイス（ユニット間同期リフレッシュ）やCPUデバイス書き込み/読み出し機能で設定したデバイスは常にユニット間同期の入出力リフレッシュ時にリフレッシュされます。

### ユニット間同期モジュールを使用しない場合の動作について

(5-10 / 原本 p.547 / 5-171)

ユニット間同期機能使用時、CPUシステム設定の「スキャンタイム関連の設定」で「毎スキャンモジュール・待機モジュールを同期する」にチェックすると、毎スキャンモジュール/待機モジュールをユニット間同期周期で実行することで、ユニット間同期モジュールを使用せずにユニット間同期が実行できます。

【画面】CPUシステム設定 (原本 p.547)
- 左ツリー: プログラムの設定(モジュール実行順設定 / 定周期実行とユーザ割り込み設定 / スキャンタイム関連の設定(選択中) / プロテクト設定 / その他の設定)、システムの設定(ローカル全体割付設定 / プログラム別デバイス設定 / CPUユニットバッファ容量設定 / デバイス記録バッファ容量設定 / 停電保持設定 / イベント/エラー設定 / デジタルトリマ上限値の設定 / アクセスウィンドウ設定 / その他の設定)
- 右「スキャンタイム関連の設定」:
  - ☑ ユニット間同期する(U) — 「拡張ユニットの動作とラダープログラム実行を同期します。対象ユニット及び周期は、ユニットエディタで設定します。」
    - ◉ ユニット間同期モジュールを同期する(M)
    - ○ 毎スキャンモジュール・待機モジュールを同期する(F)
  - ☐ 一定スキャンタイム運転を行う(R) — スキャンタイム設定値(S): 100 × 0.01ms = 1.00ms 「必ず、実測スキャンタイムよりも大きい値を設定してください。実測スキャンタイムはスキャンタイムモニタで確認できます。」
  - ☐ END処理時間の設定を有効にする(E) — END処理時間設定値(T): 100 × 0.01ms = 1.00ms 「設定を有効にすると、ラダー以外の要因によるスキャンタイムのばらつきを小さくすることができます。また、END処理時間を大きく設定することで、通信とロギングの速度を上げることができます。」
  - 右側の図: ラダー実行 / END処理 の繰り返しと「スキャンタイム設定値」「END処理時間」の範囲表示
  - ボタン: OK / キャンセル / 適用(A)

**ユニット間同期モジュールを使用する場合の動作**

「ユニット間同期モジュールを同期する」を選択している場合

【図】ユニット間同期モジュールを使用する場合のスキャン (原本 p.547)
- 凡例: 薄灰色＝ユニット間同期モジュール、濃灰色＝END処理時間。
- 「スキャンタイム」はEND処理時間(濃灰色)の終わりから次のEND処理時間の終わりまで。
- 「ユニット間同期周期」は一定間隔の点線で示され、各点線の位置からユニット間同期モジュール(薄灰色)が実行される。
- ユニット間同期モジュールはスキャンの途中(ラダー実行中)やEND処理の直後にも割り込んで実行され、スキャンタイムとユニット間同期周期は一致しない。

ユニット間同期周期ごとにユニット間同期モジュールを割り込み処理として実行します。

**ユニット間同期モジュールを使用しない場合の動作**

「毎スキャンモジュール・待機モジュールを同期する」を選択している場合

【図】ユニット間同期モジュールを使用しない場合のスキャン (原本 p.547)
- 凡例: 黒＝END処理時間。
- 「スキャンタイム」と「ユニット間同期周期」は同じ長さで、ユニット間同期周期の区切り(点線)がEND処理時間の終わりと一致する。
- 各周期内でラダー実行の後にEND処理が行われ、END処理時間の長さは周期ごとに異なって描かれている(残り時間をEND処理が埋める形)。

毎スキャンモジュール・待機モジュールがユニット間同期周期ごとに実行されます。つまり、スキャンタイム＝ユニット間同期周期としてCPUユニットのプログラム処理が実行されます。

### リフレッシュタイミングの設定（拡張ユニット用リレー・DMのみ対象）

(5-10 / 原本 p.548 / 5-172)

ユニット間同期機能使用時、拡張ユニットのユニット設定で「リフレッシュタイミング」を「一括（END処理）」に設定することで、各ユニットの入出力リレー、入出力DMに対する出力リフレッシュと入力リフレッシュを通常プログラム実行のEND処理で実行することができます。

【画面】ユニット設定「ユニット間同期機能」 (原本 p.548)
- ⊟ ユニット間同期機能
  - ユニット間同期機能: 使用する

> **ポイント**
> リフレッシュタイミングの設定が有効なデータは拡張ユニット用リレー・DMのみです。リフレッシュデバイス（ユニット間同期リフレッシュ）、CPUデバイス書き込み／読み出し機能で設定したデバイスは、常にユニット間同期の入出力リフレッシュ時にリフレッシュされます。

**リフレッシュタイミングを「ユニット間同期」に設定した場合**

拡張ユニット用リレー・DMは、ユニット間同期実行開始時にリフレッシュ（書き込み／読み出し）されます。

【図】リフレッシュタイミング「ユニット間同期」の動作 (原本 p.548)
- CPUユニット: 通常スキャン(ラダープログラム、END処理)とユニット間同期の2段。ユニット間同期は「ユニット間同期周期」間隔で3回実行され、その間通常スキャンは中断(点線)。
- 拡張ユニット1・拡張ユニット2: 内部周期。各ユニット間同期の開始位置に濃灰色の区間があり、そのタイミングでCPUユニットと拡張ユニット1・2の間の矢印(リフレッシュ)が描かれている。
- END処理のタイミングには拡張ユニットとの矢印は描かれていない。

ユニット間同期周期ごとにユニット間同期モジュールを割り込み処理として実行します。

**リフレッシュタイミングを「一括（END処理）」に設定した場合**

拡張ユニット用リレー・DMは、END処理でリフレッシュ（書き込み／読み出し）されます。

【図】リフレッシュタイミング「一括（END処理）」の動作 (原本 p.548)
- CPUユニットの通常スキャン・ユニット間同期の配置は「ユニット間同期」設定時と同じ。
- 拡張ユニット1・拡張ユニット2の内部周期には、ユニット間同期の位置に濃灰色の区間が引き続き描かれているが、CPUユニットとの矢印(リフレッシュ)はユニット間同期の位置ではなく、通常スキャンのEND処理の位置に描かれている。

> **ポイント**
> ユニット間同期実行時にリレー・DMのリフレッシュが不要な拡張ユニットの設定を「一括（END処理）」に設定することで、ユニット間同期モジュールの実行時間を短くすることができます。反面、「一括（END処理）」に設定した拡張ユニットのリレー・DMのリフレッシュ状態は、ユニット間同期モジュールの実行タイミングの状態とは一致しなくなります。

### ユニット間同期の性能仕様

(5-10 / 原本 p.552-553 / 5-176〜5-177)

ユニット間同期実行時に次のリフレッシュ時間が必要になります。
リフレッシュ時間に対して十分（5倍+75μs以上）に余裕がある周期をユニット間同期周期に設定してください。

- N：ユニット番号
- In_R[N]：ユニット番号Nの割り付け入力リレーのch数（占有ch数）
- In_DM[N]：ユニット番号Nの割り付け入力DMのワード数（占有DM数）
- Out_R[N]：ユニット番号Nの割り付け出力リレーのch数（占有ch数）
- Out_DM[N]：ユニット番号Nの割り付け出力DMのワード数（占有ch数）
- In_Buf[N]：ユニット番号Nから読み出すバッファメモリのワード数
- Out_Buf[N]：ユニット番号Nに書き込むバッファメモリのワード数
- In_CPU[N]：ユニット番号Nから読み出すCPUデバイスのワード数
- Out_CPU[N]：ユニット番号Nに書き込むCPUデバイスのワード数
- T_Ref[N]：ユニット番号Nの割り付けられたデバイスのリフレッシュ時間
- T_Buf[N]：ユニット番号Nのバッファメモリ、CPUデバイスのリフレッシュ時間
- T_Total:全ユニットの同期リフレッシュ時間

**T_Ref[N]の計算式**

```
(a)T_Ref[N] = 0
(b)T_Ref[N] = 2.5 + (0.04 × (In_R[N] + In_DM[N] + Out_R[N] + Out_DM[N]))
```

※(a) ユニット割り付けデバイスのリフレッシュタイミングをEND処理に設定している場合
　(b) ユニット割り付けデバイスのリフレッシュタイミングをユニット間同期に設定している場合

**T_Buf[N]の計算式**

```
(a)T_Buf[N] = 0
(b)T_Buf[N] = 0.04 × (In_Buf[N] + Out_Buf[N]) + 0.1 × (In_CPU[N] + Out_CPU[N])
```

※(a) バッファメモリ、CPUデバイスをリフレッシュしない場合
　(b) バッファメモリ、CPUデバイスをリフレッシュする場合

```
T_Total = T_Ref[1]+T_Buf[1]+ T_Ref[2]+T_Buf[2]+・・・
```

**KV-SAD04を2台使用時の例**

```
T_Ref[N]の計算　（リフレッシュタイミングをユニット間同期に設定）
    (1台目)T_Ref[1]＝2.5＋（0.04 × (3＋21＋3＋32)) ＝4.9μs
    (2台目)T_Ref[2]＝T_Ref[1]
T_Buf[N]の計算　（バッファメモリはリフレッシュしない）
    (1台目)T_Buf[1]＝0μs
    (2台目)T_Buf[2]＝T_Buf[1]

T_Total = 4.9＋4.9＋0＋0 = 9.8μs
```

> 補足(原文にはない): 「5倍+75μs以上」を上の例に当てはめると 9.8×5+75 = 124μs となる。

### ユニット間同期の設定手順

(5-10 / 原本 p.554-555 / 5-178〜5-179)

### ユニット間同期トレース

(5-10 / 原本 p.556-557 / 5-180〜5-181)

ユニット間同期トレースとは、ユニット間同期を実行しているKV-8000/7000シリーズ用拡張ユニット（X-Unit）の内部データと、リレー(R)やデータメモリ(DM)などのCPUユニットのデバイス値をユニット間同期周期のタイミングで同時にサンプリングし、波形でモニタする機能です。

【画面】ユニット間同期トレース[SAMPLE] - SAMPLE.rcm (原本 p.556)
- メニュー: ファイル(F) / 編集(E) / 表示(V) / 通信(C) / ヘルプ(H)。ツールバーに動作モード「CPU+ユニット」、トリガタイプ SINGLE、データ番号 0。
- 左「デバイス一覧」(No. / デバイス / 選択値 / A-B)に12行のデバイス、右に各デバイスの波形。下部にタブ「デバイス一覧」「トリガ設定」、ステータスバー「レディ」「USB」「待機中」「データ点数 38330」。
- **要確認**: デバイス一覧の各行の名称・値、波形の軸値は画面が小さく判読困難。原本 p.556 参照

> **参考**
> ユニット間同期トレースの基本的な操作方法は、リアルタイムチャートモニタと同じです。詳細は、『KV STUDIOユーザーズマニュアル』「9-6　リアルタイムチャートモニタ」を参照してください。

> **ポイント**
> ユニット間同期トレースに対応しているユニットはKV-8000/7000シリーズ用拡張ユニット（X-Unit）のみです。KV-8000/7000シリーズ用拡張ユニット（S-Unit）、KV-5000/3000シリーズ用拡張ユニットは対応していません。

**■ 起動方法**

1. メニューから【モニタ/シミュレータ(N)】>【リアルタイムチャートモニタ(H)】を選択します。
   [リアルタイムチャートモニタ]が起動します。
2. 動作モードを「CPU+ユニット」に切り換えます。
   ［ユニット間同期トレース］が起動します。

【画面】動作モード切換 (原本 p.556)
- 動作モードのプルダウン: CPU / ユニット / CPU+ユニット(選択)。右にトリガタイプ SINGLE、データ番号 0。

> **ポイント**
> - ユニット間同期トレースは、KV STUDIOから起動したリアルタイムチャートからのみ起動できます。単独起動したリアルタイムチャートモニタからは起動できません。
> - ユニット間同期トレースは、CPUユニットのユニット間同期機能の設定が「使用する」の場合のみ、使用可能です。「使用しない」に設定されている場合は、表示しません。
