## 5-3 CPUメモリ（ユーザメモリ）

(5-3 / 原本 p.403 / 5-27)

### CPUメモリ（ユーザメモリ）でできること

(5-3 / 原本 p.403 / 5-27)

内蔵されたCPUメモリ（ユーザメモリ）領域を使用して、ラダープログラムのロード/セーブやデバイス値のロギング、ラダープログラムからファイルの作成などを実現できます。

- **CPUメモリからCPUユニットへのデータ読み出し**
  CPUメモリに保存された任意の（プロジェクト）フォルダをアクセスウィンドウで選択して、データを読み出すことができます。
  データはラダープログラム、デバイス、コメント、ユニット設定情報、ロギング設定情報などのプログラムデータと、DM、EM、W、FM、ZF、CM、R、MR、LR、CRなどのデバイスファイルデータがあります。
  「プロジェクトデータの保存・読み出し」（5-35ページ）
- **自動読み出し機能**
  電源投入時に、「AutoLoad」、または「AtLoad＊＊」（＊＊ : 01～99）という名前の（プロジェクト）フォルダに格納されているデータを自動的にCPUユニットに読み出します。また「RunLoad」、または「RnLoad＊＊」（＊＊ : 01～99）という名前のフォルダに保存しておくと、PRG→RUN切換時に自動的に読み出します。
  「オートローディング機能」（5-45ページ）
- **CPUユニットからCPUメモリへのデータ保存**
  CPUユニットからCPUメモリへ、プログラムファイル（ラダープログラム、デバイス、コメント、ユニット設定情報、ロギング設定情報）と全領域のデバイスファイル（DM、EM、W、FM、ZF、CM、R、MR、LR、B、CR）を保存できます。保存されたファイルは新規に作成された（プロジェクト）フォルダに格納されます。フォルダ名は自動的につけられ、動作正常終了時にアクセスウィンドウに表示されます。
  「プロジェクトデータの保存・読み出し」（5-35ページ）
- **レシピロード・セーブ機能**
  デバイス・変数の値をデータテーブルとして複数保存しておき、データテーブルを切り換えることでCPUユニット内のデバイス・変数の値を切り換えられます。段取り替えなどの用途に活用できます。
  「レシピロード・セーブ」（5-50ページ）
- **ロギング・トレース機能**
  記録するデバイスと取り込むタイミング（トリガ）を《KV STUDIO》で登録すれば、CPUメモリにデータを自動的に格納します。CSV形式で保存されますので、Microsoft Excelなどの表計算ソフトに取り込んでそのまま使用することができます。
  「5-5 ロギング・トレース」5-57ページ
- **運転記録機能**
  保存するデータの種類と保存するタイミング（トリガ）を設定すると、トリガ発生時にCPUのデバイス値やカメラ入力ユニットの映像データを自動的にCPUメモリに保存します。保存したデータは《KV STUDIO》のリプレイ機能で再生できます。
  「5-6 運転記録機能」5-86ページ

> **ポイント**
> メモリカードを使用しても同様のことが実現できます。

> **ポイント**
> レシピロード・セーブ機能を使用する場合はCPU機能バージョンを2.0以降にバージョンアップしてください。

#### CPUメモリの活用例

(5-3 / 原本 p.404 / 5-28)

- デバイス値のロギングがメモリカードレスで実現可能。ログから集計し、資料作成が簡単になります。
  【図】(原本 p.404) 生産数表示の搬送ライン → KV-8000 に「データログの保存」→ 「KV STUDIOまたは転送ツールでログを取得。パソコンで集計や資料作成などに。」(生産集計の表とグラフ)
- 正常に動作していた時点のプログラムデータを保存しておくことで、変更後にトラブルが発生した場合でも簡単に現状復帰できます。
  【図】(原本 p.404) ラダー → 「KV STUDIOまたは転送ツールでCPUメモリに保存」→ KV-8000「正常に動作していたタイミングにまで復元可能」
- ExcelやWord、PDFなどで作成した設計資料をプログラムと一緒に保存でき、保全作業時に設計と比較して確認できます。
  【図】(原本 p.404) 「トラブルシューティング」の表・「配線図」(左側コネクタ / 右側コネクタ) → 「KV STUDIOまたは転送ツールでCPUメモリに保存」→ KV-8000「プログラムと合わせて読み出し可能」
- デバイスコメントや変数を格納する領域として活用できます。
  【図】(原本 p.404) CPUメモリ = プロジェクト領域 + ユーザメモリ。「初期設定」と「調整後」で境界位置が異なる(調整後はプロジェクト領域が大きく、ユーザメモリが小さい)。「使い方に合わせてメモリ構成と変更可能」

### CPUメモリについて

(5-3 / 原本 p.405 / 5-29)

#### 使用できるCPUメモリ領域

(5-3 / 原本 p.405 / 5-29)

プログラム領域とユーザメモリ領域を足し合わせたものがCPUメモリ領域です。

【図】CPUメモリ領域 (原本 p.405)
- KV-8000 の CPUメモリ:64MB は「プロジェクト領域」(上側)と「ユーザメモリ」(下側)で構成される
- 「領域の境界はCPUメモリ容量設定で変更可能」

各領域に格納されるデータは以下のとおりです。

| プロジェクト領域 | ユーザメモリ領域 |
|---|---|
| ユニット設定情報 | ファイルレジスタ |
| デバイス初期値設定 | ユーザドキュメント |
| CPUシステム設定 | ロギングデータ |
| 運転記録設定 | プロジェクトデータ |
| ユーザ認証設定 | その他 |
| ロギング・トレース設定 | |
| プログラム | |
| デバイスコメント | |
| 変数 | |
| ラダーモニタデータ | |

(原本の表 プロジェクト領域10項目 / ユーザメモリ領域5項目 → md 10行。左右の列は独立した列挙で、同じ行の項目どうしに対応関係はない)

ユニット設定/ユニットデータ/アクセスウィンドウ設定などは別領域です。

#### 設定方法

(5-3 / 原本 p.405 / 5-29)

KV STUDIOの【ツール】→【CPUメモリ容量設定】から領域を変更できます。

【画面】CPUメモリ容量設定 (原本 p.405)
- 容量設定(S): スライダ(左端 プロジェクト領域 / 右端 ユーザメモリ領域)、目盛り 0kB 〜 67108.864kB
- 表: 項目 / 設定値(kB) / 消費状況(kB)〔現在のプロジェクト / PLC内のプロジェクト〕
  - プロジェクト領域: 25165.824 / 367.008( 1.46%) / -
  - ユーザメモリ領域: 41943.040 / 9000.439( 21.46%) / -
- [PLC内の消費状況更新(U)] ボタン
- プログラム容量の目安: ラダー:1500kステップ / デバイスコメント:224694個
- [OK] [キャンセル]

#### CPUメモリ（ユーザメモリ）のデータを読み書きする方法

(5-3 / 原本 p.406-407 / 5-30〜5-31)

CPUメモリ（ユーザメモリ）のデータを読み書きするには次の3つの方法があります。
①ストレージ転送ツールを使用してPLC経由で読み書きを実行する
②サーバ機能を使用してPLC経由で読み書きを実行する
③KV STUDIOからPLC転送機能を使用して読み書きを実行する※
（※ユーザドキュメント、ファイルレジスタ設定のみ）

**①ストレージ転送ツールを使用してPLC経由で読み書きを実行する**

KV STUDIOのメニューの【ツール（T）】→【ストレージ転送ツール】を起動します。

CPUメモリ（ユーザメモリ）内のフォルダと、パソコン内のフォルダをバックアップまたはリストアします。

#### 使用上の注意事項

(5-3 / 原本 p.407 / 5-31)

CPUメモリを使用するうえでの一般的な注意事項を以下に記します。

> **注記**
> - 次の場合、CPUメモリに保存したデータが失われる恐れがあります。記録したデータが失われた場合は、弊社は一切その責任を負いかねます。あらかじめご了承ください。
>   - ユーザまたは第三者がCPUメモリを誤った使用方法で使用したとき
>   - CPUメモリが、静電気・電気的ノイズの影響を受けたとき
>   - CPUメモリへの保存回数が1万回を超えたとき（PLC本体エラー143：CPU累積書込回数オーバー　が発生します）

> **ポイント**
> - メモリカードアクセス中にCPUメモリへの書き込みは実行できます。
>   （メモリカードアクセス中のメモリカード書き込み、CPUメモリアクセス中のCPUメモリ書き込みは実行できません。）
> - ユーザメモリに常時書き込みを実行する場合、書き込み速度に制限がかかります。高速での読み書きが必要になる場合、RAM上にファイルを作成し、電源断の直前に書き込みを行うことで高速に書き込みができます。 「RAMモード」（5-47ページ）
> - 「隠しファイル属性」や「読み取り専用属性」がついたファイル/フォルダをユーザメモリに書き込んだ場合、これらの属性は解除されます。

**保存方法**

CPUユニットのアクセスウィンドウ上からプロジェクトデータを保存すると、プロジェクトフォルダ「KVSAVE ＊＊」（＊＊は番号 : 01～99）を自動的に作成します。番号は、CPUメモリ内のフォルダ名として存在しない最小の二桁の数字になります。

#### コントロールリレーを使用してロード/セーブする場合

(5-3 / 原本 p.414-416 / 5-38〜5-40)

##### ロード

(5-3 / 原本 p.414-415 / 5-38〜5-39)

プログラムのロードはRUNモード中は実行できません。PRGモードに切り換えて、コントロールリレーを操作してください。

**ロード時のタイムチャート**

【図】ロード時のタイムチャート (原本 p.414)
- プロジェクトロード実行要求（CR5500）: ①でON → ③でOFF → ④でON → ⑥でOFF
- プロジェクトロード実行完了（CR5504）: ②でON(成功)。④の要求OFF→ONでOFFし、⑤(失敗)で再びON
- プロジェクトロード実行失敗（CR5505）: ⑤でON
- プロジェクトロードドライブ番号（要求）（CM1880）/ プロジェクトロードフォルダ番号（要求）（CM1881）: ①の要求ONより前に値が確定
- プロジェクトロード実行完了コード（CM1884）: ②と⑤のタイミングで値が変化
- プロジェクトロードドライブ番号（完了）（CM1882）/ プロジェクトロードフォルダ番号（完了）（CM1883）: ②のタイミングでのみ値が変化(⑤では変化しない)

**プロジェクトロード成功時**

①プロジェクトロード時ドライブ番号（要求）とプロジェクトロード時フォルダ番号（要求）にロードしたいプロジェクトデータの入ったドライブ番号、フォルダ番号をセットし、プロジェクトロード実行要求リレーをONします。（モニタや、タッチパネル、通信）
②プロジェクトロードが実行完了すると、プロジェクトロード実行完了リレーが ON します。プロジェクトロードドライブ番号（完了）、プロジェクトロードフォルダ番号（完了）にはロードしたプロジェクトデータを読み出したドライブ番号とフォルダ番号が格納されます。（CPUユニット）
③プロジェクトロード実行完了リレーが ON したら、プロジェクトロード実行要求リレーを OFF します。（モニタや、タッチパネル、通信など）次回プロジェクト実行要求リレーがOFF→ONすると、プロジェクトロード実行完了リレーがOFFします。（CPUユニット）

**プロジェクトロード失敗時**

④プロジェクトロード時ドライブ番号（要求）とプロジェクトロード時フォルダ番号（要求）にロードしたいメモリカードの入ったドライブ番号、フォルダ番号をセットし、プロジェクトロード実行要求リレーをONします。（モニタや、タッチパネル、通信など）
⑤プロジェクトロードが失敗すると、プロジェクトロード実行完了リレーとプロジェクトロード実行失敗リレーが ON します。プロジェクトロードドライブ番号（完了）とプロジェクトロードフォルダ番号（完了）は更新されません。（CPUユニット）
⑥プロジェクトロード実行失敗リレーが ON したら、プロジェクトロード実行要求リレーを OFF します。（モニタや、タッチパネル、通信）次回プロジェクト実行要求リレーがOFF→ONすると、プロジェクトロード実行完了リレー、プロジェクトロード実行失敗リレーがOFFします。（CPUユニット）

**参考プログラム**

プロジェクトロードは、RUNモード中は実行できないため、参考プログラムはありません。

##### セーブ

(5-3 / 原本 p.415-416 / 5-39〜5-40)

プログラムのセーブを、ラダープログラムでコントロールリレーを制御しておこなう場合は、SET命令またはKEEP命令で実行してください。

**セーブ時のタイムチャート**

【図】セーブ時のタイムチャート (原本 p.415)
- プロジェクトセーブ実行要求（CR5502）: ①でON → ③でOFF → ④でON → ⑥でOFF
- プロジェクトセーブ実行完了（CR5506）: ②でON(成功)。④の要求OFF→ONでOFFし、⑤(失敗)の時点で再びONに描かれている
- プロジェクトセーブ実行失敗（CR5507）: ⑤でON
- プロジェクトセーブドライブ番号（要求）（CM1888）/ プロジェクトセーブフォルダ番号（要求）（CM1889）: ①の要求ONより前に値が確定
- プロジェクトセーブ実行完了コード（CM1892）: ②と⑤のタイミングで値が変化
- プロジェクトセーブドライブ番号（完了）（CM1890）/ 「プロジェクトロードフォルダ番号（完了）（CM1891）」(図中の表記のまま): ②のタイミングでのみ値が変化

※ セーブ時にフォルダ番号を指定する場合は、プロジェクトセーブ時フォルダ番号（要求）（CM1888）を使用します。

> 補足(原文にはない): 上の※はデバイス表ではプロジェクトセーブ時フォルダ番号（要求）が CM1889、ドライブ番号（要求）が CM1888 となっている。原文どおり転記した。また⑤の本文は「プロジェクトセーブ実行失敗リレーがONします」のみで実行完了リレーに触れていないが、タイムチャート上は⑤で CR5506 もONに描かれている。**要確認**: 原本 p.415-416 参照。

**プロジェクトセーブ成功時**

①プロジェクトセーブ時ドライブ番号（要求）にセーブ先のドライブ番号を格納し、プロジェクトセーブ実行要求リレーをONします。指定したフォルダに格納したい場合にはプロジェクトセーブ時フォルダ番号（要求）にフォルダ番号を格納しておきます。（ラダーやモニタ、タッチパネル、通信など）
②プロジェクトセーブが実行完了すると、プロジェクトセーブ実行完了リレーが ON します。プロジェクトセーブ時ドライブ番号（完了）にはセーブ先のドライブ番号が、プロジェクトセーブ時フォルダ番号（完了）にはセーブ先のフォルダ番号が格納されます。（CPUユニット）
③プロジェクトセーブ実行完了リレーが ON したら、プロジェクトセーブ実行要求リレーを OFF します。（ラダーやモニタ、タッチパネル、通信など）次回プロジェクト実行要求リレーがOFF→ONすると、プロジェクトセーブ実行完了リレーがOFFします。（CPUユニット）

**プロジェクトセーブ失敗時**

④プロジェクトセーブ時ドライブ番号（要求）にセーブ先のドライブ番号を格納し、プロジェクトセーブ実行要求リレーをONします。指定したフォルダに格納したい場合にはプロジェクトセーブ時フォルダ番号（要求）にフォルダ番号を格納しておきます。（ラダーやモニタ、タッチパネル、通信など）
⑤プロジェクトセーブが失敗すると、プロジェクトセーブ実行失敗リレーがONします。（CPUユニット）
⑥プロジェクトセーブ実行失敗リレーが ON したら、プロジェクトセーブ実行要求リレーを OFF します。（ラダーやモニタ、タッチパネル、通信など）次回プロジェクト実行要求リレーがOFF→ONすると、プロジェクトセーブ実行完了リレー、プロジェクトセーブ実行失敗リレーがOFFします。（CPUユニット）

**参考プログラム**

(5-3 / 原本 p.416 / 5-40)

MR200の立ち上がりでCPUメモリ（ドライブ番号：1）にプロジェクトをセーブするプログラムです。
プロジェクトセーブフォルダ番号（要求）に0を格納すると、空き番号を検索してフォルダ番号とします。
プロジェクトセーブは、SET命令を使用して実行してください。

使用デバイス

| デバイス | ラダー図のコメント | 用途 |
|---|---|---|
| MR200 | — | セーブ起動(立ち上がり) |
| CM1888 | プロジェクトセーブドライブ番号（要求） | #1 を格納(CPUメモリ) |
| CM1889 | プロジェクトセーブフォルダ番号（要求） | #0 を格納(空き番号を検索) |
| CR5502 | プロジェクトセーブ実行要求 | SET / RES |
| CR5506 | プロジェクトセーブ実行完了 | 完了で要求をRES |

| MR201 | セーブ失敗 | 失敗記憶 |

〈ニモニックリスト〉(原本のまま)

```
LDP MR200
DW #1 CM1888
CON
DW #0 CM1889
CON
SET CR5502
LD CR5506
RES CR5502
LD CR5507
SET MR201
RES CR5502
```

### オートローディング機能

(5-3 / 原本 p.421-422 / 5-45〜5-46)

電源投入時やPRG→RUN時にCPUメモリに保存されているプロジェクトデータを自動的に読み出します。
コントロールメモリ（CM）を使用して、複数のフォルダから読み出すフォルダを選択することができます。

#### 電源投入時に読み出す

(5-3 / 原本 p.421 / 5-45)

1. 《KV STUDIO》を使用して、「AutoLoad」、または「AtLoad＊＊」（＊＊ : 01～99）のフォルダ名称でプロジェクトデータを作成します。ストレージ転送ツールやFTPサーバ機能などを使用して、CPUメモリ（ユーザメモリ）にプロジェクトデータを書き込みます。
   「ラダープログラムなど（デバイスファイル以外）」（5-44ページ）
2. CPUユニットの電源をOFFします。
3. CPUユニットの電源を投入します。
   自動的にデータが読み出されます。

**読み出すフォルダの指定方法**

読み出すフォルダを指定する場合は、あらかじめCM1790に数値を格納します。
- CM1790の値が0の場合
  フォルダ名「AutoLoad」が読み出されます。
  「AutoLoad」フォルダがCPUメモリ（ユーザメモリ）に存在しない場合は、オートロードされません。電源投入前のプログラムで動作します。エラーは発生しません。
- CM1790の値が01～99の場合
  フォルダ名「AtLoad＊＊」（＊＊ : CM1790の値（01～99））が読み出されます。

フォルダ番号の指定手順
1. 電源投入している状態で、タッチパネルなどの外部機器からCM1790に数値を格納します。
2. 電源を切ります。
3. 電源を投入します。
4. CM1790で指定したフォルダが読み出されます。
5. 読み出し完了後、CM1790に0が格納され、CM1792に読み出したフォルダ番号が格納されます。

> **参考**
> オートロード完了後、CM1790に0が格納されるので、次回電源投入時、同じフォルダ番号は読み出されません。ただし、CM1790に0が格納されている状態でメモリカードに「AutoLoad」フォルダがあると、次回電源投入時に読み出されるので注意してください。

> **ポイント**
> - 《KV STUDIO》のCPUシステム設定でライトプロテクト/プロジェクトロード禁止されている場合はエラー（オートローディング失敗）が発生し、PRGモードになります。エラークリア後、RUNモードで動作するとオートロード実行前のプログラムで動作します。
>
> 以下の場合はエラー（オートロードフォルダ）が発生し、PRGモードになります。
> - CM1790の値が100以上の場合
> - CM1790で指定したフォルダがCPUメモリ（ユーザメモリ）にない場合
> - PLC本体に格納されているプロジェクトの機能バージョンと転送するプロジェクトの機能バージョンが異なる場合、CPUのオールクリア/初期化が必要になります。

### RAMモード

(5-3 / 原本 p.423-424 / 5-47〜5-48)

RAMモードとはCPUメモリにファイル保存する際に、一度RAMにファイルを作成し、完成したファイルをまとめて1回で保存することで、CPUメモリに対して、高速でファイル保存する機能です。

> **ポイント**
> - RAMモードで使用するRAMは電源をOFFするとクリアされます。
>   電源をOFFする前に、CPUメモリ保存処理を実行してください。

【図】RAMモード未使用時 (原本 p.423)
- KV-8000 から CPUメモリ(ユーザメモリ)へ直接多数の書き込み(矢印)。一部の書き込みに×印
- 「高速で書き込みを実行すると、CPUメモリの書き込み回数制限に短期間で到達するため、書き込み速度を制限」

【図】RAMモード使用時 (原本 p.423)
- KV-8000 からの多数の書き込みは RAM（揮発）に入り、RAM から CPUメモリ(ユーザメモリ)へは1本の矢印でまとめて書き込み
- 「RAM上でファイル作成するため、CPUメモリへの書き込み回数を抑えることができる」

> **ポイント**
> - ファイルレジスタ命令またはストレージ命令でCPUメモリにアクセスする場合は、命令語RAMモード動作リレー（CR3207）をONしてRAMモードに切り換えます。
> - ロギングを使用してCPUメモリにアクセスする場合はロギング/トレース設定のオプションで、「不揮発メモリへのファイル保存を行う」のチェックを外すとRAMモードで動作します。
> - CPUメモリへの書き込み超過によるメモリの劣化を防止するため、CPUメモリへの書き込み速度を制限しています。

#### 設定方法

(5-3 / 原本 p.424 / 5-48)

ラダープログラム中でCPUメモリ命令語RAMモードリレー（CR3207）をONします。
CPUメモリに書き込む際には、CPUメモリ保存処理要求リレー（CR3200）をONします。

**タイムチャート**

【図】RAMモードのタイムチャート (原本 p.424)
- CPUメモリ命令語RAMモード(CR3207): OFF → ON(ストレージ命令の実行より前) → 保存完了後にOFF
- (ストレージ命令など): CR3207 ON中に「実行中」
- CPUメモリ保存処理要求(CR3200): ストレージ命令の実行終了後にON(短いパルス)
- CPUメモリ保存処理中(CR3201): CR3200 ONを受けてON → 保存処理完了でOFF
- CPUメモリ保存処理完了(CR3202): CR3201 がONした時点でOFF(それ以前のONは破線で表示) → CR3201 がOFFした時点でON

①CPUメモリ命令語RAMモードリレー（CR3207）をONし、ストレージ命令などを実行します。（ラダー）
②ストレージ命令の実行が完了し、保存が必要になったタイミングで、CPUメモリ保存処理要求リレー（CR3200）をONします。（ラダー）
③CPUメモリの保存を開始するとCPUメモリ保存処理中リレー（CR3201）がONします。CPUメモリ保存処理完了リレー（CR3202）がONしていた場合はOFFします。（CPU）
④CPUメモリ保存処理が完了するとCPUメモリ保存処理中リレーがOFFし、CPUメモリ保存処理完了がONします。（CPU）

**ラダープログラム例**

(5-3 / 原本 p.424 / 5-48)

使用デバイス

| デバイス | ラダー図のコメント | 用途 |
|---|---|---|
| MR000 | CPUメモリRAMモード | RAMモード指令 / MPRINT実行条件 |
| MR001 | CPUメモリ書き込み | MPRINT実行(立ち上がり) |
| MR002 | CPUメモリ保存処理 | 保存要求起動(立ち上がり) |
| CR3207 | CPUメモリ命令語RAMモード | OUT |
| CR3201 | CPUメモリ保存中 | b接点(保存中でないこと) |
| CR3200 | CPUメモリ保存要求 | SET |
| MR100 | — | MPRINT命令のオペランド |

〈ニモニックリスト〉(原本のまま)

```

OUT CR3207
LD MR000
ANP MR001
MPRINT "1:¥sample.csv" "test" MR100

```

> **参考**
> - CPUメモリ命令語RAMモードリレーがON中であってもCPUメモリ保存処理要求は実行できます。
> - CPUメモリ保存要求はSET命令で実行してください。

## 5-4 レシピロード・セーブ

(5-4 / 原本 p.426 / 5-50)

### レシピロード機能/レシピセーブ機能の概要

(5-4 / 原本 p.426-427 / 5-50〜5-51)

KV-8000(A)ではデバイス・変数の値をデータテーブルとして複数保存しておき、データテーブルを切り換えることでCPUユニット内のデバイス・変数や、KV-XD02のユニット変数の値を一斉に切り換えられます。このデータテーブルのことをレシピデータといいます。
レシピロード機能を使用するとあらかじめ保存されたレシピデータを読み出して、デバイス・変数の値に反映できます。
レシピセーブ機能を使用すると、現在のデバイス・変数の値を使用して新たなレシピデータを作成できます。
レシピデータはKV STUDIO上で生成し、CPUユニットのストレージ（メモリカード/CPUメモリ）に保存します。また、CPUユニットのストレージ内のレシピデータをKV STUDIOで読み出すことも可能です。

【図】レシピロード・セーブの概念図 (原本 p.426)
- パソコン(KV STUDIO) →「レシピデータ生成」→ レシピデータ 1〜3(例: レシピデータ 1 = DM0=50 / DM1=2 / Name=“ABC“ …)
- レシピデータ →「レシピロード」→ KV-8000
- KV-8000 →「レシピセーブ」→ レシピデータ
- レシピデータ →「レシピデータ読み出し」→ パソコン(KV STUDIO)

レシピロード・セーブ機能の仕様は以下のとおりです。

| 項目 | 内容 |
|---|---|
| レシピデータの対象 | デバイス/変数 |
| レシピデータの最大個数 | 1000個（0～999） |
| レシピデータの格納先 | メモリカード/CPUメモリ |
| RUNモードでのロード・セーブ | ロード・セーブともにRUNモード時でも可能 |
| レシピロード・セーブの実行方法 | ラダープログラムからCR/CMを操作して実行 |

(原本の表 5行 → md 5行)

> **ポイント**
> - レシピロード・セーブ機能はCPU機能バージョン2.0以降のKV-8000でのみ使用できます。
> - TIMER型、COUNTER型の変数はレシピロード・セーブ機能では読み出し・保存できません。

#### レシピロード機能

(5-4 / 原本 p.426-427 / 5-50〜5-51)

レシピロード機能とは、あらかじめ作成してメモリカード/CPUメモリに保存しておいたレシピデータの内容を読み出して、CPUユニットのデバイス・変数の値をレシピ中の値で上書きする機能です。読み出すレシピは、レシピのフォルダ番号を指定して選択します。
レシピデータの内容はKV STUDIOで設定してCPUユニットに転送します。

【図】レシピロード機能 (原本 p.427)
- 「レシピデータ 1 に登録されているデバイス・変数の値を読み出し」: レシピデータ 1 (DM0=50 / DM1=2 / Name=“ABC“)
- 「CPU ユニット内の同じデバイス・変数の現在値を上書き」: CPU ユニット (DM0=50 / DM1=2 / Name=“ABC“)

#### レシピセーブ機能

(5-4 / 原本 p.427 / 5-51)

レシピセーブ機能は、参照フォルダ番号内に保存されているレシピデータに登録されているデバイス・変数を対象にして、同じデバイス・変数の値を出力フォルダ番号で指定したレシピデータとして出力する機能です。
出力したレシピデータの内容はKV STUDIOで読み出せます。

【図】レシピセーブ機能 (原本 p.427)
- 「レシピデータ 1 に登録されているデバイス・変数を参照」: レシピデータ 1 (DM0=50 / DM1=2 / Name=“ABC“)
- CPU ユニット (DM0=100 / DM1=40 / Name=“XYZ“) 「CPU ユニット内の同じデバイス・変数の現在値をレシピデータ 2 として保存」→ レシピデータ 2
- **要確認**: 図中の各値(DM0=50 / DM0=100 等)がどのボックスに属するかはテキスト抽出と画像の配置から判断した。原本 p.427 参照。

> **参考**
> 設定した全ての変数のバックアップを保存する場合は、プロジェクトセーブ機能を使用します。
> 「プロジェクトデータの保存・読み出し」（5-35ページ）

### レシピデータ生成・読み出しの手順

(5-4 / 原本 p.428-429 / 5-52〜5-53)

ここではKV STUDIO上でレシピデータを作成してCPUユニットのストレージに転送する手順と、CPUユニットのストレージに存在するレシピデータをKV STUDIO上に読み出す手順について説明します。

#### レシピデータの生成（KV STUDIO→CPUユニット）

(5-4 / 原本 p.428-429 / 5-52〜5-53)

1. KV STUDIOメニューの【モニタ/シミュレータ(N)】→【デバイス値一括変更/読出(D)】を選択します。
2. デバイス値一括変更/読出ウィンドウ上でレシピデータに含めるデバイス・変数を登録します。
   【画面】デバイス値一括変更/読出 (原本 p.428): 列 プログラム / デバイス / 現在値 / 表示形式 / コメント。登録例: ｸﾞﾛｰﾊﾞﾙ DM0, DM1, Product_A.RED, Product_A.GREEN, Product_A.BLUE(10進数16BIT)、Main Pos_X[0], Pos_X[1](FLOAT)
   - ローカル変数を入力する場合はあらかじめプログラムを指定する必要があります。
   - 構造体・配列型変数はメンバや要素まで指定してください。
3. レシピデータとして登録する値を入力します。
   【画面】(原本 p.428) 入力例: DM0=50, DM1=100, Product_A.RED=255, Product_A.GREEN=255, Product_A.BLUE=0, Pos_X[0]=+5.9, Pos_X[1]=+19.65

> **参考**
> デバイス値一括変更/読出ウィンドウメニューの【PLC(P)】→【PLCから全項目読出(R)】を選択すると、接続しているCPUユニット内のデバイス・変数の値を一括で読み出して現在値に反映できます。

4. デバイス値一括変更/読出ウィンドウメニューの【ファイル(F)】→【メモリカード保存(Z)】を選択します。
   ロード方法は「CR5508のOFF→ON（レシピロード）時にロードする」を選択します。レシピデータを作成するフォルダと、レシピデータの番号（フォルダ番号：0～999）を指定し、〔OK〕をクリックします。
   【画面】メモリカード保存 (原本 p.428): 出力先フォルダ E:¥KVRCP¥KVRCP002 / フォルダ選択(F) E:¥ [...](フォルダを選択するダイアログが表示されます。) / フォルダ番号(N) 2 [CM1871] / ロード方法(L) CR5508のOFF→ON(レシピロード)時にロードする / [OK] [キャンセル]

> **ポイント**
> - メモリカードに直接保存する場合は、メモリカード直下を指定してください。パソコンのフォルダなどメモリカード以外に保存する場合は、「KVRCP」フォルダごとメモリカード直下にコピーしてください。
> - フォルダを選択する前に、ロード方法を選択してください。
> - パソコンにデータ書き込み権限が付与されていない場合、メモリカードなどの外部メディアへの保存に失敗します。詳細は、パソコンの管理者にお問い合わせください。

5. レシピデータをストレージに格納します。
   メモリカードにレシピデータを保存した場合は、メモリカードをCPUユニットに挿入します。CPUメモリにレシピデータを保存する場合は、ストレージ転送ツールやFTPサーバ機能、FTPクライアント機能などを使用して「KVRCP」フォルダをCPUメモリ直下に転送します。

#### レシピデータの読み出し（CPUユニット→KV STUDIO）

(5-4 / 原本 p.429 / 5-53)

1. CPUユニットのストレージ内のレシピデータをパソコン上に転送します。
   メモリカードにレシピデータが保存されている場合は、メモリカードを抜き取りパソコンに挿入します。CPUメモリにレシピデータが保存されている場合は、ストレージ転送ツールやFTPサーバ機能、FTPクライアント機能などを使用して「KVRCP」フォルダ内の「KVRCP***」フォルダ（***は読み出したいレシピデータの番号）をパソコン上に転送します。
2. KV STUDIOメニューの【モニタ/シミュレータ(N)】→【デバイス値一括変更/読出(D)】を選択します。
3. デバイス値一括変更/読出ウィンドウメニューの【ファイル(F)】→【読出(R)】を選択します。
   フォルダを参照するダイアログが表示されるので、手順1でパソコンに転送した「KVRCP***」フォルダを選択します。
4. レシピデータからKV STUDIOに読み出すデバイス・変数を選択します。
   【画面】メモリカード読出デバイス選択 (原本 p.429): 「どのデバイスデータを読み出しますか？」/ ALL (全デバイス) ▼ / [OK]
   「ALL（全デバイス）」を選択すると、レシピデータ内のすべてのデバイス・変数の値を読み出せます。

### レシピロード・セーブの手順

(5-4 / 原本 p.430-431 / 5-54〜5-55)

ここでは、CPUユニットのストレージに保存されているレシピデータの内容をロードしてCPUユニットのデバイス・変数に反映させる手順と、CPUユニットのデバイス・変数の値を使用してレシピデータを上書き・新規作成する手順を説明します。

#### レシピロードの手順

(5-4 / 原本 p.430 / 5-54)

【図】レシピロードのタイムチャート (原本 p.430)
- レシピロード実行要求 (CR5508): ①でON → ③でOFF → 2回目の要求でON → ④の後にOFF
- レシピロード実行完了 (CR5510): ②でON。2回目の要求のOFF→ONでOFF → ④で再びON
- レシピロード実行失敗 (CR5511): ④でON
- レシピロード時ドライブ番号 (CM1870) / レシピロード時フォルダ番号 (CM1871): ①の要求ONの時点で値が確定
- レシピロード時完了コード (CM1873): ②で「0」に変化、④で別の値に変化

① レシピロード時ドライブ番号（0：メモリカード/1：CPUメモリ）とレシピロード時フォルダ番号にロードしたいレシピデータが保存されているドライブ番号とフォルダ番号を指定し、レシピロード実行要求をONします。
② レシピロードが正常に完了すると、レシピロード実行完了がONします。また、レシピロード時完了コードに「0」が格納されます。
③ レシピロード実行完了がONしたことを確認し、ラダープログラムからレシピロード実行要求をOFFします。レシピロード実行完了は次回のレシピロード実行要求のOFF→ON時に自動的にOFFします。
④ レシピロードに失敗すると、レシピロード実行完了とレシピデータ実行失敗がともにONします。レシピロード時完了コードには失敗した要因に応じた完了コードが格納されます。

#### レシピセーブの手順

(5-4 / 原本 p.431 / 5-55)

【図】レシピセーブのタイムチャート (原本 p.431)
- レシピセーブ実行要求 (CR5512): ①でON → ③でOFF → 2回目の要求でON → ④の後にOFF
- レシピセーブ実行完了 (CR5514): ②でON。2回目の要求のOFF→ONでOFF → ④で再びON
- レシピセーブ実行失敗 (CR5515): ④でON
- レシピセーブ時ドライブ番号 (CM1875) / レシピセーブ時参照フォルダ番号 (CM1876) / レシピセーブ時出力フォルダ番号 (CM1877): ①の要求ONの時点で値が確定
- レシピセーブ時完了コード (CM1878): ②で「0」に変化、④で別の値に変化

① レシピセーブ時ドライブ番号（0:メモリカード/1:CPUメモリ）とレシピセーブ時出力フォルダ番号でレシピデータの出力先を指定し、レシピセーブ実行要求をONします。このときにレシピデータとして出力する対象のデバイス・変数は、レシピセーブ時参照フォルダ番号で指定した番号のレシピデータに記載されているデバイス・変数になります。
② レシピセーブが正常に完了すると、レシピセーブ実行完了がONします。また、レシピセーブ時完了コードに「0」が格納されます。
③ レシピセーブ実行完了がONしたことを確認し、ラダープログラムからレシピセーブ実行要求をOFFします。レシピセーブ実行完了は次回のレシピセーブ実行要求のOFF→ON時に自動的にOFFします。
④ レシピセーブに失敗すると、レシピセーブ実行完了とレシピデータ実行失敗がともにONします。レシピセーブ時完了コードには失敗した要因に応じた完了コードが格納されます。
