## 4-1 シーケンス制御とは

(4-1 / 原本 p.100 / 4-2)

下図のような自動車の組立工程では、機械や装置の各動作、順序および条件を制御装置にあらかじめ記憶させておきます。運転を開始すると、機械や装置の状態・条件に従って一連の目的動作が順次実行され、自動車が組み立てられていきます。このような制御をシーケンス制御と呼びます。
シーケンス制御のための装置に、《KV-8000シリーズ》のようなPLC（Programable Logic Controller）が使われます。

【図】＜自動車工場の車体組立工程＞ (原本 p.100)
- コンベアライン上を車体が流れ、各所でクランプ・ハンドリング装置やシート取り付け装置などが作業するイラスト。数値・信号名の記載はなし。

> **参考**
> - JIS（日本工業規格）には、「シーケンス制御とは、あらかじめ定められた順序、または、一定の論理によって定められた順序に従って制御の各段階を逐次進めていく制御」と定義されています。
> - PLCの制御には、シーケンス制御の他にフィードバック制御があります。
>   フィードバック制御は、対象から検出した現在値と目標値を比較した結果が一致するまで制御を繰り返します。
>   （例）温度制御、圧力制御、速度制御

### シーケンス制御の例

(4-1 / 原本 p.101 / 4-3)

シーケンス制御について、全自動洗濯機を例にして具体的に見てみましょう。
全自動洗濯機はスタートボタンを押すと、あらかじめ定められた順序に従って、洗濯工程が自動的に進行していきます。この洗濯工程の制御は、次のようになります。

【図】全自動洗濯機の洗濯工程フロー (原本 p.101)

| 工程(図のブロック) | 説明(原文) |
|---|---|
| 開始（ON） | ①洗濯物を投入し、スタートボタンを押します。 |
| 給水Ⅰ | ②スタートボタンが押されたら、洗剤を投入して給水バルブを開けます。 |
| 洗濯 | ③規定の給水量（水位）へ達したことを検出したら、給水バルブを閉じて洗濯用モータを起動します。 |
| 排水Ⅰ | ④規定の時間が経過したら、洗濯用モータを止めて排水バルブを開けます。 |
| 脱水Ⅰ | ⑤排水完了（水位が0）を検出したら、排水バルブを閉じて脱水用モータを起動します。 |
| 給水Ⅱ | ⑥規定の時間が経過したことを検出したら、脱水用モータを止めて給水バルブを開けます。 |
| すすぎ | ⑦規定の給水量（水位）へ達したことを検出したら、給水バルブを閉じて洗濯用モータを起動します。 |
| 排水Ⅱ | ⑧規定の時間が経過したことを検出したら、洗濯用モータを止めて排水バルブを開けます。 |
| 脱水Ⅱ | ⑨排水完了（水位が0）を検出したら、排水バルブを閉じて脱水用モータを起動します。 |
| 完了（終了） | ⑩規定の時間が経過したことを検出したら、脱水用モータを止めます。洗濯完了を表示して、音で通知します。 |

(原本の図 10工程 → md 10行)

- 工程は 開始 → 給水Ⅰ → 洗濯 → 排水Ⅰ → 脱水Ⅰ → 給水Ⅱ → すすぎ → 排水Ⅱ → 脱水Ⅱ → 完了 の順に矢印で接続。
- 「洗濯」「脱水Ⅰ」から「蓋が開いたら」→「一時停止」（カチッ）、「一時停止」から「蓋が閉じたら」→元の工程（「洗濯」「脱水Ⅰ」）へ戻る。
- 「すすぎ」「脱水Ⅱ」から「蓋が開いたら」→「一時停止」（カチッ）、「一時停止」から「蓋が閉じたら」→元の工程（「すすぎ」「脱水Ⅱ」）へ戻る。

### シーケンス制御の種類

(4-1 / 原本 p.102 / 4-4)

基本的なシーケンス制御は、主に「順序制御」「条件制御」「時限制御」の3種類に分けられます。これらの制御を組み合わせて、目的とする制御回路を設計します。

#### 順序制御

(4-1 / 原本 p.102 / 4-4)

順序制御は、検出器など、外部からの信号によって動作終了を確認し、あらかじめ定められた順序に従って、次の動作を開始する制御です。
〔全自動洗濯機のシーケンス制御における順序制御〕
「②給水Ⅰ」→給水が完了→「③洗濯（洗濯用モータの起動）」
「④排水Ⅰ」→排水が完了→「⑤脱水Ⅰ（脱水用モータの起動）」

> **参考** 順序制御で使用する代表的なラダー命令語・・・「STG」「JMP」など

#### 条件制御

(4-1 / 原本 p.102 / 4-4)

条件制御は、制御対象の状態信号を組み合わせて、あらかじめ定められた条件が満足された時に動作させる制御です。
〔全自動洗濯機のシーケンス制御における条件制御〕
「③洗濯」→洗濯槽の蓋が開けられたら→「一時停止」→蓋が閉じられたら→「③洗濯」
「⑤脱水Ⅰ」→洗濯槽の蓋が開けられたら→「一時停止」→蓋が閉じられたら→「⑤脱水Ⅰ」

> **参考** 条件制御で使用する代表的なラダー命令語・・・「STP」「STE」「CJ」「NCJ」「LABEL」など

#### 時限制御

(4-1 / 原本 p.102 / 4-4)

時限制御は、制御対象への動作指令がタイマなどを使った時間経過や時刻によって終了し、あらかじめ定められた順序に従って、次の動作を開始する制御です。
〔全自動洗濯機のシーケンス制御における時限制御〕
「③洗濯」→規定時間の経過を検出→「④排水Ⅰ」
「⑤脱水Ⅰ」→規定時間の経過を検出→「⑥給水Ⅱ」

> **参考** 時限制御で使用する代表的なラダー命令語・・・「TMR」「LDWK」など

## 4-2 プログラミング言語

(4-2 / 原本 p.103 / 4-5)

《KV STUDIO》では、「ラダープログラム」と「ST言語」、「KVスクリプト」を使用してプログラムを作成できます。
作成したプログラムをCPUユニットで動作させるための言語として、「ニモニック」が使用されます。また、16ビット/32ビットや符号付き/符号なしなどは命令語ではなく、サフィックスを使用して使い分けます。

### ラダープログラム

(4-2 / 原本 p.103 / 4-5)

ラダー回路とは、実体配線図を図式化したもので、《KV STUDIO》で書かれたラダー回路をラダープログラムといいます。
《KV STUDIO》では、汎用のスイッチやランプの他に、ON時間、OFF時間を制御する便利な命令語や、PID制御なども命令語として用意しており、組み合わせて記述することで、シーケンス制御を簡単に記述できます。

【プログラム例1】ラダープログラムの例 (原本 p.103)

| デバイス | 図中の用途 |
|---|---|
| R000 | 入力a接点(T1の駆動条件) |
| R001 | 入力a接点 |
| R002 | 入力a接点 |
| R003 | 入力a接点 |
| T1 | タイマ(コイルボックス)、および接点 |
| T2 | タイマ(コイルボックス)、および接点 |
| R500 | 出力コイル |
| R501 | 出力コイル |

(原本の図 デバイス8種 → md 8行)

```
LD   R000
TMR  T1   K?      ; 設定値は図に記載なし(要確認)
LD   T1
AND  R001
OUT  R500
LD   T1
AND  R002
TMR  T2   K?      ; 設定値は図に記載なし(要確認)
LD   T2
AND  R003
OUT  R501
```

- **要確認**: 図中の T1 / T2 はコイルボックス(「T1」「T2」)のみで設定値の記載がない。上記の TMR 命令・設定値は図からの推定。原本 p.103 参照。

さらに、《KV STUDIO》では、拡張ラダーモードが使用でき、ラダーの行数を削減したり、処理順序を明確にしたりできるので、視認性が向上できます。
→「拡張ラダーモード」（4-258ページ）

### ST言語

(4-2 / 原本 p.104 / 4-6)

ラダープログラムは、シーケンス制御の記述に適している一方、数値を扱う複雑な演算処理や文字列を扱う処理については、記述が複雑になり、デバッグやメンテナンスも困難になりがちです。
ラダープログラムでは記述が複雑になる部分をST言語で代替記述して、効率よくプログラムを作成できます。

【プログラム例2】ST言語の画面例 (原本 p.104)

| 行番号 | デバイス/変数 | 図中の用途 |
|---|---|---|
| 00211 | bFlag1 | a接点 |
| 00211 | bFlag2 | b接点 |
| 00211 | bComp | 出力コイル |
| 00212 | uiValue / uiIdx | ST内の変数 |

(原本の図 変数5種 → md 4行。uiValue/uiIdx は同一行にまとめた)

行 00211 (ラダー):
```
LD   bFlag1
ANB  bFlag2
OUT  bComp
```

行 00212 (ST):
```
uiValue := 0 ;                    //uiValueに0を格納します。
FOR uiIdx := 0 TO 100 BY 1        //uiIdxの値が100を超えるまで繰り返す
DO
  uiValue := uiValue + uiIdx ;    //uiIdxの値をuiValueに加算します。
END_FOR ;                         //増分値を加算して、FOR～に戻ります。
```

図中の吹き出し(原文):
- ラダーと混在でき、行ごとにコメントが記述できます。
- 制御文が記述できるのでプログラムの流れがわかりやすくなります。
- 演算処理の内部レジスタを意識しなくても記述できます。

> **ポイント**
> ST言語を使用するには、CPU機能バージョン2.1以降である必要があります。

### KVスクリプト

(4-2 / 原本 p.105 / 4-7)

ラダープログラムは、シーケンス制御の記述に適している一方、数値を扱う複雑な演算処理や文字列を扱う処理については、記述が複雑になり、デバッグやメンテナンスも困難になりがちです。
KVスクリプトは、これらラダープログラムの問題点を補うために開発されたプログラミング言語です。ラダープログラムでは記述が複雑になる部分をスクリプトで代替記述して、効率よくプログラムを作成できます。

【プログラム例3】KVスクリプトの画面例 (原本 p.105)

| 行番号 | デバイス | 図中の用途 |
|---|---|---|
| 00001 | R01000 | a接点 |
| 00001 | R01001 | b接点 |
| 00001 | R02000 | 出力コイル |
| 00002 | DM100 / DM101 | スクリプト内のデバイス |

(原本の図 デバイス5種 → md 4行。DM100/DM101 は同一行にまとめた)

行 00001 (ラダー):
```
LD   R01000
ANB  R01001
OUT  R02000
```

行 00002 (KVスクリプト):
```
DM100 = 0                       'DM100に0を格納します
FOR DM101 = 0 TO 100 STEP 1     'DM101の値が100を超えるまで繰り返します
DM100 = DM101 + DM100           'DM101の値をDM100に加算します
NEXT                            '増分値を加算してFOR～に戻ります
```

図中の吹き出し(原文):
- ラダーと混在でき、スクリプトの行ごとにコメントが記述できます。
- 制御文が記述できるのでプログラムの流れがわかりやすくなります。
- 演算処理も内部レジスタを意識しなくても数学式のように記述できます。

> **参考**
> スクリプトプログラムはラダープログラムに変換されてから実行されます。
> スクリプトプログラムの動作確認などは、変換されたラダープログラムでモニタする事ができます。

→『KV-8000/7000/5000/3000/1000シリーズ・KV Nanoシリーズスクリプトプログラミングマニュアル』

### ニモニック

(4-2 / 原本 p.106 / 4-8)

ニモニックは、作成したラダープログラムをCPUユニットで動作させるための言語です。
拡張ラダーは、ニモニックをシンボル化することによって、視覚的にわかりやすく表現したものです。
拡張ラダーで作成したプログラムは、CPUユニットへの転送時にニモニックリストへ変換されます。
ニモニックリストは《KV STUDIO》上で編集できますが、通常のラダープログラム作成時に意識する必要はありません。

【プログラム例4】ニモニックリスト例 (原本 p.106、原本記載のまま)

```
LD   R000
OUT  R500
LD   R002
OUT  R501
LD   R003
OUT  R502
```

### サフィックス

(4-2 / 原本 p.107 / 4-9)

サフィックスとは命令語やデバイスの接尾語としてつくもので、使用すると、デバイスのデータ型の扱いを変更できます。以下の6種類があります。

□.U　　□.S　　□.D　　□.L　　□.F　　□.DF　　□.A

※ □にはサフィックス対応の命令語が入ります。

**例**
```
MOV.（U）
MOV.S
MOV.D
MOV.L
MOV.F
MOV.DF
MOV.A
```

| サフィックス | 扱い(原文) | 範囲(原文) |
|---|---|---|
| □.U | 16ビット符号無しBINデータとして扱います。 | （0～65535） |
| □.S | 16ビット符号付きBINデータとして扱います。 | （－32768～＋32767） |
| □.D | 32ビット符号無しBINデータとして扱います。 | （0～4294967295） |
| □.L | 32ビット符号付きBINデータとして扱います。 | （－2147483648～＋2147483647） |
| □.F | 単精度浮動小数点型実数データとして扱います。 | －3.4E＋38≦ N ≦－1.4E－45 / N ＝ 0 / ＋1.4E－45≦ N ≦＋3.4E＋38 （有効桁数 : 約7桁） |

(原本の表 7行 → md 7行)

□.Uは、《KV STUDIO》上では表示が省略されます。また、サフィックスを持たない命令は、16ビット符号無しBINデータとして扱います。

  プロジェクトパスワード設定時も、確認ダイアログは表示されません。
- 読み出しを実行する場合2
  プロジェクトパスワードを設定して[パスワード解除]ダイアログを表示できます。
- 書き込みを実行する場合
  ライトプロテクトを設定して上書き時に[確認]ダイアログを表示できます。

【画面】KV STUDIO 確認ダイアログ (原本 p.115)
- タイトル: KV STUDIO
- 文言: 「PLC本体はライトプロテクトされています。強行しますか？」
- ボタン: 〔はい(Y)〕〔いいえ(N)〕

> **参考**
> プロジェクトパスワード設定時は、パスワード認証に失敗すると、次回読み出しが可能になるまでに一定時間待つ必要があります。また待ち時間は認証失敗のたびに延長されます。パスワード認証に失敗したため、読み出し認証ができない場合、プロジェクトパスワード認証禁止状態リレー（CR2314）がONしています。
> パスワード認証に連続で失敗した回数、および累積の回数は、プロジェクトパスワード連続認証失敗回数（CM1658）とプロジェクトパスワード累積認証失敗回数（CM1659）に格納されます。プロジェクトパスワード連続認証失敗回数は、認証成功時、プログラム転送正常終了時、オールクリア/初期化実行時にクリアされ、プロジェクトパスワード累積認証失敗回数は、オールクリア/初期化実行時のみクリアされます。

#### プロジェクトのパスワード

(4-3 / 原本 p.116 / 4-18)

プロジェクトにパスワードを設定して、CPUユニットからの読み出しに制限をかけることができます。
次の手順でパスワードを設定します。

1. ［ワークスペース］を選択します。
2. 右クリックして表示されるメニューから［プロジェクトプロパティ（F）］を選択します。
   別手順 メニューから【ファイル（F）】→【プロジェクトプロパティ（F）】を選択します。
   ［プロジェクトプロパティ］ダイアログが表示されます。

   【画面】［プロジェクトプロパティ］ダイアログ (原本 p.116)
   - プロジェクト名: プレス機
   - 作成日時: 2019/04/17 09:41:45
   - 更新日時: 2019/04/17 13:40:00
   - 転送日時: 2019/04/17 13:39:26
   - 保存先: C:¥User¥Documents¥KEYENCE¥KVS10J¥KVS¥F (以降は画面で切れている)
   - コメント(C): 型式1200シリーズ / Ver.3 オプション4
   - ボタン: 〔パスワード設定(P)...〕
   - 作成者(A): ＊＊製作所
   - アクセスウィンドウ表示コメント(W): (グレーアウト)
   - ボタン: 〔OK〕

3. 〔パスワード設定〕ボタンを押します。
   ［パスワード設定］ダイアログが表示されます。

   【画面】［パスワード設定］ダイアログ (原本 p.116)
   - プレス機
   - パスワード(P): (入力欄)
   - 確認(C): (入力欄)
   - ボタン: 〔OK〕〔キャンセル〕

4. パスワードとパスワードの確認を入力して、〔OK〕ボタンを押します。
   パスワード設定後、パスワード設定したプロジェクトをCPUユニットから読み出す時、［パスワード解除］ダイアログが表示されます。
   パスワードを入力しないと、プロジェクトをCPUユニットから読み出せません。
   また、パスワードが異なるプロジェクトをPLC転送するときも、PLC内のプロジェクトを保護するため、パスワードを入力するか、全項目を転送する必要があります。

#### プロジェクトのライト/リードプロテクト

(4-3 / 原本 p.117 / 4-19)

プロジェクトにプロテクト設定をして、CPUユニット本体への書き込みや読み出しに制限をかけることができます。
プロテクト設定は、ワークスペースから【CPUシステム設定】→【プロテクト設定】を選択します。

【画面】［CPUシステム設定］— プロテクト設定 (原本 p.117)
- 左ツリー: プログラムの設定(モジュール実行順設定 / 定周期実行とユーザ割り込み設定 / スキャンタイム関連の設定 / プロテクト設定 / その他の設定)、システムの設定(ローカル全体割付設定 ― プログラム別デバイス設定 / CPUユニットバッファ容量設定 / デバイス記録バッファ容量設定 / 停電保持設定 / イベント/エラー設定 / デジタルトリマ上限値の設定 / アクセスウィンドウ設定 / その他の設定)
- 右ペイン「プロテクト設定」:
  - ライトプロテクト: KV STUDIOからのプログラム転送時に「強制的に書き込みますか？」という確認メッセージを表示します。 □PLC転送時に確認メッセージを表示する(W)
  - リードプロテクト: PLCからプログラム読出ができないように設定します。 □プログラム読出を不可にする(R)
  - プロジェクトパスワード: KV STUDIOからのプログラム読出時にパスワード入力を要求するようにPLCを設定します。 プロジェクトパスワードの設定 〔設定(S)〕
  - メモリカード: □メモリカード/CPUメモリ内のプロジェクトのロードを禁止する(M)

それぞれチェックを入れてCPUユニットに転送することで、プロテクト設定が有効になります。

> **ポイント**
> リードプロテクトをかけた状態でCPUユニットに転送すると、その後ラダープログラムの実行状態はモニタできません。
> デバッグ完了後にリードプロテクトをかけて、PLC転送を実行してください。
> パスワード設定とリードプロテクトを両方使用した場合、パスワード確認ダイアログは表示されず、プロジェクトの読み出しはできません。

> **参考**
> - プログラムパスワードについては、→「モジュールパスワード」（4-114ページ）、→「ファンクションブロックのパスワード設定」（4-141ページ）、→「マクロパスワード」（4-191ページ）を参照してください。
> - メモリカードのプロテクト設定に関しては、メモリカード/CPUメモリからのプロジェクトロードを禁止できます。ユーザ認証設定と合わせて設定しておくと、KV STUDIOからユーザ認証に成功したユーザのみプロジェクト変更することができます。
