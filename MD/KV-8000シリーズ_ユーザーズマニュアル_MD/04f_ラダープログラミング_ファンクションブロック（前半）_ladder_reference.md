## 4-10 ファンクションブロック

(4-10 / 原本 p.215 / 4-117)

### 概要

(4-10 概要 / 原本 p.215 / 4-117)

ファンクションブロックとは、プロジェクト内で繰り返し使用する回路ブロックを、一つの部品として任意の名称で登録したものです。ファンクションブロック化することにより、ラダー命令語と同じように使用できるため、プログラム入力工数が削減されます。回路変更時には、ファンクションブロックとして登録した1箇所のデータを修正するだけで、プロジェクト内で呼び出す全てのファンクションブロックの処理内容が変更されます。このことにより、プログラムの変更工数が削減され、修正ミスも防げます。

#### ■ ファンクションブロックの管理

(4-10 概要 / 原本 p.215 / 4-117)

《KV STUDIO》では、［ワークスペース］を使用してプロジェクトごとに管理します。

【図】ファンクションブロック導入前/導入後 (原本 p.215)
- ＜ファンクションブロック導入前＞: プロジェクト1 の [モジュールA] [モジュールB] それぞれに同じ処理(ファンクションブロックC 相当の回路)が書かれている。
- 同じ処理をファンクションブロックとして登録。
- ＜ファンクションブロック導入後＞: プロジェクト1 に [モジュールA] [モジュールB] [ファンクションブロックC] があり、モジュールA・B からファンクションブロックCをファンクションブロック呼び出しする。

#### ■ ファンクションブロックの特長

(4-10 概要 / 原本 p.216 / 4-118)

**● オリジナル命令語として使用できる**

プログラム内に何度も出てくる同じラダー回路をファンクションブロックとして登録すれば、以後の入力工数や入力ミスを削減できます。
結果として、見た目のラダー行数が減り、プログラム構造を把握しやすくなります。
登録するファンクションブロック名は自由に付けることができます。

**● 引数が使用できる**

引数を使用すれば、ファンクションブロック内にある命令語のオペランド（デバイスや値）をファンクションブロック呼び出し時に指定できるため、汎用性の高いファンクションブロックを作成できます。
また、引数は任意の名称を設定できるため、引数の内容がわかりやすくなり、プログラムの可読性を向上することができます。
「引数設定」（4-131ページ）

**● パスワードが設定できる**

ファンクションブロックの内容を容易に変更できなくするため、パスワードを設定できます。
パスワードを設定した場合、パスワードを知らない人はファンクションブロックのプログラムを表示、編集できません。
［プログラムプロパティ］ダイアログでパスワードを設定します。

**● 2種類のファンクションブロックが作成できる**

ファンクションブロックには、『ファンクションブロック』と『ファンクション』の2種類があります。
『ファンクションブロック』と『ファンクション』の違いは以下のとおりです。

| 項目 | 『ファンクションブロック』 | 『ファンクション』 |
|---|---|---|
| 実行条件 (「ファンクションブロックの種類」（4-120ページ）) | 実行条件がONすると、動作を実行します。動作が停止する条件は、ファンクションブロックの起動に使用した命令語によって異なります。「ファンクションブロック」（4-120ページ） | 実行条件がONしている間だけ実行します。実行条件がOFFすると動作を終了します。 |
| プログラムの実体 | インスタンスの個数分だけラダープログラムの実体を作成し、プログラム容量が増加します。「ファンクションブロックインスタンス」（4-121ページ） | 同一の領域を使用するため、プログラム容量は増えません。 |
| ローカル変数/デバイスの使用時 (「4-12 ローカルデバイス」（4-200ページ）) | インスタンスの個数分だけ別々の領域が占有されます。そのため、デバイスの使用状況を意識せずに使用できます。「ファンクションブロック」（4-120ページ） | 共通の領域が使用されます。同一スキャンで複数回実行する場合は、ファンクション内で毎回初期化を実行してください。 |
| ネスト構造 (「ファンクションブロックのネスト」（4-140ページ）) | 最大8重まで対応できます。 | 最大8重まで対応できます。（ただし、ファンクションからはファンクションブロックを呼び出しできません） |

## ファンクションブロックの種類

(4-10 ファンクションブロックの種類 / 原本 p.218 / 4-120)

ファンクションブロックには、『ファンクションブロック』と『ファンクション』があります。

### ファンクションブロック

(4-10 / 原本 p.218 / 4-120)

#### ● 概要

(4-10 / 原本 p.218 / 4-120)

ファンクションブロックは、実行条件がONの場合、ファンクションブロック内のプログラムを実行します。ファンクションブロックを実行するための命令語には3種類あり、それぞれ以下の特徴があります。

| 項目 | FBCALL ファンクションブロックコール | FBSTRT ファンクションブロックスタート | FB ファンクションブロック呼び出し |
|---|---|---|---|
| 起動方法 | ファンクションブロックの実行条件のON | (同左) | (同左) |
| 停止方法(共通) | • ファンクションブロックを実行したプログラム（モジュールやファンクションブロックなど）を停止する<br>• MC～MCR命令間で実行した場合、MC命令の実行条件をOFFする | (同左) | (同左) |
| 停止方法(命令別) | • FBCALL 命令の実行条件をOFFする | • ファンクションブロック内でFEND命令を実行する | (同左: FBSTRT と共通セル) |
| インスタンス名で指定 | ○ | ○ | － |

(原本の表 4行(停止方法は2段) → md 4行)

> **ポイント**
> - モジュールのEND～ENDH間に記載したプログラムからファンクションブロックを起動した場合、モジュールを停止してもファンクションブロックは停止しません。
> - MC～MCR命令間で実行した場合、MC命令の実行条件がOFFされると、引数タイプOUTの引数には実行結果が反映されません。
> - FBCALL/FBSTRT命令はCPU機能バージョン2.0以降のKV-8000でのみ使用できる命令です。CPU機能バージョン2.0以降のKV-8000でプログラムを作成する場合は、FBCALL/FBSTRT命令を使用してファンクションブロックを実行することを推奨します。
> - ST言語でインスタンス名を指定して実行した場合、実行条件をOFFすることで停止できます。

#### ● 使用方法

(4-10 / 原本 p.218 / 4-120)

ラダープログラムに配置して使用します。

【図】ファンクションブロックの配置 (原本 p.218)
- 実行条件: MR000 (a接点) → ファンクションブロックシンボル(ファンクションブロック A)の EN に接続、ENO から右母線へ。
- シンボル上部の「インスタンス B」= ファンクションブロックの実体を表す名前。

#### ● ファンクションブロックインスタンス

(4-10 / 原本 p.219 / 4-121)

ファンクションブロックを配置すると、ファンクションブロック型の変数が登録されます。ファンクションブロック型の変数を登録すると、実行するための実体となるインスタンスが生成されます。同じファンクションブロックに対して異なる名前で変数を登録した場合は、それぞれが異なるインスタンスを生成し、異なるメモリ領域を占有します。インスタンスを指定してファンクションブロックを実行する場合は、FBCALL/FBSTRT命令を使用します。

【図】インスタンスとメモリ領域 (原本 p.219)
- 変数設定: 変数名「インスタンス B」データ型「ファンクションブロック A」/ 変数名「インスタンス C」データ型「ファンクションブロック A」。
- それぞれメモリ領域を確保(インスタンス B の領域 / インスタンス C の領域)。
- プログラム上ではインスタンスを指定して実行: インスタンス B(ファンクションブロック A)、インスタンス C(ファンクションブロック A)がそれぞれの領域を使用。

> **ポイント**
> - インスタンスを指定できるのは、FBCALL/FBSTRT命令でファンクションブロックを実行する場合のみです。FB命令の場合は、インスタンスは指定できず、必ず呼び出した回数だけの実体が生成されます。

#### ● 停止条件

(4-10 / 原本 p.222 / 4-124)

ファンクションブロックは以下の場合に停止します。
- 読み出し元のプログラムが停止した場合
- ファンクションブロック内でFEND命令を実行した場合（FBSTRT/FB命令の場合）
- ファンクションブロックの実行条件をOFFした場合（FBCALL命令やST言語からインスタンス名で実行した場合）

【図】停止条件 (原本 p.222)
- インスタンスB(ファンクションブロックA)の実行条件 OFF、インスタンスB内で ON の接点により FEND を実行: 「FBSTRT/FB命令で実行した場合、実行条件をOFFにしてファンクションブロック内でFEND命令を実行します。」
- インスタンスD(ファンクションブロックC)の実行条件 OFF: 「FBCALL命令で実行した場合、実行条件をOFFにしてファンクションブロックを停止します。FEND命令は不要です。」

> **ポイント**
> ・FB/FBSTRT命令でファンクションブロックを実行した場合は、ファンクションブロックの実行条件をOFFにした状態でFEND命令を実行してください。ファンクションブロックの実行条件がONの状態でFEND命令を実行しても、ファンクションブロックは停止しません。
> ・FBCALL命令やST言語からインスタンス名でファンクションブロックを実行した場合は、ファンクションブロックの実行条件をOFFにしてファンクションブロックを停止してください。
> ・FBインスタンスを配列型で使用する場合、実行条件のON/OFFで実行/停止できるのは添え字で指定したインスタンスのみです。
> 添え字に定数以外を指定している場合、実行/停止前に添え字を変更すると、変更前の添え字で指定したインスタンスは実行/停止しないため、注意してください。

### ファンクション

(4-10 / 原本 p.226 / 4-128)

#### ● 概要

(4-10 / 原本 p.226 / 4-128)

ファンクションは、サブルーチンプログラムと同様に、実行条件がONの場合のみ、ファンクション内のプログラムを実行します。実行完了後、ファンクションの次のステップに進みます。実行条件がOFFの場合は、ファンクション内のプログラムを実行せずに次のステップに進みます。

#### ● 使用方法

(4-10 / 原本 p.226 / 4-128)

ラダープログラムに配置して使用します。

【図】MR0 (a接点) → ファンクションA (原本 p.226)

#### ● 動作説明

(4-10 / 原本 p.226 / 4-128)

ファンクションの動作説明を下図に示します。
モジュール1内でファンクションAを2回呼び出す例を示します。
実行条件がONの場合、モジュール1を抜けファンクションA内のラダープログラムを実行します。
実行完了後、モジュール1に戻り、ファンクションAの次のステップに進みます。
実行条件がOFFの場合、ファンクションAは実行せず、次のステップに進みます。

【図】ファンクション動作説明 (原本 p.226)
- モジュール1 内で ON → ファンクションA 実行後に次の回路へ戻る。2回目の ON → 同じファンクションA を実行後に次の回路へ戻る。3回目は OFF → 実行しない(×)で次の回路へ。
- 吹き出し: 「呼び出される回数によらず、ファンクションは1つの同じ実体（ファンクションA）を生成します。呼び出される場所が異なる場合でも、ファンクション内で使用されるローカル変数・ローカルデバイスは、毎回同じデバイスとして動作します。」

> **ポイント**
> - ファンクション内で使用するローカル変数・ローカルデバイスは共通です。同一スキャン内に複数回実行する場合や、割り込みプログラムでファンクションを実行する場合は、注意してください。
> - ファンクション内で使用されるローカルデバイスの値は、モニタ時には同一スキャン内で最終に実行された結果を表示します。
> - ファンクションはインスタンスを生成しません。

#### ● ファンクションの戻り値

(4-10 / 原本 p.228 / 4-130)

ファンクションの戻り値とは、ファンクション内部のプログラムで使用できる、ファンクション名と同じ名前を持つ引数です。戻り値の値はファンクション外部のプログラムから参照できます。スクリプトではFUN関数を使用することで、ファンクションの戻り値を直接扱えるため、ファンクション内部の演算結果を格納するための引数を設定する必要がありません。

以下は、Function1の戻り値をDM100に格納するためのST、KVスクリプトです。

```
ST記述　　　　DM100 := Function1(DM0、DM1);
スクリプト記述　DM100 = FUN("Function1", DM0, DM1)
```

※ DM0、DM1はFunction1の引数です。

例えばFunction1の内部のプログラムが第1引数を底辺、第2引数を高さとする三角形の面積を求めるプログラムであれば、上記のように記述することでDM100に三角形の面積の演算結果が格納されます。

(4-10 引数設定 / 原本 p.229-232 / 4-131〜4-134)

### ■ 引数とは

(原本 p.229 / 4-131)

引数とは、ファンクションブロック実行時にファンクションブロックの実体に対して引き渡すデバイスや値です。ファンクションブロックの入出力、もしくはファンクションブロック呼び出し命令（FBCALL、FBSTRT、FB, FUN）のオペランドとして指定します。ファンクションブロックでは引数に対してデバイスや値が引き渡され、ファンクションブロック内のラダープログラムでは、引数名を使用してプログラムを作成します（下記の例では、引数1、引数2、引数3が引数名）。引数はファンクションブロックが実行中であれば毎スキャン更新されます。
引数を引き渡す際に使用するラベルは、そのファンクションブロック内でのみ使用できます。

【図】引数の引き渡し (原本 p.229)
- モジュール1: インスタンスB(ファンクションブロックA)、EN に実行条件、引数1 ← R001、引数2 ← #50、引数3 → DM0、ENO。
- 呼び出されたインスタンスB 内部: `引数1` 接点 → `MOV 引数2 引数3`。これは `R001` 接点 → `MOV #50 DM0` として動作する。
- 吹き出し: 「ファンクションブロック呼び出し時に指定したデバイスや値を、引数に引き渡して、ファンクションブロック内のラダープログラム内で引数を使用して実行します。」

FB内部の書き起こし(図の例):

| 引数名 | 引き渡すデバイス/値 |
|---|---|
| 引数1 | R001 |
| 引数2 | #50 |
| 引数3 | DM0 |

```
LD   引数1
MOV  引数2 引数3
```

#### ● 引数名

(原本 p.230 / 4-132)

- 引数タイプ：IN、OUT、IN-OUTの場合
  引数の名称を最大128文字（半角全角区別なし）で設定します。
  設定した引数名は、ファンクションブロック内でローカル変数と同様に使用できます。
  「付-9 使用できない文字一覧」（付-40ページ）
- 引数タイプ：ユニットの場合
  UR*、UM*、UV*の引数が固定で割り当てられます。*は、引数設定の上から順に0からの数字です。

#### ● 引数タイプ

(原本 p.230 / 4-132)

引数には、IN、OUT、IN-OUT、ユニットの4つのタイプがあります。各タイプの仕様を下表に示します。
引数は、合計で最大64個まで設定できます。また、各タイプには、IN、OUT、IN-OUTはそれぞれ32個まで、ユニットは8個まで設定できます。

| 引数名 | 引数タイプ | 説明 | 表示位置※1 | 間接指定（＊） | インデックス修飾（ : ） |
|---|---|---|---|---|---|
| 任意の引数名 | IN ※1 | ファンクションブロック実行開始時、指定したデバイスまたは定数の値を引数に格納します。 | 左 | × | × |
| 任意の引数名 | OUT ※1 | ファンクションブロック実行完了時、引数の値を指定したデバイスに格納します。 | 右 | × | × |
| 任意の引数名 | IN-OUT | ファンクションブロック実行開始時、指定したデバイスへの参照を引数に格納します。ファンクションブロック実行中に引数に対して行う処理は、都度指定したデバイスへ反映されます。 | 左右※1 | × | ○※3 |
| UR: UR0～UR7 | ユニット※2 / 先頭R | ファンクションブロック実行開始時、指定したユニットに割り付けられた先頭リレー（R）への参照を引数に格納します。ファンクションブロック実行中に引数に対して行う処理は、都度指定したデバイスへ反映されます。 | 左 | × | ○ |
| UM: UM0～UM7 | ユニット※2 / 先頭DM | ファンクションブロック実行開始時、指定したユニットに割り付けられた先頭データメモリ（DM）への参照を引数に格納します。ファンクションブロック実行中に引数に対して行う処理は、都度指定したデバイスへ反映されます。 | 左(同上) | × | ○ |
| UV: UV0～UV7 | ユニット※2 / 番号 | ファンクションブロック実行開始時、指定したユニットの番号を引数に格納します。 | 左(同上) | × | × |

(原本の表 6行 → md 6行)

※1 引数タイプにより、ファンクションブロックのシンボル上で表示される位置が異なります。
引数タイプIN-OUTの場合、左右の2箇所に同じ入出力デバイスが表示され、どちらからでも編集できます。
※2 ファンクションブロックの入出力には、対象となるユニット番号のみ指定します。
1つのファンクションブロックで引数として指定できるユニットは、最大8台です。
※3 データ型が配列・構造体の場合はインデックス修飾できません。

> **参考**
> 可変長の文字列および配列を引数として使用する場合は、引数タイプをIN-OUTに設定してください。

#### ● データ型/ユニット種類

(原本 p.231 / 4-133)

引数のデータ型を設定します。設定できるデータ型は引数タイプにより異なります。

- 引数タイプ：IN、OUT、IN-OUTの場合
  引数のデータ型を設定します。設定できるデータ型は引数タイプにより異なります。

| 引数タイプ | BOOL (ビット) | UINT (1ワード符号なし整数) | INT (1ワード符号あり整数) | UDINT (2ワード符号なし整数) | DINT (2ワード符号あり整数) | REAL (単精度浮動小数点型) | LREAL (倍精度浮動小数点型) | STRING (文字列) | 配列 | 構造体 |
|---|---|---|---|---|---|---|---|---|---|---|
| IN | ○ | ○ | ○ | ○ | ○ | ○ | ○ | ○※1 | ○※1 | ○ |
| OUT | ○ | ○ | ○ | ○ | ○ | ○ | ○ | ○※1 | ○※1 | ○ |
| IN-OUT | ○ | ○ | ○ | ○ | ○ | ○ | ○ | ○※1 | ○※1 | ○ |

(原本の表 3行 → md 3行)

※1 IN/OUT に設定した場合はあらかじめ最大文字数、要素数を設定します。IN-OUT に設定した場合は最大文字数、要素数を可変に設定できます。ただし、IN-OUTに設定したSTRING型配列は、要素数は可変に設定できますが、最大文字数は可変に設定できません。

文字数や配列の要素数が大きい引数については、IN/OUTに設定するとコピー処理に時間がかかるため、IN-OUTに設定して使用することを推奨します。

- 引数タイプ：ユニットの場合
  ユニットの種類を設定します。ユニットエディタで配置されているユニットから設定できます。

#### ● 初期値

(原本 p.231 / 4-133)

引数のタイプがIN、OUTの場合、初期値を設定できます。引数タイプがIN-OUTの場合、初期値の設定はできません。
初期値を設定した場合、引数の値を省略した場合に、初期値を使用してファンクションブロックを実行します。

> **ポイント**
> - CPU機能バージョン2.0以降のKV-8000では以下の場合にも引数が初期化されます。
>   - 保持設定を行っている引数は、ファンクションブロック定義を変更してプログラムを転送したとき
>   - 保持設定を行っていない引数は、PROGRAMモード→RUNモードに切り換えたとき
>     ただし、FB命令で実行しているファンクションブロックの引数は、保持設定を行っている場合でもPROGRAMモード→RUNモード切り換え時に初期化されます。
>
>   ファンクションブロックの起動、および停止時には初期化されません。
> - CPU機能バージョン1.0のKV-8000ではファンクションブロックの起動、および停止時にも引数が初期化されます。

#### ● 保持

(原本 p.231 / 4-133)

引数タイプがIN、またはOUTの場合は保持設定を行えます。
「保持」にチェックを入れた場合、引数の値が電源断時も保持されるようになります。

> **ポイント**
> - インスタンス名を指定しないFB命令を使用した場合は値が保持されません。保持が必要な場合は、FBCALL命令またはFBSTRT命令を使用してインスタンス名を指定して実行するようにしてください。
> - 引数の保持設定を行う場合はVer.11.0以降のKV STUDIOを使用してKV-8000のCPU機能バージョンを2.0以降にアップデートしてください。

#### ● 非公開

(原本 p.232 / 4-134)

以下の条件を満たす引数は、非公開に設定できます。
- 引数タイプがIN
- 初期値が設定されている
- 非公開に設定しない引数は、すべて非公開に設定した引数よりも小さいNo.に並べられている
  （非公開に設定した引数は、No.がもっとも大きい引数に自動的に変更されます。）

非公開に設定した引数は、ファンクションブロックのシンボルに表示されません。代わりに[オペランド変更]ダイアログの詳細表示で表示・編集します。また、パスワードを設定して表示・編集を制限することもできます。

#### ● コメント

(原本 p.232 / 4-134)

引数の名称の下に表示する説明用のコメントを必要に応じて設定できます。

> **ポイント**
> - ファンクションブロック名称の下のコメント欄はプログラムプロパティで設定してください。
> - CPU機能バージョン2.0未満の場合、引数一つにつき以下のサイズのローカルワークを使用します。
>   - 引数タイプがIN、OUTの場合
>     表示形式がLREAL（倍精度浮動小数点型）の場合は4ワード、それ以外は2ワード
>   - 引数タイプがIN-OUTの場合は2ワード
>   - 引数タイプがユニットの場合は6ワード
> - CPU機能バージョン2.0以降の場合、引数一つにつき以下のサイズのローカルワークを使用します。
>   - 引数タイプがIN、OUTの場合
>     データ型が構造体、配列、文字列の場合はデータサイズを偶数ワードに切り上げたサイズ、LREAL型は4ワード、それ以外のデータ型は2ワード
>   - 引数タイプがIN-OUTの場合は4ワード
>   - 引数タイプがユニットの場合は6ワード
> - 同じ『ファンクション』をメインルーチンプログラムと割り込みプログラムで同時に実行した場合、割り込みプログラム実行時に引数の値は退避・復帰されます。
> - 退避・復帰する引数が使用するローカルワークのワード数の合計が6912ワードを超えると演算エラー[ラダースタックオーバーフロー]が発生します。
> - ファンクションブロックの引数設定と、引数に指定した変数のデータ型が異なる場合、引数設定により以下の挙動を示します。
>   - IN引数、OUT引数
>     構造体、配列（要素数指定）：データ型・要素数が異なる場合は変換エラー
>     文字列（最大文字数指定） ：データ型が異なる場合は変換エラー
>     その他のデータ型 ：データ型が異なる場合は変換時に警告
>   - IN-OUT引数
>     構造体、配列（要素数指定）：データ型もしくは要素数が異なる場合は変換エラー
>     配列（要素数可変） ：データ型が異なる場合は変換エラー
>     文字列（最大文字数指定） ：データ型もしくは最大文字数が異なる場合は変換エラー
>     その他のデータ型 ：データ型が異なる場合は変換時に警告
> - IN、OUTに設定した引数は、ワーク領域にコピーされます。そのため、引数のサイズが大きい場合は、コピーの時間が発生せずワーク領域の消費が少ないIN-OUT引数に設定することを推奨します。

ファンクションブロックB 内部(図中の引数 → 実デバイス対応を併記):

```
LD   UR0            ; → R30000
AND  入出力3         ; → MR000
MPS
ANB  UR0:#1         ; → R30001 (b接点)
MOV  入力1 UM0:#3    ; #1000 → DM10003
MPP
AND  UR0:#2         ; → R30002
MOV  UM0:#4 出力2    ; DM10004 → 出力2 (→ DM0)
RES  入出力3         ; → MR000
END
ENDH
```

> 補足(原文にはない): 図では UR0・入出力3 の直列の後で分岐し、上段 UR0:#1(b接点)→MOV、下段 UR0:#2(a接点)→MOV と RES の並列出力になっている。MPS/MPP による分岐表現は本md作成時の書き起こし。

> **参考**
> ユニットデバイスUR0/UM0を使用するときは、間接参照を使用してデバイス番号を指定します。
> 例）ユニットの先頭リレー番号がR30000のときにR36604を指定する場合
> R36604 = R30000 + 66ch (=66 × 16 = 1056) + 4
> = R30000 + 1060
> = UR0:#1060

## 引数の省略設定

(4-10 引数の省略設定 / 原本 p.236 / 4-138)

ファンクションブロックでは、使用するパラメータの値や出力するデバイスを設定せずに、実行することができます。詳細な設定が用意できるようにファンクションブロックを作成し、簡易的に使用する場合は代表的な値を使用するなどの使い方ができます。

引数タイプがINもしくはOUTの引数は、入出力デバイスの指定を省略してファンクションブロックを使用できます。

> **ポイント**
> - CPU機能バージョン1.0のKV-8000では、引数タイプがINの場合は初期値を設定している場合のみ省略できます。
> - CPU機能バージョン1.0のKV-8000では、省略しないすべての引数が省略する引数よりも小さいNo.に並べられている必要があります（途中のNo.の引数は省略できません）。

引数タイプがINの引数を省略した場合、ファンクションブロック実行開始時に初期値が設定されている場合は設定した初期値が、初期値が設定されていない場合は0が自動的に格納されます。
「初期値」（4-133ページ）
引数タイプがOUTの引数を省略した場合、ファンクションブロック実行完了時、その引数の値は出力されません。

| UR/UM/UV0 | ユニット | --- | | □ | □ |
| Input1 | IN | UINT | | □ | □ |
| Input2 | IN | UINT | #100 | □ | □ |
| Output1 | OUT | UINT | | □ | □ |
| InOut1 | IN-OUT | UINT | | □ | □ |

【図】FBInstance1 (NewProgram) のシンボル (原本 p.236)
- EN / ENO、UnitNo ← #0、Input1 ← (空欄)「初期値が設定されていないため、#0が格納されます。」、Input2 ← #100「初期値（#100）が格納されます。」、InOut1 ← DM100(左右)、Output1 → (空欄)「OUT引数の場合、何も格納されません。」


> - 「???」で引数を省略する場合、?はすべて半角文字で間にスペースなどを入れずに入力してください。

## ファンクションブロックのネスト

(4-10 ファンクションブロックのネスト / 原本 p.238 / 4-140)

ファンクションブロックから、別のファンクションブロックを呼び出すことができます。（ファンクションブロックのネスト）
以下のように、ネストできるファンクションブロックは、プログラムの種類（『ファンクションブロック』/『ファンクション』）により異なります。

| 呼び出し元プログラム種類 | 呼び出し可能: ファンクションブロック | 呼び出し可能: ファンクション |
|---|---|---|
| ファンクションブロック | ○ | ○ |
| ファンクション | × | ○ |

(原本の表 2行 → md 2行)

最大8段までネストできます。

【図】ネスト (原本 p.238): モジュール1 → 呼び出し → ファンクションブロック1 → 呼び出し → ファンクションブロック2 → 呼び出し → ファンクションブロック3 … (最大8段)

> **ポイント**
> - 呼び出し元のファンクションブロックと同じファンクションブロックをネストすることはできません。
> - プログラムの種類が『ファンクションブロック』の場合、インスタンスごとに別々の実体を生成します。
> ネストを使用する場合はプログラム・ローカルデバイスの容量に注意してください。
> プログラムの種類が『ファンクション』の場合、呼び出される回数によらず、生成する実体は1つになるため、ネストを使用してもプログラム・ローカルデバイスの容量は増加しません。
> 「ファンクションブロックの種類」（4-120ページ）
> - 8段以上ネストしたプログラムは《KV STUDIO》の変換時に変換エラーが発生します。
> - 照合不一致状態でプログラムを転送し、実行時にネストが8段以上になった場合、CPUエラーE33「プログラムネスト制限オーバー」が発生し、運転を停止します。

## ファンクションブロックのシステムデバイス

(4-10 ファンクションブロックのシステムデバイス / 原本 p.241 / 4-143)

ファンクションブロックシステムデバイスとは、ファンクションブロックの動作状況を取得するためのデバイスです。

### ■ ファンクションブロック実行開始時1スキャンのみONビット「＠CR2008」

(4-10 / 原本 p.241 / 4-143)

ファンクションブロックが実行を開始した1スキャン目のみONになります。
2スキャン目以降はOFFになります。
自ファンクションブロック内のみ参照可能です。ファンクションブロックを呼び出しているプログラム内では参照できません。
《KV STUDIO》上での表記は、「＠CR2008」となります。

### ■ ファンクションブロック実行開始時1スキャンのみOFFビット「＠CR2007」

(4-10 / 原本 p.241 / 4-143)

ファンクションブロックが実行を開始した1スキャン目のみOFFになります。
2スキャン目以降はONになります。
自ファンクションブロック内のみ参照可能です。ファンクションブロックを呼び出しているプログラム内では参照できません。
《KV STUDIO》上での表記は、「＠CR2007」となります。

> **ポイント**
> ファンクションブロックシステムデバイスには、デバイスコメントを付けられません。

> **参考**
> ファンクションブロックシステムデバイスは、《KV STUDIO》によってCPUユニットの内部ワーク領域へ自動的に割り付けられます。

> **ポイント**
> ファンクションブロック内では、@CR2008などのシステムデバイスが使用できますが、ファンクション内では使用できません。
