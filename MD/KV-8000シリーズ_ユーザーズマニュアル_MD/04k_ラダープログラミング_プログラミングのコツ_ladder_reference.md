**動作内容の検討**

動作フロー、仕様書、タイムチャート、回路図などを記述することによって動作内容を検討します。

【図】動作内容の検討の例 (原本 p.334)
- 動作フロー:
  1. 押しボタンスイッチ PB1:ON / 押しボタンスイッチ PB2:OFF → パイロットランプ（PL）点灯
  2. 押しボタンスイッチ PB1:OFF / 押しボタンスイッチ PB2:OFF → PB1がOFFしてもパイロットランプ（PL）点灯状態を保持する
  3. 押しボタンスイッチ PB1:OFF / 押しボタンスイッチ PB2:ON → PB2をONするときパイロットランプ（PL）消灯
- 回路図: PB1はa接点のスイッチ、PB2はb接点のスイッチ。PB1・PB2・リレーRL・パイロットランプPLで構成(RLの接点による自己保持回路)。**要確認**: 配線の詳細な接続は原本 p.334 参照
- タイムチャート: PB1接点 / PB2接点 / PL の ON/OFF。PB1接点が最初にONするとPLがONし、PB1接点がON/OFFを繰り返してもPLはONを保持。PB2接点がONするとPLがOFF。その後PB1接点が再びONするとPLが再びON

### プログラム作成を支援する

(4-15 / 原本 p.336 / 4-238)

ラダープログラムを作成する上で、入力・修正工数を削減できる便利な機能を紹介します。

#### ニモニック入力

(4-15 / 原本 p.336-337 / 4-238〜4-239)

ニモニック入力はマウス操作なしで命令語を入力できるため、[命令語パレット]を利用するよりも短い時間でプログラムを作成できます。

**■ 入力方法**

命令語の先頭文字をキーボードで入力します。

（例） MOV命令を入力する場合

【図】MOV命令のニモニック入力手順 (原本 p.336)
1. 入力するセルにカーソルを合わせてキーボードの[M]キーを押します。(R1000 のa接点の右のセルを選択)
2. [ニモニック直接入力]ダイアログが表示されるので、続けて入力します。(ダイアログ: 直接入力「mov #1000 DM100」/ コメント / 〔上書き(O)〕〔挿入(I)〕〔キャンセル(C)〕、ツールチップ「転送先デバイス (2/2)」)
3. [Enter]キーを押すと、[ラダー編集]ウィンドウ上にラダーシンボルが表示されます。

入力結果のニモニック:
```
LD   R1000
MOV  #1000 DM100
END
```

> **参考**
> [ニモニック直接入力]ダイアログは、【ツール】→【オプション】の[編集・キーの設定]で「直接入力ダイアログの縮小表示」をチェックすると縮小表示されます。

各命令語の詳細については、『KV-8000/7000/5000/3000/1000シリーズ・KV Nanoシリーズ命令語リファレンスマニュアル』を参照してください。

> **参考** (原本 p.337)
> - 入力する命令語やオペランドに指定する対象デバイスや値を、短縮して入力できます。
>   （例） A 0 → LD R000
>   「付-6 ニモニック短縮入力一覧」（付-23ページ）
> - 既に入力済みのセルを［ニモニック直接入力］ダイアログで編集する時は、[Esc]キーもしくは[F2]キーを押します。（【ツール】→【オプション】の[編集・キーの設定]で「直接入力ダイアログをEnterキーで起動」をチェックすると、[Enter]キーを[ニモニック直接入力]ダイアログに割り当てられます。）

**■ 入力アシスト**

ニモニック入力には、命令語の入力をアシストする機能がいくつかあります。

**● 命令語の一覧表示**

命令語の頭文字を入力すると、入力した頭文字を先頭にした［命令語候補］ダイアログが表示され、命令語を選択できます。

【図】入力した頭文字を先頭にした［命令語候補］ダイアログ (原本 p.337) — 直接入力に「m」を入力した例。候補一覧:

| 命令語 | 表示名 |
|---|---|
| MAX | 最大値検索 |
| MC | マスターコントロール |
| MCALL | マクロコール |
| MCMP | 多段コンパレータ |
| MCR | マスターコントロールリセット |
| MDSTOP | モジュールストップ |
| MDSTRT | モジュールスタート |
| MEF | メフ |
| MEND | マクロエンド |
| MEP | メップ |
| MIN | 最小値検索 |
| MOV | 転送 |
| MPX | マルチプレクス |

(原本の表(画面内一覧) 13行 → md 13行)

**● 命令語のオペランド簡易説明表示**

現在入力中のオペランドの簡単な説明と、何番目のオペランドかが表示されます。

【図】オペランド簡易説明表示 (原本 p.337)
- 第1オペランド入力中: 直接入力「MOV #1000」、ツールチップ「転送元データ (1/2)」
- 第2オペランド入力中: 直接入力「MOV #1000 DM00100」、ツールチップ「転送先デバイス (2/2)」

**● 未使用デバイスの簡易検索**

デバイス種別または番号の途中まで入力した後に「?」と入力すると、未使用デバイスが一覧表示されます。

【図】未使用デバイスの簡易検索 (原本 p.337) — 直接入力「MOV #1000 DM?」で一覧に DM1, DM3, DM4, DM6, DM7, DM8, DM9, DM10 が表示される例

#### ショートカットキー

(4-15 / 原本 p.338-341 / 4-240〜4-243)

ショートカットキーを使用すると、マウスを使わずにキーボードだけで操作できます。また、キーボードの打鍵数が減るため、入力工数の削減につながります。
代表的なショートカットキーを説明します。
- 「付-7 ショートカットキー一覧」（付-25ページ）

**■ 入力・編集**

| キー | 機能 |
|---|---|
| [Esc] / [F2] | [ニモニック直接入力]ダイアログが表示され、ニモニックでの直接入力・編集ができます。「ニモニック入力」（4-238ページ） |
| [Enter] | ＜エディタモードで空白のセルを選択している場合＞［ニモニック直接入力］ダイアログが表示され、ニモニックでの直接入力・編集ができます。＜エディタモードで入力済みのセルを選択している場合＞［オペランド編集］ダイアログが表示されます。＜モニタモード、シミュレータモードの場合＞［検索/置換］ダイアログボックスが表示されます。 |

**■ 各ブロックの説明** (原本 p.345)

**● デバイスブロック** (表示例: 「異常停止クリア」 / 「R008」)

ラダーブロック図で使用されているデバイスを表示します。[リレーションマッピング]ウィンドウ左上の〔表示切替〕ボタンをクリックするか、[Ctrl]＋[G]を押すことでデバイスコメント表示とデバイス表示を切り換えます。

**● ラダーブロック** (表示例: 「Main 42行」)

検索したデバイスが使用されているモジュール名と行番号を表示します。選択すると、選択ラダー表示ウィンドウに対象となるラダープログラムを表示します。

> **ポイント**
> 選択ラダー編集ウィンドウ上ではラダープログラムの編集はできません。対象のラダープログラムを編集する場合は、選択ラダー編集ウィンドウ上で右クリックし、【ジャンプ】を選択し、元のラダープログラムを編集します。
> スクリプトの展開はできません。

**● フローブロック** (表示例: 「[3]フロー」)

検索したデバイスがユニットプログラム（フロー）で使用されている場合に、対象ユニットのユニット番号を表示します。

**● 設定ブロック** (表示例: 「[3]PLCリンク」)

検索したデバイスが使用されているユニット設定の名称とユニット番号を表示します。設定ブロックに表示されるユニット設定は以下のとおりです。
- PLCリンク
- PROTOCOL STUDIO
- 産業用イーサネット（EtherNet/IP（アダプタ）、PROFINET、CC-Link IE Field、EtherCAT）
- 簡易PLCリンク
- FLリフレッシュ設定
- シリアルPLCリンク
- デバイス初期値設定
- ユニット間同期リフレッシュ

**● デバイス値変更ブロック** (表示例: 「[0]デバイス値変更」)

検索したデバイスがタッチパネルやアクセスウィンドウからデバイス値を変更された場合に表示します。

> **ポイント**
> デバイス値変更ブロックはモニタ/オンラインエディット/リプレイモードの場合のみ表示します。

#### KVスクリプト

(4-15 / 原本 p.354 / 4-256)

【図】ラダープログラム → KVスクリプト (原本 p.354)

ラダープログラム(行00001〜00008):
```
LD   MR1000
ANB  MR1001
OUT  MR2000
LD   CR2002
LDA  #0
STA  DM1000
FOR  #100
LD   CR2002
LDA  DM101
ADD  DM100
STA  DM100
INC  DM101
NEXT
END
ENDH
```
- ラダーでは複数行に渡って記述され、プログラムの流れがわかりにくい。加減算や乗除算といった簡単な演算も専用の命令語を使わなければならず、回路ブロック単位のコメントではわかりにくい。
- **要確認**: 図中の行00002の STA 先は「DM1000」と読める(KVスクリプト側は DM100 = 0)。原本 p.354 参照
- 行00004〜00005 は CR2002 から LDA/ADD/STA と INC DM101 の2分岐(図の縦線)。

KVスクリプト(行00001: ラダー、行00002: スクリプト):
```
LD   MR1000
ANB  MR1001
OUT  MR2000
```
```
DM100 = 0                          'DM100に0を格納します
FOR DM101 = 0 TO 100 STEP 1        'DM101の値が100を超えるまで繰り返します
DM100 = DM101 + DM100              'DM101の値をDM100に加算します
NEXT                               '増分値を加算してFOR～に戻ります
```
- 制御文が記述できるのでプログラムの流れがわかりやすくなります。
- 演算処理も内部レジスタを意識しなくても数学式のように記述できます。
- ラダーと混在でき、スクリプトの行ごとにコメントが記述できます。

**■ 拡張ラダーモード** (原本 p.356)

通常のラダー表記の場合、OUT、TMR命令などの出力命令は、ラダー1行に1つしか配置できません。拡張ラダーを使用すると、1行に複数の出力命令を配置できますので、プログラムの行数削減、処理順序の明確化が可能です。

《KV STUDIO》では、拡張ラダーで入力する状態（拡張ラダーモード）と通常ラダーで入力する状態（通常ラダーモード）を切り換えられます。
次の手順で、モードを切り換えます。

1. メニューから【編集（E）】→【拡張ラダーモード（G）】を選択します。
   - 別手順: [拡張ラダーモード]アイコンをクリック

> **参考**
> - 拡張ラダーモードが有効になっている時は、メニューの【拡張ラダーモード（G）】にチェックが表示され、枠付きのアイコンが表示されます。
> - 拡張ラダーモードを選択すると、出力命令を入力する時に、カーソルが自動的に右端に移動せずに続けて命令語が入力できます。拡張ラダーモードでない場合は、出力命令を入力すると、カーソルが自動的に右端に移動します。
> - デフォルトは拡張ラダーモードOFFです。

**■ 変換できないラダー** (原本 p.357)

変換エラーになる代表的なパターンを以下に示します。

**● 母線または出力線に接続されていない**

すべての接点やコイルは、母線から出力線に至る経路上にあるようにし、未接続がないようにしてください。

【図】(原本 p.357)
- 母線側が未接続(×)のまま R1000 のコイルに線が引かれている例
- a接点の出力線側が未接続(×)の例

> **参考**
> 右図のラダーは未接続のため、変換エラーになります。

【図】(原本 p.357): A(a接点) の後に B と C の並列回路があるが、並列回路の接続が不正(×、破線丸で囲み)で、R1000 のコイルへ下側から線が接続されている例

**■ 2重コイル** (原本 p.360)

プロジェクト内で同じデバイスのOUT/OUB命令を2回以上使用すると、1スキャン内で1番最後に実行される命令が優先され、その他の命令は無視されます。
それぞれが離れた行、または違うプログラムに存在する場合は、以下のように対処します。

（例）下図のようにR2000の出力命令を2回使用している場合

変更前(2重コイル):
```
LD   R000
ANB  R001
OUT  R2000
LD   R002
OUT  R2001
  :
LD   R003
OUT  R2000
```
変更後:
```
LD   R000
ANB  R001
OUT  R1000
LD   R002
OUT  R2001
  :
LD   R003
OUT  R1001
  :
LD   R1000
OR   R1001
OUT  R2000
```
それぞれを違うデバイスで一旦出力し、別途まとめてORでR2000に出力します。

2重コイルは変換エラーになりませんが、動作が煩雑になるため使用しないでください。
2重コイルの存在をチェックするには、《KV STUDIO》のメニューから【変換（A）】→【2重コイルチェック（D）】を選択してください。

> **ポイント**
> - 同じファンクションブロック、マクロを2回以上呼び出す場合、グローバルデバイスを使用したOUT/OUB命令があると2重コイルになります。
> - 2重コイルになっている場合でも、動作していないモジュールやファンクションブロック内に記載されている場合は影響ありません。

**● 同じファンクションブロック、マクロ間での2重コイルを避ける方法** (原本 p.361)

ファンクションブロック、マクロ内にグローバルデバイスを使用したOUT／OUB命令があり、そのプログラムを2回以上呼び出す場合に発生する2重コイルは、以下のように対処すると避けられます。

① ファンクションブロック、マクロ内にあるOUT/OUB命令のオペランドを引数タイプがIN-OUTの引数もしくは引数Pにします。
```
変更前:  LD R000 / OUT R2000
変更後:  LD R000 / OUT P1
```
② ファンクションブロック、マクロ呼び出し命令で指定する①で追加した引数は、呼び出すごとに異なる内部補助リレーを指定します。
```
変更前:  MCALL マクロA DM0      ・・・  MCALL マクロA DM100
変更後:  MCALL マクロA DM0 R1000 (P1)   ・・・  MCALL マクロA DM100 R1001 (P1)
```
> 補足(原文にはない): 図では MCALL の第2引数欄に R1000 / R1001 が入り、その下に引数名 P1 が表示されています。呼び出し前の実行条件部分は図で省略(波線)されています。

③ 別途まとめてORで出力するラダープログラムをファンクションブロック、マクロ外に追加します。
```
LD   R1000
OR   R1001
OUT  R2000
```

**■ インターロック**

プログラム内で一方が動作している場合に、他方の動作をできなくさせて、両者が同時に作動しないように排他処理された構成をインターロックといいます。
実際の装置には必要になる場合が多いのですが、『KV-8000/7000/5000/3000/1000シリーズ・KV Nanoシリーズ命令語リファレンスマニュアル』などで紹介しているサンプルプログラムでは、動作の説明が煩雑になるため省略しています。

（例） R2000とR2001が同時にONしない回路
```
LD   R000
MPS
ANB  R2001
AND  R001
OUT  R2000
MPP
ANB  R2000
AND  R002
OUT  R2001
```
R000とR001がON→R2000がONしている状態でR002がONしても、R2000のB接点が挿入されているため、R2001はONしません。

モジュールやマクロの実行中ONビットを使用すると、簡単にインターロック回路を作成できます。
- 「マクロの実行中ONビット」（4-189ページ）
- 「マクロシステムデバイス」（4-188ページ）

**■ スキャンタイムの短縮** (原本 p.362)

スキャンタイムが長くなると入出力や値の更新周期が大きくなるため、機械や装置の応答性が悪くなります。また、スキャンタイムが300msを超えると「スキャンタイムオーバー（CPU本体エラー No.30）」が発生し、運転を継続できません。
以下の項目を実施することによって、スキャンタイムを短縮できます。

**● 必要のないモジュールを停止する**

動作に必要のないモジュールを実行状態のままにしている場合は、モジュール命令（MDSTRT/MDSTOP）を使用して、必要な時だけモジュール実行させてください。
- 「モジュール命令」（4-115ページ）

**● 必要のないラダー回路ブロックをジャンプする**

動作に必要のないラダー回路ブロックを条件分岐（CJ/NCJ～LABEL命令）、ステップ（STP～STE命令）などで囲み、必要な時だけ実行させてください。

**● 繰り返し（FOR～NEXT命令間）の内容を少なくする**

FOR～NEXT命令間の繰り返し実行するラダー回路ブロック内に無駄な部分があると、繰り返し回数分の処理時間がスキャンタイムに加算されます。繰り返し実行する必要のない処理は、FOR～NEXT命令の外に記述してください。

> **参考**
> CJ/GOTO命令を使用して繰り返し処理するプログラムを作成する場合も同様です。

**● 32ビット/64ビットデータを扱うオペランドに偶数番号のデバイスを指定する**

サフィックスが.D/.L/.F/.DFの場合など32ビット/64ビットデータを扱う命令語のオペランドに、DM/W/TMなどの16ビットのワードデバイスを指定する場合は、偶数番号のデバイスを使用してください。奇数番号からの2ワードを使用すると、処理速度が遅くなります。

> **参考**
> DM/TMの場合は、ローカルデバイスも同様に偶数番号を使用してください。変換時、偶数番号のローカルデバイスは必ず偶数番号のグローバルデバイスに、奇数番号のローカルデバイスは奇数番号のグローバルデバイスに割り付けられます。そのため、各プログラムの割付個数よりも多くのデバイス領域を消費する場合があります。

**■ モジュール、ファンクションブロック、マクロの有効活用** (原本 p.363)

モジュール、ファンクションブロック、マクロを有効に活用してプログラムを構造化するためには、ローカルデバイスや変数を最大限使用してください。以下にローカルデバイスを使用する上での注意事項を示します。
- CPUユニットや使用するユニットに割り当てられているデバイス、タッチパネルなどの外部接続機器で参照するデバイス、プロジェクト全体で共通して使用したり、モジュール間でデータの受け渡しが必要なデバイス以外は、全てローカルデバイスとして使用してください。
- ローカルデバイスは、0番を先頭にできるだけ詰めて使用してください。
- RやDMはユニットに割り当てられるため、グローバルデバイスとして使用する領域が必要です。ローカルデバイスは、MR/LRやEMを優先して使用してください。
- 「4-12 ローカルデバイス」（4-200ページ）
- 「4-5 変数」（4-55ページ）

**■ インデックス修飾と間接指定の使い分け**

命令語のオペランドで指定するデバイスを運転中に変更する方法として、「インデックス修飾」と「間接指定」があります。

＜インデックス修飾＞
- ○指定方法がシンプルである。
- △指定するデバイスの種類を変更できない。
- △インデックスレジスタZはローカルデバイスとして使用できない。
  - →「ZPOP」「ZPUSH」命令を使用すれば、インデックスレジスタの使用可能点数を意識せずに使用できます。

＜間接指定＞
- ○指定するデバイスの種類を変更できる。
- △指定方法が複雑である。（アドレスを扱うには専用命令を使用する必要がある）

デバイスの種別を変更する場合以外は、簡単に扱える「インデックス修飾」を使用されることをおすすめします。
- 「インデックスレジスタによる修飾」（4-44ページ）

### デバッグの進め方

(4-15 / 原本 p.363 / 4-265)

プログラムの誤りを取り除くことをデバッグと言います。
《KV STUDIO》の「モニタ」機能を使用すれば、実際に接続したCPUユニットの状態を確認できます。
また、モニタ中にラダープログラムの編集が可能な「オンラインエディット」機能を併用すれば、より効率よくデバッグを進められます。
CPUユニットがなくても、パソコンだけでラダープログラムの動作が確認できる「シミュレータ」機能を使用すれば、CPUユニットの動作をパソコン上でシミュレートしてデバッグを進められます。
「リプレイ」機能を使用すると、装置でトラブルが発生した際のデータを保存して、あとから《KV STUDIO》で再生できるため、トラブル要因の解析に活用できます。

#### モニタ

(4-15 / 原本 p.366 / 4-268)

モニタとは、ラダーエディタで作成したラダープログラムをCPUユニットに転送し、実際に実行させて動作状況を確認するものです。

モニタを使うと、次のことができます。
- プログラムの動作状況が、ラダー図やリアルタイムチャートモニタでリアルタイムに確認できます。
- CPUユニットの運転モードが切り換えられます。
- 強制セット/リセットをすることにより、入力接点をモニタ画面上で強制ON/OFFできます。
- デバイスのデータやタイマ・カウンタの設定値や現在値を簡単に変更できます。
- デバイスの現在値などを、範囲を指定して保存／読み出しできます。
- デバイスの一部を初期値に戻せます。

モニタを開始するには、メニューから【モニタ／シミュレータ（N）】→【PLC転送→モニタモード（C）】を選択します。操作の前にCPUユニットとパソコンを接続し、通信できる状態にしておいてください。
- 別手順: ・[PLC転送→モニタモード]アイコンをクリック ・[Ctrl]＋[F8]

> **参考**
> 《KV STUDIO》のタイトルバーに現在の状態（モニタ／オンラインエディット／エディタなど）が表示されます。

モニタの各操作は、ツールバーまたはメニューでおこないます。

各機能の詳細は『KV STUDIO ユーザーズマニュアル』「9章 モニタ／シミュレータ」を参照してください。

#### オンラインエディット

(4-15 / 原本 p.367 / 4-269)

オンラインエディット機能を使用すると、《KV STUDIO》のモニタ画面上で直接ラダープログラムを変更できます。プログラム作成時の最終デバッグでの現場調整や簡単なプログラムを変更する時に便利な機能です。
モニタ実行中に、メニューから【モニタ／シミュレータ（N）】→【オンラインエディット開始（O）】を選択して、オンラインエディットを開始します。
編集箇所が水色に表示され、どのセルに修正を加えているかが一目で確認できます。
編集箇所の水色は転送が終了すると元の背景色に戻ります。
- 別手順: •モードバーで「オンラインエディット」を選択する • [オンラインエディット]アイコンをクリック • [F10]

> **注意**
> PLCがRUN状態でオンラインエディット機能を使用する場合、使用方法を誤ると装置及び作業者に多大な被害を与える可能性があります。次に記載する注意事項を十分に確認の上、正しく使用してください。
> - 装置周辺をよく確認の上、不測の事態が発生しても人的・物的被害が起こらない状態で使用してください。
> - プログラム転送後直ちに動作する回路（実行条件がB接点の回路など）を追加しないでください。機器が暴走するおそれがあります。
> - ONしている出力命令（OUTなど）を削除して転送すると、出力がON状態で保持されます。

> **参考**
> オンラインエディット転送時は、変更した回路ブロックのみPLC本体に書き込みます。ただし、以下の場合は変更したプログラム全体を書き込みます。
> - 複数のモジュールを変更した場合
> - ローカルワーク領域を超えるようなST/スクリプト編集をおこなった場合
> - ローカルワーク領域を超えるような変数の追加をおこなった場合
> - ファンクションブロック内のプログラムを編集した場合（ファンクションブロック全体が転送されます。）
> - マクロ内のプログラムを編集した場合（マクロ全体が転送されます。）
> - ローカルデバイスの個別割当個数を変更した場合
> - マクロの呼び出しを追加した場合
> - ファンクションブロックの呼び出しを追加した場合
> - ENDH命令を編集した場合
> - 構造体を編集した場合（編集した構造体が使用されているモジュールやファンクションブロックが転送されます。）
> - 複数のモジュールやファンクションブロックで使用されているグローバル変数、ファンクションブロックの引数を編集した場合（編集したグローバル変数、ファンクションブロックが使用されているモジュールおよびファンクションブロックが転送されます。）

RUN中書き込み時の制限事項や注意事項は、「RUN中書き込みについて」（4-267ページ）を参照してください。
オンラインエディット機能の詳細は、『KV STUDIO ユーザーズマニュアル』「9-9 オンラインエディット機能」を参照してください。

#### シミュレータ

(4-15 / 原本 p.368 / 4-270)

シミュレータとは、ラダーエディタで作成したラダープログラムの動作を、PLCを接続せずにパソコン上でシミュレートするものです。
シミュレータを使うと、次のことができます。
- ラダーモニタ、登録モニタ（タイムチャート）、一括モニタを使用して、プログラムの動作状況をリアルタイムで確認できます。
- 連続スキャン／連続ステップ、1ステップ／1スキャンなど、さまざまな実行方法でシミュレートできます。
- 逆1ステップ、逆連続ステップなどの便利機能で、効率よくデバッグ作業ができます。
- タイマ、カウンタ、デバイスなどの設定値や現在値を簡単に変更できます。
- 接点の強制セットおよびリセットができます。

シミュレータを開始するには、メニューから【モニタ／シミュレータ（N）】→【シミュレータ（L）】を選択します。
- 別手順: •モードバーで「シミュレータ」を選択する • [シミュレータ]アイコンをクリック • [Ctrl]＋[F2]

> **参考**
> 《KV STUDIO》のタイトルバーに現在の状態（シミュレータ／モニタ／エディタなど）が表示されます。

シミュレータの各操作は、ツールバーまたはメニューでおこないます。

各機能の詳細は、『KV STUDIO ユーザーズマニュアル』「9-11 シミュレータ機能－シミュレータの実行」を参照してください。

**■ モニタとの違い**

シミュレータでは、1スキャン実行／1ステップ実行／逆1ステップ実行など、モニタよりも細かい運転状態の制御が可能です。
CPUの動作のみシミュレートするため、拡張ユニットの動作を確認できません。また、一部のCPU内蔵機能やデバイスの動作にも制限があります。
- 『KV STUDIOユーザーズマニュアル』「9-11 シミュレータ機能－シミュレータでの制限」

> **参考**
> タイマの数値は、パソコンの性能によりばらつくことがあります。

シミュレータエディット機能を使用すると、《KV STUDIO》のシミュレータ動作中に直接ラダープログラムを変更できます。プログラム作成時の最終デバッグでの現場調整や簡単なプログラムを変更する時に便利な機能です。
モニタ/オンラインエディットを実行していない状態で、メニューから【モニタ／シミュレータ（N）】→【シミュレータエディット】を選択して、シミュレータエディットを開始します。

編集箇所の水色は転送が終了すると元の背景色に戻ります。
- 別手順: •モードバーで「シミュレータエディット」を選択する

#### リプレイ

(4-15 / 原本 p.370 / 4-272)

リプレイとは、設定したトリガが成立した前後の運転記録を再生する機能です。運転記録を再生・停止・巻き戻し・コマ送りなどをしながら確認することで、トラブル発生時の状況を把握できます。CPUユニット内の運転記録を読み出すか、すでに取得した運転記録を開くかを選択してリプレイモードに移行します。

リプレイで再生できる運転記録の内容は以下のとおりです。

| 種類 | 詳細 |
|---|---|
| デバイス | トリガ条件成立前後のPLCデバイス、拡張ユニットのバッファメモリの、スキャンタイムごとのデータ |
| カメラ | トリガ条件成立前後のフレームレートごとにKV-CA02で撮影した映像データ |
| イベント/エラー | トリガ条件成立前後のエラーやデバイス値変更などのイベント履歴 |
| プロジェクトデータ | トリガ条件成立時のプロジェクトデータ |

(原本の表 4行 → md 4行)

リプレイ中では以下のことができます。
- トラブル発生時のデバイスデータをラダープログラムで1スキャンごとに状態を確認したり、カメラで撮影したコマ送りの映像と照らし合わせて確認したりできます。
- デバイスの値が変化した、エラーが発生したなどのイベントを選択して運転記録を再生する位置を指定できるため、装置で異常が発生した際の状態を簡単に把握できます。
- トラブル発生時のデバイスデータをリアルタイムチャートモニタに登録し、時系列データとして表示できます。
- VT5シリーズと連携することで、トラブル発生時のデバイスデータをHMI上でモニタできます。

リプレイを開始するには、メニューから【運転記録/リプレイ(R)】→【リプレイモード(R)】を選択します。
- 別手順: •モードバーで「リプレイ」を選択 •メニューの【運転記録/リプレイ(R)】→【CPUユニット内の運転記録を読出→リプレイモード(O)】を選択 •メニューの【デバッグ(D)】→【イベント/エラーモニタ(E)】を選択し、〔リプレイモード〕をクリック

> **ポイント**
> - リプレイを使用する場合、KV STUDIO Ver.10.0以降またはKV REPLAY VIEWERが必要です。
> - リプレイを使用できるのは対応機種にKV-8000(A)を選択している場合のみです。
> - リプレイモードからエディタモード以外には変更できません。
> - リプレイモードの詳細は、『KV STUDIO ユーザーズマニュアル』を参照してください。
> - リプレイモード移行時に起動しているプロジェクトと運転記録のプロジェクトが異なる場合、起動中のプロジェクトを閉じて運転記録のプロジェクトを起動するか、起動中のプロジェクトを使用して運転記録を再生するかを選択するダイアログが表示されます。
