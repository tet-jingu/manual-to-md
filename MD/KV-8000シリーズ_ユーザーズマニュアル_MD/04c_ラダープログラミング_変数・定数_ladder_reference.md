## 4-5 変数

(4-5 / 原本 p.153 / 4-55)

KV-8000(A)では、プログラムで用いられる要素として、ユーザが自由に設定できる変数と、リレー、タイマ・カウンタ、データメモリなど、専用の記号と番号で指定できるデバイスを用意しています。どちらも、命令語の後に記述して、命令で使用するデータを与えたり、命令の実行結果を格納するために使用します。この節では変数について説明します。

- あらかじめ定義した名前を用いてプログラミングできるため、プログラムの可読性が向上します。

【図】デバイスでプログラミングした場合 / 変数でプログラミングした場合 (原本 p.153)
- デバイスでプログラミングした場合: 接点 R1000 → コイル R2000、演算式 `DM4.L = DM2.L / DM0.L`
- 変数でプログラミングした場合: 接点 Ax1_Ready → コイル Ax1_MotorON、演算式 `Speed = MovingDistance / OperationTime`

- 変数の設定に合わせて必要なサイズが CPU ユニットのワーク領域に自動的に割り付けられます。そのため、割り付けを意識する必要がありません。
- 異なるプロジェクト間でプログラムをコピーした場合も、変数の割り付けは自動で行われます。デバイスのように、デバイスマップを変更してコピーする必要がなく、プログラムの流用性が向上します。
- タッチパネルディスプレイ VT5 シリーズも、KV-8000 シリーズの変数に対応しているため、デバイスのようにPLCのデバイス番号を変更した際にタッチパネル側のデバイス番号もあわせて変更する、といった作業が不要になります。
- プログラムで使用している未登録の変数は後から一括取り込みできるため、あらかじめすべての変数を登録してからプログラムを作成する必要はありません。
- デバイスと変数を混在して使用できます。

> **ポイント**
> - 変数を使用できるのは、CPU機能バージョン2.0以降のKV-8000のみです。変数を使用する場合は、Ver.11.0以降のKV STUDIOからCPU機能バージョンをアップデートしてください。
> - タッチパネルで変数を使用できるのは、VT STUDIO Ver.8.0以降で、対応機種がVT5シリーズの場合のみです。
> - VT STUDIOで変数を使用する場合、KV STUDIOの変数情報を取得しておく必要があります。詳細は、『VT STUDIO リファレンスマニュアル』を参照してください。
> - KV-XD02で設定できるユニット変数はラダープログラムでは使用できません。

### 変数の種類

(4-5 / 原本 p.153 / 4-55)

変数には、以下の2種類があります。

**■ グローバル変数**

プロジェクト全体で共通して扱う変数です。グローバル変数として定義した変数は、複数のプログラムや、タッチパネルディスプレイVT5シリーズから参照できます。例えば、「Var_X」というグローバル変数を定義した場合、モジュールAで「Var_X」を使用した場合と、モジュールBで「Var_X」を使用した場合とで、同じ実体を参照します。
また、グローバル変数をCPUユニットのデバイスに手動で割り付けることも可能です。

**■ ローカル変数**

プログラム単位で扱う変数です。ローカル変数として定義した変数は、各プログラム内でのみ参照が可能です。例えば、モジュールAで「Var_Y」というローカル変数を定義し、モジュールBでも「Var_Y」という変数を定義した場合、モジュールAで使用する「Var_Y」とモジュールBで使用する「Var_Y」は異なる実体を参照します。ローカル変数はVT5シリーズからは参照できないため、VT5シリーズから参照する変数はグローバル変数として登録してください。
また、ローカル変数はCPUユニットのデバイスには手動で割り付けられません。

### 変数とデータ型一覧

(4-5 / 原本 p.154 / 4-56)

変数を使用する場合、明示的にデータ型を定義する必要があります。CPUユニットは定義されたデータ型に応じて必要なデータサイズを自動的にワーク領域に割り付けます。

| ワード | 589824ワード |
| タイマ | 4000点 |
| カウンタ | 4000点 |

(原本の表 4行 → md 4行)

**変数の仕様**

| 項目 | 内容 |
|---|---|
| 最大定義数 | 100000個※1 |
| 変数名の最大長 | 128文字（全角/半角問わずに128文字） |
| 最大保持設定数 | 30000設定※2※3 |

(原本の表 3行 → md 3行)

※1 グローバル変数とローカル変数の合計です。変数名の文字数によっては 100000 個設定できない場合があります。
※2 ビット、ワード、カウンタの合計です。それぞれの個数は CPU システム設定で設定します。変数名の文字数によっては30000個設定できない場合があります。
※3 変数編集ウィンドウで登録した変数名1つにつき1設定とカウントします。例えば10000個の要素を持つ配列型変数を1つ設定した場合、設定数は1になります。

> 配列や構造体など1つの変数名で複数のビットやワードを占有する変数を設定することで、変数領域すべてを保持することも可能です。

### 配列

(4-5 / 原本 p.155 / 4-57)

配列とは、同じデータ型のデータの集合体を1つの名前で定義するデータ型です。配列を構成する1つ1つのデータを要素といいます。配列では、変数名の他に、データ型と要素数と次元数を設定します。次元数がnの配列を、n次元配列と呼びます。以下に、1次元配列～3次元配列の例とイメージ図を示します。

- 1次元配列　変数名：Array_A　要素数：5の場合
- 2次元配列　変数名：Array_B　要素数：5×4の場合
- 3次元配列　変数名：Array_C　要素数：6×5×4の場合

【図】配列のイメージ図 (原本 p.155)
- Array_A: [0] [1] [2] [3] [4] の横1列(要素数 5)
- Array_B: 行 [0,x]〜[4,x](要素数 5)× 列 [x,0]〜[x,3](要素数 4)。図示セル: [0,0] [0,1] [0,2] [0,3] / [1,0] [1,1] [1,2] [1,3] / (原本で空欄の行) / [4,0] [4,1] [4,2] [4,3]
- Array_C: 立方体図。手前面 [0,0,0]〜[0,4,3]、奥方向に [1,0,0]〜[1,0,3] … [5,0,0]〜[5,0,3]、最奥・最下・右端の要素に矢印で [5,4,3]

> **ポイント**
> 配列型変数ではすべての要素のデータ型が共通になります。

**■ 配列型変数の記載**

(4-5 / 原本 p.156 / 4-58)

**● 配列型変数の要素の指定**

プログラム上で配列の要素を指定して使用する場合は、配列名と[ ]の添え字を組み合わせて使用します。2次元以上の配列の場合は、要素番号を「カンマ(,)」で区切って指定します。例えば、3次元配列Array_Cの[5,0,3]の要素を使用する場合、プログラム上では以下のとおり「Array_C[#5,#0,#3]」と記載します。（#は省略して入力できます）

ラダー例(原本 p.156。原本にニモニックリストはなく、ラダー図から書き起こし):
```
LDP  MR000
MOV  #0 Array_C[#5,#0,#3]
```

**● 配列型変数の全体の指定**

配列を構成する全要素のことを「配列全体」といいます。プログラムで配列全体を指定する場合は、変数名だけを記載します。例えば、Array_Aという配列全体を指定する場合は、「Array_A」と記載します。

ラダー例(原本 p.156。ラダー図から書き起こし):
```
LDP  MR000
ACNT Array_A #1 duAryLen
```

> **参考**
> KV STUDIO Ver.11.0では配列をラダープログラムで扱えます。

> **ポイント**
> 変数名だけを記載して配列全体として扱う命令語はACNT/WSIZE/BSIZE命令のみです。
> その他の命令語で変数名だけを記載した場合は先頭要素から命令語が扱う範囲のみを扱います。
> 例えば、UINTの配列型変数Array_Aに対して「MOV.D 0 Array_A」と記述した場合はArray_A[0]とArray_A[1]の2ワードのみに0が格納されます。

### 配列の仕様

(4-5 / 原本 p.156 / 4-58)

| 項目 | 内容 |
|---|---|
| 1次元あたりの最大要素数 | 589823 |
| 最大次元数 | 8 |
| 1配列あたりで占有可能な最大データサイズ | 589823ワード |
| 指定可能なデータ型 | BOOL / UINT / INT / UDINT / DINT / REAL / LREAL / STRING / 構造体 / ファンクションブロック |
| 指定可能な添え字※1 | デバイス/定数/変数/演算式※2 |
| 添え字に使用できるデータ型 | UINT / INT / UDINT / DINT |

(原本の表 6行 → md 6行)

※1 添え字には0または正の整数を指定してください。その他の数を指定した場合、変換エラーまたは演算エラーが発生します。
※2 添え字に演算式を使用できるのは KV スクリプトのみです。ラダープログラム上では添え字に演算式を使用できません。

> **ポイント**
> - 要素数「10」で設定したArray_Aという配列に対してArray_A[10]（11番目の要素）と指定するなど、指定可能な範囲を超えて要素を指定した場合、意図しない領域の値を参照する可能性があります。特に、添え字に変数や演算式を使用する場合は、配列を参照する前にACNT命令やWSIZE命令を実行して配列の要素数や配列全体のデータサイズを取得し、指定可能な範囲を超えた要素を参照しないようにしてください。配列の範囲外を指定した場合は、変換エラーまたは演算エラーが発生します。
>   「ACNT」（4-67ページ）、「WSIZE」（4-69ページ）、「BSIZE」（4-71ページ）
> - 配列の添え字にデバイスを指定した場合は16ビット符号無し整数として扱われます。
> - 配列の添え字にビットデバイス(R、MRなど)、BOOL型の変数、ワードデータのビット指定などのビットデータは指定できません。
> - KV STUDIOのバージョンによって、配列のデータ型の表記が以下のとおり異なります。
>   例：要素数が3のUINT型配列の場合
>   - Ver.11.20以降　ARRAY[0..2] OF UINT
>   - Ver.11.10以前　UINT[3]

### 構造体

(4-5 / 原本 p.157 / 4-59)

構造体とは、異なるデータ型の、複数の変数の集合体を1つの名前で定義するデータ型です。構造体を構成する1つ1つのデータをメンバといいます。構造体では、変数名の他に、構造体を構成するメンバ名とメンバのデータ型を設定します。構造体には以下のような特長があります。

- 事前に構造体のメンバとデータ型を登録しておくことで、同じ構造を持った変数を作りやすくなる
- 登録モニタウィンドウなどでモニタする際に構造体変数を登録すると、すべてのメンバを一括でモニタできる
- メンバ名で内容を確認できるので、視認性が高くなる

モータ軸の以下の情報をプログラムで使用する場合を例に説明します。
- 現在座標(CurCoordinate)
- 現在速度(CurSpeed)
- 軸制御中(Control)
- 軸エラー(Error)
- 軸エラーコード(ErrorCode)

構造体を使用しない場合、軸を複数使用しようとすると以下のように軸番号が異なるだけの同一内容の変数を登録する必要があります。
構造体を使用する場合は、軸情報のデータ構造を構造体として事前に定義しておくことで、複数の軸を使用する場合でもデータ型に同じ構造体を設定するだけで済みます。

**■ 構造体型変数の記載**

(4-5 / 原本 p.158 / 4-60)

プログラム上で構造体型変数を使用する際の記載方法について説明します。

**● 構造体型変数のメンバの指定**

プログラムで構造体型変数のメンバを使用する場合は、「構造体型変数名+ピリオド(.)+メンバ名」と記載します。例えば、Ax1というAxisInfo型変数のCurSpeedというメンバを参照する場合は、「Ax1.CurSpeed」と記載します。

ラダー例(原本 p.158。ラダー図から書き起こし):
```
LDP   MR000
MOV.L Ax1.CurSpeed DM0
```

また、構造体型変数のメンバのデータ型に構造体を指定できます。以下の例では、「ProductInfo」という構造体型の変数Product_Aに「ProductionDate」という構造体型変数がネストされています。

| 変数名 | データ型 |
|---|---|
| Product_A | ProductInfo |

「ProductInfo」型データの定義

| メンバ名 | データ型 |
|---|---|
| Name | STRING[20] |
| SerialCode | STRING[20] |
| ProductionDate | DateInfo |

「DateInfo」型データの定義

| メンバ名 | データ型 |
|---|---|
| Year | UINT |
| Month | UINT |
| Day | UINT |

(原本の表 1行 / 3行 / 3行 → md 1行 / 3行 / 3行)

Product_AのDayをプログラムで指定する場合は、「Product_A.ProductionDate.Day」と記載します。

ラダー例(原本 p.158。ラダー図から書き起こし):
```
LDP  MR000
MOV  #31 Product_A.ProductionDate.Day
```

> **ポイント**
> 構造体のネストは最大8段までです。

**● 構造体型変数の全体の指定**

構造体型変数を構成する全メンバを「構造体全体」といいます。プログラムで構造体全体を指定する場合は、変数名だけを記載します。例えば、Product_Aという構造体型変数の構造体全体を指定する場合は「Product_A」と記載します。

ラダー例(原本 p.158。ラダー図から書き起こし):
```
LDP   MR000
WSIZE Product_A duWordSize
```

> **ポイント**
> - FMOV命令などを使用して構造体全体に値を書き込む場合、転送データ数に構造体全体のデータ数より大きな値を指定すると、意図しない領域の値を変更してしまう可能性があります。FMOV命令などで構造体全体を参照する場合は、命令実行前にWSIZE命令を実行して構造体全体のデータサイズを取得してください。
>   「WSIZE」（4-69ページ）
> - 変数名だけを記載して構造体全体として扱うのはWSIZE/BSIZE命令のみです。その他の命令語で変数名だけを記載した場合、構造体の先頭から命令語が扱う範囲のみを扱います。
>   例えば、構造体型変数Ax1に対して「MOV.D 0 Ax1」と記述した場合、Ax1の先頭から2ワードのみに0が格納されます。
>   「BSIZE」（4-71ページ）

**● 構造体メンバのオフセット指定**

(4-5 / 原本 p.159 / 4-61)

構造体のメンバをオフセット指定することで、各メンバのワーク領域内のメモリ配置を設定できます。メモリ配置を設定することで、外部機器とデータリンクする際に両者の構造体型メンバのメモリ配置を一致させることができます。構造体メンバのオフセットは、「自動」と「手動」から設定できます。

**● オフセットが自動の場合**

オフセットが自動の場合、メモリ配置は以下のルールに従って自動で行われます。境界の調整のためのパディングは自動的に挿入されます。

| 項目 | 内容 |
|---|---|
| 構造体の先頭 | 構造体のメンバで、最も大きいアライメントサイズの境界に構造体の先頭が割り付けられます。ただし、CPUユニットのデバイスに割り付ける場合は、アライメントサイズに関わらずワード単位での割付が可能です。 |
| 各メンバの先頭 | 各メンバのアライメントサイズの境界に割り付けられます。ただし、BOOL型の配列は16ビットの境界に割り付けられます。 |

(原本の表 2行 → md 2行)

例)以下のメンバを持つ構造体の場合

| メンバ名 | データ型 |
|---|---|
| Var_A | BOOL |
| Var_B | INT |
| Var_C | INT |
| Var_D | DINT |

(原本の表 4行 → md 4行)

構造体のメンバのうち、最もアライメントサイズが大きいのはVar_Dの32ビットなので、ワーク領域の先頭から数えて偶数番目の領域に構造体の先頭を配置します。各メンバの配置は以下のとおりです。

【図】オフセット自動時のメモリ配置 (原本 p.159) — 縦軸: ワーク領域(ワード) +0〜+5、横軸: ビット 0〜15
- +0: ビット0 = Var_A、ビット1〜15 = 調整のためのパディング
- +1: Var_B
- +2: Var_C
- +3: 調整のためのパディング(16ビット)
- +4〜+5: Var_D
- 図中注記: 「Var_Bのアライメントサイズが16ビットなので、Var_Bの先頭が16ビットの境界に来るように、Var_Aの後に15ビットのパディングを挿入します。」
- 図中注記: 「Var_Dのアライメントサイズが32ビットなので、Var_Dの先頭が32ビットの整数倍の境界(左記例では4ワード(64ビット))に来るようにVar_Cの後に16ビットのパディングを挿入します。」

※次のアライメントサイズの境界位置までオフセットすることをパディングといいます。

**● オフセットが手動の場合**

(4-5 / 原本 p.160 / 4-62)

オフセットが手動の場合、以下のルールに従ってメモリ配置を任意に設定できます。

| 項目 | 内容 |
|---|---|
| 構造体の先頭 | 構造体のメンバで、最も大きいアライメントサイズの境界に構造体の先頭が割り付けられます。ただし、CPUユニットのデバイスに割り付ける場合は、ワード単位での割付が可能です。 |
| 各メンバの先頭 | BOOL型のメンバはビット単位で、それ以外のデータ型のメンバはワード単位で、構造体の先頭からのオフセットを指定できます。<br>ただし、オフセット数の上限はワードオフセットの場合はワーク領域の終端まで、ビットオフセットの場合は15ビットです。 |

(原本の表 2行 → md 2行)

例)以下のメンバ、オフセット指定を持つ構造体をDM1001に割り付けた場合の場合

| メンバ名 | データ型 | ワードオフセット | ビットオフセット |
|---|---|---|---|
| Var_A | BOOL | 0 | 0 |
| Var_B | INT | 2 | 0 |
| Var_C | INT | 3 | 0 |
| Var_D | DINT | 5 | 0 |

(原本の表 4行 → md 4行)

CPUユニットのデバイスに割り付ける場合、ワード単位で指定できるため、DM1001のように奇数番目のデバイスに構造体の先頭を配置できます。

【図】オフセット手動時のメモリ配置 (原本 p.160) — 縦軸: DM1001〜DM1007、横軸: ビット 0〜15
- DM1001: ビット0 = Var_A、ビット1〜15 = 調整のためのパディング
- DM1002: 調整のためのパディング
- DM1003: Var_B
- DM1004: Var_C
- DM1005: 調整のためのパディング
- DM1006〜DM1007: Var_D
- 図中注記: 「Var_Bのワードオフセットが32ビットなので、Var_Aの後に31ビットのパディングを挿入します。」
- 図中注記: 「ワード単位でのオフセットを指定できるため、先頭+5のような奇数番目から32ビットアライメントのデータ型を指定することも可能です。」

### ACNT 配列要素数取得

(4-5 / 原本 p.165-166 / 4-67〜4-68)

**ACNT** — 配列要素数取得: 指定した次元の配列要素数を取得します。

- ラダープログラム: 実行条件 ─ [ACNT S n D]
- 入力方法: `ACNT␣S␣n␣D↵`

| オペランド | 説明 | 占有領域 |
|---|---|---|
| S | 配列全体を指定します。※1※2 | ― |
| n | 要素数を取得する次元数（1～8）を指定します。 | 16ビット |
| D | 結果の格納先を指定します。 | 32ビット |

(原本の表 3行 → md 3行)

※1 S に指定できるのは配列型の変数名だけです。配列以外の変数や変数以外の要素は指定できません。
※2 FB引数の可変長配列は指定できません。

**動作説明**

ACNT　実行条件がONのとき、S で指定した配列の n 次元目の要素数を[D・D+1]に格納します。

例　S=Array_A（5×4の2次元配列）、n=2の場合
- 【図】(原本 p.165) Array_A は [0,0]〜[4,3](縦 要素数5 × 横 要素数4)。[D+1・D] に 4 が格納される。

> **ポイント**
> - ACNT命令で取得するのはワードサイズではなく要素数です。例えば、UDINT（2ワード符号なし整数）が4個の次元を指定した場合、[D・D+1]には4が格納されます。ワードサイズの8が格納されるわけではありません。

**演算フラグ**

| フラグ | 内容 |
|---|---|
| CR2009 | 変化なし |
| CR2010 | 変化なし |
| CR2011 | 変化なし |
| CR2012 | ・以下のいずれかの条件が成立した場合はON、それ以外はOFF<br>　・n に定数以外を指定し、n が0もしくは存在しない次元数の場合<br>　・間接参照、インデックス修飾が不適切な場合<br>・以下の条件をすべて満たす場合は、変化しません。<br>　・n に定数を指定している<br>　・D に間接指定、インデックス修飾を使用していない、およびオペランドの範囲外アクセスのチェックが行われない場合 |

(原本の表 4行 → md 4行)

**サンプルプログラム**

入力リレーR000の立ち上がりで、5×4の2次元配列Array_Aの2次元目の要素数をDM0に格納します。
その後、Array_A[4,0]、Array_A[4,1]…Array_A[4,3]に0を格納します。

【図】(原本 p.166) Array_A の [4,0] [4,1] [4,2] [4,3] の行を囲み「0を格納」。

使用デバイス・変数:

| デバイス / 変数 | 用途(原本ラダー図・説明文より) |
|---|---|
| R000 | 入力リレー(立ち上がりで実行) |
| Array_A | 5×4の2次元配列 |
| duAryLen | ACNT の結果格納先 |
| nLoop | FOR のループ回数(duAryLen − 1) |
| idx | 2次元目の添え字 |
| CR2002 | 常時ON |

〈ニモニックリスト〉(原本 p.166 転記)
```
LDP    R000
ACNT   Array_A #2 duAryLen
CAL-.D duAryLen #1 nLoop
MOV.D  #0 idx
FOR.D  nLoop
LD     CR2002
MOV    #0 Array_A[#4,idx]
INC.D  idx
NEXT
LDP    R000
MOV.D  #0 nLoop
```

- **要確認**: 説明文は「要素数をDM0に格納」だが、ラダー図・ニモニックでは ACNT の格納先は duAryLen(DM0 は現れない)。原本 p.166 参照。
- **要確認**: ラダー図では配列への書き込みが「MOV.D #0 Array_A[#4, idx]」と描かれているが、ニモニックリストは「MOV #0 Array_A[#4,idx]」。原本 p.166 参照。

(4-5 / 原本 p.167-168 / 4-69〜4-70)

※2 FB引数の可変長配列、可変長文字列は指定できません。

**動作説明**

例　S=以下の構造体型変数を指定した場合

(原本の表 4行 → md 4行)

(原本 p.168 / 4-70)
