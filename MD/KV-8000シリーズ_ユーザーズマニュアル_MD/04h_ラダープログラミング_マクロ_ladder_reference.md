## 4-11 マクロ

(4-11 / 原本 p.276 / 4-178)

### 概要

(4-11 / 原本 p.276 / 4-178)

プロジェクト内で何度も繰り返して使用するラダー回路に、任意の名前を付けて登録したものをマクロと呼びます。マクロ化することにより、ラダー命令語と同じように使用できるため、プログラム入力工数が削減されます。回路変更時には、マクロとして登録した1箇所のデータを修正するだけで、プロジェクト内で呼び出す全てのマクロ命令の処理内容が変更されます。このことにより、プログラムの変更工数が削減され、修正ミスも防げます。

**■ マクロの管理**

《KV STUDIO》では、［ワークスペース］を使用してプロジェクトごとに管理します。

【図】マクロ導入前/導入後 (原本 p.276)
- ＜マクロ導入前＞: プロジェクト1 の [モジュールA] [モジュールB] それぞれに同じ処理が記述されている
- 同じ処理をマクロとして登録
- ＜マクロ導入後＞: プロジェクト1 に [モジュールA] [モジュールB] [マクロC] があり、各モジュールからマクロ呼び出し命令で マクロC を呼び出す

### マクロの特長

(4-11 / 原本 p.277 / 4-179)

**● オリジナル命令語として使用できる**

プログラム内に何度も出てくる同じラダー回路をマクロとして登録すれば、以後の入力工数や入力ミスを削減できます。
結果として、見た目のラダー行数が減り、プログラム構造を把握しやすくなります。
登録するマクロ名は自由に付けることができます。

**● 引数が使用できる**

引数を使用すれば、マクロ内にある命令語のオペランド（デバイスや値）をマクロ呼び出し時に指定できるため、汎用性の高いマクロを作成できます。
- 参照: 「引数設定」（4-186ページ）

**● 2種類のマクロが作成できる**

マクロには、『サブルーチン型マクロ』と『自己保持型マクロ』があります。
『サブルーチン型マクロ』は、サブルーチンプログラムと同様に実行条件がONの場合のみ実行します。
『自己保持型マクロ』は、一旦実行を開始するとマクロ実行停止命令（MEND マクロエンド）が実行されるまで、実行条件の状態にかかわらず動作を続けます。
拡張ユニットや外部機器に処理を要求し、完了までに時間がかかる（スキャンをまたぐ）処理の場合などに便利です。
- 参照: 「マクロの種類」（4-181ページ）

**● ローカルデバイスが使用できる**

別のマクロで同じ番号のローカルデバイスを使用しても、別デバイスとして扱われるため、マクロ内のみで使用するデバイスの割り付けが簡単にできます。
- 参照: 「4-12 ローカルデバイス」（4-200ページ）

**● パスワードが設定できる**

マクロの内容を容易に変更できなくするため、パスワードを設定できます。
パスワードを設定した場合、パスワードを知らない人はマクロのプログラムを表示、編集できません。
［プログラム プロパティ］ダイアログでパスワードを設定します。

**● 呼び出すごとに実体を作成する**

マクロは、モジュール内で呼び出されるごとに、ラダープログラムの実体を作成します。同じスキャン内で何度も同じマクロを実行する場合や、スキャンをまたいで実行するマクロが複数ある場合、ローカルデバイスを併用することで、使用するデバイスの衝突やそれぞれのマクロの実行状態を意識せずに使用できます。
- 参照: 「マクロとサブルーチンプログラムの違い」（4-196ページ）
- 参照: 「ファンクションブロックとマクロの違い」（4-175ページ）

## マクロの種類

(4-11 / 原本 p.279 / 4-181)

マクロには、サブルーチン型マクロと自己保持型マクロがあります。

### サブルーチン型マクロ

(4-11 / 原本 p.279-280 / 4-181〜4-182)

**● 概要**

サブルーチン型マクロは、サブルーチンと同様に実行条件がONの場合のみ、マクロ呼び出し命令（MCALL）ごとにマクロ内のプログラムを実行します。実行完了後、マクロ呼び出し命令の次のステップに進みます。実行条件がOFFの場合は、マクロ内のプログラムを実行せずに次のステップに進みます。

**● 使用方法**

サブルーチン型マクロは、モジュールからのMCALL命令により起動します。

(図からの書き起こし。原本にニモニックリストの記載なし)
```
LD     MR0
MCALL  マクロA        ; MCALL命令により起動
```

**● 動作説明**

サブルーチン型マクロの動作説明を下図に示します。
モジュール1内でマクロAを2回呼び出す例を示します。

> **参考**
> 作成したマクロの実体を区別するために、マクロ名の後ろに「#（管理番号）」を付けて管理します。
> 《KV STUDIO》では、モニタ・シミュレータ時のみ表示されます。

【図】サブルーチン型マクロの動作説明 (原本 p.279)
- モジュール1 内に MCALL マクロA が2箇所ある
- 1つ目の MCALL は実行条件 ON → マクロA#1 に移って実行し、終了後モジュール1の次の回路へ戻る
- 2つ目の MCALL は実行条件 OFF → マクロA#2 は実行されず(×)、モジュール1の次の回路へ進む
- 図中の吹き出し: 「MCALL命令により、それぞれ別々に実体（マクロA#1、マクロA#2）が作成されます。MCALL命令の実行条件がONの場合、モジュール1を抜けてそれぞれのマクロを実行します。」

**● 実行停止時の動作**

サブルーチン型マクロの実行停止時（実行条件ON→OFF時）の動作は、各プログラムの［プログラムプロパティ］→「実行停止時にOFF処理する」の設定により異なります。

> **ポイント**
> KV-8000Aの場合は設定は表示されず、常に「実行停止時にOFF処理する」にチェックしている場合と同じ動作になります。

### 自己保持型マクロ

(4-11 / 原本 p.281-283 / 4-183〜4-185)

**● 概要**

自己保持型マクロは、サブルーチン型マクロと同様に実行条件がONの場合、マクロ呼び出し命令（MSTRT）ごとにマクロ内のプログラムを実行します。一旦マクロが起動すると、次スキャン以降もマクロ内のマクロ実行停止命令（MEND マクロエンド）が実行されるまで、マクロ呼び出し命令の実行条件にかかわらず動作し続けます。

**● 使用方法**

自己保持型マクロは、モジュールからのMSTRT命令により起動します。

(図からの書き起こし。原本にニモニックリストの記載なし)
```
LD     MR0
MSTRT  マクロA        ; MSTRT命令により起動
```

**● 動作説明**

自己保持型マクロの動作説明を下図に示します。
ここでは、モジュール1内でマクロAを2回呼び出す例を示します。

> **参考**
> 作成したマクロの実体を区別するために、マクロ名の後ろに「#（管理番号）」を付けて管理します。
> 《KV STUDIO》では、モニタ・シミュレータ時のみ表示されます。

1. 実行条件がONの場合、マクロＡを起動します。
   - 【図】(原本 p.281): モジュール1 の MSTRT マクロA ×2 が両方とも実行条件 ON → マクロA#1、マクロA#2 をそれぞれ実行(各マクロ内に MEND あり)
2. 一旦起動すると、MSTRT命令の実行条件の状態にかかわらず実行し続けます。
   - 【図】(原本 p.282): 1つ目の MSTRT は ON、2つ目の MSTRT は OFF。吹き出し「実行条件がOFFになっても実行し続けます。」 マクロA#1、マクロA#2 とも実行される
3. マクロ内にあるMEND命令の実行条件がONすると、停止します。
   - 【図】(原本 p.282): 両方の MSTRT が OFF、マクロA#1・マクロA#2 内の MEND の実行条件が ON → 両マクロとも停止(破線で表示)

> **ポイント**
> - 自己保持型マクロにはMEND命令が必ず必要です。
> - マクロの実行を停止するには、マクロの実行条件を必ずOFFにしてください。マクロの実行条件がONの場合は、MEND命令の実行条件がONしてもマクロは停止しません。

**● 実行停止時の動作**

(4-11 / 原本 p.283 / 4-185)

自己保持型マクロの実行停止時（MEND命令実行時）の動作は、各プログラムの［プログラムプロパティ］→「実行停止時にOFF処理する」の設定により異なります。

> **ポイント**
> KV-8000Aの場合は設定は表示されず、常に「実行停止時にOFF処理する」にチェックしている場合と同じ動作になります。

**「実行停止時にOFF処理する」にチェックしていない場合**
自己保持型マクロは、マクロ停止命令（MEND）が実行された次のスキャンで停止します。

**「実行停止時にOFF処理する」にチェックしている場合**
自己保持型マクロは、マクロ停止命令（MEND）が実行された次の1スキャンのみ、実行条件を全てOFFとして実行されます。※
その次のスキャンから停止となります。

【図】【自己保持型マクロの動作イメージ】(「実行停止時にOFF処理する」チェックあり / 原本 p.283)

| 項目 | 1スキャン | 1スキャン | 1スキャン | 1スキャン | 1スキャン | 1スキャン |
|---|---|---|---|---|---|---|
| マクロAを呼び出す実行条件 | OFF | ON | ※1 | ※1 | OFF※2 | OFF※3 |
| マクロA内にあるMEND命令の実行条件 | - | OFF | OFF | ON | ※1 | - |
| マクロA | 停止 | 実行 | 実行 | 実行 | OFF条件で実行 | 停止 |

(原本の表 3行 → md 3行)

- ※1: ON/OFFどちらの状態でも動作に影響ありません。
- ※2: 必ずOFFしてください。OFFするまでMEND命令を無視して実行し続けます。
- ※3: ON状態であれば、マクロの実行を開始します。

※ ただし、以下の命令は例外となります。

| 命令語 | 状態 |
|---|---|
| OUB命令 | OFFします。 |
| OFDL命令 | リセットします。 |
| SHOT命令 | リセットします。(同上: 原本は OFDL と結合セル) |
| C命令 | 状態保持します。 |
| CJ/NCJ/GOTO命令 | 分岐しません。 |

(原本の表 5行 → md 5行)

> **参考**
> マクロの実行停止時のOFF処理は、MC命令の実行条件がOFF時と同じ処理を1スキャンのみおこないます。

## 引数設定

(4-11 / 原本 p.284-285 / 4-186〜4-187)

### ■ 引数とは

(4-11 / 原本 p.284 / 4-186)

引数とは、マクロ呼び出し時にマクロの実体に対して引き渡すデバイスや値です。マクロ呼び出し命令のオペランドとして指定します。マクロ内では、引き渡されたデバイスや値を使用してラダープログラムを実行します。引数は、マクロが実行中であれば毎スキャン更新されます。

【図】引数の概念 (原本 p.284)
- モジュール1: `MCALL マクロA R001 #50` (R001 = 引数1、#50 = 引数2)
- 呼び出し先 マクロA: 引数1 の a接点 → `MOV 引数2 DM0`
- 実行時は 引数1 → R001、`MOV 引数2 DM0` → `MOV #50 DM0` として実行
- 吹き出し: 「マクロ呼び出し時に指定したデバイスや値を、マクロ内のラダープログラム内で使用して実行します。」

(図からの書き起こし。原本にニモニックリストの記載なし。モジュール1側の実行条件接点のデバイス名は図に記載なし)
```
; モジュール1
MCALL  マクロA R001 #50
; マクロA (マクロ内での記述)
LD     引数1
MOV    引数2 DM0
```

### ■ 引数デバイス一覧

(4-11 / 原本 p.284 / 4-186)

引数デバイスとは、その引き渡されたデバイスや値が、マクロ内のどの命令語のオペランドとして使用されるかを指定するためのデバイスです。引数デバイスは、マクロ内でしか使用できません。
ワークスペースの設定したいマクロ上で、右クリックメニューから【引数設定（Z）】を選択して表示される［マクロの引数設定］ダイアログで設定します。引数デバイスにはP、V、UR、UM、UVの5種類があります。各デバイスの仕様を下図に示します。マクロの引数は最大10個まで指定できます。

| 種類 | 記号 | 範囲 | 説明 | 間接指定（＊） | ローカルデバイス（@） | インデックス修飾（ : ） |
|---|---|---|---|---|---|---|
| デバイス | P | P0～P9 | デバイスを引数として受け取ります。 | × | × | ○ |
| 値※2 | V | V0～V9 | デバイスの値または定数を引数として受け取ります。 | × | × | × |
| ユニットデバイス（R）※1 | UR | UR0～UR9 | 拡張ユニットに割り付けられた先頭リレー（R）を引数として受け取ります。 | × | × | ○ |
| ユニットデバイス（DM）※1 | UM | UM0～UM9 | 拡張ユニットに割り付けられた先頭データメモリ（DM）を引数として受け取ります。 | × | × | ○ |
| ユニット番号※1 | UV | UV0～UV9 | 拡張ユニットのユニット番号を受け取ります。 | × | × | × |

(原本の表 5行 → md 5行)

- ※1 マクロ呼び出し命令では、対象となるユニット番号のみ指定します。
  1つのマクロ内で引数として指定できるユニットは、最大5台です。
- ※2 DRを指定すると、マクロ呼び出し直前にダイレクト処理をおこない、その結果を引数として受け取ります。

## マクロシステムデバイス

(4-11 / 原本 p.286 / 4-188)

マクロシステムデバイスとは、マクロの動作状況を取得するためのデバイスです。
実行中ONビットのみ、他のプログラムから参照可能です。

> **ポイント**
> マクロシステムデバイスには、デバイスコメントを付けられません。

> **参考**
> マクロシステムデバイスは、《KV STUDIO》によってCPUユニットの内部ワーク領域へ自動的に割り付けられます。

**● マクロ実行開始時1スキャンのみONビット「＠CR2008」**

マクロが実行を開始した1スキャン目のみONになります。
2スキャン目以降はOFFになります。
自マクロ内のみ参照可能です。マクロを呼び出しているモジュール内では参照できません。
《KV STUDIO》上での表記は、「＠CR2008」となります。

**● マクロ実行開始時1スキャンのみOFFビット「＠CR2007」**

マクロが実行を開始した1スキャン目のみOFFになります。
2スキャン目以降はONになります。
自マクロ内のみ参照可能です。マクロを呼び出しているモジュール内では参照できません。
《KV STUDIO》上での表記は、「＠CR2007」となります。

**● 実行中ONビット「_（マクロ名）_（識別番号）」**

実行中ONビットは、そのマクロが実行中にONします。
各モジュールから参照できるため、マクロ呼び出しの前に参照するなどして、マクロの実行を制御する場合に有効です。
《KV STUDIO》上での表記は、「_（マクロ名）_（識別番号）」（アンダースコア＋マクロ名＋アンダースコア＋識別番号）となります。

**例** (原本 p.286)
- `_一括送信_2` (a接点) 、 `_パラメータ演算_1` (b接点)

> **参考**
> マクロの実行中ONビットを使用するには、呼び出すマクロごとに識別番号が必要です。
> 「マクロの実行中ONビット」（4-189ページ）

## マクロの実行中ONビット

(4-11 / 原本 p.287-288 / 4-189〜4-190)

### ■ 概要

(4-11 / 原本 p.287 / 4-189)

実行中ONビットは、そのマクロが実行中にONします。各モジュールから参照できるため、マクロ呼び出しの前に参照するなどして、マクロの実行を制御する場合に有効です。
マクロの実行中ONビットを使用するためには、呼び出すマクロごとに識別番号が必要です。
《KV STUDIO》上での表記は、「_（マクロ名）_（識別番号）」となります。

### ■ 実行中ONビット設定方法

(4-11 / 原本 p.287 / 4-189)

実行中ONビットは、［オペランド編集］ダイアログの「識別番号（実行中ビット）」にチェックを入れると使用できます。

1. MCALL/MSTRT命令にカーソルを合わせて 〔Enter〕キーを入力します。
   ［オペランド編集］ダイアログが表示されます。
   - 別手順: MCALL/MSTRT命令にカーソルを合わせて、メニュー【編集（E）】→【オペランド変更（O）】を選択
   - 【図】(原本 p.287): `MCALL マクロA DM0 DM1` にカーソル → 〔Enter〕 → ［オペランド編集］ダイアログ(列: タイトル / 属性 / 引数、1行目: デバイス DM0、2行目: 値 DM1、□識別番号(実行中ビット)(C): 0、〔上書き〕〔キャンセル〕)
2. 「識別番号（実行中ビット）」にチェックを入れて、識別番号を入力します。
   - 【画面】(原本 p.287): ☑識別番号(実行中ビット)(C): 1
   > **ポイント**
   > マクロの実行中ONビットは、［識別番号（実行中ビット）］にチェックが入っていないと使用できません。
3. 〔上書き〕ボタンをクリックします。
   識別番号（実行中ビット）が設定されます。
   - 【図】(原本 p.287): 命令表示が `MCALL マクロA_1 DM0 DM1` となり、「_1」が識別番号

同じプロジェクト内で同じマクロを何度も使用する場合は、番号を変えて使用します。

> **ポイント**
> 同じマクロに同じ番号を指定すると、変換エラーになります。

### ● 使用例

(4-11 / 原本 p.288 / 4-190)

【図】吹き出し: 「マクロ4_1、マクロ4_2が動作中は、R000がONしてもマクロ5は実行されません。」

使用デバイス:

| デバイス | 内容 |
|---|---|
| CR2008 | 実行条件(原本図の表記のまま) |
| R000 | マクロ5 呼び出し条件 |
| _マクロ4_1 | マクロ4_1 実行中ONビット |

(原本の図中デバイス 4件 → md 4行)

> **ポイント**
> 未使用マクロ（プロジェクト内のマクロ呼び出し命令で指定されていないマクロ）の実行中ONビットを記述すると、変換エラーになります。

MCALL  マクロ4 @DM0 #100        ; 実行中ONビットを使用できません。

- ※1 マクロ名称以外のオペランドの個数や、指定できるデータは、実行するマクロに設定されている引数設定によって以下のとおり異なります。

  - V ：デバイス、変数、ラベル、定数を指定できます。
  - ユニット：定数のみ指定できます。

- ※3 ""、#、$は使用できません。KV STUDIOで設定してマクロ名称を直接入力してください。

### 動作説明

(4-11 / 原本 p.292 / 4-194)

- **MCALL** 実行条件がONの間、 S で指定したサブルーチン型マクロを毎スキャン実行します。
  指定したマクロは、OFF→ONになったスキャンから実行を開始します。
- **MSTRT** 実行条件がONのとき、 S で指定した自己保持型マクロを起動します。
  指定したマクロは、OFF→ONになったスキャンから実行を開始します。
  一旦実行を開始すると、実行条件がOFFでもマクロを実行し続けます。
- **MEND** 実行条件がONのとき、MEND命令が記述されている自己保持型マクロを停止します。

プログラムの設定により、停止時のOFF処理の動作が異なります。
- サブルーチン型マクロ： 「実行停止時の動作」（4-182ページ）
- 自己保持型マクロ： 「実行停止時の動作」（4-185ページ）

> **ポイント**
> - MCALL/MSTRT命令の呼び出し個数や順序を変更すると、RUN中書き込みできません。
> - 自己保持型マクロの実行を停止するには、マクロ内のMEND命令を使用します。
>   MSTRT命令の実行条件がONのままの場合には、MEND命令は無視されます。
> - MEND命令は、モジュール内やサブルーチン型マクロ内に記述できません。
> - MEND命令で他のマクロを停止することはできません
> - マクロ内の微分実行型命令の前回状態は、マクロの実行開始時に毎回初期化されます。
>   （立ち上がり微分：ON、立ち下がり微分：OFF）
> - MCALL/MSTRT命令の属性が値のオペランドにT/C/CTH/CTCを指定した場合は、以下の値がマクロに引き渡されます。
>   - T/C : 現在値（32ビットデータ）
>   - CTH : 現在値（32ビットデータ）
>   - CTC : 設定値（32ビットデータ）
> - 以下の場合、各モジュールが停止もしくは各命令間の実行条件がOFFしたとき、実行中のマクロは停止します。
>   - MCALL/MSTRT命令をモジュールに記述した場合
>   - MCALL/MSTRT命令をマスターコントロール（MC～MCR命令間）に記述した場合
>   - MCALL命令をステージ（STG～JMP命令間）に記述した場合
> - 以下の場合、各命令間の実行条件がOFFしたとき、実行中のマクロは中断します。
>   次に各命令間が実行されたときにマクロの実行を再開します。
>   このときマクロ内の微分実行型命令の前回状態は、初期化されません。
>   （初期化モジュール内に記述した場合は、　運転開始時1スキャンのみ実行します。）
>   - MCALL/MSTRT命令をサブルーチン（SBN～RET命令間）に記述したとき
>   - MCALL/MSTRT命令を条件分岐（CJ/NCJ～LABEL命令間）に記述したとき
>   - MCALL/MSTRT命令をステップ（STP～STE命令間）に記述したとき
>   - MCALL/MSTRT命令を割り込み（INT～RETI命令間）に記述したとき
>   - MSTRT命令をステージ（STG～JMP命令間）に記述したとき
> - マクロ内で、MCALL命令、MSTRT命令は使用できません。
> - ファンクションブロック・ファンクション内でMCALL/MSTRT命令は使用できません。
> - マクロ内でサブルーチンプログラムを使用できますが、割り込みプログラムは使用できません。
> - プロジェクト内で同じマクロを複数回実行する場合、マクロ内でOUT/OUB命令にグローバルデバイス/グローバル変数を使用すると、2重コイルになります。

### サンプルプログラム

(4-11 / 原本 p.293 / 4-195)

使用デバイス:

| デバイス | 内容 |
|---|---|
| R000 | 入力リレー(マクロA 実行条件) |
| R001 | 入力リレー(マクロB 起動、立ち上がり) |
| R002 | 入力リレー(マクロB 停止、マクロB内) |
| EM0 | マクロA 引数1 |
| #10 | マクロA 引数2 / マクロB 引数2 |
| #1 | マクロB 引数1（ユニット番号） |

(原本の図中デバイス 6件 → md 6行)

入力リレーR000がONの間、引数1をEM0、引数2を#10としてサブルーチン型マクロ「マクロA」を実行します。

〈ニモニックリスト〉(原本記載のまま)
```
LD     R000
MCALL  マクロ A EM0 #10
```

入力リレーR001の立ち上がりで、引数1（ユニット番号）を#1、引数2を#10として自己保持型マクロ「マクロB」の実行を開始します。

〈ニモニックリスト〉(原本記載のまま)
```
LDP    R001
MSTRT  マクロ Ｂ #1 #10
```

入力リレーR002がONの時、自己保持型マクロ「マクロB」を停止します。

〈ニモニックリスト〉(原本記載のまま。マクロB内に記述)
```
LD     R002
MEND
```

## マクロとサブルーチンプログラムの違い

(4-11 / 原本 p.294-297 / 4-196〜4-199)

マクロはサブルーチンプログラムと同様に、呼び出し命令によって動作します。マクロの動作をサブルーチンの動作と比較して説明します。
サブルーチンプログラムについての詳細は、 「サブルーチンプログラム」（4-94ページ）を参照してください。

### ● 実体の作成

(4-11 / 原本 p.294-295 / 4-196〜4-197)

【マクロ】
モジュール内でマクロ呼び出し命令（MCALL、MSTRT）を記述するごとに、同じ数の実体が作成されます。

> **参考**
> - プロジェクトに登録されていて一度も呼び出されないマクロ（未使用マクロ）は、CPU ユニットへ転送されません。未使用マクロは、プロジェクト照合時やPLCとの照合時に照合する対象に含まれません。
> - 作成したマクロの実体を区別するために、マクロ名の後ろに「#（管理番号）」を付けて管理します。《KV STUDIO》では、モニタ・シミュレータ時のみ表示されます。

【図】マクロの実体の作成 (原本 p.294)
- モジュール1 に MCALL マクロA ×2、モジュール2 に MCALL マクロA ×2
- それぞれの呼び出しから マクロA#1、マクロA#2、マクロA#3、マクロA#4 が作成される
- 図中の文言: 「呼び出されるごとにそれぞれ実体が作成されます。」「プロジェクトに登録されているマクロA」

【サブルーチン】
プログラム内のEND命令とENDH命令間に作成し、そのプログラムのメインルーチンプログラム内に記述されたサブルーチンコール命令（CALL）によって実行されます。呼び出し命令ごとに実体が作成されることはありません。

【図】サブルーチンの呼び出し (原本 p.295)
- モジュール1: `CALL #0` ×3 → END → `SBN #0` 〜 `RET` → ENDH。3つの CALL #0 はすべて同じ SBN #0 を呼び出す
- モジュール2: END → `SBN #0` 〜 `RET` → ENDH。モジュール1の CALL #0 からモジュール2の SBN #0 は呼び出せない(×)
- 吹き出し: 「ECALL命令を使用すれば、他モジュールのサブルーチンを実行できます。」

### ● 呼び出せる箇所

(4-11 / 原本 p.295 / 4-197)

【マクロ】
マクロ呼び出し命令は、モジュール内であれば、メインルーチン／サブルーチン／割り込みルーチンのどこにでも記述できます。マクロ内にはマクロ呼び出し命令を記述できません。

【サブルーチン】
サブルーチンコール命令は、サブルーチンを作成したプログラム内のみ有効です。他のモジュール内のサブルーチンを実行する場合は、モジュール間サブルーチンコール命令を使用します。

### ● 名称

(4-11 / 原本 p.295 / 4-197)

【マクロ】
自由に名前を決められます。
- 参照: 「使用できない文字一覧」（付-40ページ）

【サブルーチン】
番号で管理します。

### ● 引数

(4-11 / 原本 p.296 / 4-198)

【マクロ】
引数を持てます。

【サブルーチン】
引数を持てません。

### ● 実行条件OFF時の動作

(4-11 / 原本 p.296 / 4-198)

【マクロ】
「実行停止時にOFF処理する」にチェックしていない場合、マクロ内のプログラムは実行されません。記述された各デバイスは、最後に実行された時の状態を保持します。
「実行停止時にOFF処理する」にチェックしている場合、停止時に1スキャンのみマクロ内のプログラムの全ての実行条件をOFFとして実行します。例えば、OUT命令で記述されたデバイスは自動的にOFFになります。
- 参照: 「マクロの種類」（4-181ページ）

【サブルーチン】
サブルーチン内のプログラムは実行されません。記述された各デバイスは、最後に実行された時の状態を保持します。

> **ポイント**
> KV-8000Aの場合は設定は表示されず、常に「実行停止時にOFF処理する」にチェックしている場合と同じ動作になります。

### ● 微分実行型命令の初期状態

(4-11 / 原本 p.296 / 4-198)

【マクロ】
微分実行型命令などで微分を検出するための前回状態は、実行開始時立ち上がり微分の場合がONに、立ち下がり微分の場合がOFFになります。実行開始時に直ちに微分を検出することはありません。

【サブルーチン】
初回の実行開始時のみマクロと同様です。2回目からの実行開始時は、前回実行時の状態になります。

### ● MC（マスターコントロール）～MCR（マスターコントロールリセット）命令間で呼び出す場合の動作

(4-11 / 原本 p.296 / 4-198)

・MC命令の実行条件がONの時
マクロ、サブルーチンとも通常通りの動作です。

・MC命令の実行条件がOFFの時
【マクロ】
上記の「実行条件OFF時の動作」と同様に停止します。（自己保持型マクロも停止します。）
【サブルーチン】
実行されません。

### ● 使用する場面

(4-11 / 原本 p.297 / 4-199)

**呼び出しているそれぞれの箇所で使用しているデバイスの状態や値を保持したい場合**

【マクロ】・・・○
呼び出し命令ごとに別々に実体を作成するため、ローカルデバイスを併用すれば、デバイスの衝突などを意識せずに前回実行時の状態を保持できます。

【サブルーチン】・・・△
同じプログラムを実行することになるため、間接指定などを使用してデバイスの状態や値を退避・復帰させるプログラムを組む必要があります。

**一通りの動作が完了するまで実行させたい場合**

【マクロ】・・・○
『自己保持型マクロ』を使用すれば、実行開始後はマクロ実行停止命令（MEND）が実行されるまで、実行条件の状態にかかわらず動作し続けます。
また、このような処理を同時に複数実行したい場合も、デバイスの衝突やそれぞれの動作状態を意識せずに使用できます。

【サブルーチン】・・・△
動作完了時まで実行条件がOFFしないようにプログラムする必要があります。
また、このような処理を同時に複数実行したい場合は、デバイスの衝突やそれぞれの動作状態を意識してプログラムする必要があります。

**ステップ数を削減したい場合**

【マクロ】・・・△
呼び出し命令ごとに実体を作成するため、ステップ数を削減できません。

【サブルーチン】・・・○
何度呼び出しても実体を作成しないため、呼び出し回数が多いほどステップ数の削減につながります。
