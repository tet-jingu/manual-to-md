## 4-12 ローカルデバイス

(4-12 / 原本 p.298 / 4-200)

従来、PLCで扱うデバイスはプロジェクト全体で共通の存在でした。そのため、プログラム中に使用する全てのデバイスをユーザ側で管理する必要がありました。
《KV STUDIO》では、プログラムごとに独立したデバイスとして使用可能なローカルデバイスを扱えます。別のプログラムで同じ番号のローカルデバイスを使用しても、別のデバイスとして扱われるため、モジュール内やマクロ内のみで使用するデバイスの割り付けが簡単に管理できます。
各プログラム内のみで有効なローカルデバイスに対して、プロジェクト全体で共通して扱うデバイスをグローバルデバイスと呼びます。

【図】従来とKV STUDIOのデバイス管理の比較 (原本 p.298)
- ＜従来＞: 「プロジェクト」の中に「プログラム」と「（グローバル）デバイス」が1つずつ並ぶ。
- ＜KV STUDIOでは＞: 「プロジェクト」の中に「モジュールA」「モジュールB」「マクロC」があり、それぞれが「プログラム」と「ローカルデバイス」を持つ。プロジェクト全体に共通の「グローバルデバイス」が別にある。

### ローカルデバイスの記述方法

(4-12 / 原本 p.298 / 4-200)

ローカルデバイスの指定は、デバイス名の先頭に「@」を付けて記述します。

**例**

| ＜グローバルデバイス＞ | ＜ローカルデバイス＞ |
|---|---|
| EM0 | @EM0 |
| MR0 | @MR0 |

(原本の表 2行 → md 2行)

> **ポイント**
> タイマ・カウンタ命令のオペランドとしてデバイス番号を指定する場合のみ、「@＋（デバイス番号）」と記述します。
> （ニモニック入力例 : TMR @0 #100）

### ローカルデバイス一覧

(4-12 / 原本 p.299 / 4-201)

プロジェクト作成時に確保されるローカルデバイス/グローバルデバイスの個数・範囲の初期値を下記に示します。ローカルデバイスの予約個数は、[ワークスペース]上の[CPUシステム設定]→[ローカル全体割付設定]で変更できます。

| デバイス名※1 | ローカルデバイス: プロジェクト全体での予約個数※2 | グローバルデバイス: 個数・範囲 | 合計個数 |
|---|---|---|---|
| リレー（R）※3 | なし | 32000 点（2000ch） R000 ～ R199915 | 32000 点（2000ch） |
| 内部補助リレー（MR）※3 | 32000 点（2000ch） | 32000 点（2000ch） MR000 ～ MR199915 | 64000 点（4000ch） |
| ラッチリレー（LR）※3 | 8000 点（500ch） | 8000 点（500ch） LR000 ～ LR49915 | 16000 点（1000ch） |
| タイマ（T）※4 | 1500 点 | 2500 点 T0 ～ T2499 | 4000 点 |
| カウンタ（C）※4 | 1500 点 | 2500 点 C0 ～ C2499 | 4000 点 |
| データメモリ（DM） | 25000 点 | 40535 点 DM0 ～ DM40534 | 65535 点 |
| 拡張データメモリ（EM） | 45000 点 | 20535 点 EM0 ～ EM20534 | 65535 点 |
| テンポラリデータメモリ（TM） | なし | 512 点 TM0 ～ TM511 | 512 点 |

(原本の表 8行 → md 8行)

- ※1 リンクリレー（B）、リンクレジスタ（W）、ファイルレジスタ（ZF）、コントロールリレー（CR）、コントロールメモリ（CM）、インデックスレジスタ（Z）は、ローカルデバイスとして使用できません。
  @FMxxxを使用した場合、ワーク領域をローカルデバイスとして消費します。
- ※2 プロジェクト新規作成時に、ローカルデバイスとして使用可能なデバイスの領域を一括で確保します。（モジュールを10個使用して、マクロを50回呼び出すと想定して計算しています。）各デバイスの予約個数は任意に変更できます。
- ※3 チャンネル（ch）単位で使用個数を設定します。
- ※4 タイマ・カウンタ命令のオペランドとしてデバイス番号を指定する場合のみ、「@＋（デバイス番号）」と記述します。（ニモニック入力例 : TMR @0 #100）。

> **ポイント**
> - リレー（R）とテンポラリデータメモリ（TM）をローカルデバイスとして使用する場合は、使用個数を設定する必要があります。
> - 以下のデバイスは、グローバルデバイスとして扱う必要があります。
>   - CPUユニットや拡張ユニットに割り当てられているデバイス
>   - タッチパネルなどの外部接続機器で参照するデバイス
>   - プロジェクト全体で共通して使用するデバイス
>   - モジュール間でデータの受け渡しが必要なデバイス
> - ローカルデバイスは、0番を先頭にできるだけ詰めて使用してください。
> - RやDMはユニットに割り当てられるため、グローバルデバイスとして使用する領域が必要です。ローカルデバイスは、MRやEMを優先して使用してください。
> - 使用可能範囲外でローカルデバイス/グローバルデバイスを使用すると、変換エラーになります。
> - オペランドに先頭デバイスを指定する各命令語、インデックス修飾、間接指定を使用する場合は、ローカルデバイス/グローバルデバイスの使用可能範囲を超えないようにしてください。

### ローカルデバイスの割付

(4-12 / 原本 p.300 / 4-202)

ローカルデバイスは変換時、デバイスの種類ごとにあらかじめ用意されている予約領域に自動的に割り付けられます。

【図】ローカルデバイスの割付 (原本 p.300)
- 左: 「プロジェクト1」内に「グローバルデバイス」と、「モジュールA」「モジュールB」「マクロC」(各「プログラム」+「ローカルデバイス」)。
- 右: 「デバイス領域」(先頭〜最後)。先頭側が「プロジェクト1のグローバルデバイス」、その後ろが「ローカルデバイスの予約領域」で、上から「モジュールAのローカルデバイス」「モジュールBのローカルデバイス」「マクロCのローカルデバイス」「未使用」(最後)。
- 各モジュール/マクロのローカルデバイスが「変換」の矢印で予約領域内の各区画に割り付けられる。

> **ポイント**
> ファンクションブロック、マクロの場合、プロジェクト内で呼び出す回数分のローカルデバイスを割り付けます。
> ファンクションブロックの種類がファンクションの場合、実体は常に1つになるため、複数回呼び出しても、1つ分のみのローカルデバイスを割り付けます。

> **参考**
> ローカルデバイスには、グローバルデバイスと同様にデバイスコメントを使用できます。

#### ● ラダー入力時

(4-12 / 原本 p.302 / 4-204)

ラダー入力時にエラーになる代表例を以下に示します。

## 4-13 割り込み

(4-13 / 原本 p.304 / 4-206)

### 概要

(4-13 / 原本 p.304 / 4-206)

通常PLCは、入力処理→プログラムの実行→出力処理を繰り返すことで、ラダーシーケンスが進んでいきます。したがって、スキャンタイムより短い信号は入力できません。
割り込み処理機能を使えば、スキャンタイムに依存せずに、割り込みが発生した時点で処理ができます。
割り込みが発生すると、プログラム実行中でもその場で一旦処理を中断し、割り込み要因に応じた割り込みプログラムを実行します。割り込みプログラムが終了すると、中断していたプログラムの処理を再開します。

【図】割り込みの流れ (原本 p.304)
- スキャンタイム: 入力処理 → プログラム実行 → 出力処理 → (入力処理へ戻る)の繰り返し。
- プログラム実行中に「割り込み要因の発生」で「割り込みプログラム実行」へ移り、終了後「割り込み発生の次の命令に戻る」。
- 割り込みプログラム実行には「ダイレクト入力機能」(入力)と「ダイレクト出力機能」(出力)が点線で接続されている。

#### ■ 割り込み要因の種類

(4-13 / 原本 p.304 / 4-206)

プログラムにより設定できる割り込み要因には、拡張ユニットからの割り込み（64個まで）と定周期モジュール（4個まで）、ユニット間同期モジュールがあります。
- 参照: 「定周期モジュール」（4-103ページ）

#### ■ デバイスの処理について

(4-13 / 原本 p.305 / 4-207)

割り込み時のデバイスの処理は以下のとおりです。
入出力処理の詳細については、「割り込み時の入出力処理」（4-212ページ）を参照してください。

【図】デバイスの処理のタイミング (原本 p.305)
- 横軸: 出力処理 → 入力処理 → メインルーチン プログラム → 出力処理 → 入力処理。
- メインルーチン実行中に「割り込み要因発生」(①の位置)で「割り込みプログラム（出力処理）」が挿入される。

**①割り込みプログラムの開始時/終了時の処理**
割り込みプログラムの開始時に、内部レジスタ、演算フラグ、TM0～TM3、Z11～Z23の値をシステム内に記憶し、割り込みプログラム終了時に記憶した値に戻します。
割り込み中にこれらの値を変更してもメインルーチンプログラムには影響しません。変更した値は、割り込みプログラム中のみ有効になります。
その他のデバイスは、割り込みプログラム中に変更した値が、割り込みプログラム終了後、メインルーチンプログラムに反映されます。

> **ポイント**
> インデックスレジスタZ1～Z10は、CPUシステム設定の「ユーザ割り込み設定」で退避/復帰処理をするように設定できます。

> **参考**
> 自動的にリフレッシュされないデバイス値を最新の状態に更新するには、以下のように処理してください。
> - 「DR」で入出力リレーを記述します。
> - 「RFSX/RFSY」命令を記述します。
>
> 参照: 「ダイレクト処理について」（4-83ページ）

#### ■ 処理時間

(4-13 / 原本 p.305 / 4-207)

以下の条件をすべて満たす場合、割り込みプログラム開始までの時間は15µs以内（TYP.4µs）になります。
- 〔CPUシステム設定〕の〔ユーザ割り込み設定〕で、「命令実行中に割り込み許可する」をチェックしている場合
- その割り込みプログラムより優先度の高い割り込みプログラムを使用していない
- KV-5000/3000シリーズ用拡張ユニットを使用していない（使用した場合は最大+14µs）
- ユニット間同期の入力リフレッシュ、もしくは出力リフレッシュにて大量のデバイスをリフレッシュ対象にしていない
- ロギング/トレース設定で、1つのIDで513ワード以上のデバイスを登録していない

なお、割り込みプログラムの起動/終了処理（各デバイスのリフレッシュ/退避/復帰）時間は合計2.5µsです。

> **参考**
> 割込み開始までの処理時間は上記のとおりですが、割り込みプログラムの先頭でKV-5000/3000シリーズ用拡張ユニットに対してダイレクト処理命令を実行した場合、処理完了までの時間がかかることがあります。
> - KL-N20V, KV-CL20, KV-DN20, KV-H20, KV-H20S, KV-H40S使用時：115µs
> - 上記以外のKV-5000/3000シリーズ用の拡張ユニット使用時：55µs

### 割り込みプログラムの実行方法

(4-13 / 原本 p.306 / 4-208)

以下のようにプログラムを記述することで、割り込み処理が可能になります。

**割り込みプログラムの例** (原本 p.306、ラダー図から書き起こし。原本にニモニックリストの掲載なし)

| デバイス / オペランド | 内容 |
|---|---|
| CR2008 | 運転開始時1スキャンON |
| IEDGE #1 #0 #1 | ユニット番号 #1 (KV-SIR32XT) / 入力番号 #0 / 検出条件 #1 |
| INT #1 #0 | ユニット番号 #1 / 割込要因 #0 |

(原本の表なし → md 3行: ラダー図中の注記を整理)

```
LD   CR2008
EI                      ; メインルーチンプログラム
LD   CR2008
IEDGE #1 #0 #1          ; KV-SIR32XT ユニット番号#1 入力番号#0 検出条件#1
 (中間の回路は原本で波線表記)
END
INT  #1 #0              ; 割り込みプログラム ユニット番号#1 割込要因#0
 (割り込み処理内容は原本で波線表記)
RETI
ENDH
```

- メインルーチンプログラム: EI命令を実行しないと割り込みプログラムは実行できません
- ※KV-SIR32XTの入力状態で割り込みを実施する場合は、IEDGE命令を使用して割り込み検出条件を設定します。
- 割り込みプログラム: 割り込みプログラムは、「END」、「ENDH」間に記入します。

#### ■ 割り込み許可（EI）命令

(4-13 / 原本 p.306 / 4-208)

運転開始時は、割り込みが禁止状態になっています。
割り込みプログラムを実行するには、割り込み許可（EI）命令を実行する必要があります。
メインルーチンプログラム内に、EI命令を記述してください。

> **参考**
> - 割り込みを禁止する場合は、割り込み禁止（DI/DIC）命令を使用します。
> - 割り込み禁止時に割り込みが発生しても、次に割り込みを許可されるまで処理を保留します。
> - 割り込みプログラムの開始時は、割り込み許可状態です。
> - 割り込み許可（EI）命令を実行していない場合でも周辺処理実行によるシステム割り込みは実行されます。

- 参照: 「EI命令」4-218ページ
- 参照: 「DI命令」4-218ページ、「DIC命令」4-220ページ

#### ■ INT/RETI命令

(4-13 / 原本 p.306 / 4-208)

END/ENDH命令の間に、割り込み要因をオペランドにしてINT命令を記述します。
INT命令の後に割り込み処理内容をプログラムして、最後にRETI命令を記述します。

> **ポイント**
> - 1つの割り込み要因に対してINT命令は1回のみ記述できます。
> - 割り込みプログラム内では、使用できない命令語があります。
>   「割り込みプログラムで使用できない命令語」（4-210ページ）を参照してください。
> - KV-SIR32XTを使用して割り込み実行時に、割り込み応答を高速にする場合は、ユニットエディタの設定で入力時定数を小さく設定してください（初期値：10µs)。

- 参照: 「INT/RETI命令」（4-222ページ）

### 割り込みの優先度

(4-13 / 原本 p.307 / 4-209)

複数の割り込み要因が同時に発生した場合の優先度を設定できます。
《KV STUDIO》のワークスペースから[CPUシステム設定]を開いて、[プログラムの設定]の[定周期実行とユーザ割り込み設定]で設定します。

【図】[CPUシステム設定]→[定周期実行とユーザ割り込み設定] 画面 (原本 p.307)
- 「定周期／ユニット間同期モジュールの設定(C)」: 列 モジュール名 / 周期 / 単位 / 運転開始時に実行状態にする。行 一定サンプリング 100.00 ms ☑、低速サンプリング 100.00 ms ☑
- 「割り込み優先度の設定(S)」: 列 項目 / 割込要因 / 優先度。行 一定サンプリング(中)、低速サンプリング(中)、[1]KV-XH16ML [0]制御周期(高)、[2]KV-XLE02 [0]ユニット割り込み要因0(低)
- チェック項目: ☑「命令実行中に割り込み許可する(N)」、☐「割り込みプログラム起動時にZ1〜Z10を退避し、完了時に復元する(Z)」、ボタン「初期化(I)」
- ボタン: OK / キャンセル / 適用(A)

優先度は「高/中/低」で設定できます。割り込みプログラム実行中は、自身より高い優先度の割り込みは受け付けますが、同じか低い優先度の割り込みは実行中の割り込みプログラムが終了するまで保留されます。
また、「命令実行中に割り込み許可する」にチェックを付けると、処理時間の長い命令語の実行途中に割り込めるため、割り込み応答時間のばらつきを抑制できます。
割り込みプログラム実行中に別の割り込みが発生した場合、優先度の設定により動作が異なります。以下の表を参考にしてください。

| 実行中割り込みプログラム（A）の優先度 | 発生した割り込みプログラム（B）の優先度: 高 | (B): 中 | (B): 低 |
|---|---|---|---|
| 高 | 保留 | 保留 | 保留 |
| 中 | 即実行 | 保留 | 保留 |
| 低 | 即実行 | 即実行 | 保留 |

(原本の表 3行 → md 3行)

- 保留　 : 現在実行中の割り込みプログラム（A）終了後に、発生した割り込みプログラム（B）を実行します。
- 即実行 : 現在実行中の割り込みプログラム（A）を中断し、発生した割り込みプログラム（B）を実行します。割り込みプログラム（B）の実行が終了した後、割り込みプログラム（A）が再開します。

### 割り込み時の入出力処理

(4-13 / 原本 p.310-311 / 4-212〜4-213)

#### ■ 入力処理

(原本 p.310 / 4-212)

割り込みプログラム開始時、そのスキャンの入力処理（I/Oリフレッシュ）で取得した状態です。
割り込みプログラム内で、その時点の入力リレーの状態を取得するため、DRでリレー番号を指定する、またはダイレクトリフレッシュ命令（RFSX命令）を使用してリフレッシュを行う必要があります。

**例**

【図】入力処理のタイミングと各時点のラダー状態 (原本 p.310)
- R30000: OFF→ON の立ち上がりで「割り込み要因発生」。
- R30001・R30002: メインルーチンの入力処理の後、割り込み要因発生より前に OFF→ON。
- 入力処理(1回目)で取り込んだ状態: R30001:OFF / R30002:OFF。次スキャンの入力処理: R30001:ON / R30002:ON。
- 各時点の回路の状態(左から):
  1. メインルーチン(1回目入力処理後): R30001 OFF、R30002 OFF
  2. 割り込みプログラム内: DR30001 ON、R30002 OFF
  3. メインルーチン(割り込み後、次の出力処理前): DR30001 ON、R30002 OFF
  4. 次スキャン(入力処理後): R30001 ON、R30002 ON
- 割り込みプログラム内の回路(図から): DR30001 の接点 → コイル、R30002 の接点 → コイル。**要確認**: 出力コイルのデバイス名は図に記載なし(原本 p.310 参照)。

上記のような割り込みプログラムが実行されると、
- ①メインルーチンプログラムの入力処理 → R30001 : OFF　R30002 : OFF
- ②割り込みプログラムの入力処理 → R30001 : ON　R30002 : OFF

になります。
入力リレーDR30001はダイレクト入力なので、割り込みプログラム実行時の状態が取り込めます。
入力リレーR30002は割り込みプログラム中でも、メインルーチンプログラムの入力処理の状態で扱われます。
メインルーチンプログラムでは割り込みプログラム内でダイレクトリフレッシュをしているので、割り込みプログラム内の状態（ON)になります。

#### ■ 出力処理

(原本 p.311 / 4-213)

割り込みプログラムには出力処理がありません。割り込みプログラム終了後、メインルーチンプログラムの出力処理（自動リフレッシュ）で外部に出力します。
ただし、出力リレーをDRと記述すると（DR30200など）、プログラムが実行されると、直ちに外部に出力されます。（ダイレクト出力）

**例** (原本 p.311、割り込みプログラム内の回路をラダー図から書き起こし)

```
LD   CR2002        ; ①
SET  DR30200       ;   ダイレクト出力 → 直ちに外部出力
LD   CR2002        ; ②
SET  R30201        ;   通常出力 → メインルーチンの出力処理で外部出力
```

【図】出力処理のタイミング (原本 p.311)
- メインルーチン プログラム実行中に割り込みプログラム(①②)が挿入される。
- ①の実行時点で「R30200:出力」、②の実行時点では内部処理のみで、外部への「R30201:出力」はメインルーチン後の出力処理のタイミング。

上記のような割り込みプログラムが実行されると、
- ①行目で、出力リレーDR30200はダイレクト出力リレーなので、直ちに外部に出力します。
- ②行目で、出力リレーR30201は内部処理ではONしますが、ダイレクト出力リレーではないのでメインルーチンプログラムの出力処理で外部に出力されます。

**例**
割り込みプログラム内でダイレクト出力したい場合は、出力リレーにDRを使用してください。

> **参考**
> 自動的にリフレッシュされないデバイス値を最新の状態に更新するには、以下のように処理してください。
> - 「DR」で入出力リレーを記述します。
> - 「RFSX/RFSY」命令を記述します。
> - 「UREAD/UWRIT」命令などダイレクトリフレッシュ命令を記述します。
> - ユニット専用命令を記述します。
>
> 参照: 「ダイレクト処理について」（4-83ページ）

- 実行条件 ─[ ↑IEDGE n1 n2 S ](微分) … 入力方法: [@][I][E][D][G][E][␣][n1][␣][n2][␣][S][↵]

| オペランド | 説明 | 占有サイズ |
|---|---|---|
| n1 | ユニット番号（0～48）を指定します。 | 16ビット |
| n2 | 入力番号またはそれを格納する先頭を指定します。（0～31）※2 | 16ビット |
| S | 検出条件またはそれを格納する先頭を指定します。（0～3）※2 | 16ビット |

(原本の表 3行 → md 3行)

- ※1 定数のみ指定可能です。
- ※2 ビットデータを指定する場合は、チャンネルの先頭を指定してください。

> 補足(原文にはない): 原本 p.322 のオペランド表には※1の付いた行が見当たりません。**要確認**: ※1の対象オペランド(n1と思われる)は原本 p.322 参照。

**動作説明** (原本 p.323 / 4-225)
- **IEDGE** 実行条件がONの時、S で指定した1ワードのデータを n1 番目のユニットの n2 番目の要因の割り込みの検出条件に設定します。
  S の値により、検出条件は以下のようになります。

| S | 検出条件 |
|---|---|
| 0～1 | 立ち上がり |
| 2 | 立ち下がり |
| 3 | 立ち上がり・下がり両方 |

(原本の表 3行 → md 3行)

> **ポイント**
> - S に4～65535を指定した場合は演算エラーにはなりませんが、検出条件は変更されません。
> - 本命令が実行完了したタイミングで、上記検出条件の設定が変更されます。

- **@IEDGE** 実行条件の立ち上がりで、1スキャンだけ実行します。

**演算フラグ**

| フラグ | 内容 |
|---|---|
| CR2009 | 変化なし |
| CR2010 | 変化なし |
| CR2011 | 変化なし |
| CR2012 | 以下の場合はON、それ以外はOFF。<br>• 間接指定、インデックス修飾の範囲が不適切な場合。<br>• n1 で指定したユニット番号が49以上の場合<br>• n2 で指定した入力番号が32以上の場合<br>• S から連続した16ビットの領域を確保できない場合<br>• n1 で指定したユニット番号のユニットがKV-SIR32XTではない場合<br>• オペランドの範囲外アクセスが発生した場合 |

(原本の表 4行 → md 4行)

- ※ CR2012がONした場合、命令は実行されません。
  CR2012がONした場合、CM5150～CM5176にエラーの詳細情報が格納されます。
