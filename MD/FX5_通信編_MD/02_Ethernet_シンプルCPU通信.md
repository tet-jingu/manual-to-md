## 0. 結論サマリ

- シンプルCPU通信＝**パラメータ設定だけで相手機器とデバイスデータを送受信する「プログラムレス」通信**。
- **交信設定が「定期」の場合、ラダーは一切不要。**
- **交信設定が「要求時」の場合のみ、要求を送信するラダーが必要**（`SD10350` / `SD10351` の該当ビットをOFF→ONする）。
- 状態監視・エラー監視をラダーで行う場合は、`SD10356`〜`SD10359`、`SD10380`〜、`SD10412`〜 を使う。
- 最大接続台数: FX5S/FX5UJ **8台** / FX5U・FX5UC **16台** / Ethernetユニット **32台**。

## 2. 交信設定と、ラダーの要否

| 交信設定 | 動作 | ラダー |
|---|---|---|
| **定期**（デフォルト） | 設定した実行間隔（10ms〜65535ms、1ms単位）で自動的に交信する | **不要** |
| **要求時** | 設定No.に対応する **要求時交信開始要求のOFF→ON** で交信を実施する | **必要**（§4） |

主なパラメータ項目:

| 項目 | 内容 |
|---|---|
| 通信パターン | 読出 / 書込 |
| 交信設定 | 定期 / 要求時 |
| 実行間隔 | 10ms〜65535ms（交信設定＝定期のとき） |
| 交信相手 | IPアドレス、ポート番号、機器種別 |
| ビットデバイス | 転送元／転送先の種別・先頭・最終 |
| ワードデバイス | 転送元／転送先の種別・先頭・最終 |
| 通信タイムアウト時間／通信リトライ回数／異常監視時間 | タイミング関連 |

## 4. ラダー実装パターン（要求時交信）

### 4.1 基本形（設定No.1・CPUユニット内蔵Ethernet）

```
<<要求発行>>
X0(交信要求指示)  SD10358.0(準備完了)  SD10356.0(実行状態・b接点)
──┤├──────────┤├──────────────┤/├──[ SET SD10350.0 ]   ; 要求時交信開始要求ON

<<要求解除（交信開始を確認したら落とす）>>
SD10356.0(実行状態)
──┤├──[ RST SD10350.0 ]

<<状態監視>>
[= SD10380 H3] ──( 実行中表示 )
[= SD10380 HA] ──( 交信不可表示 )

<<エラー監視>>
[<> SD10412 K0]
──┤├──[ MOV SD10412 D100 ]   ; エラーコード退避
          [ MOV SD10476 D101 ]   ; 異常応答コード（CFB4H時のみ有効）
          [ SET M900 ]           ; エラー表示
```

### 4.2 Ethernetユニット（FX5-ENET）の場合

```
X0  Un\G313.0(b接点)
──┤├──────┤/├──[ SET Un\G300.0 ]   ; 設定No.1の要求時交信開始要求
Un\G313.0 ──[ RST Un\G300.0 ]
```

### 4.3 要求時交信の注意（必読）

- **要求は「OFF→ONの立上り」で実施される。** 常時ONでは繰り返し実行されない。
- **要求時交信を実行中、または準備完了がOFFの間に要求(`SD10350`/`SD10351`)をOFFすると、要求時交信は実行されない。**
  → 準備完了フラグを確認してからONし、実行状態フラグがONしてからOFFする。
- 要求ONから交信完了までの時間は、Ethernet回線の負担率・他通信機能の動作状態・交信相手のスキャンタイム・システム構成によって変動する。

| 項目 | 設定値 |
|---|---|
| 通信パターン | 書込 |
| 交信設定 | 要求 |

## 6. プログラム作成・設計上の注意（違反するとトラブルになる）

1. **自局ポート番号を重複させない。** 次の場合はシンプルCPU通信が実行できない:
   - シンプルCPU通信の自局ポート番号と、相手機器接続構成設定のポート番号が重複
   - ソケット通信など他機能のポート番号と重複
   - シンプルCPU通信設定同士でポート番号が重複
2. **交信相手のIPアドレスと機器種別を事前に確認する。** 相手が存在しない／機種設定が誤っていると準備処理が完了せず実行できない。
3. **通信パターンが「書込」の場合、交信相手の制御データを書き換える可能性がある**（誤動作の原因）。相手先のデバイス種類・範囲を必ず確認する。
4. **本機能の実行中は、他の通信機能はTCPで通信することを推奨。** UDPで併用すると受信取りこぼしやタイムアウトが起きることがある。
5. **実行間隔を短くするとSDメモリカードへのアクセスが遅れる**（データロギング、メモリダンプ、拡張ファイルレジスタ、イベント履歴、バックアップ/リストア、FTPサーバ/クライアント、Webサーバ）。通信頻度を下げる（実行間隔・通信タイムアウト時間・異常時監視時間を長くする、設定数を減らす）。
6. **IPフィルタ機能で交信相手を遮断していると実行できない。** 相手側のセキュリティ機能も解除する。
7. **リモートパスワードが設定されていると実行できない。** 交信相手先のリモートパスワードを解除する。
8. **システム側でセットするSM/SDには書き込まない**（システムダウン・通信エラーの原因）。
9. 自局デバイスに**ファイルレジスタ(R)** を使う場合、設定範囲分のデバイスを確保する。範囲外だとその設定No.は実行されない。
10. **Ethernetユニットは交信相手1台（1グループ）につき1コネクションを占有する。**
    最大接続台数 = 32 −（SLMPなど他機能で占有しているコネクション数）
11. 交信相手が二重化システムの場合、**制御系IPアドレス**を交信相手先IPアドレスに設定する。
12. **交信相手がMODBUS/TCP対応機器でブロードキャスト(00H)を指定する場合**:
    - 通信パターンに「読出」を指定しない（応答が返らずタイムアウトになる）
    - 同じ設定No.でビットデバイスとワードデバイスを同時に設定しない（1設定につきどちらか片方）
    - 複数設定する場合、自局ポート番号をすべて異なる値にする
    - **通信リトライ回数 = 0、通信タイムアウト時間 = 異常監視時間** に設定する

## 7. トラブルシューティング（シンプルCPU通信のみ）

### 7.1 診断ツール

`[診断]` → `[シンプルCPU通信診断]` で、設定No.ごとに 通信パターン／交信設定／交信相手／状態／IPアドレス／ポート番号／実行間隔(現在・最大・最小)／正常完了回数／異常完了回数／リトライ回数／最新エラー／エラー詳細 を確認できる。

- `[最新エラーコードをクリア]` ボタンで、`SD10412`〜（CPUユニット）／`Un\G416`〜（Ethernetユニット）もクリアされる。
- **最新エラーは通信が正常に戻っても表示されたまま**になる（別エラー発生時に上書きされる）。

### 7.2 交信相手と通信できない

| 確認項目 | 処置方法 |
|---|---|
| エラーコード（診断画面／`SD10412`〜）にエラーが出ていないか | エラー要因を取り除く。通信リトライ回数・通信タイムアウト時間を増やすと通信できる場合は設定を見直す。ケーブル・ハブ・ルータなど回線状況（混雑）を確認する |
| 通信状態が「準備中(1H)」のままになっていないか | CPUユニットとハブ間のケーブル状態、ハブの動作を確認する |
| 通信状態が「交信不可(AH)」のままになっていないか | その設定No.の**自局ポート番号が他機能と重複していないか**確認する |
| パラメータが書き込まれているか | エラーコードを確認して処置する。再度パラメータを書き直す |
| パラメータを間違えて設定していないか | IPアドレス・機器種別・デバイス範囲を確認する |

### 7.3 通信が不安定

| 確認項目 | 処置方法 |
|---|---|
| エラーコードにエラーが出ていないか | エラー要因を取り除く |
| 通信リトライが発生していないか | ケーブル・ハブ・ルータなどの回線状況（混雑）を確認する |
| シンプルCPU通信中にパラメータを書き換えていないか | エラーコードを確認して処置し、電源OFF→ONまたはリセットする |

### 7.4 設定した実行間隔で交信できない

| 確認項目 | 処置方法 |
|---|---|
| CPUユニットのスキャンタイムが長くないか | スキャンタイムを短くする／実行間隔の設定値を大きくする |
| 他のEthernet通信機能を同時実行していないか | 同時実行しているEthernet通信機能を見直す |
| SLMP対応機器からの応答が遅くないか | 交信相手の機能実行状況を確認する／実行間隔を見直す |

### 7.5 シンプルCPU通信のエラーコード

エラーコードは `SD10412`〜`SD10443`（設定No.1〜32）に格納される。

| コード | 異常内容と原因 | 処置方法 |
|---|---|---|
| 4006H | 初期通信に失敗した | 通信開始のタイミングをずらす |
| 4030H | 指定したデバイス名が扱えない | 指定したデバイス名を確認する |
| 4031H | 指定したデバイスNo.が範囲外である | 指定したデバイスNo.を確認する |
| C0B2H | 中継局/相手局で受信バッファ・送信バッファに空きがない | 要求間隔（実行間隔）を空ける／アクセスが1局に集中しないようにする／応答を待ってから次の要求を行う |
| C201H | 交信に使用したポートがリモートパスワードのロック状態である | リモートパスワードのアンロック処理を実行してから交信する |
| CFB0H | 再送タイムアウトにより送信に失敗した | 交信相手の動作・回線状態・通信開始待ち時間・IPアドレス/Ethernetアドレスを確認する。相手にARP機能があるか確認する。交信相手がMODBUS/TCP対応機器かつ書込パターンの場合、転送先にInput/Input Registerを指定しない |
| CFB1H | 相手機器と接続できない、または切断された | 接続ケーブル・回線状態・IPアドレス/Ethernetアドレス・ARP機能を確認する |
| CFB2H | 指定された自局ポート番号が重複して使用されている | ポート番号が重複しないよう見直す |
| CFB3H | CPUユニットに対する要求に失敗した | CPU応答監視タイマの監視時間、デバイス・ラベルアクセスサービス処理設定を見直す |
| **CFB4H** | **相手機器から異常応答を受信した** | **`SD10476`〜`SD10507`（異常応答コード）を確認する** |
| CFB5H | 相手機器から受信したフレームが異常である | 相手機器の動作・回線状態を確認する |
| CFBFH | シンプルCPU通信を実行できない | ノイズ対策を実施する。再発する場合は三菱電機システムサービスに相談する |

> **CFB4Hの読み解き方**: `SD10412`〜 がCFB4Hのときだけ、`SD10476`〜（シンプルCPU通信異常応答コード）に相手機器側のエラーコードが格納される（交信相手が他社製シーケンサ、MODBUS/TCP対応機器、三菱FX3(Ethernetブロック・アダプタ)の場合）。コードの意味は**相手機器のマニュアル**を参照する。
> CFB4Hは「異常応答が返ってきた場合」と「異常な応答伝文を受信した場合（バイナリ通信時にASCII応答を受信するなど）」の両方で格納される。後者の場合、異常応答コードにはエラーコードではない値が入る。

### 7.6 IPアドレス重複検出

| デバイス（CPUユニット） | デバイス（Ethernetユニット） | 名称 |
|---|---|---|
| SD10251 | Un\G201 | IPアドレス重複状態格納エリア |
| SD10252〜SD10254 | Un\G202〜Un\G204 | IPアドレス重複時に先に接続していたノードMACアドレス |
| SD10255〜SD10257 | Un\G205〜Un\G207 | IPアドレス重複時に後で接続したノードMACアドレス |

**復旧手順（エラーコード 2160H）**

1. ユニット診断でIPアドレス重複異常が発生していないか確認する
2. 通信不良で診断できない場合、別ネットワークで直結接続して、ユニット診断またはイベント履歴で確認する
3. 上記デバイスで重複している機器を特定する
4. IPアドレスをネットワーク内で未使用のものに変更し、電源OFF→ONまたはリセット後に元のネットワークへ接続する

> FX5U/FX5UCのファームウェアバージョンが 1.061 未満の場合、IPアドレス重複検出時にCPUユニットが処理を停止しネットワークダウンする（上記特殊デバイスも非対応）。

## 8. ラダー生成前チェックリスト

- [ ] 交信設定が「定期」なら**ラダー不要**であることを確認したか（不要な回路を作らない）
- [ ] 「要求時」の場合、`SD10350`/`SD10351` の該当設定No.のビットを特定したか
- [ ] 要求のONを**準備完了フラグ（SD10358/SD10359）成立後**に行っているか
- [ ] 要求のOFFを**実行状態フラグ（SD10356/SD10357）がONしてから**行っているか（実行中や準備完了OFF中にOFFすると実行されない）
- [ ] 状態監視に `SD10380`〜、エラー監視に `SD10412`〜 を使っているか
- [ ] CFB4H時に `SD10476`〜（異常応答コード）も確認する回路にしたか
- [ ] 自局ポート番号を他機能・他設定と重複させていないか
- [ ] 「書込」パターンで相手の制御デバイスを壊す設定になっていないか
