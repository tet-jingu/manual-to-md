## 0. 結論サマリ

- FX5がFTPサーバになり、**相手機器（FTPクライアント）がSDメモリカード内のファイルを読出し／書込み／一覧表示**できるようにする機能。
- **ラダーは不要。** パラメータ設定だけで動作する。操作はすべて相手機器（FTPクライアント）側から行う。
- ラダーで考慮すべきことは1点だけ: **稼動中のシステムに対してファイル転送・状態制御が行われるため、システム全体が正常に働くようプログラム上でインタロック回路を構成する**こと。
- **FTPクライアント機能とFTPサーバ機能は同時に使用しない。**
- **同時にログインできる相手機器は1台のみ。**

---

## 1. できること

| 操作 | 内容 |
|---|---|
| 読出し（ダウンロード） | SDメモリカードからファイルを読み出す |
| 書込み（アップロード） | SDメモリカードへファイルを書き込む |
| ファイル名閲覧 | SDメモリカード内のファイル名・情報を表示する |

> **アクセスできるのはCPUユニットに装着したSDメモリカードのみ**（ドライブ2固定）。

## 2. パラメータ設定（GX Works3）

`[パラメータ]` → ユニット形名 → `[ユニットパラメータ]` → `[Ethernetポート]` → `[応用設定]` → `[FTPサーバ設定]`

| 項目 | 内容 | 設定範囲 |
|---|---|---|
| **FTPサーバ使用有無** | 本機能の使用/未使用 | 使用しない / **使用する**（デフォルト: 使用しない） |
| ログイン名 | 相手機器がログインするときのログイン名 | 最大12文字（半角英数字）（デフォルト: **FXCPU**） |
| パスワード設定 | ログイン用パスワード | 半角1〜32文字（数字、アルファベット、特殊文字 `? ! & \ % # * ( ) [ ]` など）（デフォルト: **FXCPU**） |
| FTPタイマ設定（コマンド入力監視タイマ） | FTPクライアントからのコマンド入力を監視する時間 | 1〜16383 s / 100〜16383000 ms（100ms単位・FX5U/FX5UCのみ）（デフォルト: **900s**） |
| FTPタイマ設定（応答監視タイマ） | 要求データ受信から応答を返すまでの監視時間 | 1〜16383 s / 100〜16383000 ms（100ms単位・FX5U/FX5UCのみ）（デフォルト: **5s**） |
| **RUN中書込み許可** | 相手機器からのRUN中書込みの許可/禁止 | **禁止** / 許可（デフォルト: 禁止） |

> - **パスワードはデフォルト（FXCPU）のままでも使用可能だが、不正アクセスの要因になるため変更を推奨。**
> - コマンド入力監視タイマ値を超えてコマンド入力がないと、**FTPコネクションが切断される**。再開にはログインからやり直す。
> - タイマ値を変更するときは、相手機器またはシステム管理者と相談する。

### パスワードを忘れた場合の復旧手順

1. CPUユニットからエンジニアリングツールにパラメータを読み出す
2. `応用設定` で **[デフォルトに戻す]** ボタンをクリックし、応用設定の内容をすべてデフォルトに戻す
3. 再度 `FTPサーバ設定` および `応用設定` を設定する
4. パラメータをCPUユニットに書き込む
5. **電源OFF→ONまたはリセット**でパラメータを有効にする

## 3. ファイル指定の書式

| 項目 | 内容 |
|---|---|
| 指定形式 | `ドライブ名(ドライブ2固定):\フォルダ名\ファイル名.拡張子` |
| 指定例 | `2:\LOGGING\LOG01\00000001\LOG01_00000001.BIN` |
| ドライブ | **ドライブ2（SDメモリカード）固定** |
| 区切り | `\` を使用する |

**ワイルドカード**（複数ファイルを対象にできるコマンドで使用）

| 記号 | 意味 |
|---|---|
| `*` | 指定位置から任意の文字列（なしも含む）すべてのファイルを対象にする |
| `?` | 指定位置が任意の1文字（なしの場合は含まない）のファイルを対象にする（複数使用可） |

## 4. 相手機器（FTPクライアント）側の操作手順

```
1. FTPクライアントの起動                           : ftp
2. CPUユニットへのログイン                         : open <CPUユニットのIPアドレス>
   （FTPがリモートパスワードの対象なら）
   リモートパスワードのアンロック                  : quote password-unlock <リモートパスワード>
3. ファイル変換なしを通知                          : binary
4. ファイル一覧の確認                              : dir  または ls
5-a. 読出し
   （ファイルパスワードが設定されていれば）        : quote passwd-rd <読出しパスワード>
   ファイル読出し                                  : get <ファイル名>
5-b. 書込み
   （ファイルパスワードが設定されていれば）        : quote passwd-wr <書込みパスワード>
   （上書きする場合は先に削除）                    : delete <ファイル名>
   ファイル書込み                                  : put <ファイル名>
5-c. 削除
   （ファイルパスワードが設定されていれば）        : quote passwd-wr <書込みパスワード>
   ファイル削除                                    : delete <ファイル名>
6. （リモートパスワード対象なら）ロック            : quote password-lock
7. 接続の切断                                       : bye
```

### サポートするFTPコマンド

| コマンド | 機能 | RUN中書込み禁止時 | 備考 |
|---|---|---|---|
| `binary` | ファイルを変換せずに転送する通知（CPUユニットは自動的にこの設定） | 実行可 | 省略形 `bin` |
| `bye` / `quit` | 回線の切断と終了 | 実行可 | — |
| `cd` | カレントディレクトリを変更 | 実行可 | 例: `cd 2:\LOGGING\` |
| `close` | 回線を切断 | 実行可 | — |
| `delete` / `mdelete` | ファイルを削除 | **実行不可** | **RUN中はパラメータファイル・プログラムファイルを削除できない** |
| `dir` / `ls` / `mdir` / `mls` | ファイル情報・ファイル名を表示 | 実行可 | `dir` はファイル名・作成日時・容量を表示 |
| `get` / `mget` | CPUユニットからファイルを読み出す | 実行可 | — |
| `put` / `mput` | CPUユニットへファイルを書き込む | **実行不可** | — |
| `open` | FTPサーバと接続 | 実行可 | — |
| `pwd` | カレントディレクトリを表示 | 実行可 | — |
| `quote` | FTPサーバのサブコマンドを送信 | 実行可 | **CPUユニット専用サブコマンドのみ使用可** |
| `user` | ユーザ名・パスワードを入力 | 実行可 | — |

### quoteコマンドで使えるサブコマンド

| サブコマンド | 機能 |
|---|---|
| `passwd-rd` | ファイルパスワード（読出しパスワード）の設定／表示／クリア |
| `passwd-wr` | ファイルパスワード（書込みパスワード）の設定／表示／クリア |
| `password-lock` | リモートパスワードをアンロック状態からロック状態にする |
| `password-unlock` | リモートパスワードをロック状態からアンロック状態にする |

使用例（コマンドプロンプト）: `quote stop`

## 5. 設計・運用上の注意（重要）

### ラダー設計に関わるもの

1. **稼動システムに対するファイル転送・状態制御は、システム全体が正常に働くように設計する。** プログラム上でインタロック回路を構成する。
2. **RUN中書込み許可を「許可」にすると、相手機器から稼働中のCPUに書き込める。** 誤動作リスクを設計時に評価する（デフォルトは禁止）。

### CPUユニット側の処理

3. **ファイルアクセス中に電源OFF・リセット・SDメモリカードの抜き差しを行わない**（ファイルが壊れる可能性がある）。
4. **ファイルアクセス中は、エンジニアリングツールなど周辺機器からのファイル操作を行わない**（RUN中書込みなどのオンライン操作も同様）。中断された処理はFTP機能終了後に再実行する。
5. **FTPクライアント機能とFTPサーバ機能を同時に使用しない。**

### 通信処理

6. ファイル転送でタイムアウトエラーが発生すると **TCP/IP接続はクローズされる**。再開にはログインからやり直す。
7. FTPコネクションでは**相手機器の生存確認**が行われる。
8. **同時にログインできる相手機器は1台のみ。** ログイン状態で他のFTPクライアントから接続するとエラーになる。
9. **FTP転送中にUDP/IPで他の通信機能を同時実行するとタイムアウトなどが発生する場合がある。** 転送後に通信するか、TCP/IPで通信する。
10. 転送処理時間は、Ethernet回線の負担率・同時使用コネクション数・システム構成により変動する。

### ファイル書込み

11. **既存ファイルへの上書き保存はできない。** `delete` / `mdelete` で削除してから書き込む。
12. **読出し専用属性のファイル、FTP以外の機能からロックされているファイルは書き込めない。**
13. **SDメモリカードにプロテクトがかかっていると書込み系の転送はできない。**
14. **容量の大きいファイルを書き込む場合はSTOP状態にする。** RUN状態で書き込むと通信エラーになることがある。
15. 書き込めるファイル数は最大で「書き込めるファイルの最大数 − 1」個まで。

### ファイル削除

16. **ファイル削除のタイミングは、CPUユニットやエンジニアリングツールを含むシステム全体で取り決める。**
17. 読出し専用属性・ロック中のファイルは削除できない。
18. SDメモリカードにプロテクトがかかっていると削除できない。

### FTPクライアント側

19. FTPクライアントによってはFTPコマンドの仕様がマニュアルと異なる場合がある。
20. **Microsoft Internet Explorer からのFTP操作はできない**（エラーになる）。
21. **FTPコマンドで指定するIPアドレスは0埋めしない**（"1" を "001" としない）。

### ポート番号

22. FTPサーバは **20(14H), 21(15H)** を使用する。**ソケット通信やMODBUS/TCPなど他機能でこれらのポート番号を指定しない。**

## 6. トラブルシューティング（FTPサーバのみ）

### 6.1 交信できないときの確認フロー（PDF p.786, 790）

| 確認項目 | 処置方法 |
|---|---|
| CPUユニットはファイル転送機能(FTPサーバ)を使用する設定になっているか | `応用設定` の `FTPサーバ設定` で「FTPサーバ使用有無」を「使用する」に修正する |
| ログイン名・パスワードが間違っていないか | パラメータで設定したログイン名・パスワードを確認して再度ログインする |
| ログイン時のIPアドレスが正しいか | パラメータで設定したCPUユニットのIPアドレスを確認して再度ログインする |
| 実行したコマンドの使用方法が正しいか | コマンドの使用方法を確認し、正しい方法で使用する |
| IPフィルタ設定で相手機器のIPアドレスを遮断していないか | 遮断を解除、または透過アドレスとして設定して再度コマンド送信する |
| エラーコードを確認したか | エラーコードを確認し、異常箇所を修復する（PDF p.792〜） |

上記の処置でも解決できない場合は、各CPUユニットのトラブルシューティングを行い、ハードウェアに異常がないか確認する。

### 6.2 よくある失敗と原因

| 現象 | 原因 |
|---|---|
| `put` が失敗する | 同名ファイルが既に存在する（上書き不可）／読出し専用属性／ファイルロック中／SDカードのプロテクト／RUN中書込み禁止設定 |
| `delete` が失敗する | RUN中にパラメータファイル・プログラムファイルを削除しようとした／読出し専用属性／ロック中／SDカードのプロテクト |
| 途中でコネクションが切れる | コマンド入力監視タイマ（デフォルト900s）超過／生存確認の失敗／タイムアウトエラー |
| 2台目のクライアントが接続できない | **同時ログインは1台のみ** |
| 大きなファイルの書込みで通信エラー | RUN状態で書き込んでいる → STOP状態にする |

## 7. チェックリスト

- [ ] SDメモリカードを装着したか（アクセス対象はドライブ2のみ）
- [ ] 「FTPサーバ使用有無」を「使用する」にしたか
- [ ] ログイン名・パスワードをデフォルトから変更したか（セキュリティ）
- [ ] RUN中書込み許可の設定は意図どおりか（デフォルト: 禁止）
- [ ] コマンド入力監視タイマ・応答監視タイマの値は運用に合っているか
- [ ] FTPクライアント機能と同時に使っていないか
- [ ] 他機能でポート番号 20, 21 を使っていないか
- [ ] **ラダーを書こうとしていないか**（本機能自体にラダーは不要。必要なのは稼動中の安全を守るインタロック設計のみ）
