## 0. 結論サマリ

- CPUユニットがFTPクライアントになり、**専用命令でFTPサーバとファイルを送受信**する機能。ラダー必須。
- 命令は2つだけ:
  - **`SP.FTPPUT`**: CPUユニットのファイルをFTPサーバへ**送付**
  - **`SP.FTPGET`**: FTPサーバのファイルをCPUユニットへ**取得**
- **SDメモリカードが必要**（FX5Sの場合はSDメモリカードユニットが必要）。
- 接続可能なFTPサーバは **1台**、FTP転送モードは **バイナリモード** のみ。
- **FTPクライアント機能とFTPサーバ機能は同時に使用しない。**
- **FTPクライアントは自局ポート番号 62000〜65534 を使用する。** 他機能でこの範囲を使わない。

---

## 1. 転送可能なファイル

| 命令 | 転送できるもの |
|---|---|
| `SP.FTPPUT`（送付） | **LOGGINGフォルダ、DEBUGフォルダ以下のファイル**（ロギングファイル、メモリダンプファイル） |
| `SP.FTPGET`（取得） | FTPサーバ上の**汎用データ**（バイナリデータ、CSVデータなど） |

### パス指定例

| 対象 | パス |
|---|---|
| ロギングファイル | `2:\LOGGING\LOG01\00000001\20200110_00000001.BIN` |
| メモリダンプファイル | `2:\DEBUG\MEMDUMP\MEMDUMP_00.DPD` |
| FTPサーバ上のファイル | `\DATABASE\DATA01.CSV` |

- 区切り文字は半角の `\` または `/`。ただし**FTPサーバによっては `\` を区切り文字として使えない**場合がある。
- ワイルドカード `*` `?` を使用できる（例: `2:\LOGGING\LOG01\00000001\*.*`）。

## 2. 設定手順

1. **FTPサーバ側の設定**: FTPクライアント用のログイン名・パスワード・ホームディレクトリを設定し、**ファイル書込み/読出し権限を付与**する
2. **CPUユニット側のIPアドレス設定**（FTPサーバと同じアドレスクラスにする）
3. **FTPクライアント設定**:
   `[パラメータ]` → ユニット形名 → `[ユニットパラメータ]` → `[Ethernetポート]` → `[応用設定]` → `[FTPクライアント設定]`

| 項目 | 内容 | 設定範囲 |
|---|---|---|
| FTPクライアント使用有無 | 本機能を使うか | 使用しない / **使用する**（デフォルト: 使用しない） |
| FTPサーバ指定 | FTPサーバの指定方法 | FTPサーバアドレス(固定) |
| FTPサーバIPアドレス | 接続先FTPサーバのIPアドレス | 0.0.0.1〜223.255.255.254 |
| ログイン名 | FTPサーバのログイン名 | 1〜32文字（半角英数字・半角記号） |
| パスワード | FTPサーバのパスワード | 0〜32文字（半角英数字・半角記号） |
| 接続方式 | FTPサーバの接続方式 | **PORTモード** / PASVモード（デフォルト: PORTモード） |
| ポート番号 | FTPサーバの制御用ポート番号 | 1〜65535（デフォルト: 21） |

> 動作確認済みFTPサーバ: Microsoft Internet Information Services (IIS)（Windows 10 / 8.1 / 8）

## 3. コントロールデータ（両命令共通の考え方）

| オフセット | 項目 | 内容 |
|---|---|---|
| +0 | **使用用途設定エリア** | **b2: 転送完了ファイル削除設定**（0: 削除しない / 1: 削除する）<br>**b3: ファイル転送時の一時ファイル作成設定**（0: 作成する / 1: 作成しない） |
| +1 | **完了ステータス** | 0: 正常完了 / 0以外: エラーコード（§7.3） |
| +2 | 処理ファイル総数 | 転送対象のファイル総数（ワイルドカード指定時に有効） |
| +3 | 処理完了ファイル数 | 転送が完了したファイル数 |

完了デバイス（他のEthernet専用命令と同じ考え方）:

| デバイス | 動作 |
|---|---|
| (d)+0 | 命令完了で1スキャンON |
| (d)+1 | **異常完了時のみON**。このとき `(s1)+1` にエラーコードが格納される |

## 4. ラダー実装パターン

### 4.1 SP.FTPPUT — ロギングファイルをワイルドカードで一括送付

ロギングファイル切替え完了（`SM1218` の立下り）をトリガに、指定フォルダ内の全ファイルをFTPサーバへ送り、送付済みファイルはSDメモリカードから削除する例。

```
<<コントロールデータ初期化>>
SM402(RUN後1スキャンON)
──┤├──[ SET D0.2 ]   ; b2 = 1: 転送完了ファイルを削除する
          [ RST D0.3 ]   ; b3 = 0: 一時ファイルを作成する

<<転送実行>>
SM1218(ロギングファイル切替え中) の立下り
──┤↓├──[ SET M100 ]                    ; 駆動フラグON

M100  SM600(メモリカード使用可フラグ)
──┤├───────┤├──[ SP.FTPPUT 'U0' D0 "2:\LOGGING\LOG01\00000001\*.*" "LOGGING" M0 ]
                          │   │                                        │
                          │   └ 転送元（CPUユニット側・ワイルドカード可）
                          │                                            └ 転送先（FTPサーバ側フォルダ）
                          └ コントロールデータ先頭 D0（D0〜D3）

<<完了処理>>
M0  ──[ RST M100 ]              ; 命令完了で駆動フラグOFF
M0  M1(b接点) ──[ SET M101 ]    ; 正常完了表示
M0  M1        ──[ SET M102 ]    ; 異常完了表示
M1            ──[ MOV D1 D102 ] ; 完了ステータス（エラーコード）を退避
```

使用デバイス:

| デバイス | 用途 |
|---|---|
| SM402 | RUN後1スキャンのみON |
| SM600 | メモリカード使用可フラグ |
| SM1218 | データロギング設定No.1 ロギングデータ保存ファイル切替え中 |
| D0 | 使用用途設定エリア（D0.2 / D0.3） |
| D1 | 完了ステータス |
| D2 | 処理ファイル総数 |
| D3 | 処理完了ファイル数 |
| D102 | ファイル転送完了ステータス退避先 |
| M0 / M1 | 完了デバイス / 異常完了デバイス |
| M100 | 駆動フラグ |

### 4.2 SP.FTPPUT — 1ファイルずつ順次転送（ファイル名を間接指定）

転送元ファイル名をデバイスに組み立てて指定することで、指定フォルダのロギングファイルを1ファイルずつ順に転送できる。フォルダが切り替わっても継続して転送できる。

```
<<コントロールデータ初期化>>
SM402 ──[ RST D0.2 ]   ; b2 = 0: 転送完了ファイルを削除しない
        [ RST D0.3 ]   ; b3 = 0: 一時ファイルを作成する

<<転送するファイル名を作成>>
SM1218 の立下り
──┤↓├──[ DMOV SD1210 D1000 ]        ; 最新保存ファイル番号(下位/上位)
          [ ASCI D1000 D2000 K8 ]      ; ファイル番号をASCII化
          [ $+ ... D2010 ]             ; "2:\LOGGING\LOG01\00000001\" + 番号 + ".BIN" を連結
          → D200〜D238 に転送元ファイル名文字列を作成

<<転送実行>>
M100  SM600 ──[ SP.FTPPUT 'U0' D0 D200 "LOGGING" M0 ]
```

使用デバイス（追加分）:

| デバイス | 用途 |
|---|---|
| SD1210 / SD1211 | データロギング設定No.1 最新保存ファイル番号（下位／上位） |
| D200〜D238 | 転送元ファイル名（文字列） |
| D1000, D1001 | フォルダ番号算出用 |
| D1010 | 転送元ファイル名の文字列長 |
| D2000〜D2099 | ファイル名編集作業領域 |

### 4.3 SP.FTPGET — FTPサーバからCSVを取得してデバイスに展開

FTPサーバの `DATABASE` から `DATA1.CSV` を取得し、`SP.FREAD` でD1000以降に展開する例。

```
<<コントロールデータ初期化>>
SM402 ──[ RST D200.2 ]              ; SP.FTPGET b2 = 0: 転送完了ファイルを削除しない
        [ RST D200.3 ]              ; SP.FTPGET b3 = 0: 一時ファイルを作成する
        [ MOV H100 D210 ]           ; SP.FREAD 実行タイプ = CSV形式変換読出し(10進数・16ビット)
        [ MOV K1000 D212 ]          ; SP.FREAD 要求読出しデータ数 = 1000ワード
        [ MOV K0   D213 ]           ; SP.FREAD 最大読出しデータ数 = 0（固定）
        [ DMOV H0  D214 ]           ; SP.FREAD ファイル位置 = 先頭から
        [ MOV K10  D216 ]           ; SP.FREAD 列数指定 = 10列
        [ MOV K0   D217 ]           ; SP.FREAD データタイプ指定 = ワード

<<ファイル取得>>
X0 ──[ MOV H0 D201 ][ SET M300 ]
M300 ──[ SP.FTPGET 'U0' D200  "\DATABASE\DATA1.CSV"  "2:\..."  M200 ]
M200  M201(b) ──[ SET M301 ]           ; 取得正常完了
M200  M201    ──[ SET M302 ][ MOV D201 D302 ]   ; 取得異常完了＋ステータス退避

<<取得ファイルの読出し>>
M301 ──[ SET M310 ]
M310 ──[ SP.FREAD ... D210 ... D999 D1000 M210 ]
M210  M211(b) ──[ SET M303 ]
M210  M211    ──[ SET M304 ][ MOV D211 D304 ]
```

使用デバイス:

| デバイス | 用途 |
|---|---|
| D200 | SP.FTPGET 使用用途設定エリア（D200.2 / D200.3） |
| D201 | SP.FTPGET 完了ステータス |
| D202 / D203 | 処理ファイル総数 / 処理完了ファイル数 |
| M200 / M201 | SP.FTPGET 完了デバイス / 異常完了デバイス |
| D210〜D217 | SP.FREAD コントロールデータ |
| D999 | SP.FREAD 読出し結果データ数 |
| D1000〜D1999 | SP.FREAD 読出しデータ |
| M210 / M211 | SP.FREAD 完了デバイス / 異常完了デバイス |

## 5. プログラム作成上の注意（違反するとバグ・トラブルになる）

1. **`SM600`（メモリカード使用可フラグ）をインタロックに入れる。**
2. **命令完了（(d)+0）で駆動フラグをOFF**し、多重実行しない。
3. 異常完了時は **完了ステータス `(s1)+1` を必ず退避**する（次の実行で上書きされる）。
4. **FTPクライアント機能とFTPサーバ機能を同時に使用しない。**
5. **CPUユニットのバックアップ/リストア機能実行中は、ファイル転送機能用命令を実行できない**（エラー 4C44H）。
6. **ファイル転送中は、エンジニアリングツールなど外部機器からのファイル操作を行わない。** 中断された処理は転送終了後に再実行する。
7. **SDメモリカード強制使用停止は、ファイル転送完了を確認してから実行する**（転送途中で中断される）。
8. **ファイル転送中にRUN→STOPしても、転送は完了するまで継続する**（ワイルドカード指定時を含む）。
9. **自局ポート番号 62000〜65534（F230H〜FFFEH）をFTPクライアントが使用する。** 他機能でこの範囲を使わない。
10. **FTP転送中にUDP/IPで他の通信機能（MELSOFT接続、SLMP）を同時実行するとタイムアウトなどが発生する場合がある。** 転送後に通信するか、TCP/IPで通信する。
11. **大きいファイルは転送に長時間かかる**。例: スキャンタイム5ms、ファイルサイズ16MBで `SP.FTPPUT` 約548秒。
12. **転送中にケーブル断や電源断・リセットが発生した場合、FTPサーバ内に残った一時ファイル・不完全なファイルを削除してから再実行する。**
13. FTPサーバが **TCP KeepAlive機能**（KeepAlive用ACK伝文への応答）に対応していないと、コネクションが切断されることがある。生存確認に応答がない場合、CPUユニットはFTPサーバが生存していないものとしてコネクションを切断する。

## 6. トラブルシューティング（FTPクライアントのみ）

### 6.1 交信できないときの確認フロー（PDF p.787）

1. **FTPサーバ側のIPアドレス設定は正しいか** → FTPサーバ側で設定したIPアドレスでログインする
2. **FTPサーバ側のログイン名・パスワードは正しいか** → 設定したログイン名・パスワードでログインする
3. **FTPサーバ側の接続方式は正しいか** → PORT / PASV をFTPサーバ側と一致させる。プロキシサーバがある場合はネットワーク管理者に確認する
4. **FTPサーバ側のポート番号は正しいか** → FTPサーバ側のポート番号と一致させる
5. **IPフィルタ設定で相手機器のIPアドレスを遮断していないか** → 遮断を解除、または透過アドレスとして設定する
6. その他の確認項目は §5 の注意事項を参照

### 6.2 完了ステータスエラーコード（`(s1)+1` に格納）

| コード | 異常内容と原因 | 処置方法 |
|---|---|---|
| 41C5H | 指定されたファイルが存在しない | ファイルを確認後、再度実行する |
| 41C7H | 指定されたファイルまたはドライブが存在しない | ファイルまたはドライブ(メモリ)を確認後、再度実行する |
| 41CCH | 指定されたファイルが存在しない、または指定のサブディレクトリが存在しない | ファイル名・サブディレクトリ名を確認後、再度実行する |
| 41CDH | ファイルのアクセスがシステムで禁止されている | ファイル・サブディレクトリを確認後、再度実行する |
| 41CEH | 指定のファイルの属性が読出し専用のため書込みできない | 指定ファイルの属性を確認後、再度実行する |
| 41CFH | 指定されたドライブ(メモリ)の容量を超えている | ドライブ(メモリ)の容量を確認後、再度実行する |
| 41D8H | 指定のファイルにアクセス中である | しばらくしてから再度実行する |
| 41DFH | SDメモリカードがライトプロテクトON状態で `SP.FTPPUT`（転送完了ファイル削除="削除する"）を実行した／同状態で `SP.FTPGET` を実行しファイル転送に失敗した | ライトプロテクトスイッチをOFFにする／転送完了ファイル削除設定を"削除しない"にする |
| 41E4H | メモリカードのアクセスに失敗した | メモリカードの装着を確認して再実行／カードを交換／データバックアップ後にメモリ初期化 |
| 41EBH | ファイル名の指定方法に誤りがある | ファイル名を確認する。`SP.FTPGET` 実行時、転送先フォルダパスと一時ファイル名の長さの合計が255文字を超えていないか見直す |
| 41FEH | SDメモリカードが挿入されていない／使用停止状態／`SM606`(SDメモリカード強制使用停止指示)により使用停止 | メモリカードを挿入し直す／使用停止スイッチを下方向にスライド／強制使用停止解除指示を行う |
| 4C40H | ワイルドカード指定時に、一致するファイルが転送可能ファイル数の上限を超えている／一致する転送可能なファイルがない | ワイルドカード指定を見直す／指定フォルダパスが存在するか確認する |
| 4C43H | FTPクライアント送付の処理完了ファイル数と処理ファイル総数の値が不一致 | 再度実行する |
| 4C44H | **バックアップ/リストア機能実行中にファイル転送機能(FTPクライアント)を実行した** | バックアップ/リストア機能の完了後に再度実行する |
| C035H | レスポンス監視タイマ値以内に相手機器の生存確認ができなかった | 相手機器の動作・接続ケーブルを確認する |
| C616H | FTPサーバへの制御ポートの接続に失敗した | 内蔵EthernetのIPアドレス設定・FTPサーバ設定・接続状態を見直す。FTPサーバでユーザセッションを切断する。通信準備中の可能性があるため時間をおいて再実行する |
| C618H | FTPサーバへのログインに失敗した | FTPサーバ設定（ログインユーザ名、ログインパスワード）とFTPサーバソフトウェア側の設定・通信履歴を確認する |
| C619H | FTPサーバへのFTPコマンドの実行に失敗した | FTPサーバ設定（フォルダパス、接続方式）、アクセス権限（書込み/読込み）、指定フォルダパス・ファイルの存在、FTPサーバソフトウェアの設定・通信履歴、ファイルアクセス中かどうかを確認する |
| C620H | FTPサーバへのデータ転送ポートの接続に失敗した | 接続方式(PORT/PASV)、FTPサーバ・ファイアウォールの設定を確認する |
| C621H | FTPサーバへのデータ転送ポートの切断に失敗した | FTPサーバの状態・回線を確認する |
| C622H | ファイル転送中にエラーが発生した | 回線・FTPサーバの状態を確認し、不要ファイルを削除して再実行する |

## 7. ラダー生成前チェックリスト

- [ ] SDメモリカードを装着し、`SM600`（メモリカード使用可）をインタロックに入れたか
- [ ] FTPクライアント設定（使用する / サーバIP / ログイン名 / パスワード / 接続方式 / ポート番号）を設定したか
- [ ] コントロールデータ4ワード（使用用途／完了ステータス／処理ファイル総数／処理完了ファイル数）を確保したか
- [ ] b2（転送完了ファイル削除）、b3（一時ファイル作成）を意図どおり設定したか
- [ ] 完了デバイスを2点連続で確保し、`(d)+1` で異常判定しているか
- [ ] 命令完了で駆動フラグをOFFし、多重実行しない構成か
- [ ] 異常時に完了ステータスを退避しているか
- [ ] 転送元／転送先のパス指定は正しいか（`2:\LOGGING\...`、ワイルドカードの使い方）
- [ ] FTPサーバ機能と同時に使っていないか
- [ ] 他機能でポート番号 62000〜65534 を使っていないか
