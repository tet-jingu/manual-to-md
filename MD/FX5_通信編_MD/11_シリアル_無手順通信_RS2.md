## 0. 結論サマリ

- 無手順通信＝**プリンタ・バーコードリーダなどと無手順でデータを送受信する機能**。`RS2` 命令1つで実装する。
- 最大 **4チャンネル同時**、**送信最大4096点／受信最大4096点**。
- ラダーの骨格は常に同じ:
  1. 駆動接点で `RS2` を常時実行（＝送受信待機状態）
  2. 送信は **送信要求フラグ `SM856x` を SET** するだけ（**自動でリセットされる。プログラムでリセットしない**）
  3. 受信は **受信完了フラグ `SM856x` のON** を見て受信データを別デバイスへ退避し、**フラグをRSTして次受信を許可**
- **同一シリアルポートで駆動するRS2命令は1個だけ**。インバータ通信命令・通信プロトコル支援命令とは同一ポートで併用不可。

## 3. RS2命令

```
[駆動接点]──[ RS2  (s)  (n1)  (d)  (n2)  (n3) ]
ST: ENO := RS2(EN, s, n1, n2, n3, d);
```

| オペランド | 内容 | 範囲 |
|---|---|---|
| (s) | 送信データの先頭デバイス | — |
| (n1) | 送信データの点数 | 0〜4096 |
| (d) | 受信データ格納先頭デバイス | — |
| (n2) | 受信データの点数 | 0〜4096 |
| (n3) | 通信CH | FX5S/FX5UJ: K2〜K4、FX5U: K1〜K4、FX5UC: K1, K3〜K4 |

- (s), (d) は **ワードデバイス**（T, ST, C は使用不可）。
- 送信だけ使う場合は `(n2)=K0`、受信だけ使う場合は `(n1)=K0` にできるが、**(n2)=0 で駆動すると受信完了フラグがONしたままとなり受信待機にならない**。受信するなら (n2) は1以上。

### 注意事項（命令レベル）

- `RS2` 命令は **インバータ通信命令・通信プロトコル支援命令と同じシリアルポートに対して使用できない**。
- **ヘッダ・ターミネータ・タイムアウト時間・8bit処理モードは、RS2命令駆動前（OFF中）に変更する。** 駆動中の変更禁止（駆動した時点の値が有効になる）。
- **RUN中書込みでRS2命令を削除すると通信は即停止する。**

## 5. 伝文フレームの構成

通信設定により下記の組合せから選択される（最大12通り）。

```
[ヘッダ] + データ + [ターミネータ] + [サムチェック] + [CR+LF]
```

| 要素 | 送信時 | 受信時 |
|---|---|---|
| ヘッダ | 送信データの先頭に自動付加 | 設定コードを連続受信した時点で**受信開始**（ヘッダは格納されない） |
| ターミネータ | 送信データのあとに自動付加 | 受信した時点で**受信完了** |
| サムチェック | データ+ターミネータのサムを計算して付加 | 受信サムと計算サムを比較。不一致で 7200H |
| CR+LF | 送信データの最終に付加 | CR+LFを連続受信した時点で受信完了 |

- サムチェックコード＝対象データを16進加算した結果の**下位1バイトをASCII2桁に変換**したもの。
- **サムチェックを[付加する]にする場合は必ずターミネータを設定する。**
- CR+LF使用時は**伝文中にCRを含めない**こと。

## 6. 16ビットモード / 8ビットモード

| モード | 送信データの扱い | 受信データの扱い |
|---|---|---|
| 16ビットモード | 1ワードを下位8bit→上位8bitの順に2バイト送信 | 1ワードに2バイト格納（下位→上位） |
| 8ビットモード | 各ワードの**下位8bitのみ**有効（上位8bitは無視） | 1ワードに1バイト（下位8bit）格納 |

> 8ビットモードでは**受信データ格納先の上位8bitに以前のデータが残る**。マスク処理すること。
> 処理モードは通信設定で設定し、**RS2命令駆動時に切り替わる**。

## 7. 送受信の動作

### 7.1 送信

1. `RS2` 命令を駆動（送受信待機状態）
2. 送信データを (s) 以降に書き込み、点数を (n1) に設定
3. **送信要求フラグを SET** → その後の `RS2` 命令実行で送信開始（演算周期に関係なく割込みで送信）
4. ターミネータ・サムチェック・CR+LF まで送り終えると**送信完了 → 送信要求フラグは自動リセット**

**送信時の禁止事項**

- 送信要求フラグがONしている間に **送信データの点数・内容を変更しない**
- **送信要求フラグをプログラムでリセットしない**（正しいデータが送信されない）
- 送信指令は**パルスで与える**

### 7.2 受信

1. `RS2` 命令実行で受信待機中になる
2. データ受信開始（ヘッダ指定時はヘッダを連続受信した時点から開始、ヘッダを除いて格納）
3. 下記いずれか1つが成立で**受信完了 → 受信完了フラグON**
   - (n2) で設定した受信点数分を受信した
   - ターミネータ／サムチェック／CR+LF を正しく受信した
   - 受信が中断し、タイムアウト時間を経過しても次データが来ない（**タイムアウト判定フラグもON**）
4. 受信データを別デバイスへ退避
5. **受信完了フラグをRST** → 受信待機中に戻る

**受信時の禁止事項・注意**

- **受信完了フラグがONしている間は新たなデータを受信できない。** 必ずRSTする。
- **タイムアウト判定フラグは自動でOFFしない。** 受信完了フラグをリセットすると連動してOFFする。
- **受信データ点数 (n2) はターミネータ・サムチェック・CR+LFを含めた点数**を設定する。少ないとシリアル通信エラーがONする（ターミネータ[付加しない]の場合はエラーにならない）。
- タイムアウト機能を使うと、**送信データ数が変動する機器もターミネータなしで受信できる**。

### 7.3 半二重双方向(RS-485)時

- **送信完了 → 受信開始の間を100μs以上空ける**
- 受信中に送信要求フラグをONしない
- 送信中はデータ受信できないため、相手機器からシーケンサへ送信させない

### 7.4 制御線モード(RS-232C)

| モード | 用途 |
|---|---|
| 制御線なし | 制御線を使わない |
| 通常モード | 送信のみ／受信のみの用途。DR(DSR)がOFFで送信待機中は送信待機フラグがON |
| インタリンクモード | 受信データ数が「設定受信点数-30」になるとER(DTR)をOFFし相手に送信中断を要求。**受信点数(n2)は31点以上必須**（30点以下だと受信した瞬間にER(DTR)がOFFする） |
| モデムモード | モデム接続用 |

インタリンクモードの手順:

1. 受信数が「(n2)-30」に達する → ER(DTR) OFF → 相手は送信中断（OFF後も最大30バイトは受信可能）
2. タイムアウト時間後、タイムアウト判定フラグと受信完了フラグがON
3. 受信データを移動 → 受信完了フラグをRST → ER(DTR) ON、タイムアウト判定フラグOFF → 相手は送信再開
4. 受信完了まで1〜3を繰り返す

## 8. ラダー実装パターン

### 8.1 基本形（CH1・送受信両用）

```
M0(駆動接点)
──┤├──[ RS2  D100  D0  D200  K30  K1 ]
                 │    │    │    └ 受信点数 30点
                 │    │    └ 受信データ格納先頭
                 │    └ 送信点数（D0の値を使用）
                 └ 送信データ先頭

<<送信処理>>
M1(送信指令・パルス)
──┤↑├──[ $MOV "TEST SEND1" D100 ]   ; 送信データ書込み
          [ MOV  K10  D0 ]            ; 送信点数
          [ SET  SM8561 ]             ; 送信要求 → 送信開始（自動リセットされる）

<<受信処理>>
SM8562(受信完了フラグ)
──┤├──[ BMOV D200 D500 K15 ]        ; 受信データを退避
          [ RST SM8562 ]              ; 受信完了フラグをリセット（必須）
```

> 送信点数 (n1) に定数ではなくデバイス(D0)を指定すると、可変長送信ができる。

### 8.2 常時受信待機（RUNモニタ駆動）

```
SM400(常時ON)
──┤├──[ RS2  D100  K4  D200  K20  K1 ]
```

### 8.3 プリンタ印字例（CH2・FX5-232-BD・送信のみ）

パラメータ: FX5-232-BD / 無手順通信 / データ長8bit / パリティ偶数 / ストップビット2bit / 2400bps / 制御線通常モード

```
X0(RS2命令駆動)
──┤├──[ RS2  D10  K11  D50  K0  K2 ]

X1(送信指令)
──┤├──[ PLS M0 ]
M0
──┤├──[ MOV H6574 D10 ]   ; "te"
          [ MOV H7473 D11 ]   ; "st"
          [ MOV H6C20 D12 ]   ; " l"
          [ MOV H6E69 D13 ]   ; "in"
          [ MOV H0D65 D14 ]   ; "e" + CR
          [ MOV H0A   D15 ]   ; LF
          [ SET SM8571 ]      ; CH2の送信要求フラグ
```

## 9. プログラム作成上の注意（違反するとバグになる）

1. **同一シリアルポートで駆動するRS2命令は1個だけ。** 命令自体は何回でも書けるが、切り替えるときは**1スキャン以上のOFF期間**を設ける（重複駆動で 1810H）。
2. 使用するシリアルポートのプロトコル形式が[無手順通信]でないと `RS2` は使えない（3600H）。
3. **他の通信（インバータ命令など）で使用中のシリアルポートには `RS2` を使えない。**
4. 送信要求フラグを**プログラムでリセットしない**（自動リセット）。
5. 受信完了フラグは**必ずプログラムでリセット**する。しないと次のデータを受信できない。
6. タイムアウト判定フラグは受信完了フラグのリセットに連動してOFFする。
7. ヘッダ・ターミネータ・タイムアウト時間・8bit処理モードは**RS2駆動前に設定**する。
8. インタリンクモード使用時は **(n2) を31点以上**にする。
9. RS-485半二重時は**送信完了→受信開始を100μs以上空ける**。
10. 受信点数にはターミネータ・サムチェック・CR+LFを**含めた点数**を設定する。
11. **RUN中書込みでRS2命令を削除すると通信は即停止する。**

| 2822H | 命令で指定できないデバイスを指定している | RS2命令に設定したオペランドが対象外 | プログラムと通信設定を確認 |
| 3405H | 指定可能な範囲外のデータを入力した | オペランドの要素番号範囲やデータ値が範囲外 | プログラムと通信設定を確認 |
| 2820H | 命令で指定したデバイス、ラベルが使用可能な範囲を超えている | オペランドが該当デバイスの範囲外 | プログラムと通信設定を確認 |
| 1810H | 演算エラー | **同一チャンネルのRS2命令が重複している** | 駆動するRS2命令を1ポート1個にする |
| 3600H | 演算エラー | **指定したチャンネルにパラメータ設定していない** | プロトコル形式を[無手順通信]に設定する |

## 11. ラダー生成前チェックリスト

- [ ] 通信CH `(n3)` はそのCPUユニットで使用可能な番号か
- [ ] パラメータのプロトコル形式を[無手順通信]にしたか
- [ ] 駆動するRS2命令は該当ポートに1つだけか
- [ ] 送信指令はパルス化したか
- [ ] 送信要求フラグを SET のみで使い、RSTしていないか
- [ ] 受信完了フラグを受信データ退避後に RST しているか
- [ ] 受信点数 (n2) にターミネータ・サム・CR+LF分を含めたか（インタリンクモードなら31点以上）
- [ ] ヘッダ／ターミネータ／タイムアウト／8bitモードの変更をRS2駆動前に行っているか
- [ ] 8ビットモードの場合、受信ワード上位バイトのゴミを考慮したか
- [ ] 同一ポートでインバータ通信命令・通信プロトコル支援命令を使っていないか
