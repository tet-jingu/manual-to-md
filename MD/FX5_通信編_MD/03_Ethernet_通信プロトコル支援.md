## 0. 結論サマリ

- 相手機器（計測器・バーコードリーダ等）のプロトコルをGX Works3に登録し、**ラダーからはプロトコル番号を指定して実行するだけ**にする機能（内蔵Ethernet版）。
- 命令は **`SP.ECPRTCL`** のみ。**1命令で最大8プロトコルを連続実行**できる。
- **使用できるコネクションは No.1〜8**、かつ **交信手段が「通信プロトコル」に設定されたコネクションのみ**。
- ⚠ **`SP.ECPRTCL` 単体ではコネクションのオープン/クローズを行わない。** 別途 `SP.SOCOPEN` / `SP.SOCCLOSE` が必要（→ 01_Ethernet_ソケット通信.md）。
- 実行条件に **`SD10692`（通信プロトコル準備完了）= 1** を必ず入れる。
- 交信データコードは、選択した設定にかかわらず **バイナリコード交信** になる。

## 1. 仕様・登録上限

| 項目 | 値 |
|---|---|
| 登録可能プロトコル数 | 最大 **64** |
| 登録可能パケット数 | 最大 **128** |
| パケットデータエリアサイズ | 最大 **6144バイト** |
| 1プロトコルの受信パケット数 | 最大 **16** |
| 1パケットの最大データ長 | **2046バイト**（TCP/IPの場合） |
| 使用可能コネクション | No.1〜8 |
| 通信プロトコルライブラリ | SLMP(4Eフレーム)、MODBUS/TCP など（**クライアントのみ対応**） |

> パケット数が上限に達すると、プロトコル数に余裕があってもプロトコルを追加できない。パケットデータエリアサイズが上限に達した場合も同様。

### 通信タイプ

| 通信タイプ | 処理内容 |
|---|---|
| 送信のみ | 1つの送信パケットを1回送信する |
| 受信のみ | 最大16まで登録した受信パケットの中で一致するものがあれば受信する |
| 送信&受信 | 送信パケットを送信後、最大16の受信パケットの中で一致するものがあれば受信する |

## 2. 準備手順（ラダーを書く前に必須）

1. **プロトコル設定データの作成**
   `[ツール]` → `[通信プロトコル支援機能]` → ユニットタイプ **"CPU(Ethernet)"** を選択 → `[ファイル]` → `[新規作成]`
   - `[編集]` → `[プロトコル追加]` で 通信プロトコルライブラリ / ユーザプロトコルライブラリ / 新規追加 から選択（プロトコル番号 1〜64）
   - `[編集]` → `[プロトコル詳細設定]` で送受信パラメータを設定（ライブラリから選んだプロトコルは変更不可）
   - パケット設定で構成要素（ヘッダ・局番・コマンド・データ部・誤りチェックコード・ターミネータ等）を定義
2. **プロトコル設定データの書込み**
   `[オンライン]` → `[ユニット書込]`（**ユニット拡張パラメータ**に書き込まれる）
3. **ユニットパラメータの設定**
   `[パラメータ]` → ユニット形名 → `[ユニットパラメータ]` → `[Ethernetポート]` → `[基本設定]` → `[相手機器接続構成設定]`
   - ユニット一覧から相手機器（UDP接続機器 / Active接続機器 / Unpassive接続機器 / Fullpassive接続機器）をドラッグ＆ドロップ
   - **相手機器との「交信手段」を「通信プロトコル」に設定する**
4. パラメータをCPUユニットへ書き込み、**リセットまたは電源OFF→ON**
5. `SP.SOCOPEN` でコネクションをオープン
6. `SP.ECPRTCL` でプロトコルを実行
7. 通信終了後、`SP.SOCCLOSE` でクローズ

> パケット設定が「変数未設定」「構成要素未設定」「構成要素エラー」の場合、**CPUユニットにプロトコルを書き込めない**。
> メーカ名・パケット名・プロトコル詳細設定の種別/バージョン/説明・パケット設定の構成要素名は**書き込まれないため読み出しても表示されない**（通信プロトコルライブラリから選択したプロトコルを除く）。

## 3. 通信プロトコル交信の実行条件

`SD10692`（通信プロトコル準備完了）が **1** のときだけ実行できる。

| 状態 | SD10692 | 備考 |
|---|---|---|
| プロトコル設定データが正常 | **1** | 電源ON/リセット時にチェックされ、正常なら1になる |
| プロトコル設定データが異常 | 0 | エラー内容が `SD10710`〜`SD10713` に格納される |
| プロトコル設定データ未書込み | 0 | チェック自体が行われない |

> **`SD10692` はプロトコル実行時のインタロック信号として使う。**
> プロトコルが登録されているかは `SD10714`（登録数）、`SD10722`〜`SD10725`（登録有無）で確認できる。

## 4. SP.ECPRTCL命令

```
[実行条件]──[ SP.ECPRTCL  "U0"  (s1)  (s2)  (s3)  (d) ]
ST: ENO := SP_ECPRTCL(EN, U0, s1, s2, s3, d);
```

| オペランド | 内容 | 範囲 |
|---|---|---|
| (U) | ダミー。文字列 `"U0"` を入力 | — |
| (s1) | コネクション番号 | **1〜8** |
| (s2) | 連続実行するプロトコルの数 | 1〜8 |
| (s3) | コントロールデータ先頭デバイス | **18ワード占有** |
| (d) | 命令完了で1スキャンONするデバイス先頭 | **2点占有** |

> (d) には T, ST, C を使用できない。

### コントロールデータ（18ワード）

| デバイス | 項目 | 内容 | 設定範囲 | セット側 |
|---|---|---|---|---|
| (s3)+0 | 実行数結果 | 実行したプロトコル数（**エラーが発生したプロトコルも含む**）。設定に誤りがある場合は0 | 0, 1〜8 | システム |
| (s3)+1 | 完了ステータス | 命令の実行結果。複数実行時は**最後に実行したプロトコルの結果**。0: 正常 / 0以外: エラーコード | — | システム |
| (s3)+2 | 実行プロトコル番号指定1 | 1番目に実行するプロトコル番号 | **1〜64** | ユーザ |
| (s3)+3 | 実行プロトコル番号指定2 | 2番目 | 0, 1〜64 | ユーザ |
| (s3)+4 | 実行プロトコル番号指定3 | 3番目 | 0, 1〜64 | ユーザ |
| (s3)+5 | 実行プロトコル番号指定4 | 4番目 | 0, 1〜64 | ユーザ |
| (s3)+6 | 実行プロトコル番号指定5 | 5番目 | 0, 1〜64 | ユーザ |
| (s3)+7 | 実行プロトコル番号指定6 | 6番目 | 0, 1〜64 | ユーザ |
| (s3)+8 | 実行プロトコル番号指定7 | 7番目 | 0, 1〜64 | ユーザ |
| (s3)+9 | 実行プロトコル番号指定8 | 8番目 | 0, 1〜64 | ユーザ |
| (s3)+10 〜 (s3)+17 | 照合一致受信パケット番号1〜8 | 各プロトコルで照合一致した受信パケット番号。通信タイプが「送信のみ」・エラー発生・実行数未満の場合は 0 | 0, 1〜16 | システム |

> **シリアル版 `S(P).CPRTCL` とは (s3)+0 と (s3)+1 の意味が入れ替わっている**（Ethernet版は +0=実行数結果、+1=完了ステータス）。取り違えに注意。

### 完了デバイスの動作

| デバイス | 動作 |
|---|---|
| (d)+0 | 命令完了スキャンのEND処理でON、次のEND処理でOFF（1スキャンON） |
| (d)+1 | **正常完了時: OFFのまま変化しない** / **異常完了時: 完了スキャンのEND処理でON**、次のEND処理でOFF |

### 命令レベルの注意事項

1. **複数プロトコル実行中、m番目でエラーが発生するとm+1番目以降は実行されず、命令は異常完了する。**
2. **実行可能なコネクションは、交信手段が「通信プロトコル」に設定されたコネクションのみ。**
3. **同一コネクションに対して同一命令を実行した場合、先に実行中の命令が完了するまで後の命令は無視される。**
4. **`SP.ECPRTCL` 単体ではオープン/クローズを行わない。** `SP.SOCOPEN` / `SP.SOCCLOSE` を別途実装する。
5. 複数プロトコル連続実行中にm番目でキャンセル要求を受けた場合、`(s3)` には次が格納される:

| デバイス | 格納内容 |
|---|---|
| (s3)+0 | 実行したプロトコル数 |
| (s3)+1 | エラーコード |
| (s3)+10 〜 (s3)+m+8 | 実行済みプロトコルの照合一致受信パケット番号 |

### エラー（SD0/SD8067に格納される演算エラー）

| コード | 内容 |
|---|---|
| 2820H | 指定するデバイスが使用可能な範囲を超えたとき |
| 2821H | 指定したデバイス範囲が重複しているとき |
| 2822H | 指定できないデバイスを指定したとき |
| 3405H | 指定可能な範囲外のデータを入力したとき |

## 6. ラダー実装パターン

### 6.1 全体の流れ

```
1. SP.SOCOPEN   でコネクションをオープン（交信手段=「通信プロトコル」のコネクション）
2. SP.ECPRTCL   でプロトコルを実行（SD10692=1 かつ SD10680.n=ON を条件に）
3. SP.SOCCLOSE  でコネクションをクローズ（Active接続時。Passive/UDPではCLOSEしない）
```

### 6.2 基本形（コネクションNo.1でプロトコル4→7→5を連続実行）

```
<<① コネクションのオープン>>
M1000  SD10680.0(b)  SD10681.0(b)
──┤├─────┤/├────────┤/├──[ MOVP H0 D100 ]
                                   [ SP.SOCOPEN "U0" K1 D100 M100 ]

<<② プロトコル番号の設定>>
[ MOV K4 D12 ]   ; (s3)+2 1番目に実行するプロトコル番号
[ MOV K7 D13 ]   ; (s3)+3 2番目
[ MOV K5 D14 ]   ; (s3)+4 3番目

<<③ プロトコル実行>>
X20   [= SD10692 K1]   SD10680.0
──┤├──────┤├────────┤├──[ SP.ECPRTCL "U0" K1 K3 D10 M0 ]
                                    │   │   └ コントロールデータ先頭 D10（D10〜D27）
                                    │   └ 連続実行数 3
                                    └ コネクション番号 1

<<④ 完了処理>>
M0  M1(b接点) ──[ SET M101 ]              ; 正常完了
M0  M1        ──[ SET M102 ]              ; 異常完了
M1            ──[ MOV D11 D200 ]          ; (s3)+1 完了ステータス（エラーコード）を退避
                [ MOV D10 D201 ]          ; (s3)+0 実行数結果を退避

<<⑤ 受信パケット番号による分岐>>
M0  M1(b接点) ──[ MOV D20 D210 ]          ; (s3)+10 1番目プロトコルの照合一致受信パケット番号
; D210 = 1 → 正常応答(Normal response)、2 → 異常応答(Error response) など

<<⑥ クローズ（Activeオープンの場合のみ）>>
M4000  SD10680.0 ──[ SP.SOCCLOSE "U0" K1 D200 M200 ]
```

デバイス割付の例:

| デバイス | 内容 |
|---|---|
| D10 | (s3)+0 実行数結果 |
| D11 | (s3)+1 完了ステータス |
| D12〜D19 | (s3)+2〜+9 実行プロトコル番号1〜8 |
| D20〜D27 | (s3)+10〜+17 照合一致受信パケット番号1〜8 |
| M0 | 完了デバイス (d)+0 |
| M1 | 完了時の状態表示デバイス (d)+1 |

### 6.3 プロトコルのキャンセル

```
Xnn(キャンセル指示) ──[ MOV K1 SD10759 ]   ; コネクションNo.1のキャンセル要求
; キャンセル完了で SD10759 は 2 になる
```

**キャンセル時の動作（プロトコル実行状態による）**

| キャンセル時の実行状態 | 動作 |
|---|---|
| 1: 送信待ち | 送信を中止。以降の受信やプロトコルも実行しない。命令は異常完了 |
| 2: 送信処理中（送信未完了） | **既に送信中のパケットは中断せず送信完了させる**。以降は実行しない。異常完了 |
| 2: 送信処理中（送信完了済） | 以降の受信やプロトコルを実行しない。異常完了 |
| 3: 受信データ待ち | 受信を中止。以降のプロトコルも実行しない。異常完了 |
| 4: 受信処理中 | **照合処理・一般データ処理などを中断し、専用命令を強制終了**。異常完了 |

## 7. プログラム作成上の注意（違反するとバグになる）

1. **`SD10692 = 1` を実行条件に入れる。**
2. **オープン/クローズは `SP.SOCOPEN` / `SP.SOCCLOSE` で別途実装する。** オープン完了信号 `SD10680.n` でインタロックする。
3. コントロールデータは **18ワード連続**、`(d)` は **2点連続**で確保する。
4. `(s2)`（連続実行数）と `(s3)+2`〜`(s3)+9` に設定したプロトコル番号の個数を一致させる。
5. **途中でエラーが起きると残りのプロトコルは実行されない。** `(s3)+0`（実行数結果）で「どこまで実行できたか」を確認する。
6. **同一コネクションに同じ命令を重ねて実行しない**（後の命令は無視される）。
7. 使用できるのは**交信手段が「通信プロトコル」のコネクションのみ**。ソケット通信用に設定したコネクションでは実行できない。
8. **ポート番号**: 推奨 1024〜5548, 5570〜61439。1〜1023（WELL KNOWN PORT）、5549〜5569（システム使用・指定禁止）、61440〜65534（他機能使用）は避ける。
9. 交信データコードは設定にかかわらず**バイナリコード交信**になる。

## 8. トラブルシューティング（Ethernet通信プロトコル支援のみ）

### 8.1 プロトコルが実行できない（SD10692 = 0）

`SD10710`〜`SD10713` で異常箇所を特定する。

| 確認順 | デバイス | 見方 |
|---|---|---|
| 1 | SD10710 | 異常を検出したプロトコル番号（1〜64）。0なら異常なし、65535は特定不可 |
| 2 | SD10711 | 0: パケット設定/構成要素設定の異常 / 1: プロトコル詳細設定の異常 |
| 3 | SD10712 | （SD10711=0のとき）0: 送信パケット / 1〜16: 受信パケット番号 |
| 4 | SD10713 | （SD10711=0のとき）1〜32: 構成要素番号 |

プロトコル設定データ未書込みの場合は、`SD10714`（登録数）が0、`SD10722`〜`SD10725` が全ビット0になる。

### 8.2 通信プロトコル支援機能に関係するエラーコード

エラーコードは `(s3)+1`（完了ステータス）と、コネクションのエラーコード `SD10130`〜`SD10137` に格納される。

| コード | 異常内容と原因 | 処置方法 |
|---|---|---|
| C400H | 通信プロトコル準備未完了時(`SD10692`=0)にプロトコルを実行した | プロトコル設定データを書き込み、`SD10692`=1 を確認してから実行する |
| C401H | CPUユニットに登録されていないプロトコル番号を指定した／設定データが不正 | `SD10714` / `SD10722`〜`SD10725` で登録状況を確認する |
| C404H | プロトコル実行中にキャンセル要求を受け付けた | キャンセル要求の発行元と原因を確認する |
| C405H | `SP.ECPRTCL` 命令のコントロールデータに誤りがある | コントロールデータ（実行数、プロトコル番号）を見直す |
| C410H | **受信待ち時間がタイムアップした** | 相手機器の応答、ケーブル・回線を確認する。プロトコル詳細設定の受信待ち時間を見直す |
| C411H | 受信したデータが **2046バイトを超える** | パケット構成を見直し、分割送信させる |
| C417H | 受信したデータのデータ長、またはデータ数が不正である | 相手機器のパケットフォーマットと、データ長/データ数格納エリアの設定を確認する |
| C431H | **`SP.ECPRTCL` 命令実行中にコネクションがクローズされた** | クローズ処理とプロトコル実行の排他を見直す。相手機器からの切断要因を確認する |
| C024H | 交信手段が通信プロトコル以外のコネクションで命令を実行した | コネクションの「交信手段」を「通信プロトコル」に設定する |
| C1B1H | 指定されたコネクションはオープンされていない | `SD10680.n` でインタロックし、`SP.SOCOPEN` 後に実行する |
| C035H | レスポンス監視タイマ値以内に相手機器の生存確認ができなかった | 相手機器の動作と接続ケーブルを確認する |

> 上記以外のEthernet共通エラーコードは PDF p.796〜800 を参照。

### 8.3 受信が照合一致しないとき

- `(s3)+10`〜`(s3)+17`（照合一致受信パケット番号）が **0** のままなら、どの受信パケットとも一致していない。
- コネクションごとの **受信照合結果**（コネクション1なら `SD10742`〜`SD10757`）を確認する。
  - b0〜b7: 照合不一致となった**構成要素番号**
  - b8〜b15: 照合不一致の**要因**
- 相手機器の実際の応答電文とパケット設定（固定データ、レングス、誤りチェックコード等）を突き合わせる。
