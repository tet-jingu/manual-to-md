### 9.12 任意トランジェントコマンド送信機能[RD77MS] (9.12 / 印刷 p.379 / 原本 p.381)

「任意トランジェントコマンド送信機能」は，任意のトランジェントコマンドをサーボアンプに対して送信できる機能です。トランジェントコマンドを非同期的に送信するため，固定周期で読み出す必要のないデータの受信に使用可能です。また，要求データ → 応答データ受信を一連の動作で実行します。

#### 任意トランジェントコマンド送信機能に必要なデータ設定 (9.12 / 印刷 p.379 / 原本 p.381)

### 9.13 イベント履歴機能 (9.13 / 印刷 p.385 / 原本 p.387)

「イベント履歴機能」は，エラー情報やユニットに対して行った操作を，イベントとしてCPUユニットのデータメモリまたはSDカードに保存する機能です。保存したイベント情報は，エンジニアリングツールで表示することができ，その発生履歴を時系列で確認することができます。また，イベント履歴の「付加情報」を参照することで，エラーの詳細情報を確認できます。

【図】イベント履歴機能の概要(9.13 / 印刷 p.385 / 原本 p.387)
- 構成: エンジニアリングツール(パソコン)、CPUユニット(CPUデータメモリ／SDメモリカード)、シンプルモーションユニット(RD77MS4 / RD77GF4)。RD77MS 側は SSCNETⅢ(/H)、RD77GF 側は CC-Link IE フィールドネットワークでサーボアンプ・モータを接続。
- 吹き出し: 「CPUユニットが自号機および自号機が管理するユニットで発生したイベント情報を，一括して収集して保存可能。」
- 吹き出し: 「エンジニアリングツールで，接続先のCPUが保持しているイベントの発生履歴を確認可能。」
- イベント履歴の表示例(列: 日時*1 / ユニット / 内容):

| 日時*1 | ユニット | 内容 |
|---|---|---|
| 2014/4/7 16:55 | アナログ | パラメータ操作を行った。 |
| 2014/4/7 19:27 | 電源 | 電源ユニットで異常が発生した。 |
| 2014/4/7 19:28 | 位置決め | 原点復帰方式エラー発生。 |
| 2014/4/7 19:29 | CPU | BATTERY ERRが発生した。 |
| 2014/4/7 19:45 | CPU | お客様がPC読出しを行った。 |
| 2014/4/8 00:00 | CPU | 時刻合わせを行った。 |

*1 CPUユニットの時計機能で設定された値を表示しています。

### 9.14 SSCNET通信の切断／再接続機能[RD77MS] (9.14 / 印刷 p.389 / 原本 p.391)

システムの電源ON中に，SSCNET系統の途中にあるサーボアンプ，またはSSCNETⅢケーブルを交換する場合に，SSCNET通信を一時的に切断／再接続する機能です。

#### 制御内容 (9.14 / 印刷 p.389 / 原本 p.391)

"[Cd.102]SSCNET制御指令"にはSSCNET通信の切断／再接続の要求を設定し，"[Md.53]SSCNET制御ステータス"には指令受付待ちや実行待ちの状態が格納されます。また，この機能で切断したサーボアンプを再接続する場合も，このバッファメモリを使用して再接続処理を行います。

SSCNET系統の先頭軸(シンプルモーションユニットと直接接続しているサーボアンプ)の電源をOFF/ONする場合は，切断／再接続する必要はありません。

#### 制御上の注意事項 (9.14 / 印刷 p.389 / 原本 p.391)

- SSCNET通信切断処理完了後，サーボアンプのLED表示が"AA"になったことを確認してから，サーボアンプの電源をOFFしてください。
- 「軸No.: SSCNET通信の切断指令」，「-10: SSCNET通信の再接続指令」を"[Cd.102]SSCNET制御指令"に設定した時点では，"[Md.53]SSCNET制御ステータス"が「-1: 実行待ち」に変化するだけで，実際の処理は実行されません。「-2: 実行指令」を"[Cd.102]SSCNET制御指令"に設定して，処理を実行してください。
- 接続されていないサーボアンプ軸や仮想サーボアンプの「軸No.: SSCNET通信の切断指令」を設定した場合は，"[Md.53]SSCNET制御ステータス"が「-1: 実行待ち」にならず状態は変化しません。
- SSCNET系統の途中にあるサーボアンプを，切断機能を使用せず電源OFFした場合，他の軸が誤作動する恐れがあります。必ず切断機能を使用し，サーボアンプの電源をOFFしてください。
- 多軸一体型サーボアンプでは，切断／再接続指令はA軸に対して行ってください。
- ドライバ間通信機能を使用している場合，切断／再接続指令を実行すると切断はできますが，再接続はできません。
- アンプなし運転モード中は，切断／再接続／実行指令を受付けません。"[Md.53]SSCNET制御ステータス"は「0: 指令受付待ち」になります(切断中も解除されます)。"[Md.53]SSCNET制御ステータス"が「1: 切断軸あり」のときアンプなし運転モードへ切り換えた場合，再度通常運転モードへ切り換えた時点で切断した軸は自動的に再接続されます。"[Md.53]SSCNET制御ステータス"が「-1: 実行待ち」のときにアンプなし運転モードへ切り換えた場合，切断／再接続指令は無効になります。

#### 切断／再接続手順 (9.14 / 印刷 p.390 / 原本 p.392)

サーボアンプ／SSCNETⅢケーブル交換時の切断／再接続手順を下記に示します。

##### ■切断手順 (9.14 / 印刷 p.390 / 原本 p.392)

1. "[Cd.102]SSCNET制御指令"に切断する軸No.を設定する。(設定値: 1～最大制御軸数)
2. "[Md.53]SSCNET制御ステータス"が「-1: 実行待ち」になったことを確認する。(切断実行待ち中)
3. "[Cd.102]SSCNET制御指令"に「-2: 実行指令」を設定する。
4. "[Md.53]SSCNET制御ステータス"が「1: 切断軸あり」になったことを確認する。(切断完了。"[Md.26]軸動作状態"は「20: サーボ未接続」となる。)
5. 切断するサーボアンプのLED表示"AA"確認後，サーボアンプの電源をOFFする。

【図】切断手順のタイミング(9.14 / 印刷 p.390 / 原本 p.392)
- [Cd.102]SSCNET制御指令: 0 → 「1～最大制御軸数」(切断指令(切断するサーボアンプの軸No.)) → 「-2」(切断実行指令) → 「0」(切断指令クリア)。
- [Md.53]SSCNET制御ステータス: 0(指令受付待ち) → [Cd.102]に軸No.設定後に「-1」(切断実行待ち) → [Cd.102]に-2設定後に「-2」(切断実行中) → 「1」(切断軸あり)。
- 矢印: [Cd.102]の各変化の後に [Md.53] が変化する。「切断完了」の矢印は [Md.53] が -2 → 1 に変化する時点を指し、その時点で [Cd.102] は「0」(切断指令クリア)になっている。

##### ■再接続手順 (9.14 / 印刷 p.390 / 原本 p.392)

1. サーボアンプの電源をONする。
2. "[Cd.102]SSCNET制御指令"に「-10: SSCNET通信の再接続指令」を設定する。
3. "[Md.53]SSCNET制御ステータス"が「-1: 実行待ち」になったことを確認する。(再接続実行待ち中)
4. "[Cd.102]SSCNET制御指令"に「-2: 実行指令」を設定する。
5. "[Md.53]SSCNET制御ステータス"が「0: 指令受付待ち」になったことを確認する。(再接続完了)
6. 再接続した軸の"[Md.26]軸動作状態"の「0: 待機中」を確認後，サーボアンプの運転を再開する。

【図】再接続手順のタイミング(9.14 / 印刷 p.390 / 原本 p.392)
- [Cd.102]SSCNET制御指令: 0 → 「-10」(再接続指令) → 「-2」(再接続実行指令) → 「0」(再接続指令クリア)。
- [Md.53]SSCNET制御ステータス: 1(切断軸あり) → [Cd.102]に-10設定後に「-1」(再接続実行待ち) → [Cd.102]に-2設定後に「-2」(再接続実行中) → 「0」(指令受付待ち)。
- 「再接続完了」の矢印は [Md.53] が -2 → 0 に変化する時点を指し、その時点で [Cd.102] は「0」(再接続指令クリア)になっている。

> **Point**
> "[Md.53]SSCNET制御ステータス"が「-1: 実行待ち」のとき，"[Cd.102]SSCNET制御指令"に｢0: 指令なし｣を設定すると，実行待ちの指令をキャンセルできます。

#### データ転送順について (9.16 / 印刷 p.398 / 原本 p.400)

サーボトランジェント伝送は1軸あたり4点まで登録でき，1つずつ順番にトランジェント伝送を行います。

複数軸に対し同時にトラジェント送信要求を行った場合の処理性能は，ネットワークの通信モードにより，以下のようになります。

| 通信モード設定 | 転送順(「→」が1リンクスキャンに対応) |
|---|---|
| 標準モード | 設定1(全軸分) → 設定2(全軸分) →<br>設定3(全軸分) → 設定4(全軸分) → 設定1(全軸分) → ・・・ |
| 高速モード*1 | 設定1(軸1) → ・・・→ 設定4(軸1) →<br>設定1(軸2) → ・・・→ 設定4(軸2) →<br>⋮<br>設定1(最大制御軸) → ・・・→ 設定4(最大制御軸) →<br>設定1(軸1) → ・・・ |

*1 高速モードではトランジェント伝送の優先度が低くなるため，複数軸のトランジェント伝送処理が標準モードよりも遅くなります。

#### 注意事項 (9.16 / 印刷 p.398 / 原本 p.400)

ドライバ原点復帰式では，トランジェント伝送にてドライバの原点データの取得を行います。そのため，ドライバ原点復帰実行中にトランジェント伝送にてスレーブ機器のオブジェクトを読書きしている場合，エラー「ABS基準点リードエラー」(エラーコード: 1975H)となる場合があります。

### 9.18 テストモード (9.18 / 印刷 p.400 / 原本 p.402)

テストモードは，エンジニアリングツールから軸の試運転や調整を行うモードです。複数軸同時にテスト運転や軸の調整などを行えるため，タンデム構成のようなシステムもスムーズに立上げることができます。

エンジニアリングツールのテストを起動するとシンプルモーションユニットに対してテストモードの要求を行います。

テストモードの要求が正常に受け付けられた場合，テスト画面が表示されテストモードの各機能が選択可能となります。

テストモードの操作方法の詳細は，エンジニアリングツールの「シンプルモーションユニット設定機能」のヘルプを参照してください。

| 機能 | 動作 |
