## 9 共通機能 (第9章 / 印刷 p.354-378 / 原本 p.356-380 の範囲)

### 9.8 仮想サーボアンプ機能 (9.8 / 印刷 p.354 / 原本 p.356)

仮想サーボアンプ機能を使用すると，サーボアンプを接続していなくても仮想的に(接続しているものとみなして)動作できます。仮想サーボアンプ軸を同期制御のサーボ入力軸として使用することで，仮想的な入力指令で同期制御ができます。また，サーボアンプ未実装の軸をシミュレーション動作させる用途にも使用できます。

#### RD77MSの仮想サーボアンプ機能 (9.8 / 印刷 p.354 / 原本 p.356)

##### 制御内容 (9.8 / 印刷 p.354 / 原本 p.356)

- フラッシュ ROMに設定された"[Pr.100]接続機器"の値が「00000FFFH，00001FFEH，00001FFFH」の場合，電源投入直後から仮想サーボアンプとして動作します。
- フラッシュ ROMに設定された"[Pr.100]接続機器"の値が「00000000H」の場合，電源投入後にバッファメモリの"[Pr.100]接続機器"を「00000FFFH，00001FFEH，00001FFFH」に設定して，シーケンサレディ信号[Y0]をOFF → ONすると，仮想サーボアンプとして動作します。
- 仮想サーボアンプを設定した軸に実際のサーボアンプは接続しないでください。MR-J4(W)-Bを接続した場合，サーボアンプのLED表示状態は"Ab"となり認識されません。MR-J5(W)-Bを接続した場合，サーボアラーム「接続モード異常1」(アラーム番号: 3E.9)が発生し，認識されません。サーボアラームの発生後にMR-J5(W)-Bの電源をリセットした場合，サーボアンプのLED表示状態は"Ab"となり認識されません。また，後続のサーボアンプが最終局まで接続できなくなります。
- 仮想サーボアンプの送り現在値，送り機械値の値は以下のようになります。
  - 絶対位置検出システムでない場合，送り現在値，送り機械値共に「0」となります。
  - 絶対位置検出システムの場合，原点を確立した状態のときは，最後にユニット電源を切断したときのアドレスとなります。原点を確立していない状態のときは，送り現在値，送り機械値共に「0」となります。
- エンジニアリングツールのシステム設定で仮想サーボアンプを設定した場合，「絶対位置検出システム(PA03)」*1は「0: 無効(インクリメンタルシステムで使用する。)」の設定となります。絶対位置システムとして使用する場合は，バッファメモリに「1: 有効(絶対位置検出システムで使用する。)」を設定してください。

\*1 MR-J3(W)-B/MR-J4(W)-Bの場合です。MR-J5(W)-Bの場合は，「絶対位置検出システム選択(PA03.0)」を設定してください。

> **Point**
> 実際のサーボアンプと仮想サーボアンプを切り換えて動作させることはできません。フラッシュ ROMに設定された"[Pr.100]接続機器"の値が「00000000H」以外のとき，電源投入後にバッファメモリの"[Pr.100]接続機器"を変更して，シーケンサレディ信号[Y0]をOFF → ONしても，接続機器は変更されません。接続機器を変更する場合はフラッシュ ROM書込み実施後，電源再投入またはCPUユニットリセットを行ってください。

#### RD77GFの仮想サーボアンプ機能 (9.8 / 印刷 p.356 / 原本 p.358)

##### 制御内容 (9.8 / 印刷 p.356 / 原本 p.358)

- 下表の区分に従い，実サーボアンプと仮想サーボアンプを接続した運転が可能です。

| ユニット動作モード設定 | 実サーボアンプ↔仮想サーボアンプを切り換えて運転する | 仮想サーボアンプのみ接続して運転する |
|---|---|---|
| オンラインモード | 運転可 | 運転可 |
| オフラインモード | 運転不可 | 運転可 |

- オフラインモードは，ネットワーク構成設定で"MR-J4-GF"が設定されている全局に対し，ユニット電源投入時に仮想サーボアンプが接続されます。
- オンラインモード中は，ネットワーク構成設定の設定内容に応じて，仮想サーボアンプの接続可否および方法が異なります。仮想サーボアンプの接続／切断方法については下記のようになります。

##### 制御内容 (9.9 / 印刷 p.360 / 原本 p.362)

マスタ軸とスレーブ軸の設定は，サーボパラメータで設定します。

シンプルモーションユニットの各制御は，マスタ軸に対して行います。(ただし，スレーブ軸のサーボON／OFFとサーボアラーム発生時のエラーリセットは，スレーブ軸で行う必要があります。)

マスタ軸に設定したサーボアンプは，シンプルモーションユニットからの指令(位置指令，速度指令，トルク指令)を受信し，サーボアンプのドライバ間通信でスレーブ軸に設定したサーボアンプへ制御データを送信します。

スレーブ軸に設定したサーボアンプは，サーボアンプのドライバ間通信により，マスタ軸から送信された制御データで制御されます。

【図】ドライバ間通信のシステム構成例(9.9 / 印刷 p.360 / 原本 p.362)
- シンプルモーションユニット(図はRD77MS4)から SSCNETⅢ(/H) でマスタ軸(d1)に接続し、d1 → d2 → d3 → d4 の順に数珠つなぎ。
- d1: マスタ軸(軸1 ABS/INC)、d2: スレーブ軸1(軸2 INC)、d3: スレーブ軸2(軸3 INC)、d4: スレーブ軸3(軸4 INC)。各アンプにサーボモータ1台。
- マスタ軸はシンプルモーションユニットから位置指令／速度指令／トルク指令を受信。
- [ドライバ間通信] マスタ軸 → スレーブ軸1: 制御データ1・制御データ2・制御データ3、スレーブ軸1 → スレーブ軸2: 制御データ2・制御データ3、スレーブ軸2 → スレーブ軸3: 制御データ3 が送られる。
- 図中注記: 「マスタ軸: シンプルモーションユニットからの位置指令／速度指令／トルク指令を受信」「スレーブ軸: マスタ軸からドライバ間通信により制御データを受信」。

> **Point**
> - サーボアンプの故障による通信切断時は，故障軸以降と通信できません。そのため，SSCNETⅢケーブルを接続する際は，シンプルモーションユニットに一番近い位置へマスタ軸を接続してください。
> - 1つの機構に対し，複数のモータで駆動させる場合に使用します。マスタ軸とスレーブ軸は，すべりがないように結合してください。

##### 制御上の注意事項 (9.9 / 印刷 p.360-362 / 原本 p.362-364)

> **注意**
> - ドライバ間通信による運転中にスレーブ軸でサーボアラームが発生しても，マスタ軸の位置決め制御やJOG運転を中断しません。ユーザプログラムにて停止させてください。

###### ■サーボアンプ (9.9 / 印刷 p.361 / 原本 p.363)

- ドライバ間通信を行う軸には，ドライバ間通信に対応したサーボアンプを使用してください。
- マスタ軸とスレーブ軸の組合せは，サーボパラメータにて設定します。サーボパラメータをシンプルモーションユニットに書込み後，システムの電源再投入またはリセットで有効になります。
- ドライバ間通信の運転可能状態は，システムモニタデータの"[Md.52]ドライバ間通信軸検索中フラグ"で確認してください。接続／未接続のサーボアンプ軸が混在しているとアンプなし運転に切り換えることができません。サーボアンプを全軸未接続にするか，全軸接続したときにアンプなし運転に切り換えてください。
- ドライバ間通信機能使用時に切断／再接続を行う場合，先頭軸(シンプルモーションユニットと直接接続しているサーボアンプ)でのみ，切断／再接続を行えます。先頭軸以外のサーボアンプで切断することは可能ですが，再接続はできません。
- ドライバ間通信機能における，SSCNETⅢ接続とSSCNETⅢ/H接続の違いを下記に示します。

### 9.10 マーク検出機能 (9.10 / 印刷 p.365 / 原本 p.367)

マーク検出信号(DI)の入力タイミングで，任意のデータをラッチすることができます。
また，マーク検出するデータ範囲を指定して，範囲内のデータだけをラッチすることも可能です。
マーク検出を行うモードとして，以下の3種類があります。

##### 常時検出モード (9.10 / 印刷 p.365 / 原本 p.367)

マーク検出時，常にラッチデータをマーク検出データ格納エリアの先頭に格納します。

【図】常時検出モードの格納動作(9.10 / 印刷 p.365 / 原本 p.367)
- マーク検出信号の5回の立上りすべてで、ラッチデータが「格納エリア1」に格納される(毎回上書き)。マーク検出データ格納エリアは格納エリア1のみ。

##### 指定回数モード (9.10 / 印刷 p.365 / 原本 p.367)

設定した回数分ラッチデータを格納します。
高速に連続でマーク検出信号が入力される場合に，指定した回数分の検出位置を収集することができます。

例: 設定回数「3」の場合

【図】指定回数モードの格納動作(設定回数「3」)(9.10 / 印刷 p.365 / 原本 p.367)
- 1回目の立上り → 格納エリア1、2回目 → 格納エリア2、3回目 → 格納エリア3 に格納(格納エリア1→4方向へ順に進む矢印)。
- 「4回目以降は無視される」(4回目・5回目の立上りは格納されない)。格納エリア4は使われない。

##### リングバッファモード (9.10 / 印刷 p.365 / 原本 p.367)

設定回数分のリングバッファにラッチデータを格納します。
マーク検出時，常にラッチデータを格納します。

例: 設定回数「4」の場合

【図】リングバッファモードの格納動作(設定回数「4」)(9.10 / 印刷 p.365 / 原本 p.367)
- 1回目 → 格納エリア1、2回目 → 格納エリア2、3回目 → 格納エリア3、4回目 → 格納エリア4 に格納。
- 「5回目は先頭に戻る」: 5回目の立上りは格納エリア1に格納される(格納エリア4から1へ戻る循環矢印)。

##### マーク検出機能の動作 (9.10 / 印刷 p.367 / 原本 p.369)

マーク検出時の動作は以下のようになります。

- マーク検出信号の立上り／立下りでマーク検出データが推定計算されます。ただし，マーク検出モードが指定回数モードの場合，マーク検出回数を確認し，マーク検出を行うかどうかを判定します。
- マーク検出データ範囲が設定されている場合，マーク検出時データが範囲内であることを確認します。範囲外のデータは検出しません。
- マーク検出モードに従って，マーク検出時データをマーク検出データ格納エリアに格納し，マーク検出回数を更新します。

##### [Pr.805]ラッチデータ範囲上限値，[Pr.806]ラッチデータ範囲下限値 (9.10 / 印刷 p.372 / 原本 p.374)

- 上限値 ＝ 下限値の場合

##### 注意事項 (9.10 / 印刷 p.375 / 原本 p.377)

- "[Pr.802]マーク検出データ種別"，"[Pr.803]マーク検出データ軸番号"で選択したデータが存在しない場合，マーク検出すると不定なラッチデータが格納されます。"[Pr.802]マーク検出データ種別"に項目があるデータについては，バッファメモリ番号の直接指定ではなく，項目の番号を設定し使用してください。
- "[Pr.802]マーク検出データ種別"に「9: 主軸ギア後1サイクル現在値」または「10: 補助軸ギア後1サイクル現在値」を選択し，同期制御中にカム軸1サイクル長を変更した直後にマーク検出すると，カム軸1サイクル長を変更する前のデータをラッチする場合があります。このとき，ラッチデータは実行中のカム軸1サイクル長を基に算出されます。そのため，実際に出力されたモニタデータと異なる値をラッチする場合があります。
- シンプルモーションユニットのマーク検出機能は，サーボアンプのタッチプローブ機能と連携しません。タッチプローブ機能を使用する場合は，サーボサイクリック伝送機能やサーボトランジェント伝送機能により，タッチプローブ関連オブジェクトにアクセスしてください。[RD77GF]
- "[Pr.802]マーク検出データ種別"で「8: 主軸合成ギア後現在値」～「12: カム軸1サイクル現在値(実位置)」を選択し，同期制御中以外でマーク検出すると，実際に出力されたモニタデータと異なる値をラッチする場合があります。
- 現在位置変更や原点復帰等により，ラッチ対象のデータが大きく変化したタイミングでマーク検出信号が入力された場合，正しいデータをラッチできません。
  現在位置変更や原点復帰中は，"[Cd.801]マーク検出無効フラグ"等を使用して，マーク検出を一時的に無効にしてください。
