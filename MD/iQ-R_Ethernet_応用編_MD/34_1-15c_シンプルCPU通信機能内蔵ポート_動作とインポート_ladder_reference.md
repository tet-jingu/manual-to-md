## 通信タイムアウト時間，通信リトライ回数，異常時監視時間 (原本 p.229)

交信相手から応答がないまたはエラー応答となった場合，タイムアウト時間まで経過後，リトライ(再送)されます。

交信設定が"定期"の場合は，リトライ回数+1回実施後，エラー検出し，異常時監視時間で定周期交信します。そのあとにまた交信相手から応答があれば，パラメータで指定した実行間隔での交信に戻ります。

交信設定が"要求時"の場合は，リトライ回数+1実施後，エラー検出し，シンプルCPU通信状態を"2H: 要求待ち"状態とします。

### 例: 通信リトライ回数の設定が2の場合のエラー検出タイミング

【図】通信リトライ回数2の場合のエラー検出タイミング(原本 p.229)。実行間隔ごとに「交信」を試み、失敗(前回交信通信異常)→通信タイムアウト時間経過後に通信リトライ1回目→失敗→通信タイムアウト時間経過後に通信リトライ2回目→失敗→通信タイムアウト時間経過後にエラー検出。エラー検出後は異常時監視時間の周期で「交信」を継続する。(1.14の同種図(原本p.206)と同一パターン)

> Point
> (通信リトライ回数+1)×通信タイムアウト時間経過までに応答がないとき，または通信異常となった場合にエラーとなります。

## 通信開始待ち時間 (原本 p.229)

通信開始待ち時間を設定することで，下記のような場合に通信開始のタイミングをずらすことができます。

 - 通信が集中して通信開始のタイミングが重なり，エラーとならないようにする場合
 - 交信相手が通信可能となってから通信を開始する場合

通信開始待ちの間，通信状態は"準備中"となります。

> Point
> 通信開始待ち時間を設定した場合，通信開始待ち時間内は，交信設定を"定期"とした設定No.の交信は行われず，通信開始待ち時間経過後に交信を開始します。交信設定を"要求時"とした設定No.は通信開始待ち時間内に要求時交信開始要求をOFF→ONした場合は，通信開始待ち時間経過後に交信を開始します。

## 初回交信設定 (原本 p.229)

初回交信時に交信相手からの応答がなかった場合(交信相手のIPアドレスが違う，未起動時含む)の動作を設定できます。

本設定を設定することで，シンプルCPU通信開始時点で交信相手機器が未接続(電源OFFを含む)の場合に，シンプルCPU通信開始後の交信相手機器が接続(電源ON)した時点で交信を開始できます。

> 注意事項
> 本設定は，交信設定が"要求時"の場合は無効です。また，交信設定が"定期"の場合でも，シンプルCPU通信状態が下記以外の場合は無効です。
> - 3H: 実行中
> - 5H: リトライ中
> - 6H: 監視中

> 制約事項
> 初回交信設定を使用する場合，CPUユニットのバージョンを確認してください。(550ページ 機能の追加と変更)

交信相手機器が接続(電源ON)した時点で交信を開始します。

## 設定のインポート・エクスポート (原本 p.230)

シンプルCPU通信設定の設定をCSVファイルからインポート，CSVファイルにエクスポートします。

### エクスポート

1. "シンプルCPU通信設定"の"設定項目"画面の[エクスポート]ボタンをクリックします。
2. "ファイルへエクスポート"画面でエクスポートするファイル名を入力し，[保存]ボタンをクリックします。
3. 必要に応じてエクスポートしたCSVファイルを編集してください。"シンプルCPU通信設定"の"設定項目"画面に表示される内容を編集できます。

CSVファイルの詳細なフォーマットについて示します。

 - ファイル形式は，Unicode(UTF-16 Little Endian BOMあり)です。
 - 項目間の区切りは「¥t」(タブ)です。
 - 各項目は「"」(ダブルクォーテーション) で囲まれます。
 - 項目内に「"」(ダブルクォーテーション)を含む場合，項目内の「"」(ダブルクォーテーション) は「""」(ダブルクォーテーション2個) で表示されます。
 - 行の最後は改行が設定されます。改行コードはCR+LFです。

### 注意事項

CSVファイルは，"シンプルCPU通信設定"の"設定項目"画面に表示される文字列が，別の文字列に置き換わる項目があります。別の文字列に置き換わる項目を下記に示します。

*1 CSVファイルのIPアドレス入力形式の進数で，IPアドレスがインポートされます。

*2 CSVファイルのデバイス割付方法で，転送元デバイスのデバイス範囲(点数/先頭番号/最終番号)が設定されます。

| 項目 | エンジニアリングツール | CSVファイル |
|---|---|---|
| IPアドレス入力形式*1 | 10進数 | DEC |
| IPアドレス入力形式*1 | 16進数 | HEX |
| デバイス割付方法*2 | 点数/先頭 | Points/Start |
| デバイス割付方法*2 | 先頭/最終 | Start/End |
| 初回交信設定 | 初回交信設定にチェックあり | Enable |
| 初回交信設定 | 初回交信設定にチェックなし | Disable |
| 通信パターン | 読出 | Read |
| 通信パターン | 書込 | Write |
| 交信設定 | 要求時 | 0 |
| 交信設定 | 定期 | 1 |

原本の表行数(目視カウント): 10行。上表は全10行を転記。

### インポート (原本 p.231)

1. "シンプルCPU通信設定"の"設定項目"画面の[インポート]ボタンをクリックします。
2. "ファイルのインポート"画面でインポートするファイル名を選択し，[開く]ボタンをクリックします。
3. [OK]ボタンをクリックします。
4. "シンプルCPU通信設定"の"設定項目"画面にCSVファイルのデータが反映されます。

インポート時のファイルの書式は，下記のフォーマットに従ってください。

 - 項目間の区切りは，「¥t」(タブ)を使用できます。
 - 区切り文字や改行コードを含む項目は，ダブルクォーテーションで囲んでください。

> 注意事項
> - インポートすると元の設定はすべてクリアされます。必要に応じてエクスポートするなどして退避してください。
> - CSVファイルは行の挿入や削除，項目の値を不正な値への変更は行わないでください。エラーメッセージが表示されインポートできません。
> - 10行目以降にデータが設定されたCSVファイルをインポートしてください。

## 交信設定を"定期"にした場合の動作 (原本 p.231)

### 動作

電源OFF→ON，またはCPUユニットのリセット後に交信を開始します。

交信相手先にデータを送信後，交信相手から応答がない，または異常(エラー応答)となった場合，タイムアウト時間まで経過後に，リトライ(再送)を行います。(229ページ 通信タイムアウト時間，通信リトライ回数，異常時監視時間)

 - 電源OFF→ON，またはCPUユニットのリセット後に，システム側で準備処理を行います。準備処理で異常となった場合はデータを送受信しません。このとき，シンプルCPU通信状態のCPUバッファメモリの値は，AH(交信不可)となります。
 - 通信開始待ち時間を設定した場合は通信開始待ち時間経過後交信を開始します。(229ページ 通信開始待ち時間)
 - 初回交信設定の設定内容によって初回交信の動作が異なります。初回交信設定未設定時は交信相手からの応答がなかった場合は異常となり，データを送受信しません。(異常時監視時間で定周期交信しません。)*1(229ページ 初回交信設定)
 - 同じ交信相手を複数の設定No.で設定している場合，交信設定が"定期"は，1つの処理でリトライとなると同じ交信相手の他の設定No.は実行間隔で交信しません。交信設定が"要求時"はシンプルCPU通信状態のCPUバッファメモリの値が6H(監視中)の間は実行できません。

*1 RnPCPUでは，初回交信設定はデフォルトで設定済み(有効)の状態です。設定項目の"応答があるまで交信する"にチェックが入った状態でグレーアウトしているため，設定内容を変更することはできません。

交信相手機器が接続(電源ON)した時点で交信を開始します。

## 交信設定を"要求時"にした場合の動作 (原本 p.232)

### 動作

電源OFF→ON，またはCPUユニットのリセット後，要求時交信開始要求のCPUバッファメモリをOFF→ONすると，交信を開始します。データ送受信後，要求時交信開始要求のCPUバッファメモリをシステム側で自動的にOFFし，シンプルCPU通信状態を2H(要求待ち)にします。

交信相手先にデータを送信後，交信相手から応答がない，または異常(エラー応答)となった場合，タイムアウト時間まで経過後に，リトライ(再送)を行います。(229ページ 通信タイムアウト時間，通信リトライ回数，異常時監視時間)

> Point
> - 電源OFF→ON，またはCPUユニットのリセット後に，システム側で準備処理を行います。準備処理で異常となった場合はデータを送受信しません。このとき，シンプルCPU通信状態のCPUバッファメモリの値は，AH(交信不可)となります。
> - 通信開始待ち時間を設定した場合は，通信開始待ち時間経過後に交信を開始します。なお，通信開始待ち時間中は，要求時開始要求のCPUバッファメモリをOFF→ONしても無視します。(229ページ 通信開始待ち時間)
> - 初回実行時*1は交信相手先の存在可否チェックなどの準備処理を行うため，処理時間が長くなります。
> - 要求時交信開始要求をONしたあと，プログラムなどで要求時交信開始要求のCPUバッファメモリをON→OFF→ONしても、要求は無視されます。
> - 実行状態フラグのON，要求時交信開始要求のOFF→ON，シンプルCPU通信状態3H(実行中)の更新タイミングは同一となりません。また，実行状態フラグのOFF，シンプルCPU通信状態2H(要求待ち)，要求時交信開始要求のOFFの更新タイミングは同一となりませんが，スキャンタイムが長い場合は同一となる場合があります。
> - スキャンタイムが長いと，実行状態フラグのONとOFFを同じタイミングで更新するため，プログラムで検出できない場合があります。
> - 同じ交信相手を複数の設定No.で設定している場合，1つの設定で異常を検出すると，同じ交信相手の他の設定No.も異常となります。同じ交信相手の交信設定"定期"のシンプルCPU通信状態のCPUバッファメモリの値が6H(監視中)の間も実行できません。

*1 同じ交信相手を設定したすべての交信設定"要求時"の初回実行および直前の実行が異常完了している場合が該当します。また，同じ交信相手を設定した交信設定"定期"が存在する場合で，すべての"定期"の設定が停止している場合も該当します。(交信設定"定期"が3H(実行中)の場合は該当しません。)

### 例: 設定No.1の要求時交信開始要求の動作

【図】要求時交信開始要求のタイミングチャート(原本 p.232)

- 電源OFF→ON，リセット → イニシャル処理 → 通信開始待ち時間 → (1)交信要求OFF→ON → 準備処理 → 交信開始 → 応答受信 → 交信完了 → (2)要求完了(システムでOFF) → (1)交信要求OFF→ON → 交信開始 → 応答受信 → 交信完了 → (2)要求完了
- U3En\G1090.0(要求時交信開始要求): (1)プログラムでON、(2)システムでOFF。
- U3En\G1102.0(実行状態フラグ): 交信開始でON、交信完了でOFF。
- U3En\G1106.0(準備完了): 通信開始待ち時間経過後にONし、以降ON維持。
- U3En\G1130(シンプルCPU通信状態): 0H(未設定)→1H(準備中)→2H(要求待ち)→3H(実行中、交信開始～交信完了)→2H(要求待ち)→3H(実行中)→2H(要求待ち)。
- U3En\G1194(シンプルCPU通信エラーコード)・U3En\G1322(異常応答コード): いずれも0のまま。

凡例: (1)プログラムでON (2)システムでOFF
