## 3.4 現象別トラブルシューティング (原本 p.417)

現象別のトラブルシューティングを示します。Ethernet搭載ユニットでエラーが発生している場合は，エンジニアリングツールで異常の原因を特定してください。(402ページ ユニットの状態確認)

## 相手機器と交信できない (原本 p.417)

相手機器と交信できない場合は，下記の項目を確認してください。

| 確認項目 | 処置方法 |
|---|---|
| CPUユニットのREADY LEDが消灯していないか。 | CPUユニットのREADY LEDが消灯している場合は，CPUユニットのトラブルシューティングを実施してください。(使用するCPUユニットのマニュアル) |
| RJ71EN71またはRnENCPU(ネットワーク部)のRUN LEDが消灯していないか。 | RJ71EN71またはRnENCPU(ネットワーク部)のRUN LEDが消灯している場合は，CPUユニットをリセットしてください。リセットしてもRUN LEDが点灯しない場合は，ハードウェア異常と思われます。RJ71EN71またはRnENCPUを交換し，自局と交信していた相手機器をすべて再立上げしてください。\*1 |
| Ethernetケーブルがしっかりと接続されているか。 | Ethernetケーブルがしっかりと接続されていない場合は，下記の処置を行ってください。・ケーブルは確実にロックしてください。・配線を確認してください。(MELSEC iQ-R Ethernet/CC-Link IEユーザーズマニュアル(スタートアップ編)) |
| 相手機器がEthernetの規格を満たしているか。 | 相手機器がEthernetの規格を満たしていない場合は，Ethernetの規格を満たした機器に交換してください。(MELSEC iQ-R Ethernet/CC-Link IEユーザーズマニュアル(スタートアップ編)) |
| 相手機器の電源がONになっているか。 | 相手機器の電源がONになっていない場合は，ONしてください。 |
| 相手機器，ハブ，ルータなどでエラーが発生していないか。 | 相手機器，ハブ，ルータなどでエラーが発生している場合は，各機器のマニュアルを確認し，処置してください。 |
| 相手機器とのプロトコル(TCP/IPまたはUDP/IP)が一致しているか。 | 相手機器とプロトコル(TCP/IPまたはUDP/IP)が一致していない場合は，一致するようにパラメータを修正してください。(311ページ 相手機器接続構成設定) |
| ”応用設定”の”セキュリティ ”にある”IPフィルタ設定”で相手機器からのアクセスを遮断していないか。 | ”応用設定”の”セキュリティ ”にある”IPフィルタ設定”で相手機器からのアクセスを遮断している場合は，透過するように設定を変更してください。(385ページ IPフィルタ設定) |
| 異常が発生する前に，回線上の機器(Ethernet搭載ユニット，相手機器，ハブ，ルータなど)を交換前の機器と同じIPアドレスの機器に交換していないか。 | 回線上の機器(Ethernet搭載ユニット，相手機器，ハブ，ルータなど)を交換前の機器と同じIPアドレスの機器に交換した場合は，下記のいずれかの処置を行ってください。・ARPキャッシュの更新が実行されるまで待つ(待ち時間は機器によって異なります)・回線上の機器をすべて再立上げする\*1 |
| 相手機器のIPアドレス指定は間違っていないか。 | 相手機器のIPアドレス宛にPINGを実行してください。相手機器の存在が確認できない場合は，運用するネットワーク構成に問題があります。システム管理者またはネットワーク管理者にご相談ください。 |
| ”応用設定”の”ユニット動作モード設定”が”オンラインモード”以外になっていないか。\*4 | ”応用設定”の”ユニット動作モード設定”を”オンラインモード”に設定してください。(395ページ ユニット動作モード設定) |
| イニシャル処理が正常完了しているか。(ʼイニシャル状態ʼ(Un\G1900024.0)を確認する)\*3 | イニシャル処理が正常完了していない場合は，ユニットパラメータを見直してください。(308ページ パラメータ設定) |
| 交信データコード(ASCII/バイナリ)の設定が相手機器と一致しているか。 | 交信データコードが相手機器と異なると，コマンドを正常に解読できないため送受信できません。\*2 ”基本設定”の”自ノード設定”にある”交信データコード”を相手機器と合わせてください。(309ページ 自ノード設定) |
| ”Ethernet診断”画面の”コネクション別状態”にある”強制無効化状態”欄で，対象コネクションが強制無効化状態になっていないか。 | ʼコネクション強制無効化設定エリアʼ(Un\G5646~Un\G5650)の対象コネクションのエリアをOFFし，強制無効化を解除してください。 |
| 相手機器のセキュリティ設定にて，Ethernet搭載ユニットからのアクセスを遮断していないか。 | 相手機器のセキュリティ設定(ファイアウォールなど)を見直してください。 |
| RJ71EN71またはRnENCPU(ネットワーク部)の場合，ʼIPアドレス変更機能動作状態ʼ(Un\G11715.0)がONになっていないか。 | ʼIPアドレス変更機能動作状態ʼ(Un\G11715.0)がONしている場合，IPアドレス変更機能の設定で動作しています。IPアドレス格納エリアをクリアするか，設定を見直してください。(276ページ IPアドレス変更機能) |
| エンジニアリングツールと接続する場合，接続時にタイムアウトが発生していないか。 | ”接続先指定 Connection”画面の下記より”交信タイムチェック”，”リトライ回数”を増やしてから再度接続してください。・”他局指定無し”の”自局 詳細設定”画面・”他局(単一ネットワーク)”または”他局(異種ネットワーク)”の”他局 詳細設定”画面 |

原本の表行数(目視カウント): 17行。上表は全17行を転記。

上記の処置でも解決できない場合は，交信処理別に異常箇所を確認し，処置してください。

- SLMPによる交信(420ページ SLMPによる交信ができない)
- 通信プロトコルによる交信(421ページ 通信プロトコルによる交信ができない)
- ソケット通信/固定バッファによる交信(423ページ ソケット通信/固定バッファによる交信ができない)
- ランダムアクセス用バッファによる交信(422ページ ランダムアクセス用バッファによる交信ができない)
- リンク専用命令による交信(425ページ リンク専用命令による交信ができない)
- ファイル転送機能(FTPサーバ)(425ページ ファイル転送機能(FTPサーバ)でアクセスできない)

\*1 Ethernet上の機器は，ARPキャッシュというIPアドレスとMACアドレスの対応表を保持しています。回線上の機器を同じIPアドレスの機器に交換すると，ARPキャッシュに保持されているMACアドレスと，交換した機器のMACアドレスが不一致になるため，正常に交信できなくなる場合があります。ARPキャッシュの更新は，機器のリセットまたは一定時間が経過すると実施されます。なお，時間は機器によって異なります。
\*2 Ethernet搭載ユニットの交信データコードと相手機器の交信データコードが異なるとき，エラーコード一覧にないエラーコードが相手機器側へ返されることがあります。Ethernet搭載ユニットは，データコードの異なるデータを受信したとき，コマンドを正常に解読できません。Ethernet搭載ユニットは，交信データコード設定に従い，エラー応答を返します。
\*3 RJ71EN71またはRnENCPU(ネットワーク部)のネットワーク種別を”Ethernet”に設定し，P1コネクタを使用した場合のバッファメモリアドレスです。CPUユニット(内蔵Ethernetポート部)使用時，P2コネクタ使用時またはネットワーク種別を”Q互換Ethernet”に設定した場合は，下記を参照してください。461ページ バッファメモリ
\*4 ユニットパラメータに設定があるユニットが対象です。

## 相手機器からの送信伝文を受信できないことが多発する (原本 p.418)

相手機器からの送信伝文をEthernet搭載ユニットで受信できないことが多発する場合は，下記の項目を確認してください。

上記の処置でも解決できない場合は，単体通信テストを実施し，ハードウェアに異常がないか確認してください。(404ページ 単体通信テスト)\*2

\*1 RJ71EN71またはRnENCPU(ネットワーク部)のネットワーク種別を”Ethernet”に設定し，P1コネクタを使用した場合のバッファメモリアドレスです。CPUユニット(内蔵Ethernetポート部)使用時，P2コネクタ使用時またはネットワーク種別を”Q互換Ethernet”に設定した場合は，下記を参照してください。461ページ バッファメモリ
\*2 CPUユニット(内蔵Ethernetポート部)では単体通信テストができません。CPUユニットのトラブルシューティングを行い，ハードウェアに異常がないか確認してください。(使用するCPUユニットのマニュアル)
\*3 バッファメモリの使用可否はファームウェアバージョンによって異なります。(550ページ 機能の追加と変更)

| 確認項目 | 処置方法 |
|---|---|
| エンジニアリングツールと接続する場合，[Ethernet診断][TCP状態]にて接続したいコネクションが”接続中”となっているか。 | 他のユーザが接続している可能性があるため，コネクションが切断されるのを待つか，UDP/IPで接続してください。接続に心当たりがない場合は，コネクション強制無効化設定エリアの対象コネクションエリアをONし，強制無効化を実行してください。(502ページ コネクション強制無効化設定エリア) |
| ʼ同時送信エラー検出回数(受信バッファフル回数)ʼ(Un\G5022~Un\G5023)のエラー検出回数が多くないか。\*1 | エラー検出回数が多いまたはシステムエラーが格納されている場合は，各接続機器間のデータ送受信でのEthernet回線への高負荷が考えられます。・Ethernet回線の負荷を軽減するため，ネットワークの分離またはデータ送信回数を減らすなどの対策を行ってください。・ネットワーク管理者に相談の上，Ethernet回線の負荷を軽減してください。 |
| ʼ最新エラーコードʼ(Un\G100~Un\G163(コネクションNo.1~64最新エラーコード))にシステムエラーが格納されていないか。\*1 | (上記と同様) |
| ʼ受信バッファ状態ʼ(Un\G1900030)に1Hが格納されていないか。\*3 | ・Ethernet回線の負荷を軽減するため，ネットワークの分離またはデータ送信回数を減らすなどの対策を行ってください。・固定バッファ交信を使用している場合は，BUFRCV命令が実行されているか確認してください。(72ページ 受信手順)・固定バッファ交信でCPUユニットのスキャンタイムよりも短い間隔でデータを受信する場合は，BUFRCV命令の完了デバイスのB接点を受信用のFBの実行条件に追加してください。(91ページ 使用ラベル) |
