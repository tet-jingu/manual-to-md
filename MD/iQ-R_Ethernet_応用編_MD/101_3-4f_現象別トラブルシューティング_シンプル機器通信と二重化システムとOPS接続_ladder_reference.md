## シンプル機器通信機能使用時 (原本 p.429)

### 交信相手と交信できない (原本 p.429)

シンプル機器通信機能で交信相手と交信できない場合は，下記の内容を確認し，処置してください。

\*1 Ethernetケーブル再接続時にʼ接続状態ʼ(Un\G1249309)が5H(リトライ中)の場合，通信が正常復帰するまで最大で((リトライ回数+1)×”通信タイムアウト時間”)+(”異常時監視時間”×2)の時間がかかる場合があります。ʼ接続状態ʼ(Un\G1249309)が6H(異常監視中)の場合，正常復帰するまで最大で(”異常時監視時間”×2)の時間がかかる場合があります。

| 確認項目 | 処置方法 |
|---|---|
| シンプル機器通信機能に対応しているユニットを使用しているか。 | ”システムモニタ”の”製品情報一覧”で，対象ユニットのファームウェアバージョンを確認し，シンプル機器通信に対応したユニットか確認してください。シンプル機器通信未対応のユニットを使用している場合，対応済みファームウェアにアップデートするか，対応済みのユニットに交換してください。 |
| 交信相手のIPアドレスの設定が正しいか。 | 交信相手のIPアドレスを確認し，間違っている場合は修正してください。 |
| ʼ接続状態ʼ(Un\G1249309)が3H(実行中)になっているか。 | ・1H(準備中)の場合は，通信開始待ち時間が経過するまで待ってください。・2H(要求待ち)または4H(停止中)の場合は，ʼ機能起動/停止指示ʼ(Un\G1249300.0)とʼ各プロトコルの開始要求ʼ(Un\G1249348~Un\G1249379)をONしてください。・5H(リトライ中)または6H(異常監視中)の場合は，”通信タイムアウト時間”または”異常時監視時間”経過後に再度確認してください。 |
| Ethernetケーブルがしっかりと接続されているか。 | Ethernetケーブルを正しく接続してください。\*1 |
| プロトコル設定にて，交信相手に対して適切なプロトコルが使用されているか。 | 交信相手に対して適切なプロトコルを使用していない場合は，適切なプロトコルに修正してください。プロトコルについては，交信相手のマニュアルを参照してください。 |

原本の表行数(目視カウント): 5行。上表は全5行を転記。

シンプル機器通信機能で交信相手から応答を受信しているが，照合不一致となる場合は，下記の内容を確認し，処置してください。

| 確認項目 | 処置方法 |
|---|---|
| ʼ照合不一致プロトコル番号ʼ(Un\G1249317)と，'照合不一致情報'(Un\G1249318~Un\G1249333)を確認する。 | 照合不一致となった構成要素番号と照合不一致の要因を確認し，原因となっている構成要素の設定内容を見直してください。 |
| ”送受信パラメータ設定”の”受信システムエリアクリア”の設定内容を確認する。 | ”しない”に設定されている場合は，”する”に設定してください。 |

### 系切替えが正常に行われない (原本 p.430)

二重化システム対応機能で系切替えが正常に行われない場合は，下記の内容を確認し，処置してください。

\*1 RJ71EN71のネットワーク種別を”Ethernet”に設定し，P1コネクタを使用した場合のバッファメモリアドレスです。CPUユニット(内蔵Ethernetポート部)使用時，P2コネクタ使用時またはネットワーク種別を”Q互換Ethernet”に設定した場合は，下記を参照してください。461ページ バッファメモリ
\*2 通信ケーブル抜けやパソコンの再起動により，相手機器側のみクローズした場合，異常が発生する前と同一ポートを使用して再オープンしてください。異なるIPアドレスまたはポート番号で相手機器から再度Activeオープン要求を受信した場合，コネクションをクローズしません。

| 確認項目 | 処置方法 |
|---|---|
| 待機系の電源ユニット，CPUユニットまたは二重化機能ユニットが正常か。 | 待機系の電源ユニット，CPUユニットおよび二重化機能ユニットのトラブルシューティングを実施してください。(使用するCPUユニットのマニュアル) |
| CPUユニットに対して系切替え要求が発行されているか。(制御系CPUユニットのʼ自系のネットワークユニットからの系切替え要求発行ユニットNo.ʼ(SD1645)を確認する) | 制御系CPUユニットに装着されているEthernet搭載ユニットのエラーを確認し，エラー内容を修正してください。 |
| ”応用設定”の”二重化設定”にある”通信異常時の系切替え要求発行有無”が”有効”になっているか。 | ”応用設定”の”二重化設定”にある”通信異常時の系切替え要求発行有無”を”有効”に設定してください。 |
| ”応用設定”の”二重化設定”にある”通信異常時の系切替え要求発行有無”の”ユーザ用コネクション”または”システム用コネクション”で対象コネクションが系切替え要求を発行するように設定されているか。 | ”応用設定”の”二重化設定”にある”通信異常時の系切替え要求発行有無”の”ユーザ用コネクション”または”システム用コネクション”で対象コネクションが系切替え要求を発行するように設定してください。 |
| エンジニアリングツールの設定内容とバッファメモリの内容が一致しているか。 | パラメータをCPUユニットに書き込んだ後，CPUユニットのリセットまたは電源OFFONしてください。 |
| 断線を検出しているか。 | 相手機器が異常になっていないか確認してください。 |
| ”応用設定”の”二重化設定”にある”断線検出時の系切替え要求発行有無”が”有効”になっているか。 | ”応用設定”の”二重化設定”にある”断線検出時の系切替え要求発行有無”を”有効”に設定してください。 |
| ”応用設定”の”二重化設定”にある”断線検出監視時間”の設定値は正しいか。 | ”応用設定”の”二重化設定”にある”断線検出監視時間”の設定値を見直してください。 |
| ”応用設定”の”データ交信用のタイマ設定”にある”TCP ULPタイマ”の設定値は正しいか。 | ”応用設定”の”データ交信用のタイマ設定”にある”TCP ULPタイマ”の設定値を見直してください。 |
| ”基本設定”の”相手機器接続構成設定”で”生存確認”が”KeepAlive”になっているか。 | ”基本設定”の”相手機器接続構成設定”で”生存確認”を”KeepAlive”に設定してください。 |
| ”応用設定”の”データ交信用のタイマ設定”にある”相手先 生存確認開始間隔タイマ”の設定値は正しいか。 | ”応用設定”の”データ交信用のタイマ設定”にある”相手先 生存確認開始間隔タイマ”の設定値を見直してください。 |
| ”応用設定”の”データ交信用のタイマ設定”にある”相手先 生存確認間隔タイマ”の設定値は正しいか。 | ”応用設定”の”データ交信用のタイマ設定”にある”相手先 生存確認間隔タイマ”の設定値を見直してください。 |
| ”基本設定”の”相手機器接続構成設定”で”交信手段”が”ブロードキャスト送信”になっていないか。 | ”基本設定”の”相手機器接続構成設定”で”交信手段”を”ブロードキャスト送信”以外に設定し，”センサ・機器”の”IPアドレス”を設定してください。 |
| 相手機器とのコネクションがオープン完了しているか。(ʼオープン完了信号ʼ(Un\G1900000~Un\G1900007)を確認する)\*1\*2 | ・相手機器とのコネクションがオープンしていない場合は，オープン処理を行ってください。・異常が発生している場合は，異常の要因を確認し，原因となっている箇所を修正してください。 |
| 二重化ユニットグループ設定で構成する場合に”システムパラメータ”画面の[I/O割付設定]タブにある”二重化ユニットグループ設定”が設定されているか。 | ”システムパラメータ”画面の[I/O割付設定]タブにある”二重化ユニットグループ設定”の設定を見直してください。 |
| ポートグループ設定で構成する場合に”応用設定”の”二重化設定”にある”ポートグループ設定”が設定されているか。 | ”応用設定”の”二重化設定”にある”ポートグループ設定”の設定を見直してください。 |
