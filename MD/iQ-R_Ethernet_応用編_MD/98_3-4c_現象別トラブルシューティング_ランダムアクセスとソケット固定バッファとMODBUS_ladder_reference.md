## ランダムアクセス用バッファによる交信ができない (原本 p.422)

ランダムアクセス用バッファによる交信ができない場合は，下記の内容を確認し，処置してください。

上記の処置でも解決できない場合は，単体通信テストを実施し，ハードウェアに異常がないか確認してください。(404ページ 単体通信テスト)

\*1 RJ71EN71またはRnENCPU(ネットワーク部)のネットワーク種別を”Ethernet”に設定し，P1コネクタを使用した場合のバッファメモリアドレスです。P2コネクタ使用時またはネットワーク種別を”Q互換Ethernet”に設定した場合は，下記を参照してください。461ページ バッファメモリ
\*2 通信ケーブル抜けやパソコンの再起動により，相手機器側のみクローズした場合，異常が発生する前と同一ポートを使用して再オープンしてください。異なるIPアドレスまたはポート番号で相手機器から再度Activeオープン要求を受信した場合，コネクションをクローズしません。

| 確認項目 | 処置方法 |
|---|---|
| 相手機器とのコネクションがオープン完了しているか。(ʼオープン完了信号ʼ(Un\G1900000~Un\G1900007)を確認する)\*1\*2 | ・相手機器とのコネクションがオープンしていない場合は，オープン処理を行ってください。・異常が発生している場合は，異常の要因を確認し，原因となっている箇所を修正してください。 |
| 相手機器よりコマンドが送信されているか。 | 相手機器からEthernet搭載ユニットに対してコマンドを送信してください。 |
| コマンドに設定するバッファメモリアドレスの指定が正しいか。 | バッファメモリアドレスの指定が間違っている場合は，バッファメモリアドレスを修正し，再度コマンドを送信してください。 |
| ランダムアクセス用バッファの指定アドレスにデータが設定されているか。 | データが設定されていない場合は，データを書き込んでください。 |
| 相手機器側に書込みデータが設定されているか。 | 書込みデータが設定されていない場合は，データを設定してください。 |
| コマンドを送信した機器に対して，レスポンスが返信されているか。 | ・レスポンスが無い場合は，コマンドのIPアドレスの指定が正しいか確認し，修正後に再度コマンドを送信してください。・レスポンスがあった場合は，レスポンスの終了コードおよび異常コードの内容を確認し，異常箇所を修正してください。 |
| ”基本設定”の”相手機器接続構成設定”で，相手機器との交信に使用するコネクションの交信手段が”ランダムアクセスバッファ ”以外に設定されていないか。 | ”ランダムアクセスバッファ ”以外に設定されている場合は，交信手段を修正してください。(311ページ 相手機器接続構成設定) |

## ソケット通信/固定バッファによる交信ができない (原本 p.423)

ソケット通信/固定バッファによる交信ができない場合は，下記の内容を確認し，処置してください。

上記の処置でも解決できない場合は，単体通信テストを実施し，ハードウェアに異常がないか確認してください。(404ページ 単体通信テスト)\*3

\*1\*2 (前節と同一内容の注記)
\*3 CPUユニット(内蔵Ethernetポート部)では単体通信テストができません。CPUユニットのトラブルシューティングを行い，ハードウェアに異常がないか確認してください。(使用するCPUユニットのマニュアル)

| 確認項目 | 処置方法 |
|---|---|
| 相手機器とのコネクションがオープン完了しているか。(ʼオープン完了信号ʼ(Un\G1900000~Un\G1900007)を確認する)\*1\*2 | ・相手機器とのコネクションがオープンしていない場合は，オープン処理を行ってください。・異常が発生している場合は，異常の要因を確認し，原因となっている箇所を修正してください。 |
| 送受信処理が正しく実行されたか。 | ・送受信処理が実行されていない場合は，送受信処理の実行条件を確認し，修正してください。・送受信処理が異常完了している場合は，完了ステータスにあるエラーコードを確認し，エラー原因を取り除いてください。 |
| 受信処理実行時に，ʼソケット/固定バッファ受信状態信号ʼ(Un\G1900016~Un\G1900023)がONしているか。 | ・相手機器からデータを送信してください。・送信している場合は，宛先(IPアドレス，ポート番号)が正しく設定されているか確認してください。 |
| ”基本設定”の”相手機器接続構成設定”で，相手機器との交信に使用するコネクションの交信手段が下記以外に設定されていないか。・ソケット通信による交信: ”ソケット通信”・固定バッファによる交信: ”固定バッファ (手順あり)”または”固定バッファ (手順なし)” | 左記の交信手段以外に設定されている場合は，交信手段を修正してください。(311ページ 相手機器接続構成設定) |
| ブロードキャスト通信時に”基本設定”の”相手機器接続構成設定”で，相手機器との交信に使用するコネクションの交信手段が”ブロードキャスト送信”または”ブロードキャスト受信”以外に設定されていないか。 | 左記の交信手段以外に設定されている場合は，交信手段を修正してください。(311ページ 相手機器接続構成設定) |

原本の表行数(目視カウント): 5行。上表は全5行を転記。

## MODBUS/TCPによる交信ができない (原本 p.424)

**MODBUS/TCP接続時に通信できない**

MODBUS/TCP接続時に通信できない場合は，下記の内容を確認し，処置してください。

MODBUS/TCPマスタ機能のトラブルシューティングについては，427ページ シンプルCPU通信機能使用時を参照してください。

| 確認項目 | 処置方法 |
|---|---|
| 相手機器はMODBUS/TCPに対応しているか。 | 相手機器がMODBUS/TCPに対応していない場合は，MODBUS/TCPの規格に対応した機器に交換してください。 |
| 相手機器はMODBUS/TCPマスタ機器か。 | 相手機器をMODBUS/TCPマスタ機器にしてください。 |
| 接続中の相手機器とのコネクション数が64の状態で，新しい接続を実施していないか。 | Ethernet搭載ユニットへ接続する相手機器を減らしてください。相手機器とのコネクション数が64を超えた場合，最後に交信してから最も時間が経過している相手機器とのコネクションは自動的に切断されます。 |
| MODBUS/TCP機能に対応しているEthernet搭載ユニットを使用しているか。 | Ethernet搭載ユニットのファームウェアバージョンを確認し，MODBUS/TCP機能に対応したユニットか確認してください。MODBUS/TCP機能に未対応のEthernet搭載を使用している場合は，対応済みのユニットに交換してください。 |

原本の表行数(目視カウント): 4行。上表は全4行を転記。

**MODBUS/TCPマスタ機器から送信された伝文が受信できない**

MODBUS/TCPマスタ機器から送信された伝文を受信できない場合，または受信できない事が頻発する場合は，下記の内容を確認し，処置してください。

| 確認項目 | 処置方法 |
|---|---|
| ʼ受信バッファ状態ʼ(Un\G1900030)が1(受信バッファフル発生)になることがあるか。 | 各ノード間のデータ送受信により，Ethernet回線の負荷が高いことが想定されるため，下記の処置を実施してください。・Ethernet回線の負荷を軽減するため，ネットワークの分離またはデータ送信回数を減らすなどの対策を行ってください。・ネットワーク管理者に相談の上，Ethernet回線の負荷を軽減してください。 |

原本の表行数(目視カウント): 1行。上表は全1行を転記。

**MODBUS/TCPマスタ機器に対して応答伝文が送信できない**

MODBUS/TCPマスタ機器から受信した要求伝文に対して応答伝文を送信しない，または想定した応答伝文を送信しない場合は，下記の内容を確認し，処置してください。

| 確認項目 | 処置方法 |
|---|---|
| MODBUSデバイス割付パラメータの登録内容に誤りがないか。 | MODBUSデバイス割付パラメータの設定内容を見直してください。 |
| 異常応答コードを送信していないか。 | 異常応答コードの内容を確認し，該当する問題があれば修正してください。 |
| ʼMODBUS/TCP機能用エラーログ用エリアʼ(Un\G720896~Un\G721153)にエラーコードが格納されていないか。 | 発生しているエラーコードに対応する処置を実施してください。(432ページ エラーコード一覧) |
| MODBUS/TCPマスタ機器から受信した要求伝文に誤りがないか。 | MODBUS/TCPマスタ機器が送信する要求伝文を修正してください。 |
| Ethernetフレームのアプリケーションデータ部の伝文長が6バイト以上(MBAPヘッダの交信ID~伝文長まで)あることを確認したか。 | MBAPヘッダの伝文長+6バイトが，Ethernetフレームのアプリケーションデータ部の伝文長と一致することを確認したか。 |

原本の表行数(目視カウント): 5行。上表は全5行を転記。
