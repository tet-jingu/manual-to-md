**バッファメモリアドレス・ビット位置の計算式**

各プロトコルの開始要求，各プロトコルの実行完了，各プロトコルのエラー，および各プロトコルの実行状態のバッファメモリアドレスとビット位置は，下記の計算式で算出できます。

- バッファメモリアドレス\*2: オフセット値+(1198×([設定No.]-1))+(([プロトコル番号]-1)/16)
- ビット位置: ([プロトコル番号]-1)/16の余剰

オフセット値には，下記の値を入れて計算してください。

\*2 小数点以下切り捨て

**例**

各プロトコルの開始要求(設定No.32，プロトコル番号512)のバッファメモリアドレスを求める場合

アドレス: 1249348 +(1198×(32-1))+((512-1)/16)=1286517.9375

ビット位置: (512-1)/16=31余り15(FH)

バッファメモリアドレスとビット位置は，Un\G1286517.Fとなります。

**ユーザ自由エリア(Un\G722500~Un\G1246787)**

シンプルCPU通信とシンプル機器通信時に自由に使用できるエリアです。

**\*1 照合結果コードと照合不一致の要因**

| 格納値 | 内容 | 照合不一致の要因 |
|---|---|---|
| 0H | 不一致情報なし | ― |
| 1H | データ不一致 | 固定データが設定値と一致しなかった。 |
| 2H | 受信データ不足 | 受信データがパケット構成で指定した長さより短い。 |
| 3H | パケット構成不一致 | 可変長データの後に，終端を示す固定データを受信しなかった。 |
| 4H | パケット長超過 | ・照合の結果パケット長が最大値を超過した。<br>・受信データがパケット構成で指定した長さより長い。 |
| 10H | レングス値範囲エラー | レングスの値がパケット長の最大値を超えた。 |
| 11H | レングス値不一致 | レングスの値が受信したパケットと一致しなかった。 |
| 20H | ASCII-バイナリ変換エラー | ・レングス(ASCII)または変換あり変数が指定した形式と異なる。<br>・変換あり変数で受信したデータの解析結果が異常完了した。 |
| 21H | 桁数不足 | ・変換あり変数(ASCII 16進数HEX)で受信した桁数が奇数だった。<br>・変換あり変数で指定した桁数よりも少ないデータを受信した。 |
| 22H | 桁数超過 | 変換あり変数(桁数可変)の桁数が，データ格納エリアに格納できる範囲を超えた。変換あり変数(データ数固定かつ桁数可変)で，"データ数/最大データ数"のデータ数よりも多いデータ数を受信した。 |
| 23H | 数値範囲外 | 変換あり変数で，変換後の値がデータ格納エリアに格納できる範囲外だった。 |
| 30H | 誤りチェックコードエラー | 計算した誤りチェックコードと，受信した誤りチェックコードが一致しなかった。 |
| FEH | シンプル機器通信パケット構成異常 | "シンプル機器通信設定"で設定したプロトコルデータに誤りがある。 |
