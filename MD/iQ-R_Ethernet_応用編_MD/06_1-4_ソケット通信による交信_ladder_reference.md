## 1.4 ソケット通信による交信 (1.4 / 原本 p.58)

専用命令により，Ethernetで接続された相手機器と，TCP/IPおよびUDP/IPで任意のデータを送受信できます。(510ページ ソケット通信用命令)

相手機器と1対1で双方向の通信を行いたい場合に使用します。

ソケット通信の交信例については，下記マニュアルを参照してください。

MELSEC iQ-R Ethernet/CC-Link IEユーザーズマニュアル(スタートアップ編)

【図】ソケット通信の交信方向(原本 p.58)。Ethernet搭載ユニットを中心に、Ethernet上の3台の相手機器それぞれに対して個別の矢印が引かれている。
- 相手機器1向け: 「受信またはブロードキャスト受信」(相手機器→ユニット)と「送信」(ユニット→相手機器1)の2方向
- 相手機器2向け: 「ブロードキャスト送信」(ユニット→相手機器2)
- 相手機器3向け: 「ブロードキャスト送信」(ユニット→相手機器3)

> ソケット通信の交信例については，下記マニュアルを参照してください。

### 注意事項 (原本 p.58)

ネットワーク種別で"Q互換Ethernet"を選択した場合は，ソケット通信による交信ができません。

## 設定方法 (原本 p.58)

"基本設定"の"相手機器接続構成設定"で設定します。(311ページ 相手機器接続構成設定)

1. "ユニット一覧"にある下記から相手機器を選択し，"機器一覧"または"機器構成図"にドラッグ＆ドロップします。
2. 相手機器との"交信手段"を"ソケット通信"に設定します。
3. その他，通信に必要なパラメータをコネクションに設定します。

| 相手機器名 | 内容 |
|---|---|
| UDP接続機器 | UDP/IPで相手機器と交信する場合に選択します。 |
| Active接続機器 | Ethernet搭載ユニットから相手機器に対してオープン処理を行い(Activeオープン)，TCP/IPで交信する場合に選択します。 |
| Unpassive接続機器 | 不特定の相手機器からのオープン処理を受けて(Unpassiveオープン)，TCP/IPで交信する場合に選択します。 |
| Fullpassive接続機器 | 特定の相手機器からのオープン処理を受けて(Fullpassiveオープン)，TCP/IPで交信する場合に選択します。 |

## 通信のしくみ (原本 p.60)

ソケット通信による交信では，TCP/IPおよびUDP/IPともに，相手機器と複数の通信をするために，通信を識別するポート番号を使用します。

送信の場合: 送信元となるEthernet搭載ユニットのポート番号と，送信先となる相手機器側のポート番号を指定します。

受信の場合: Ethernet搭載ユニットのポート番号を指定して，そこへ送られてきたデータを読み出します。

【図】ポート番号によるソケット通信の構成(原本 p.60)。Ethernet搭載ユニット(IPアドレス: xx.xx.xx.xx)がポート番号A・B・Cを持ち、Ethernet経由で交信相手機器1(IPアドレス: yy.yy.yy.yy、ポート番号L)・交信相手機器2(IPアドレス: zz.zz.zz.zz、ポート番号M)・交信相手機器3(IPアドレス: ww.ww.ww.ww、ポート番号N)と接続。
- (1) UDPデータをEthernet搭載ユニットのポート番号Aから相手機器1のポート番号Lへ送信
- (2) UDPデータを相手機器1のポート番号LからEthernet搭載ユニットのポート番号Aへ送信
- (3) TCP/IPのコネクションでデータ送信(ポート番号B⇔ポート番号M、双方向)
- (4) UDPデータをEthernet搭載ユニットのポート番号Cから相手機器3のポート番号Nへ送信
- (5) UDPデータを相手機器3のポート番号NからEthernet搭載ユニットのポート番号Cへ送信

## TCP/IPで交信する場合 (原本 p.61-63)

TCP/IPは相手機器のポート番号の間にコネクションを確立して，信頼性のあるデータ交信を行うプロトコルです。

TCP/IPでソケット通信を行うためには，下記の項目を確認してから交信してください。

 - 相手機器側のIPアドレスおよびポート番号
 - Ethernet搭載ユニット側のIPアドレスおよびポート番号
 - 相手機器側とEthernet搭載ユニット側のどちらがオープンする側になるのか(ActiveオープンおよびPassiveオープン)

### TCP/IPの接続動作 (原本 p.61)

TCP/IPの接続には，ActiveオープンとPassiveオープンがあります。

まず，TCP/IP接続を待つ側が指定したポート番号でPassiveオープンを行います。

TCP/IP接続する側は，Passiveオープンで待っているポート番号を指定して，Activeオープンを行います。

これによりTCP/IP接続が行われ，コネクションが確立し，交信が可能になります。

ActiveオープンとPassiveオープンの詳細については，下記を参照してください。(513ページ TCP/IP通信)

> Point
> ActiveオープンおよびPassiveオープンの表現は，相手機器によって異なる場合があります。
> - Activeオープン: TCP/IP接続側，クライアント側，コネクト側など
> - Passiveオープン: TCP/IP接続待ち側，サーバ側，リッスン側など

#### ■Activeオープン (原本 p.61)

Activeオープンでの交信の流れを示します。

【図】Activeオープンのフローチャート(原本 p.61)
```
開始 ─(TCP接続待ちになっている交信相手のポート番号を指定してActiveオープンで接続する)→ オープン処理
オープン処理 → 「送受信が完了したか?」
  NO → SOCSND命令で送信する、またはSOCRCV命令，SOCRCVS命令で受信する → 「送受信が完了したか?」(ループ)
  YES(完了，または交信相手から切断) → クローズ処理 → 完了
```

#### ■Passiveオープン (原本 p.61)

Passiveオープンでの交信の流れを示します。

【図】Passiveオープンのフローチャート(原本 p.61)
```
開始 ─(Passiveオープンで TCP接続待ちになる)→ 「送受信?」
  NO → 「送受信?」(ループ、TCP接続待ちのまま)
  YES → SOCSND命令で送信する、またはSOCRCV命令，SOCRCVS命令で受信する → 「送受信?」(ループ)
```

### TCP/IP通信時の注意事項 (原本 p.62)

#### クローズする条件

TCP/IPでの交信において，相手機器からのクローズ要求以外にも，下記の場合には'オープン完了信号'(Un\G1900000~Un\G1900007)がOFFしてクローズします。

 - 生存確認機能のタイムアウトが発生した場合
 - 相手機器側からの強制クローズを受信した場合

#### TCP/IPの接続要素

TCP/IPの接続は下記の4つの要素で管理されており，この4つの要素が同じ接続は，同時に1つしか作れません。同時に複数のTCP/IP接続を使用する場合は，4つの要素のうちでどれか1つは異なるようにしてください。

 - Ethernet搭載ユニット側のIPアドレス
 - Ethernet搭載ユニット側のポート番号
 - 相手機器側のIPアドレス
 - 相手機器側のポート番号

ただし，"Unpassive接続機器"，"Fullpassive接続機器"を選択した場合は，Ethernet搭載ユニット側のポート番号を異なる値に設定してください。加えて，残り3つの要素のうちでどれか1つは異なるようにしてください。

#### 同一のコネクションとの再接続

TCP/IPでの通信においてコネクションをクローズした後に，相手機器(IPアドレス)，自局ポート番号，相手機器ポート番号が同一のコネクションを再度接続する場合は，500ms以上経過してから行ってください。

再接続のときに時間を待つことができない場合は，Activeオープン側の自局ポート番号を変更して接続することを推奨します。

#### コネクション切断待ち時間設定

TCP/IPでの交信では，相手機器がデータ送信直後にコネクションのクローズ要求を送信する機器である場合，Ethernet搭載ユニット側でクローズ直前の受信データを読み出せないことがあります。この場合，'ソケット通信(TCP/IP)のコネクション切断待ち時間設定エリア'(Un\G760，Un\G761*1)により，Ethernet搭載ユニットのクローズ処理タイミングを遅らせることで受信データを読み出すことができます。

*1 CPUユニット(内蔵Ethernetポート部)のバッファメモリアドレスになります。

コネクション切断待ち時間設定の詳細については，下記を参照してください。(504ページ ソケット通信(TCP/IP)のコネクション切断待ち時間設定エリア)

コネクション切断待ち時間設定を使用する場合，CPUユニットのバージョンを確認してください。(550ページ 機能の追加と変更)

### 受信データ長の確認 (原本 p.63)

TCP/IPでの通信は，交信データに区切りの概念がないため，連続して送信したデータが受信側で結合されたり，一括して送信したデータが受信側で分割されたりする場合があります。受信側は必要に応じて受信データ長を確認して，処理を行ってください。

Ethernet搭載ユニット側で受信する場合，データ長が決まっているときは，固定長モードで使用することを推奨します。

相手機器側で受信する場合は，下記のように受信データ長を確認して処理を行ってください。

【図】相手機器側の受信処理フローチャート(原本 p.63)
```
相手機器側の受信処理 → 受信伝文・受信処理 → 「TCPコネクションはオープンしているか?」
  NO → TCPコネクションがクローズ → エラー処理
  YES → 「受信データを監視タイマ値以内に受信できたか?」
    NO → エラー処理
    YES → 受信サイズチェックを行う → 「受信サイズが不足していないか?」
      NO → 残りの受信伝文を受信する → (受信伝文・受信処理へ戻る)
      YES → 受信伝文に対する処理 → 「受信伝文をすべて処理したか?」
        NO → (受信サイズチェックを行う、の前段へ戻る)
        YES → 終了
```

#### ■Activeオープン時の注意事項 (原本 p.63)

'オープン完了信号'(Un\G1900000~Un\G1900007)および'オープン要求信号'(Un\G1900008~Un\G1900015)をプログラムで使用して，インタロック回路を構成してください。オープン完了信号およびオープン要求信号のON/OFFタイミングを示します。

【図】Activeオープン時のオープン完了信号/オープン要求信号タイミングチャート(原本 p.63)

<Ethernet搭載ユニット側から切断した場合>
- OPEN命令の実行と同時に'オープン完了信号'(Un\G1900000~Un\G1900007)がOFF→ONに立ち上がる。同時に'オープン要求信号'(Un\G1900008~Un\G1900015)もOFF→ONに立ち上がる。
- CLOSE命令を実行すると、Ethernet搭載ユニットよりTCP接続切断要求が出て、相手機器の応答によりTCP接続切断完了。切断完了と同時に'オープン完了信号'がON→OFFになる。'オープン要求信号'はCLOSE命令の実行と同時にON→OFF。

<相手機器側から切断した場合>
- 相手機器よりTCP接続切断要求があり、Ethernet搭載ユニットの応答によりTCP接続切断完了すると、'オープン完了信号'がON→OFFになる。
- その後CLOSE命令の実行で'オープン要求信号'がON→OFFになる。

## UDP/IPで交信する場合 (原本 p.64)

UDP/IPでの交信は，順序制御，再送制御を行わないシンプルなプロトコルです。

UDP/IPでソケット通信を行うためには，下記の項目を確認してから交信してください。

 - 相手機器側のIPアドレスおよびポート番号
 - Ethernet搭載ユニット側のIPアドレスおよびポート番号

### ■Passiveオープン時の注意事項 (原本 p.64)

 - 'オープン完了信号'(Un\G1900000~Un\G1900007)および'オープン要求信号'(Un\G1900008~Un\G1900015)をプログラムで使用して，インタロック回路を構成してください。オープン完了信号およびオープン要求信号のON/OFFタイミングを示します。
 - CPUユニットがPassiveオープンで相手機器と接続したとき，接続した相手機器のIPアドレスや，相手機器ポート番号はSP.SOCCINF命令で取得できます。
 - 相手機器からの接続は，Ethernet搭載ユニット側がオープン待ち状態になってから行ってください。CPU立上げ完了後からオープン待ち状態となるまでに，相手機器から受信したTCP/IPの接続要求はエラーになり，相手機器にコネクションの強制クローズを返します。この場合，Ethernet搭載ユニット側がオープン待ち状態になるまで時間を待ってから，相手機器側でリトライを行ってください。
 - プログラム内でGP.CONCLOSE命令またはSP.SOCCLOSE命令を実行しないでください。GP.CONCLOSE命令またはSP.SOCCLOSE命令を実行すると，該当コネクションのオープン完了信号およびオープン要求信号がOFFになり，クローズ処理するため，送受信ができなくなります。クローズしたコネクションを再度オープンするには，GP.CONOPEN命令またはSP.SOCOPEN命令を実行してください。

【図】Passiveオープン時のオープン完了信号/オープン要求信号タイミングチャート(原本 p.64)
- 交信相手よりTCP接続完了すると、'オープン完了信号'(Un\G1900000~Un\G1900007)と'オープン要求信号'(Un\G1900008~Un\G1900015)が同時にOFF→ONに立ち上がる。
- 交信相手よりTCP切断完了すると、'オープン完了信号'はON→OFFになる。
- 'オープン要求信号'は交信相手からのTCP切断完了後も常時ONのまま(OFFに戻らない)。

### UDP/IP通信時の注意事項 (原本 p.64)

 - データの消失，到着順番の入れ替わりなどが起こる場合があります。問題がある場合は，TCP/IPの使用を検討してください。
 - 接続ケーブルの断線などで，CPUユニットと相手機器間の通信回線が接続されていない場合でも，データ送信処理が正常終了する場合があります。そのため，交信手順を設けてデータ送信および受信することを推奨します。
 - CPUユニットで相手機器を変更したい場合は，SP.SOCCSET命令を使用します。
 - UDP/IPを設定したコネクションの'オープン完了信号'(Un\G1900000~Un\G1900007)および'オープン要求信号'(Un\G1900008~Un\G1900015)は常時ONになります。
 - プログラム内でGP.CONCLOSE命令またはSP.SOCCLOSE命令を実行しないでください。GP.CONCLOSE命令またはSP.SOCCLOSE命令を実行すると，該当コネクションのオープン完了信号およびオープン要求信号がOFFになり，クローズ処理するため，送受信ができなくなります。クローズしたコネクションを再度オープンするには，GP.CONOPEN命令またはSP.SOCOPEN命令を実行してください。
 - 'オープン完了信号'(Un\G1900000~Un\G1900007)がONしていても，データの送信に失敗することがあります。データの送信に失敗した場合は，再度データの送信を行ってください。

## ブロードキャスト通信 (原本 p.65)

ブロードキャスト通信とは，相手機器を特定せず，Ethernet搭載ユニットが接続されている同一Ethernet内の全Ethernet搭載ユニット装着局および相手機器に対して行う通信です。

### 設定方法 (原本 p.65)

"基本設定"の"相手機器接続構成設定"で設定します。(311ページ 相手機器接続構成設定)

1. "ユニット一覧"から"UDP接続機器"を選択し，"機器一覧"または"機器構成図"にドラッグ＆ドロップします。
2. 相手機器との"交信手段"を"ブロードキャスト送信"または"ブロードキャスト受信"に設定します。
3. その他，通信に必要なパラメータをコネクションに設定します。

### 注意事項 (原本 p.65)

 - ブロードキャスト通信の専用ポート番号は，システム内で取り決めて使用してください。
 - ブロードキャスト送信を使用する場合は，ルータを経由したアクセスはできません。
 - 同一Ethernet内に接続されている相手機器は，ブロードキャスト受信での受信伝文が不要なときには，読捨て処理が必要です。
 - CPUユニットがブロードキャスト受信でデータを受信したとき，送信した相手機器のIPアドレスや相手機器ポート番号は，SP.SOCCINF命令で取得することができます。

| 項目 | 内容 |
|---|---|
| ブロードキャスト送信 | 同一Ethernet内のすべてのEthernet機器に対して同じデータを送信します。 |
| ブロードキャスト受信 | ブロードキャスト送信で送信されたデータを受信します。 |

## 注意事項 (原本 p.66)

ソケット通信による交信時の注意事項を示します。

### ポート番号

自局ポート番号の1~1023は一般的に予約されたポート番号(WELL KNOWN PORT NUMBERS)，61440~65534は他の通信機能で使用するため，1024~4999，5010~61439を使用することを推奨します。

また，機能で使用するポートは，該当機能を使用する場合，指定しないでください。(537ページ Ethernet搭載ユニットで使用するポート番号)

### 受信データの読出し

'ソケット/固定バッファ受信状態信号'(Un\G1900016~Un\G1900023)がONになった場合は，受信データの読出しを行ってください。多くの受信データが読み出されない状態が続くと，交信に影響を与える場合があります。

### 交信中にファイルアクセスをする場合

CPUユニットはファイルアクセス処理をEthernet通信処理よりも優先して処理します。そのため，ソケット通信を使用しているときに，FTPやエンジニアリングツールなどでファイルアクセスをすると，ソケット通信の処理が遅れることがあります。

ソケット通信にて，相手機器側で応答時間の監視を行っているときにファイルアクセスをする場合，ファイルアクセスに必要な時間を加えた監視時間としてください。

### ユニットFBおよび専用命令について

 - ユニットFBまたは専用命令を使用してオープン処理を行う場合は，ユニットFBまたは専用命令が完了してから送受信を開始してください。
 - 1つのコネクションで同時に複数のユニットFBまたは専用命令を実行することはできません。同時に複数のユニットFBまたは専用命令を実行した場合，後から実行したユニットFBまたは専用命令が無処理となります。実行中のユニットFBまたは専用命令が完了した後に再実行してください。
