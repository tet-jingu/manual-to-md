## エンジニアリングツールとの直結接続ができない (原本 p.419)

エンジニアリングツールとの直結接続ができない場合は，下記の項目を確認してください。

上記の処置でも解決できない場合は，単体通信テストを実施し，ハードウェアに異常がないか確認してください。(404ページ 単体通信テスト)\*1

\*1 CPUユニット(内蔵Ethernetポート部)では単体通信テストができません。CPUユニットのトラブルシューティングを行い，ハードウェアに異常がないか確認してください。(使用するCPUユニットのマニュアル)

| 確認項目 | 処置方法 |
|---|---|
| Ethernet搭載ユニットとエンジニアリングツールがケーブル1本で直結接続されているか。 | Ethernet搭載ユニットとエンジニアリングツールがケーブル1本で接続されていない場合は，ケーブル1本で直結接続してください。 |
| ”応用設定”の”セキュリティ ”で”MELSOFTとの直結接続を禁止する”が”禁止”に設定されていないか。 | ”応用設定”の”セキュリティ ”で”MELSOFTとの直結接続を禁止する”を”禁止”に設定している場合は，”許可”に修正してください。 |
| エンジニアリングツールの接続先指定の設定が誤っていないか。 | 接続先指定の設定が誤っている場合は，下記の内容を見直してください。・”パソコン側I/F”で”Ethernetボード”を選択しているか確認してください。・”シーケンサ側I/F”の”シーケンサ側I/F CPUユニット詳細設定”画面または”シーケンサ側I/F Ethernetユニット詳細設定”画面で”Ethernetポート直結接続”を選択しているか確認してください。・”シーケンサ側I/F”が”Ethernetユニット”の場合，”他局指定”に”他局(単一ネットワーク)”を選択し，”ネットワーク通信経路”の”ネットワーク通信経路 Ethernet 詳細設定”画面で”シーケンサ側I/Fで設定されているEthernetユニットへのアクセス”を選択しているか確認してください。 |
| 接続時にタイムアウトが発生していないか。 | ”接続先指定 Connection”画面の”他局指定”の”他局詳細設定”画面で”交信タイムチェック”，”リトライ回数”を増やしてから再度接続してください。 |
| 接続機器(パソコン)が直結接続可能な仕様か。 | 接続機器(パソコン)が直結接続できない使用の場合は，ハブ経由接続にて通信を行ってください。 |

原本の表行数(目視カウント): 5行。上表は全5行を転記。

## ネットワーク上のCPUユニット検索ができない (原本 p.419)

ネットワーク上のCPUユニット検索ができない場合は，下記の項目を確認してください。

| 確認項目 | 処置方法 |
|---|---|
| ”応用設定”の”セキュリティ ”で”ネットワーク上のCPUユニット検索に応答しない”が”応答しない”に設定されていないか。 | ”応用設定”の”セキュリティ ”で”ネットワーク上のCPUユニット検索に応答しない”が”応答しない”に設定されている場合は，”応答する”に修正してください。 |
| 検索できないCPUユニットがルータの先に接続されていないか。 | ルータ経由で接続されているCPUユニットは検索できません。検索できるようにする場合は，接続を変更してください。 |
| 検索できないCPUユニットが無線LANで接続されていないか。 | 再度検索を実行してください。(パケットが消失している可能性があります) |
| 検索対象のCPUユニットのサービス処理(ファイル読出しなど)の負荷が高くないか。 | ・応答待ち時間を延ばして再度検索を実行してください。・CPUユニットのサービス処理の負荷を減らしてください。 |

原本の表行数(目視カウント): 4行。上表は全4行を転記。

## SLMPによる交信ができない (原本 p.420)

SLMPによる交信ができない場合は，下記の項目を確認してください。

上記の処置でも解決できない場合は，単体通信テストを実施し，ハードウェアに異常がないか確認してください。(404ページ 単体通信テスト)\*3

\*1 RJ71EN71またはRnENCPU(ネットワーク部)のネットワーク種別を”Ethernet”に設定し，P1コネクタを使用した場合のバッファメモリアドレスです。CPUユニット(内蔵Ethernetポート部)使用時，P2コネクタ使用時またはネットワーク種別を”Q互換Ethernet”に設定した場合は，下記を参照してください。461ページ バッファメモリ
\*2 通信ケーブル抜けやパソコンの再起動により，相手機器側のみクローズした場合，異常が発生する前と同一ポートを使用して再オープンしてください。異なるIPアドレスまたはポート番号で相手機器から再度Activeオープン要求を受信した場合，コネクションをクローズしません。
\*3 CPUユニット(内蔵Ethernetポート部)では単体通信テストができません。CPUユニットのトラブルシューティングを行い，ハードウェアに異常がないか確認してください。(使用するCPUユニットのマニュアル)

| 確認項目 | 処置方法 |
|---|---|
| 相手機器とのコネクションがオープン完了しているか。(ʼオープン完了信号ʼ(Un\G1900000~Un\G1900007)を確認する)\*1\*2 | ・相手機器とのコネクションがオープンしていない場合は，オープン処理を行ってください。・異常が発生している場合は，異常の要因を確認し，原因となっている箇所を修正してください。 |
| コマンド種別，デバイス指定，アドレス指定などコマンドフォーマットの指定が正しいか。 | コマンドフォーマットの指定が間違っている場合は，コマンドフォーマットを修正してください。(SLMPリファレンスマニュアル) |
| ”基本設定”の”自ノード設定”にある”RUN中の書込み許可/禁止設定”は”禁止”に設定されていないか。 | ”禁止”に設定されている場合は，”許可”に変更してください。(309ページ 自ノード設定) |
| 相手機器よりコマンドが送信されているか。 | 相手機器よりコマンドが送信されていない場合は，Ethernet搭載ユニットに対してコマンドを送信してください。 |
| コマンドを送信した機器に対して，レスポンスが返信されているか。 | ・レスポンスが無い場合は，コマンドのIPアドレスの指定が正しいか確認し，修正後に再度コマンドを送信してください。・レスポンスがあった場合は，レスポンスの終了コードおよび異常コードの内容を確認し，異常箇所を修正してください。 |
| ”基本設定”の”相手機器接続構成設定”で，相手機器との交信に使用するコネクションの交信手段が”SLMP”以外に設定されていないか。 | ”SLMP”以外に設定されている場合は，交信手段を修正してください。(311ページ 相手機器接続構成設定) |

原本の表行数(目視カウント): 6行。上表は全6行を転記。

## 通信プロトコルによる交信ができない (原本 p.421)

通信プロトコルによるデータ交信ができない場合は，下記の内容を確認し，処置してください。

上記の処置でも解決できない場合は，単体通信テストを実施し，ハードウェアに異常がないか確認してください。(404ページ 単体通信テスト)\*3

\*1 \*2 \*3 (上記SLMPによる交信ができないと同一内容の注記)

| 確認項目 | 処置方法 |
|---|---|
| 相手機器のIPアドレスの設定が正しいか。 | 相手機器のIPアドレスを確認し，間違っている場合は修正してください。 |
| 相手機器とのコネクションがオープン完了しているか。(ʼオープン完了信号ʼ(Un\G1900000~Un\G1900007)を確認する)\*1\*2 | ・相手機器とのコネクションがオープンしていない場合は，オープン処理を行ってください。・異常が発生している場合は，異常の要因を確認し，原因となっている箇所を修正してください。 |
| 通信プロトコルによる交信の送受信処理(専用命令)が正しく実行されたか。 | ・送受信処理が実行されていない場合は，送受信処理の実行条件を確認し，修正してください。・送受信処理が異常完了している場合は，完了ステータスにあるエラーコードを確認し，エラー原因を取り除いてください。 |
| 通信プロトコル設定およびプログラムで，相手機器に対して適切なプロトコルが使用されているか。 | 適切なプロトコルを使用していない場合は，通信プロトコル設定およびプログラムを修正してください。相手機器に対するプロトコルについては，相手機器のマニュアルを参照してください。 |
| ”基本設定”の”相手機器接続構成設定”で，相手機器との交信に使用するコネクションの交信手段が”通信プロトコル”以外に設定されていないか。 | ”通信プロトコル”以外に設定されている場合は，交信手段を修正してください。(311ページ 相手機器接続構成設定) |
| ʼ通信プロトコル準備完了ʼ(Un\G1901002.0)がONになっているか。\*1 | ʼ通信プロトコル準備完了ʼ(Un\G1901002.0)がOFFになっている場合は，プロトコル設定データを書き込んでください。 |
