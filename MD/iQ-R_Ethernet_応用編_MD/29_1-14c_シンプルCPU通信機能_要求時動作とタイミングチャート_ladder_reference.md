## 交信設定を要求時にした場合の動作 (原本 p.204)

### 交信開始方法

電源OFF→ON，またはCPUユニットのリセット後，要求時交信開始要求のバッファメモリをOFF→ONすると，交信を開始します。

> Point
> CPUユニットのリセット後に，システム側で準備処理を行います。準備処理では，パラメータ設定のチェック(自局ポート番号のチェック)を行い，準備処理で異常となった場合は，データを送受信しません。
> このとき，シンプルCPU通信状態のバッファメモリの値は，AH(交信不可)になります。

### 交信開始後の状態

交信開始からデータ送受信完了までのバッファメモリは下記の状態になります。

*1 通信開始待ち時間中は，要求時交信開始要求のバッファメモリをOFF→ONしても無視します。

*2 データ送受信完了後，要求時交信開始要求のバッファメモリをON→OFFすると，シンプルCPU通信状態のバッファメモリの値が2H(要求待ち)となり，1回の交信が完了します。

> Point
> 要求時交信開始要求を検出したあとは，プログラムなどで要求時交信開始要求のバッファメモリをON→OFF→ONしても，実行状態フラグのバッファメモリがOFF(停止中)になるまで，要求は無視されます。(異常状態にはなりません)

| 状態 | 項目 | アドレス | バッファメモリの状態 |
|---|---|---|---|
| 通信開始待ち時間中*1 | 各設定No.のシンプルCPU通信状態 | Un\G721936~Un\G721999／Un\G1247460~Un\G1247907 | 1H: 準備中 |
| 通信開始待ち時間経過後 | 各設定No.の準備完了 | Un\G721912~Un\G721915／Un\G1247412~Un\G1247439 | ON: 準備完了 |
| 通信開始待ち時間経過後 | 各設定No.のシンプルCPU通信状態 | Un\G721936~Un\G721999／Un\G1247460~Un\G1247907 | 2H: 要求待ち |
| 要求時交信開始要求を実行 | 各設定No.のシンプルCPU通信状態 | Un\G721936~Un\G721999／Un\G1247460~Un\G1247907 | 3H: 実行中 |
| 要求時交信開始要求を実行 | 各設定No.の実行状態フラグ | Un\G721908~Un\G721911／Un\G1247384~Un\G1247411 | ON: 実行中 |
| データ送受信完了*2 | 各設定No.の実行状態フラグ | Un\G721908~Un\G721911／Un\G1247384~Un\G1247411 | OFF: 停止中 |

### エラー応答時の動作

交信相手にデータを送信後，交信相手から応答がない，または異常(エラー応答)となった場合，タイムアウト時間までリトライ(再送)を行います。

リトライ中は，シンプルCPU通信状態のバッファメモリの値が5H(リトライ中)になります。

リトライは，パラメータで設定したリトライ回数+1回を実施します。

### 異常状態の動作

リトライ実施後もエラー応答となった場合は，異常状態と判定され，シンプルCPU通信エラーコードのバッファメモリにエラーコードを格納します。

異常状態の間は，実行状態フラグのバッファメモリがOFF(停止中)になるので，プログラムなどで要求時交信開始要求のバッファメモリをON→OFFとすると，シンプルCPU通信状態のバッファメモリの値が2H(要求待ち)になります。

 - 異常状態の間，同一交信相手を設定している他の設定No.は，シンプルCPU通信状態のバッファメモリの値が2H(要求待ち)のままとなります。
 - 交信相手からの応答が受信できない場合は，シンプルCPU通信エラーコードのバッファメモリにエラーコードを格納します。
 - 交信相手からエラー応答を受信した場合は，シンプルCPU通信エラーコードのバッファメモリにエラーコードを格納し，異常応答コードのバッファメモリに異常応答コードを格納します。(異常応答コードは，相手機器から返却されたコード(エラーコードや終了コードなど)を示します)

## タイミングチャート (原本 p.205)

### ■設定No.65の要求時交信開始要求の動作(正常時)

【図】要求時交信開始要求(正常時)のタイミングチャート(原本 p.205)

```
電源OFF→ON，リセット→リセット解除 → イニシャル処理 → 通信開始待ち時間 →
  交信要求OFF→ON → 交信開始 → 応答受信 → 交信要求ON→OFF → 交信停止 →
  (繰り返し) 交信要求OFF→ON → 交信開始 → 応答受信 → 交信要求ON→OFF → 交信停止
```

- '各設定No.の要求時交信開始要求'(Un\G1247300.0): (1)プログラムでONし交信要求OFF→ONと同時に立ち上がる。(2)プログラムでOFFし交信要求ON→OFFと同時に立ち下がる。以降のサイクルで(1)(2)を繰り返す。
- '各設定No.の実行状態フラグ'(Un\G1247384.0): (3)システムでON(交信開始と同時)、(4)システムでOFF(応答受信と同時)。
- '各設定No.の準備完了'(Un\G1247412.0): イニシャル処理完了後にONし、以降ONを維持。
- '各設定No.のシンプルCPU通信状態'(Un\G1247460): 0(未設定)→1(準備中)→2(要求待ち)→3(実行中、交信開始～応答受信の間)→2(要求待ち)→3(実行中)→2(要求待ち)…と遷移。
- '各設定No.のシンプルCPU通信エラーコード'(Un\G1247908)・'各設定No.の異常応答コード'(Un\G1248356)・'各設定No.の実行間隔(現在値)'(Un\G1248804): いずれも0のまま。

凡例: (1)プログラムでON (2)プログラムでOFF (3)システムでON (4)システムでOFF

### ■設定No.65の要求時交信開始要求の動作(異常時)

【図】要求時交信開始要求(異常時)のタイミングチャート(原本 p.205)

```
電源OFF→ON，リセット→リセット解除 → イニシャル処理 → 通信開始待ち時間 →
  交信要求OFF→ON → 交信開始 → データ送信 → 通信タイムアウト時間 → リトライ1回目 →
  通信タイムアウト時間 → リトライ2回目 → 通信タイムアウト時間 → 異常検出 →
  交信要求OFF→ON → 交信開始 → データ送信
```

- '各設定No.の要求時交信開始要求'(Un\G1247300.0): (1)プログラムでONし交信開始と同時に立ち上がり、異常検出後もON継続。異常検出後に再度(1)ON。
- '各設定No.の実行状態フラグ'(Un\G1247384.0): (3)システムでON(交信開始時)、(4)システムでOFF(異常検出時)、その後再度(3)ON。
- '各設定No.の準備完了'(Un\G1247412.0): (3)システムでONし，以降ON維持。
- '各設定No.のシンプルCPU通信状態'(Un\G1247460): 0→1→2→3→5(リトライ中、データ送信～異常検出の間)→2(異常検出後)→3(再交信開始)。
- '各設定No.のシンプルCPU通信エラーコード'(Un\G1247908): 0のまま推移し、異常検出時に(5)エラーコードが格納され、その後0に戻る。
- '各設定No.の異常応答コード'(Un\G1248356): 同様に0→異常応答コード→0。
- '各設定No.の実行間隔(現在値)'(Un\G1248804): 0のまま。

凡例: (1)プログラムでON (2)プログラムでOFF (3)システムでON (4)システムでOFF (5)エンジニアリングツールからのクリア要求で0クリアされます。

## 通信タイムアウト時間，通信リトライ回数，異常時監視時間 (原本 p.206)

交信相手から応答がないまたはエラー応答となった場合，タイムアウト時間まで経過後，リトライ(再送)されます。

このとき，リトライ回数+1回実施後，異常時監視時間で定周期交信します。そのあとにまた交信相手から応答があれば，パラメータで指定した実行間隔での交信に戻ります。

### 例: 通信リトライ回数の設定が2の場合のエラー検出タイミング

【図】通信リトライ回数2の場合のエラー検出タイミング(原本 p.206)。実行間隔ごとに「交信」を試み、1回目失敗(前回交信通信異常)→通信タイムアウト時間経過後に通信リトライ1回目→失敗(前回交信通信異常)→通信タイムアウト時間経過後に通信リトライ2回目→失敗(前回交信通信異常)→通信タイムアウト時間経過後にエラー検出。エラー検出後は異常時監視時間の周期で「交信」を継続する。

> Point
> (通信リトライ回数+1)×通信タイムアウト時間経過までに応答がないとき，または通信異常となった場合にエラーとなります。

## 通信開始待ち時間 (原本 p.206)

通信開始待ち時間を設定することで，下記のような場合に通信開始のタイミングをずらすことができます。

 - 通信が集中して通信開始のタイミングが重なり，エラーとならないようにする場合
 - 交信相手が通信可能となってから通信を開始する場合

通信開始待ちの間，通信状態は"準備中"となります。

> Point
> 通信開始待ち時間の間は，交信設定が"定期"の実行間隔による交信は無視されます。

## 設定のインポート・エクスポート (原本 p.207)

シンプルCPU通信設定の設定をCSVファイルからインポート，CSVファイルにエクスポートします。

### エクスポート

1. "シンプルCPU通信設定"の"設定項目"画面の[エクスポート]ボタンをクリックします。
2. "ファイルへエクスポート"画面でエクスポートするファイル名を入力し，[保存]ボタンをクリックします。
3. 必要に応じてエクスポートしたCSVファイルを編集してください。"シンプルCPU通信設定"の"設定項目"画面に表示される内容を編集できます。

> Point
> CSVファイルの詳細なフォーマットについて示します。
> - ファイル形式は，Unicode(UTF-16 Little Endian BOMあり)です。
> - 項目間の区切りは「¥t」(タブ)です。
> - 各項目は「"」(ダブルクォーテーション) で囲まれます。
> - 項目内に「"」(ダブルクォーテーション)を含む場合，項目内の「"」(ダブルクォーテーション) は「""」(ダブルクォーテーション2個) で表示されます。
> - 行の最後は改行が設定されます。改行コードはCR+LFです。

### 注意事項 (原本 p.208)

CSVファイルは，"シンプルCPU通信設定"の"設定項目"画面に表示される文字列が，別の文字列に置き換わる項目があります。別の文字列に置き換わる項目を下記に示します。

| 項目 | エンジニアリングツール | CSVファイル |
|---|---|---|
| IPアドレス入力形式*1 | 10進数 | DEC |
| IPアドレス入力形式*1 | 16進数 | HEX |
| デバイス割付方法*2 | 点数/先頭 | Points/Start |
| デバイス割付方法*2 | 先頭/最終 | Start/End |
| 初回交信設定 | ―(非対応) | Unsupported |
| 通信パターン | 読出 | Read |
| 通信パターン | 書込 | Write |
| 交信設定 | 要求時 | 0 |
| 交信設定 | 定期 | 1 |

原本の表行数(目視カウント): 9行。上表は全9行を転記(PDF p.209をrenderして確認)。

*1 CSVファイルのIPアドレス入力形式の進数で，IPアドレスがインポートされます。

*2 CSVファイルのデバイス割付方法で，転送元デバイスのデバイス範囲(点数/先頭番号/最終番号)が設定されます。

### インポート

1. "シンプルCPU通信設定"の"設定項目"画面の[インポート]ボタンをクリックします。
2. "ファイルのインポート"画面でインポートするファイル名を選択し，[開く]ボタンをクリックします。
3. [OK]ボタンをクリックします。
4. "シンプルCPU通信設定"の"設定項目"画面にCSVファイルのデータが反映されます。

インポート時のファイルの書式は，下記のフォーマットに従ってください。

 - 項目間の区切りは，「¥t」(タブ)を使用できます。
 - 区切り文字や改行コードを含む項目は，ダブルクォーテーションで囲んでください。

> 注意事項
> - インポートすると元の設定はすべてクリアされます。必要に応じてエクスポートするなどして退避してください。
> - CSVファイルは行の挿入や削除，項目の値を不正な値への変更は行わないでください。エラーメッセージが表示されインポートできません。
> - 10行目以降にデータが設定されたCSVファイルをインポートしてください。

## 交信停止・再開要求 (原本 p.210)

'各設定No.のシンプルCPU通信状態'(Un\G721936~Un\G721999，Un\G1247460~Un\G1247907)が下記のいずれかの場合に，'各設定No.の定期交信停止要求'(Un\G721900~Un\G721903，Un\G1247328~Un\G1247355)をOFF→ONすると，交信を停止できます。(状態が下記以外の場合，停止要求は無効となります。)

 - 3H: 実行中
 - 5H: リトライ中
 - 6H: 監視中

> Point
> '各設定No.の定期交信停止要求'(Un\G721900~Un\G721903，Un\G1247328~Un\G1247355)をOFF→ONすると，次回の実行間隔で送信するタイミングで停止します。
> そのため，停止要求を受け付けた状態で，交信相手からの応答がない場合，通信タイムアウト時間経過後に停止します。リトライ中は，リトライ回数に依存せずに通信タイムアウト時間経過後に停止します。

また，'各設定No.のシンプルCPU通信状態'(Un\G721936~Un\G721999，Un\G1247460~Un\G1247907)が「4H: 停止中」の場合に，'各設定No.の定期交信再開要求'(Un\G721904~Un\G721907，Un\G1247356~Un\G1247383)をOFF→ONすると，交信を再開できます。(状態が「4H: 停止中」以外の場合，再開要求は無効となります。)

ただし，交信設定で未設定または"要求時"にしている場合，'各設定No.の定期交信再開要求'(Un\G721904~Un\G721907，Un\G1247356~Un\G1247383)，および'各設定No.の定期交信停止要求'(Un\G721900~Un\G721903，Un\G1247328~Un\G1247355)をOFF→ONしても動作しません。そのため，システムによって自動でON→OFFされず，ONのままとなります。

- '各設定No.の定期交信再開要求'(Un\G721904.0): (1)プログラムでONし(再開要求あり)、(2)システムでOFF(交信再開のタイミングで)。
