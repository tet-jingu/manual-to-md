## Passiveオープンの手順 (原本 p.516)

Ethernet搭載ユニットのPassiveオープンには，下記の2種類の接続方式があります。

| 接続方式 | 内容 |
|---|---|
| Unpassive | 交信相手のIPアドレス，ポート番号を制限せず，ネットワークに接続されているすべての機器を対象にコネクションの受動的なオープン処理を行う接続方式です。 |
| Fullpassive | 交信相手のIPアドレス，ポート番号を指定することで，特定の相手機器を対象にコネクションの受動的なオープン処理を行う接続方式です。 |

Passiveオープンでのオープン/クローズ処理手順は，"基本設定"の"自ノード設定"にある"オープン方法の設定"により下記のようになります。(309ページ 自ノード設定)

原本の表行数(目視カウント): 2行。上表は全2行を転記。

### "プログラムでOPENしない"を設定した場合 (原本 p.516)

Ethernet搭載ユニットは常にオープン待ちの状態となるため，相手機器からのActiveオープンにより，コネクションが確立されます。これにより，Ethernet搭載ユニット側でオープン/クローズ処理のプログラムが不要になります。

**例: コネクションNo.1の場合のオープン/クローズ処理**

【図】Passiveオープン("プログラムでOPENしない")のタイミングチャート(原本 p.516)
- 横軸: 電源投入→パラメータ交信完了→❶→(\*1の期間)→❷(SYN受信、オープン完了)→❸(FIN受信、クローズ完了)→❹(再度オープン要求待ちへ)
- 「オープン状態」: ❷〜❸の間ON
- 「オープン可能状態(クローズ中)(Activeオープン受付け可能)」: パラメータ交信完了+\*1経過後から❷まで、および❸から❹以降でON
- 「クローズ状態」: それ以外の期間
- 「イニシャル状態」(Un\G1900024.0): パラメータ交信完了時にONし、以降ON維持
- 「オープン完了信号(コネクションNo.1)」(Un\G1900000.0): ❷でON、❸でOFF
- 「オープン要求信号(コネクションNo.1)」(Un\G1900008.0): ❶の直後(SYN受信直前)でON、❸(FIN受信)でOFF
- パケット交換: SYN受信→SYN+ACK送信、FIN受信→FIN+ACK送信

**手順説明(番号は図中の❶〜❹に対応)**

1. ユニットパラメータ設定後，Ethernet搭載ユニットのイニシャル処理の正常完了を確認します。('イニシャル状態'(Un\G1900024.0): ON)イニシャル処理が正常完了後，コネクションはオープン可能状態となり，相手機器からのオープン要求待ち状態になります。
2. 相手機器よりオープン要求(SYN)を受信すると，Ethernet搭載ユニットはオープン処理を実行します。オープン処理が正常終了すると，'オープン完了信号(コネクションNo.1)'(Un\G1900000.0)がONし，データ交信が可能になります。
3. 相手機器よりクローズ要求(FIN)を受信すると，Ethernet搭載ユニットはクローズ処理を実行します。クローズ処理が完了するとオープン完了信号がOFFし，データ交信が不可となります。
4. Ethernet搭載ユニットの内部処理が完了後，コネクションは再びオープン要求待ち状態になります。

\*1 イニシャル処理の正常完了後からオープン要求待ち状態までに受信したオープン要求(SYN)はエラーになり，Ethernet搭載ユニットはコネクションの強制クローズ(RST)を(オープン要求(SYN)を送信した相手機器へ)送信します。

> **Point**
> "基本設定"の"自ノード設定"にある"オープン方法の設定"で"プログラムでOPENしない"に設定していても，Ethernet搭載ユニット側からの専用命令でオープン/クローズ処理を行った場合，該当するコネクションはクローズ処理後，オープン要求待ち状態には戻りません。

### "プログラムでOPENする"を設定した場合 (原本 p.517)

Ethernet搭載ユニットは，相手機器からのオープン/クローズ要求の前に，Ethernet搭載ユニット側でOPEN/CLOSE命令を実行し，オープン/クローズ待ち状態にする必要があります。オープン処理の正常完了後，データ送信/受信が可能になります。

OPEN/CLOSE命令については，下記を参照してください。

MELSEC iQ-R プログラミングマニュアル(ユニット専用命令編)

**例: コネクションNo.1の場合のオープン/クローズ処理**

【図】Passiveオープン("プログラムでOPENする")のタイミングチャート(原本 p.517)
- 横軸: 電源投入→パラメータ交信完了→❶→(\*1の期間)→❷(OPEN命令、1スキャンパルス)→❸(SYN受信、オープン完了)→❹(FIN受信、クローズ完了)→❺(CLOSE命令、1スキャンパルス)
- 「オープン状態」: ❸〜❹の間ON
- 「オープン可能状態(クローズ中)(Activeオープン受付け可能)」: OPEN命令実行後(\*1経過後)から❸まで、およびCLOSE命令実行後でON
- 「クローズ状態」: それ以外の期間
- 「イニシャル状態」(Un\G1900024.0): パラメータ交信完了時にONし、以降ON維持
- 「OPEN命令」: ❷でOFF→ONし、1スキャン後OFF
- 「OPEN命令完了デバイス」: OPEN命令実行から1スキャン後にONパルス
- 「OPEN命令完了デバイス+1」: 異常完了時のみONパルス(破線表示)
- 「CLOSE命令」: ❺でOFF→ONし、1スキャン後OFF
- 「CLOSE命令完了デバイス」: CLOSE命令実行から1スキャン後にONパルス
- 「CLOSE命令完了デバイス+1」: 異常完了時のみONパルス(破線表示)
- 「オープン完了信号(コネクションNo.1)」(Un\G1900000.0): ❸でON、❹でOFF
- 「オープン要求信号(コネクションNo.1)」(Un\G1900008.0): ❷でON、❺でOFF
- パケット交換: SYN受信→SYN+ACK送信、FIN受信→FIN+ACK送信

**手順説明(番号は図中の❶〜❺に対応)**

1. ユニットパラメータ設定後，Ethernet搭載ユニットのイニシャル処理の正常完了を確認します。('イニシャル状態'(Un\G1900024.0): ON)
2. OPEN命令でオープン処理を開始します。('オープン要求信号(コネクションNo.1)'(Un\G1900008.0): ON)
3. 相手機器よりオープン要求(SYN)を受信すると，Ethernet搭載ユニットはオープン処理を実行します。オープン処理が正常終了すると，'オープン完了信号(コネクションNo.1)'(Un\G1900000.0)がONし，データ交信が可能になります。
4. 相手機器よりクローズ要求(FIN)を受信すると，Ethernet搭載ユニットはクローズ処理を実行します。クローズ処理が完了するとオープン完了信号がOFFし，データ交信が不可となります。

\*1 イニシャル処理の正常完了後からオープン要求待ち状態までに受信したオープン要求(SYN)はエラーになり，Ethernet搭載ユニットはコネクションの強制クローズ(RST)を(オープン要求(SYN)を送信した相手機器へ)送信します。

> **Point**
> - コネクションの設定を変更する場合は，OPEN命令を実行する前に変更してください。
> - オープン処理実行後，オープン処理が完了する前にオープン要求は中止できません。オープン完了後にクローズ処理(CLOSE命令)を行ってください。
