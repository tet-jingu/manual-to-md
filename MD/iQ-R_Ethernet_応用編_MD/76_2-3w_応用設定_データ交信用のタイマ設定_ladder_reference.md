## データ交信用のタイマ設定 (原本 p.382)

下記の交信を行う場合に使用するタイマを設定します。

- MELSOFT製品およびGOTとの接続
- SLMPによる交信
- 通信プロトコルによる交信
- ソケット通信/固定バッファによる交信
- ランダムアクセス用バッファによる交信
- ファイル転送機能(FTPサーバ)
- ファイル転送機能(FTPクライアント)

なお，データ交信用のタイマ設定を変更する場合は，設定時の注意事項を確認の上，設定してください。(383ページ 設定時の注意事項)

\*1 100ms単位で設定してください。

| 項目 | 内容 | 設定範囲 |
|---|---|---|
| タイマ値を変更/設定する | 各タイマ値をデフォルトから変更または設定するかを設定します。”しない”を選択した場合，各タイマ値はデフォルト値で動作します。 | ・しない・する(デフォルト: しない) |
| TCP 再送タイマ | TCP/IPのオープン，データ送信時にACKが返らない場合の再送する時間を設定します。このタイマは，リンク専用命令の到着監視時間の最小設定時間も兼ねています。 | 単位[s]: 1~16383単位[ms]: 100~16383000\*1(デフォルト: 10s) |
| 相手先 生存確認開始間隔タイマ | 相手機器からの最後の伝文受信から生存確認を開始するまでの時間を設定します。 | 単位[s]: 1~16383単位[ms]: 100~16383000\*1(デフォルト: 600s) |
| 相手先 生存確認間隔タイマ | 生存確認を行う相手機器からの応答を受信できなかったとき，再度，生存確認を行う間隔を設定します。 | 単位[s]: 1~16383単位[ms]: 100~16383000\*1(デフォルト: 10s) |
| 相手先 生存確認再送回数 | 生存確認を行う相手機器からの応答を受信できなかったとき，再度生存確認を行う回数を設定します。 | 1~99999(デフォルト: 3回) |
| 詳細設定 レスポンス監視タイマ | 下記の待ち時間を設定します。・固定バッファによる交信(手順あり)で，コマンドを送信してからレスポンスの返信を待つ時間・分割された伝文を受信するとき，最初の伝文を受信してから最後の伝文を受信するまでの時間 | 単位[s]: 1~16383単位[ms]: 100~16383000\*1(デフォルト: 30s) |
| TCP ULPタイマ | TCP/IPのデータ送信時のパケット生存時間を設定します。たとえば，TCP 再送タイマを10秒，TCP ULPタイマを30秒に設定した場合，データを送信後に相手機器から応答がなければ，10秒ごとにデータが再送され，30秒以内に応答がないとタイムアウトエラーとなります。 | 単位[s]: 1~16383単位[ms]: 100~16383000\*1(デフォルト: 30s) |
| TCP 終了タイマ | 自局からTCP/IPのコネクションをクローズする場合，自局がFINを送信し相手機器からACKが返送された後，相手機器からのFINを待つときの監視時間を設定します。TCP 終了タイマ時間を待っても相手機器からFINを受信できない場合，相手機器へRSTを送信し強制的にクローズします。 | 単位[s]: 1~16383単位[ms]: 100~16383000\*1(デフォルト: 20s) |
| TCP ゼロウィンドウタイマ | ウィンドウは，受信側の受信バッファを示します。受信側の受信バッファに空きがなくなった(ウィンドウサイズ=0)場合，受信側の受信バッファに空きができるまでデータ送信を待ちます。このとき，送信側は送信ウィンドウ確認パケットをTCP ゼロウィンドウタイマ値に従って受信側へ送信し，受信可能状態を確認します。 | 単位[s]: 1~16383単位[ms]: 100~16383000\*1(デフォルト: 10s) |
| IP組立てタイマ | 交信データは，送信局や受信局のバッファの制限によりIPレベルで分割されて送信されることがあります。このときの分割データの待ち時間を設定します。 | 単位[s]: 1~16383単位[ms]: 100~16383000\*1(デフォルト: 5s) |
