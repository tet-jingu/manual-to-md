# プログラム例 — ニモニック（命令リスト）化

> **出典**: 三菱電機 MELSEC iQ-R プログラミングマニュアル（CPUユニット／汎用FUN／汎用FB）
> 原典のプログラム例は**すべて図（画像）**のため、図を読み取って**ニモニック（命令リスト）**に書き起こしたもの。
> **ページ表記**: `PDF p.NNN` は PDFの通しページ（本文ノンブル + 2）。
>
> **このファイルの用途**: 命令の実際の使い方（接点の取り方・オペランドの並び・回路構成）を確認する。
> 命令の仕様は `02`〜`05` の各ファイル、命令の探索は `00_索引_命令一覧.md` を参照。

## ニモニック表記について

- `LD` / `LDI` / `AND` / `ANI` / `OR` / `ORI` = 接点、`OUT` / `SET` / `RST` = 出力系。
- 1行 = 1命令。オペランドは原典のラダー図の左から右の順に並べている。
- 同一接点から複数の出力が並列にぶら下がる場合は、接点を1回だけ書き、その下に出力を続けて並べている
  （GX Works3 のニモニック入力と同じ並び）。
- データ図・タイミングチャートのみで回路図がない例は、**データの遷移**として記述している。

## `OUT T，OUTH T，OUT ST，OUTH ST` — タイマ（PDF p.175）

> **注意事項**: タイマの接点で別のタイマの計測を行う場合は、**後で計測するタイマから順に**プログラミングする。
> 計測順にプログラミングすると、スキャンタイムより短い設定値のとき／設定値が1のとき、**すべてのタイマが同一スキャンでON**する。

**例1: T0〜T2 を「後から計測するタイマから順に」プログラミングした場合（正しい書き方）**

```
LD   T1
OUT  T2  K1     ; (1) T1の接点がONした次のスキャンから、T2が計測開始
LD   T0
OUT  T1  K1     ; (2) T0の接点がONした次のスキャンから、T1が計測開始
LD   X0
OUT  T0  K1     ; (3) X0がONすると、T0が計測開始
```

**例2: T0〜T2 を「計測順に」プログラミングした場合（同一スキャンでONしてしまう）**

```
LD   X0
OUT  T0  K1     ; (1) X0がONすると、T0が計測開始
LD   T0
OUT  T1  K1     ; (2) T0の接点がONすると、T1・T2の接点も同一スキャンでONする
LD   T1
OUT  T2  K1
```

## `OUT LT，OUT LST` — ロングタイマ（PDF p.177）

> **注意事項**: ロングタイマも同様に、**後で計測するロングタイマから順に**プログラミングする。

**例1: LT0〜LT2 を「後から計測するタイマから順に」プログラミングした場合（正しい書き方）**

```
LD   LT1
OUT  LT2  K1    ; (1) LT1の接点がONした次のスキャンから、LT2が計測開始
LD   LT0
OUT  LT1  K1    ; (2) LT0の接点がONした次のスキャンから、LT1が計測開始
LD   X0
OUT  LT0  K1    ; (3) X0がONすると、LT0が計測開始
```

**例2: LT0〜LT2 を「計測順に」プログラミングした場合（同一スキャンでONしてしまう）**

```
LD   X0
OUT  LT0  K1    ; (1) X0がONすると、LT0が計測開始
LD   LT0
OUT  LT1  K1    ; (2) LT0の接点がONすると、LT1・LT2の接点も同一スキャンでONする
LD   LT1
OUT  LT2  K1
```

## `RST F` — アナンシェータのリセット（PDF p.191）

回路図はなく、**データの遷移**で示されている例。

**例: SD63 が 16 で、登録されていないアナンシェータ番号がある場合に `RST F90` を実行**

| デバイス | 実行前 | 実行後 | 備考 |
|---|---|---|---|
| SD63 | 16 | 16 | 登録数 |
| SD64 | 233 | 233 | |
| SD65 | 90 | **700** | (2) SD66に格納されていたF番号が繰り上がって格納される |
| SD66 | 700 | 28 | |
| SD67 | 28 | … | |
| SD77 | … | 145 | |
| SD78 | 145 | 1027 | |
| SD79 | 1027 | **（新規登録）** | (3) 登録されていなかったF番号が格納される |

- (1) `RST F90` で F90 をリセットする。
- SD64〜SD79 から該当F番号が削除され、以降が繰り上がる。SD63 の内容が -1 される。
- SD63 が16のときは、削除と同時に**未登録のアナンシェータがONしていればその番号を新たに登録**する。
- SD64〜SD79 のアナンシェータ番号がすべてOFFすると、CPUユニット前面の **USER LED が消灯**する。

## `SFT(P)` — ビットデバイスシフト（PDF p.201）

> **ポイント**: シフトする先頭のデバイスは **SET命令でONさせる**。
> 連続で `SFT(P)` を使う場合は、**デバイス番号の大きいものから**プログラムを作成する。

**例: M10 を先頭に M11〜M14 へシフトする**

```
LD   M0
SFTP M14        ; デバイス番号の大きい順に並べる
SFTP M13
SFTP M12
SFTP M11
LD   X2
SET  M10        ; シフトの先頭デバイスをSETでON
```

動作（M15〜M8 のビット並び。シフト範囲は M11〜M14）:

| 状態 | M15 | M14 | M13 | M12 | M11 | M10 | M9 | M8 | 備考 |
|---|---|---|---|---|---|---|---|---|---|
| (1) | 0 | 0 | 0 | 0 | 0 | 1 | 1 | 0 | X02 ON |
| (2) | 0 | 0 | 0 | 0 | 1 | 0 | 1 | 0 | 1回目のシフト入力後 |
| (3) | 0 | 0 | 0 | 1 | 0 | 0 | 1 | 0 | 2回目のシフト入力後 |
| (4) | 0 | 0 | 0 | 1 | 0 | 1 | 1 | 0 | X02 ON |
| (5) | 0 | 0 | 1 | 0 | 1 | 0 | 1 | 0 | 3回目のシフト入力後 |
| (6) | 0 | 1 | 0 | 1 | 0 | 0 | 1 | 0 | 4回目のシフト入力後 |
| (7) | 0 | 0 | 1 | 0 | 0 | 0 | 1 | 0 | 5回目のシフト入力後 |

**例: ワードデバイスのビット指定の場合** — `SFT(P) D0.5` は D0 の b4 の 1/0 を b5 にシフトし、**b4 を 0 にする**。

## `LDP，LDF，ANDP，ANDF，ORP，ORF` — パルス接点（PDF p.159）

**例: LDP を使った回路と、LDP を使わない等価回路**

```
LDP  X0                LD   X0
MOV  K0  D0     ≡      MOVP K0  D0
```

```
LDP  X0                LD   X0
OUT  M0         ≡      PLS  M0
```

- `LDP` は指定ビットデバイスの**立上り(OFF→ON)のみ導通**する。ワードデバイスのビット指定時は 0→1 のとき導通。
- **`LDP` 単独の場合は、ON中実行命令のパルス化命令（□P）と同一**になる。
- `LDF` は**立下り(ON→OFF)で導通**（ビット指定時は 1→0）。
- ST・FBD/LD で `LDP`/`LDF` を使う場合は **EN に常時ON（左母線）を指定**する。

## `EGP，EGF` — エッジリレー（PDF p.170）

**例: サブルーチンプログラムで EGP を使用する**

```
LD    SM400
MOV   K0   Z0
CALL  P0          ; ❶ Z0=0 で呼び出し
MOV   K1   Z0
CALL  P0          ; ❷ Z0=1 で呼び出し
FEND

P0
LD    X0Z0
EGP   V0Z0        ; 演算結果をエッジリレー V0Z0 で記憶（AND命令扱い）
INC   D0Z0
RET
END
```

- (1) X0 の立上りで V0 がON → D0 がインクリメントされる。
- (2) X0 が立下りで V0 はOFF。
- (3) X1 の立上りで V1 がON → D1 がインクリメントされる。
- **EGP/EGF はインデックス修飾されたプログラム（サブルーチン、FOR〜NEXT）のパルス演算に使う。**

> **使用できない位置**: `EGP`/`EGF` は **AND と同じ位置**でのみ使用できる。`LD`・`OR` の位置では使えない。
> 次のような**並列回路ブロックの中**にも置けない。
>
> ```
> LD   X0
> LD   X1
> EGP  V0      ← この位置（並列ブロック内）では使用できない
> OR   X2
> ANB
> SET  M0
> ```

## `SET` — デバイスのセット（PDF p.185）

**例: X5 で Y10 をセットし、X7 でリセットする**

```
LD   X5
SET  Y10
LD   X7
RST  Y10
```

- ONさせたデバイスは、**実行指令がOFFになってもONのまま保持**される。
- SET命令でONしたデバイスは **RST命令でOFF**できる。
- 実行指令がOFFの場合、デバイスの状態は変化しない。

> **注意**: デバイスに X を使う場合は、**実入力で使用していないデバイス番号**を使う。
> 実入力デバイスと同一番号を使うと、実入力のデータが SET命令で指定した入力X に上書きされる。

## `RST` — デバイスのリセット（PDF p.187）

**例: RST でワードデバイスを指定した場合の等価回路**

```
LD   X10               LD   X10
RST  D50        ≡      MOV  K0  D50
```

実行指令がONしたときのデバイスの状態:

| デバイス | 状態 |
|---|---|
| ビットデバイス | コイル、接点をOFFする |
| タイマ、カウンタ | **現在値を0にし、コイル・接点をOFF**する |
| ワードデバイスのビット指定 | 指定ビットを0にする |
| タイマ・カウンタ以外のワードデバイス | 内容を0にする |

- 実行指令がOFFの場合、デバイスの状態は変化しない。

## `PLS` — 立上りパルス（PDF p.193）

**例: X5 の立上りで M0 を1スキャンONする**

```
LD   X5
PLS  M0
```

- 実行指令の **OFF→ON 時に指定デバイスをON**し、それ以外（ON→ON、ON→OFF、OFF→OFF）ではOFFさせる。
- 1スキャン中に (d) のPLS命令が1つだけの場合、**指定デバイスは1スキャンON**する（Sc = 1スキャン）。
- **PLS命令実行後に RUN→STOP にし、再度RUNにしてもPLS命令は実行されない。**
- 実行指令に**ラッチリレー(L)** を指定し、L がON状態で電源をOFF→ONすると、実行指令は1スキャン目にOFF→ONとなり
  PLS命令が実行されて指定デバイスがONする。このデバイスは次のPLS命令（立上り出力）でOFFする。
- PLS命令は**命令実行後の次の命令実行時にOFF処理**を行う。

> **注意**: PLS命令を **CJ命令でジャンプさせた**り、実行したサブルーチンプログラムを **CALL(P)命令でコールしなかった**場合、
> (d) で指定のデバイスが **1スキャン以上ON** になることがある。

## `DELTA(P)` — パルス化ダイレクト出力（PDF p.199）

**例: DELTA を使った回路と、SET/RST を使った等価回路**

```
LD    X100             LD   X100
DELTA DY0       ≡      SET  DY0
                       RST  DY0
```

**例: 高速カウンタユニット(RD62P2)のプリセット（スロット0、CH1）**

```
LD    X20
DMOVP K0   U0\G0      ; (1) RD62P2のバッファメモリ 0,1 にプリセット値(0)を格納
DELTAP DY1            ; (2) プリセット指令の出力
END
```

> **注意事項**: `DELTA(P)` は**インテリジェント機能ユニットへの立上り実行の指令**に使う。
> **出力ユニットを使用した実出力指令には使用できない。**

## `MC，MCR` — マスタコントロール（PDF p.203, 205）

マスタコントロールは**回路の共通母線を開閉**して、効率のよい回路切換えのプログラムを作るための命令。

**例: マスタコントロールを使用した回路**

```
LD   X0
MC   N1  M0      ; ネスティング N1、マスタコントロール接点 M0
N1               ; ← ここから MCR N1 までが「X0がONのときのみ実行」される
LD   X1
AND  X3
AND  M7
OUT  Y47
LD   M5
OUT  Y4F
LD   X6
AND  X4          ; ※原典の図ではこの行の出力は描かれていない
MCR  N1          ; マスタコントロール解除
LD   X0F
OUT  Y40         ; ← MCR以降は X0 に関係なく実行される
```

**MC命令の実行指令がOFFのときの、MC〜MCR間のデバイスの状態**

| デバイス | 状態 |
|---|---|
| 高速タイマ／低速タイマ | **カウント値は0**となり、コイル・接点ともOFFする |
| 高速積算タイマ／低速積算タイマ／カウンタ | コイルはOFFになるが、**カウント値・接点とも現在の状態を保持**する |
| OUT命令中のデバイス | **強制的にOFF**する |
| SET命令、RST命令、SFT(P)命令中のデバイス<br>基本命令、応用命令中のデバイス | **現在の状態を保持**する |

> ⚠ **MC命令がOFFの場合もMC〜MCR間の命令は実行されるため、スキャンタイムは短くならない。**

**注意事項（入れ子・PDF p.205）**

- 入れ子は **15個（N0〜N14）まで**可能。
- 入れ子にする場合、**MC命令はネスティング(N)の若番から**用い、**MCR命令は老番から**用いる。
- **MCR命令が1箇所に集まっている入れ子構造のときは、最も若いネスティング番号1つですべてのマスタコントロールを終了できる。**

```
; 入れ子（MCRを老番から順に書く場合）      ; 1つのMCRにまとめた場合（等価）
LD   X1                                    LD   X1
MC   N0  M15                               MC   N0  M15
N0                                         N0
LD   M15                                   LD   M15
OUT  （出力）                               OUT （出力）
LD   X2                                    LD   X2
MC   N1  M16                               MC   N1  M16
N1                                         N1
LD   M16                                   LD   M16
OUT  （出力）                               OUT （出力）
LD   X3                                    LD   X3
MC   N2  M17                               MC   N2  M17
N2                                         N2
LD   M17                                   LD   M17
OUT  （出力）                               OUT （出力）
MCR  N2                                    MCR  N0        ← 若番1つですべて終了
MCR  N1                                    LD   （接点）
MCR  N0                                    OUT  （出力）
LD   （接点）
OUT  （出力）
```

## `CJ，SCJ，JMP` — ポインタ分岐（PDF p.564）

**例1: 若いステップへジャンプしてループを作る**

```
P8
LD   X0
OUT  Y40
LD   X7
CJ   P9          ; (2) X7をONすると、ループから抜け出す
LD   X3
CJ   P8          ; (1) X3がONの間、P8へ戻ってループする
P9
LD   X6
OUT  Y42
```

> ⚠ `CJ`/`SCJ`/`JMP` は実行中のステップより**若いステップへジャンプできる**が、
> **ウォッチドッグタイマがタイムアップしないよう、ループから抜け出す方法を必ず用意する**こと。

**例2: ジャンプで飛ばされたデバイスは変化しない**

```
LD   X0B
CJ   P19         ; XBがONすると P19 へジャンプ
LD   X0C
OUT  Y43         ; ← 飛ばされる
LD   X0B
OUT  Y49         ; ← 飛ばされる
P19
LD   X9
OUT  Y4C
```

- CJ命令を実行中に XB・XC が ON/OFF しても、**Y43・Y49 は変化しない**。

**例3: ラベル(P□)は1ステップを占有する**

```
LD   X8
CJ   P9
LD   M33
OUT  Y30
LD   M3
OUT  Y36
P9               ; (1) ラベルは1ステップを占有する
LD   M36
OUT  Y39
LD   X9
OUT  Y3B
```

**分岐命令の使い分けと注意**

| 命令 | 動作 |
|---|---|
| `CJ` | 実行指令がONの間、指定ポインタへジャンプする |
| `SCJ` | 実行指令が **OFF→ON に変化した次のスキャンから**、指定ポインタへジャンプする（OFF および ON→OFF のときは次のステップを実行） |
| `JMP` | **無条件に**指定ポインタへジャンプする |

- **タイマのコイルをONした後、CJ/SCJ/JMP でコイルがONしているタイマをジャンプさせると、正常な計測ができなくなる。**
- CJ/SCJ/JMP で **OUT命令をジャンプさせるとスキャンタイムは短くなる**。後ろへジャンプさせた場合も短くなる。
- **ジャンプ命令は同一プログラムファイル内のポインタ番号のみ指定可能。**

## `CALL(P)` — サブルーチンプログラム呼出し（PDF p.585, 587）

**例1: ファンクションデバイス(FX, FY, FD)を引数で渡す**

```
LD    X10
CALLP P0  X0  D0  D100     ; 引数: (s1)=X0 → FX0、(s2)=D0 → FD1、(d)=D100 ← FD2
FEND

P0
LD    FX0
D*    FD1  K100  FD2       ; FD1 × K100 → FD2
RET
```

- **サブルーチン実行前**に、ビットデータの内容が `FX` に、ワードデータの内容が `FD` に転送される。
- **サブルーチン実行後**に、`FY`・`FD` の内容が対応するデバイスに転送される。

| ファンクションデバイス | 使用デバイス | データサイズ |
|---|---|---|
| FX, FY | ビットデバイス | 1点 |
| FX, FY | ワードデバイスのビット指定時 | 1ビット |
| FD | ビットデバイスの桁指定時 | **4ワード** |
| FD | ワードデバイス | **4ワード** |

**例2: 引数で指定したデバイスの占有範囲**

```
LD   X0
CALL P0  M0  D0  D30
```

- (1) `M0` を占有（FX0 へ転送）
- (2) `D0〜D3` を占有（FD1 へ転送）※FDは4ワード占有
- (3) `D30〜D33` を占有（FD2 へ転送）

**例3: 正しい演算 — FD0 に D0 を指定し、サブルーチン内で D4 を使用した場合**

```
LDI  M0
CALL P0  D0            ; FD0 ← D0〜D3
FEND

P0
LDI  M0
/    K100  K3  FD0     ; 商→FD0、余り→FD0+1
+    K100  D4
RET
```

データの動き:

| デバイス | 実行前 | CALL直後 | サブルーチン実行時 | RET実行後 |
|---|---|---|---|---|
| D0 | 0 | 0 | 0 | **33**（FD0の値に置換） |
| D1 | 10 | 10 | 10 | **1**（同上） |
| D2 | 100 | 100 | 100 | 100 |
| D3 | 1000 | 1000 | 1000 | 1000 |
| D4 | 0 | 0 | **100** | 100 |
| FD0 | 不定 | 0, 10, 100, 1000 | 33, 1, 100, 1000 | 不定 |

**ネスティング**

```
CALL P0  ──→ P0
              CALL P10 ──→ P10
                            CALL P20 ──→ P20
                            RET          RET
              RET
FEND
END
```

- **CALL(P)命令のネスティングは16重まで。** ただし16重は `CALL(P)` / `FCALL(P)` / `ECALL(P)` / `EFCALL(P)` / `XCALL` の**合計**。
- サブルーチン内でONさせたデバイスは、**サブルーチンが非実行でも保持される**。OFFさせるには `FCALL(P)` を使う。

**注意事項・使用制約**

- `CALL(P)` では **(s1)〜(s5) まで**使用できる。
- サブルーチンで使用しているファンクションデバイス数と、`CALL(P)` の引数は**同数**にする。種類も同一にする。
- **引数で指定したデバイス番号は重複させない**（重複すると正常に演算できない）。
- 引数のデバイスにタイマ・カウンタを使った場合は**現在値のみ授受**する。
- **FBD/LDプログラムはサブルーチンプログラムとして作成できない。** FBD/LDでは引数を持つサブルーチンの実行もできない。

**エラー（SD0）**

| コード | 内容 |
|---|---|
| 2820H | (s1)〜(s5)で引数に指定したデバイスがデータサイズ分確保できないとき |
| 3360H | **17重目のネスティング**が実行されたとき |
| 3380H | (P)で指定したポインタのサブルーチンプログラムが存在しないとき |
| 3381H | CALL(P)実行後、RET命令を実行する前に END / FEND / GOEND / STOP 命令を実行したとき |
| 3382H | **CALL(P)命令を実行する前に RET命令を実行**したとき |

## `FCALL(P)` — サブルーチンプログラムの出力OFFコール（PDF p.591, 592）

引数・ネスティング・エラーコードは `CALL(P)` と同じ。**違いは「サブルーチン内でONさせた出力をOFFできる」点**。

```
LD    X0
FCALL P0  M0  D0  D30      ; (1) M0→FX0 / (2) D0〜D3→FD1 / (3) D30〜D33→FD2
```

- `FD` はビットデバイスの桁指定時も**4ワード占有**（FDの上位2ワードは0になる）。
- ネスティングは16重まで（`CALL(P)` / `FCALL(P)` / `ECALL(P)` / `EFCALL(P)` / `XCALL` の合計）。
- エラーコードは `CALL(P)` と同じ（2820H / 3360H / 3380H / 3381H / 3382H）。

## `FOR，NEXT` — 繰り返し（PDF p.581）

**例: FOR〜NEXT のネスティング（3重）**

```
FOR  K5                ; 5回繰り返す
LD   X0
（処理）
FOR  K3                ; さらに3回繰り返す
LD   X1
（処理）
FOR  K100              ; さらに100回繰り返す
LD   X2
（処理）
NEXT                   ; FOR K100 に対応
NEXT                   ; FOR K3 に対応
NEXT                   ; FOR K5 に対応
```

- FOR〜NEXT間の処理を**無条件に (n) 回実行**すると、NEXT命令の次ステップへ進む。
- `(n)` は **1〜32767**。**-32768〜0 を指定した場合は (n)=1 と同一**の処理になる。
- FOR〜NEXT間の処理を実行したくないときは、**CJ / SCJ でジャンプ**させる。
- **FOR命令のネスティングは16重まで。**

**例: FOR〜NEXT間でインデックス修飾したプログラムのパルス演算（EGP を使う）**

```
LD   SM400
RST  Z0
FOR  K10
LD   M0Z0
EGP  V0Z0            ; ← FOR〜NEXT間のパルス演算には EGP/EGF を使う
OUT  M100Z0
LD   SM400
INC  Z0
NEXT
```

> ⚠ FOR〜NEXT間では、**動作出力側に立上り命令・立下り命令は使用できない**。EGP/EGF を使う。

**注意事項**

- **FOR〜NEXT間の外から、FOR〜NEXT内へ JMP命令などで分岐することはできない。**
- 対になる FOR命令と NEXT命令は、**一つのプログラムブロック内**で使用する。
- 途中で終了させたい場合は **`BREAK(P)` 命令**を使う。

**エラー（SD0）**

| コード | 内容 |
|---|---|
| 3340H | FOR命令を実行後、NEXT命令を実行する前に END / FEND / GOEND 命令を実行したとき<br>FOR〜NEXT命令間に STOP命令があるとき |
| 3341H | **FOR命令を実行する前に NEXT命令を実行**したとき |
| 3361H | FOR命令のネスティングを行っている場合、**17重目**を実行したとき |

## `DI，EI` — 割込禁止・割込許可（PDF p.568）

**例: 割込みプログラム中の `EI` が実行できる場合／できない場合**

```
; ── A: メインルーチンプログラム ──
LD   SM400
INC  D10
DI   K7              ; ← DI(指定優先度以下の割込禁止) を実行しておく
                     ;    ここで割込みが発生

; ── B: 割込みプログラム ──
I50
LD   M0
OUT  Y0
EI                   ; ← DI K7 を実行済みなら「実行可」
IRET
```

| 条件 | 割込みプログラム中の `EI` |
|---|---|
| `DI`（指定優先度以下の割込禁止）命令の**実行後** | **実行可** |
| `DI`（指定優先度以下の割込禁止）命令**未実行** | **実行不可（無処理）** |

**例: 割込み用ポインタは1ステップを占有する**

```
I10              ; (50) 割込み用ポインタ（1ステップ占有）
LD   X1C         ; (51)
OUT  Y10         ; (52)
LD   X5          ; (53)
OUT  Y30         ; (54)
IRET             ; (55)
```

> **マスタコントロール中に `EI`・`DI` があるときは、MC命令の実行・非実行に関わらず `EI`・`DI` を実行する。**

**エラー（SD0）**

| コード | 内容 |
|---|---|
| 3362H | `DI`（割込禁止）命令、`DI`（指定優先度以下の割込禁止）命令によるネスティングが**16重を超えた**場合 |

## `ECALL(P)` / `EFCALL(P)` / `XCALL` — プログラムファイル間のサブルーチンコール（PDF p.594–606）

引数の渡し方（FX/FY/FD）、占有点数、ネスティング16重の制限、エラーコードは **`CALL(P)` と同じ**。違いは呼び出し先の指定方法。

| 命令 | 用途 | 書式（ラダー） |
|---|---|---|
| `CALL(P)` | 同一プログラムファイル内／グローバルポインタのサブルーチンを呼ぶ | `CALL P0 (s1)…(s5)` |
| `FCALL(P)` | 同上。**サブルーチン内でONさせた出力をOFFできる** | `FCALL P0 (s1)…(s5)` |
| `ECALL(P)` | **別のプログラムファイル内**のサブルーチンを呼ぶ | `ECALL "ファイル名" P0 (s1)…(s5)` |
| `EFCALL(P)` | 別プログラムファイルのサブルーチンを呼び、**出力をOFF**する | `EFCALL "ファイル名" P0 (s1)…(s5)` |
| `XCALL` | 実行指令のON/OFFに応じてサブルーチンの実行／出力OFFを切り換える | `XCALL P0 (s1)…(s5)` |

> ネスティングの16重は **`CALL(P)` / `FCALL(P)` / `ECALL(P)` / `EFCALL(P)` / `XCALL` の合計**。
> 各命令の詳細は `05_応用命令_プログラム制御.md` および原典 PDF p.594〜606 を参照。

## `MC，MCR` — 入れ子構造で実行条件を順に制約する（PDF p.204）

**例: A → B → C と実行条件を順々に制約していく回路**

```
LD   A
MC   N0  M15
N0
LD   M15
OUT  （出力）        ; (1) A がONのとき実行
LD   B
MC   N1  M16
N1
LD   M16
OUT  （出力）        ; (2) A, B がONのとき実行
LD   C
MC   N2  M17
N2
LD   M17
OUT  （出力）        ; (3) A, B, C がONのとき実行
MCR  N2
LD   （接点）
OUT  （出力）        ; (2) A, B がONのとき実行
MCR  N1
LD   （接点）
OUT  （出力）        ; (1) A がONのとき実行
MCR  N0
LD   （接点）
OUT  （出力）        ; (4) A, B, C に関係なく実行
```

- ネスティングは **N0〜N14**（15個）まで使用できる。
- 入れ子構造を使うと、**プログラムの実行条件を順々に制約していく回路**が作れる。

**MC命令の注意**

- `MC` は **(d) のデバイスを変えれば、同一ネスティング(N)番号を何回でも使用できる**。
- `MC` がON時は **(d) で指定されたデバイスのコイルがON**する。
  → **OUT命令などで同一デバイスを使うとダブルコイルになる**ため、**(d) で指定したデバイスはほかの命令中で使用しない**。
- マスタコントロールを使用した回路中に**接点命令が不要な命令（FOR〜NEXT など）**がある場合、
  CPUユニットは **MC命令の実行指令に関係なくその命令を実行する**。
- 対になる `MC` と `MCR` は**一つのプログラムブロック内**で使用する。

**MCR命令の注意**

- `MCR` はマスタコントロールの**解除命令**で、範囲の終了を示す。
- **`MCR` の前には接点命令をつけない。**
- 同一ネスティング番号の `MC` と `MCR` をセットで使用する。
