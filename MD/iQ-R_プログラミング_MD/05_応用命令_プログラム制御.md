• 実行指令がOFFのときは，次のステップのプログラムを実行します。

**SCJ**

• 実行指令がOFF→ONに変化した次のスキャンから，同一プログラムファイル内の指定されたポインタ番号のプログラム

• 実行指令がOFFおよびON→OFFに変化したときは，次のステップのプログラムを実行します。

**JMP**

• 無条件に，同一プログラムファイル内の指定されたポインタ番号のプログラムを実行します。

**注意事項**

• タイマのコイルをONした後，CJ命令，SCJ命令，JMP命令でコイルのONしているタイマをジャンプさせた場合，正常な
計測ができなくなります。
• CJ命令，SCJ命令，JMP命令でOUT命令をジャンプさせるとスキャンタイムは短くなります。
• CJ命令，SCJ命令，JMP命令で後ろにジャンプさせるとスキャンタイムは短くなります。
• CJ命令，SCJ命令，JMP命令は，実行中のステップより若いステップへジャンプすることができます。ただし，ウォッチ
ドッグタイマがタイムアップしないように，この間ループから抜け出す方法を考慮してください。
• CJ命令，SCJ命令，JMP命令で飛ばされたデバイスは変化しません。
• ラベル(P○)は1ステップを占有します。
• ジャンプ命令は同一プログラムファイル内のポインタ番号のみ指定可能です。

## 割込禁止，割込許可


### `DI，EI`

• DI: 割込みプログラムの実行を禁止します。
• EI: 割込み禁止状態を解除します。
| ラダー | ST |
|---|---|
|  | ENO:=DI(EN); ENO:=EI(EN); |
| 命令 | 実行条件 |
|---|---|
| DI EI | 常時実行 |

**機能**


**DI**

• 割込みプログラムの起動要因が発生しても，EI命令が実行されるまで割込みプログラムの実行を禁止します。
• 電源投入時またはCPUユニットをリセットした場合は，DI命令を実行した状態になります。
• DI(指定優先度以下の割込禁止)命令使用時の，DI(割込禁止)命令の動作については，下記を参照してください。
567ページ DI
• DI(割込禁止)命令は割込みプログラム中には実行できません。実行した場合は無処理となります。

**EI**

• DI(割込禁止)命令実行時の割込み禁止状態を解除し，IMASK命令によって許可された割込みポインタ番号の割込みプログ
ラムを実行可能状態にします。IMASK命令非実行時は，I32~I43が割込み禁止になります。

## WDTリセット


### `WDT(P)`

ウォッチドッグタイマをリセットします。
| ラダー | ST |
|---|---|
|  | ENO:=WDT(EN); ENO:=WDTP(EN); |

**実行条件**


**機能**

• プログラム中でウォッチドッグタイマをリセットします。
• スキャンタイムが，条件によりウォッチドッグタイマの設定値を超える場合に使用します。スキャンタイムが，毎スキャ
ンウォッチドッグタイマの設定値を超える場合は，エンジニアリングツールのパラメータ設定でウォッチドッグタイマの

| WDT |  |
|---|---|
| t1 | t2 |
• WDT(P)命令は1スキャン中に2回以上使用できますが，異常発生時の出力OFFまでの時間がかかりますので注意してくだ
さい。
• WDT(P)命令を実行しても，特殊レジスタに格納されるスキャンタイムの値はクリアされません。したがって，特殊レジ
スタのスキャンタイム値は，パラメータで設定したウォッチドッグタイマの設定値よりも大きくなることがあります。

【図】ファンクションデバイス使用例のラダー図(7.3 / 原本 p.583)。以下にニモニックとして書き起こす。

```

RET
```

- FX，FYのファンクションデバイスの処理単位は，ビット単位となります。FDのファンクションデバイスの処理単位は，4ワード単位となります。引数で指定されたデバイスの種類により，取り扱うデータサイズが異なります。ファンクションデバイスで指定されたデバイスは，データサイズ分確保できるようにしてください。データサイズ分確保できない場合はエラーとなります。

| ファンクションデバイス | 使用デバイス | データサイズ |

| FX，FY | ビットデバイス | 1点 |
|  | ワードデバイスのビット指定時 | 1ビット |
| FD | ビットデバイスの桁指定時*2 | 4ワード*3 |
|  | ワードデバイス | 4ワード*3 |

【図】"指定されたデバイスの内容"の例(7.3 / 原本 p.583)。以下にニモニックとして書き起こす。

(3) D30~D33を占有(FD2へ転送)

• サブルーチンプログラムで使用しているファンクションデバイス数と，CALL(P)命令の引数は，同数にしてください。ま
た，ファンクションデバイスとCALL(P)命令の引数の種類は同一にしてください。

ん。
• CALL(P)命令で引数のデバイスにタイマまたはカウンタを使用した場合は，現在値のみ授受します。
• CALL(P)命令の引数に使用したデバイスを，サブルーチンプログラムで使用しないでください。使用した場合は，正常な
演算ができません。
• CALL(P)命令のネスティングは，16重まで可能です。ただしネスティングの16重は，CALL(P)命令，FCALL(P)命令，ECALL
命令(P)，EFCALL(P)命令，XCALL命令の合計です。
• サブルーチンプログラム内でONさせたデバイスは，サブルーチンプログラムが非実行でも保持されます。サブルーチン
プログラム実行時にONさせたデバイスは，FCALL(P)命令でOFFさせることができます。

| 演算で使用するデバイス | 演算結果(デバイスの状態) |

• 実行指令がOFFするとサブルーチンプログラムの非実行処理を行うため，OUT命令，PLS命令(パルス化命令を含む)を強制
的にOFFすることができます。

【図】プログラム例(7.3 / 原本 p.589)。「FCALL(P)命令を使用するとき」と「FCALL(P)命令を使用しないとき」の2パターンをラダー図＋タイミングチャートで比較。以下にニモニックとして書き起こす(両パターンともラダー構成は同一で，FCALL P0の有無だけが異なる)。

```
LD      X0
CALL    P0
FCALL   P0      ; (「FCALL(P)命令を使用しないとき」ではこの行が無い)
   :            (以下，他の回路は省略)
FEND
LD      X1              (P0内)
OUT     Y10
LD      X1
SET     Y11
LD      X1
PLS     M0
RET
```

- 「FCALL(P)命令を使用するとき」のタイミングチャート: X0，X1が共にONの間はY10がON，Y11がSETされ，M0がパルス出力される。X0がOFFすると(1)の箇所でFCALL命令による強制OFFが働き，Y10は強制的にOFF，M0はパルスが出力されない(条件接点OFFと同一処理)。Y11はSET命令中のデバイスのため状態を保持する。
- 「FCALL(P)命令を使用しないとき」のタイミングチャート: X0がOFFになってもFCALL命令が無いため非実行処理が行われず，Y10・Y11・M0(のSET/OUT状態)はX1の状態に応じてそのまま動作を続ける(出力状態が保持される)。


• 各ファンクションデバイスのデータサイズは下記になります。
| ファンクションデバイス | 使用デバイス | データサイズ |
|---|---|---|
| FX，FY | ビットデバイス | 1点 |
|  | ワードデバイスのビット指定時 | 1ビット |
| FD | ビットデバイスの桁指定時*2 | 4ワード*3 |
|  | ワードデバイス | 4ワード*3 |

*2 ビットデバイスの桁指定時で，(s1)~(s5)で指定されたデバイス番号が16の倍数でない場合でも，エラーになりません。

*3 使用する命令により異なります。

【図】"指定されたデバイスの内容"の例(7.3 / 原本 p.602)。以下にニモニックとして書き起こす。

```
LD      X0
XCALL   P0    M0    D0    D30
```

(1) M0を占有(FX0へ転送)
(2) D0~D3を占有(FD1へ転送)
(3) D30~D33を占有(FD2へ転送)

• XCALL命令では，(s1)~(s5)まで使用できます。
• サブルーチンプログラムで使用しているファンクションデバイス数と，XCALL命令の引数は，同数にする必要がありま
す。またファンクションデバイスとXCALL命令の引数の種類は同一にしてください。
• XCALL命令で引数で指定されたデバイス番号は，重複しないでください。重複している場合は，正常に演算ができませ
ん。
• XCALL命令のネスティングは16重まで可能です。ただし，ネスティングの16重は，CALL(P)命令，FCALL(P)命令，
ECALL(P)命令，EFCALL(P)命令，XCALL命令の合計です。
• XCALL命令の引数に使用したデバイスを，サブルーチンプログラムで使用しないでください。XCALL命令の引数に使用し
たデバイスをサブルーチンプログラムで使用した場合には，正常な演算ができません。

【図】XCALL命令のネスティング構造図(7.3 / 原本 p.602)。以下にニモニックとして書き起こす。

```
[XCALL P0  X0]  ------→ (P0)
[FEND]                      [XCALL P10 X10] ←── (P10)   [XCALL P20 X20] ←── (P20)
[END]                       [RET]                            [RET]                [RET]
```

- P0のサブルーチンプログラムからXCALL P10 X10でP10を呼び出し，P10からさらにXCALL P20 X20でP20を呼び出す(多重ネスト)。それぞれRET命令で呼出し元の次ステップへ戻る。

**注意事項**

• FBD/LDプログラムはサブルーチンプログラムとして作成できません。
• FBD/LDでは，引数を持つサブルーチンプログラムの実行はできません。

**エラー**

| エラーコード (SD0) | 内容 |
|---|---|
| 2820H | (s1)~(s5)で引数に指定したデバイスがデータサイズ分確保できないとき。 |
| 3360H | 17重目のネスティングが実行されたとき。 |
| 3380H | (P)で指定したポインタのサブルーチンプログラムが存在しないとき。 |
| 3381H | XCALL命令実行後，RET命令を実行する前にEND命令，FEND命令，GOEND命令，STOP命令を実行したとき。 |
