### 2.9 MELSOFT/FA 機器接続 (2.9 / 印刷 p.123 / 原本 p.124)

#### 2.9.1 概要 (2.9.1 / 印刷 p.123 / 原本 p.124)

パソコン（FR Configurator2）/GOT/ 中継局（シーケンサ）を Ethernet 通信で接続することができます。

##### ◆ システム構成 (2.9.1 / 原本 p.124)

- パソコン（FR Configurator2）と直接接続する場合
- GOT と直接接続する場合
- 中継局（シーケンサ）経由で接続する場合

【図】システム構成図 (原本 p.124)
- パソコン（FR Configurator2）── Ethernetケーブル ── インバータ
- GOT ── Ethernetケーブル ── インバータ
- 中継局（シーケンサ）── Ethernetケーブル ── インバータ

### 2.10 SLMP (2.10 / 印刷 p.126 / 原本 p.127)

#### 2.10.1 概要 (2.10.1 / 印刷 p.126 / 原本 p.127)

SLMP は、ネットワークの階層、境界を意識させないシームレスなアプリケーション間通信を行うための共通プロトコルです。シーケンサやパソコン、表示器など SLMP の制御手順で伝文を送受信できる外部機器との接続であれば、SLMP による通信ができます。（外部機器が SLMP に対応しているかについては、外部機器の取扱説明書を参照してください。）
インバータの製造時期によって対応していない機能があります。仕様変更の内容については 318 ページを参照してください。

##### ◆ 通信手順 (2.10.3 / 原本 p.130)

- TCP/IP 使用時
  TCP/IP で SLMP の通信を行う場合の通信手順を示します。
  TCP/IP は通信時にコネクションを確立し、通信相手に正常にデータが届いたことを確認しながら通信するため、データの信頼性が確保されます。ただし、UDP と比べると、回線の負荷が大きくなります。

【図】TCP/IP 使用時の通信手順 (原本 p.130)
- 構成: 外部機器（パソコン）とインバータをケーブルで接続
- 左列 = 外部機器側、右列 = インバータ側。流れは次のとおり。
  1. 【外部機器】コネクション要求: インバータに対してコネクション要求を行います。(Activeオープン)
  2. → 【インバータ】コネクション処理: 外部機器からのコネクション要求を受け付けます。(Passiveオープン)
  3. → 【外部機器】要求伝文の送信: コネクションが確立されたら、インバータに対して要求伝文を送信します。
  4. → 【インバータ】処理実行: 外部機器から送信された要求伝文に従い、読出し/書込みなどの処理を行います。
  5. → 【インバータ】応答伝文の返信: 処理が完了したら、外部機器に応答伝文を返信します。
  6. → 【外部機器】応答伝文の受信: インバータからの応答伝文を受信し、処理結果を確認します。
  7. 応答伝文の受信から要求伝文の送信へ戻る矢印あり:「必要に応じて繰り返します。」
  8. 応答伝文の受信 → 【外部機器】コネクションの切断: インバータに対してクローズ要求を行い、外部機器側の通信を終了します。
  9. → 【インバータ】コネクションの切断: 外部機器のクローズ要求を受け付け、インバータ側の通信を終了します。

- UDP 使用時
  UDP で SLMP の通信を行う場合の通信手順を示します。
  UDP は通信時にコネクションを確立せず、通信相手に正常にデータが届いたことも確認しないため、回線の負荷が低くなります。ただし、TCP/IP と比べると、データの信頼性は低くなります。

【図】UDP 使用時の通信手順 (原本 p.131)
- 構成: 外部機器（パソコン）とインバータをケーブルで接続
- 左列 = 外部機器側、右列 = インバータ側。流れは次のとおり。
  1. 【外部機器】要求伝文の送信: インバータに対して要求伝文を送信します。
  2. → 【インバータ】処理実行: 外部機器から送信された要求伝文に従い、読出し/書込みなどの処理を行います。
  3. → 【インバータ】応答伝文の返信: 処理が完了したら、外部機器に応答伝文を返信します。
  4. → 【外部機器】応答伝文の受信: インバータからの応答伝文を受信し、処理結果を確認します。
  5. 応答伝文の受信から要求伝文の送信へ戻る矢印あり:「必要に応じて繰り返します。」
  6. 応答伝文の受信 → 【外部機器】通信の終了: 外部機器側で通信の終了処理を行い、通信を終了します。

##### ◆ コマンド内で指定するデータ (2.10.3 / 原本 p.137)

• デバイスコード
1 バイトの数値データを送信します。

• デバイス番号（先頭デバイス番号）の指定
読出しまたは書込みするデバイスの番号を指定します。
連続するデバイスを指定する場合は、読出しまたは書込みするデバイスの先頭番号を指定します。デバイスの番号は、デバイスの種類により 10 進数または 16 進数で指定します。
3 バイトの数値データを、下位バイトから上位バイトの順に送信します｡デバイス番号が 10 進数のデバイスは、16 進数に変換して送信します。
（例）内部リレー M63、入力 X20 の場合

【図】デバイス番号の送信例 (原本 p.137)
- M63：H3F, H00, H00（3 バイト、送信順）
- X20：H20, H00, H00（3 バイト、送信順）

内部リレー M63 はデバイス番号が 10 進数のため、16 進数に変換して H00003F として、3F、00、00 の順に送信します。
入力 X20 は H000020 として、20、00、00 の順に送信します。

• デバイス点数の指定
読出しまたは書込みを行うデバイスの点数を指定します。
処理点数を示す 2 バイトの数値データを、下位バイトから上位バイトの順に送信します。
（例）5 点、20 点の場合

【図】デバイス点数の送信例 (原本 p.137)
- 5点：H05, H00（2 バイト、送信順）
- 20点：H14, H00（2 バイト、送信順）

• ビットアクセス点数の指定
ビット単位で読出しまたは書込みを行うデバイスの点数を指定します。ランダム書込み（140 ページ参照）で使用します。
（例）5 点、20 点の場合

【図】ビットアクセス点数の送信例 (原本 p.137)
- 5点：H05（1 バイト）
- 20点：H14（1 バイト）

• 読出しデータ、書込みデータ
読出しの場合は、読み出したデバイスの値が格納されます。書込みの場合は、書き込むデータを格納します。
ビット単位（サブコマンド：H0001）またはワード単位（サブコマンド：H0000）により、データの並びが異なります。

  • ビット単位（サブコマンド：H0001）の場合
  1 点を 4 ビットで指定し、指定した先頭デバイスから指定デバイス点数分を上位ビットから順に送信します。ON であれば「1」、OFF であれば「0」で表現します。
  （例）M10 から 5 点の ON/OFF を示す場合

【図】ビット単位のデータ並び例（M10 から 5 点） (原本 p.138)
- 電文の並び：先頭デバイス H0A H00 H00 ／ デバイスコード H90 ／ デバイス点数 H05 H00 ／ データ H10 H10 H10
- データ 1 バイト目 H10：上位 4 ビット = M10 = ON、下位 4 ビット = M11 = OFF
- データ 2 バイト目 H10：上位 4 ビット = M12 = ON、下位 4 ビット = M13 = OFF
- データ 3 バイト目 H10：上位 4 ビット = M14 = ON、下位 4 ビット = 「点数が奇数のとき、0で表現します。」

  • ワード単位（サブコマンド：H0000）の場合
  ビットデバイスをワード単位で扱う場合は、1 点を 1 ビットで指定します。下位バイト（ビット 0 ～ 7）から上位バイト（ビット 8 ～ 15）の順序で格納されます。
  （例）M16 から 32 点の ON/OFF を示す場合

【図】ワード単位のデータ並び例（M16 から 32 点） (原本 p.138)
- 電文の並び：先頭デバイス H10 H00 H00 ／ デバイスコード H90 ／ デバイス点数 H02 H00 ／ データ H12 HAB ／ データ HCD H34
- 図中注記：「16点単位のためデバイス点数は“02”となります。」（デバイス点数 H02 を指す）
- H12 → 第1ワードの b7～b0（"1" = b7 b6 b5 b4 = 0 0 0 1、"2" = b3 b2 b1 b0 = 0 0 1 0）＝ M23 ～ M16
- HAB → 第1ワードの b15～b8（"A" = b15 b14 b13 b12 = 1 0 1 0、"B" = b11 b10 b9 b8 = 1 0 1 1）＝ M31 ～ M24
- HCD → 第2ワードの b7～b0（"C" = b7 b6 b5 b4 = 1 1 0 0、"D" = b3 b2 b1 b0 = 1 1 0 1）＝ M39 ～ M32
- H34 → 第2ワードの b15～b8（"3" = b15 b14 b13 b12 = 0 0 1 1、"4" = b11 b10 b9 b8 = 0 1 0 0）＝ M47 ～ M40
- 凡例：0 = OFF、1 = ON

ワードデバイスは、下記の例のように 1 ワードを 16 ビットで指定します。下位バイト ( ビット 0 ～ 7) から上位バイト ( ビット 8 ～ 15) の順序で格納されます。
読出し時は、応答データに格納されている値を、ユーザ側で上下バイトを入れ換えて読み出してください。
書込み時は、書き込みたい値をユーザ側で上下バイトを入れ換えて、要求データに格納してください。
（例）D50、D51 の格納内容を示す場合

【図】ワードデバイスのデータ並び例（D50、D51） (原本 p.139)
- 電文の並び：先頭デバイス H32 H00 H00 ／ デバイスコード HA8 ／ デバイス点数 H02 H00 ／ データ HAB H56 ／ データ H0F H17
- 要求データまたは応答データの格納値：A B 5 6 | 0 F 1 7
- 読出しまたは書込みする値（上下バイトを入れ換え）：5 6 A B | 1 7 0 F
- D50の内容がH56AB(10進数で22187)を示します。
- D51の内容がH170F(10進数で5903)を示します。
