## 1.1 ご使用の前に (1.1 / 16-20 / 原本 p.18-22)

MX Componentは，パソコンからシーケンサへの通信を簡単に実現するためのライブラリです。
MX Componentが提供するコントロールを使用することで，シーケンサからデバイス情報を取得してアプリケーションの開発を行うことができます。
また，ユーティリティを利用することでシーケンサへの通信経路を詳細に設定することが可能になります。

> 本マニュアルで紹介するプログラム例を実際のシステムへ流用する場合は，対象システムにおける制御に問題がないことを十分検証ください。

### MX Componentの活用 (1.1 / 16 / 原本 p.18)

#### シーケンサに対する通信経路を幅広くサポート (1.1 / 16 / 原本 p.18)

シーケンサへの通信経路を幅広くサポートしていますので，お客様に合わせたシステム構築が可能です。

#### ユーザの開発効率を大幅に向上 (1.1 / 16 / 原本 p.18)

ユーザプログラムを作成するときには，ユーティリティ設定タイプまたはプログラム設定タイプのどちらかを選択します。(☞42ページ 通信設定方法の選択)

ユーティリティ設定タイプでは，ウィザード形式の通信設定ユーティリティを用意しています。
画面上で対話形式の設定を行うだけで，通信を行いたいCPUユニットにアクセスするための通信設定が実現できます。
また，一度通信設定を実施すれば，通信設定ユーティリティにて記憶したCPUユニットの論理局番を指定するだけでアクセスすることが可能です。

#### 通信設定の内容の保存，読出しが可能 (1.1 / 16 / 原本 p.18)

通信設定ユーティリティで設定した通信設定の内容をファイルに保存，読出しを行う機能を持っています。
開発用のパソコンから実際に使用するパソコンへ，設定データの移行が簡単に行えます。

> 開発用パソコンおよび実際に使用するパソコンには，MX Componentがインストールされている必要があります。

【図】通信設定データの移行イメージ (1.1 / 16 / 原本 p.18)
- 開発用パソコン(MX Component): 通信設定用データを入力し，保存する。
- 開発用パソコン → 実際に使用するパソコン: 通信設定データを移行する。
- 実際に使用するパソコン(MX Component): 通信設定用データを読み出し，通信経路を確立する。
- 図の結論: 現場での作業時間の短縮

#### ラベルを使用したプログラミングが可能 (1.1 / 17 / 原本 p.19)

ラベル機能を使用して，デバイスNo.を意識することなくプログラムが作成できます。
ラベル名を使用してデバイスを読み書きできます。

【図】ラベル名を指定した ReadDeviceRandom2 の例 (1.1 / 17 / 原本 p.19)

例1: 構造体ラベルの指定(図中注記「ラベル名を指定」)

```vb
'ReadDeviceRandom2関数処理の実行
iReturnCode=
DotUtlType.ReadDeviceRandom2(
"生産量",
 3,
 objData)
```

| 構造体ラベル「生産量」のメンバ | 型 |
|---|---|
| D0 | ワード |
| CN200 | ワード |
| D1 | ワード |

例2: 配列型ラベルの指定(図中注記「データ型により使用するメソッドの使い分けが必要ない」)

```vb
'ReadDeviceRandom2関数処理の実行
iReturnCode=
DotUtlType.ReadDeviceRandom2(
 "AlarmArray",
 3,
 objectValue)
```

| 配列型ラベル「AlarmArray」の要素 | 型 |
|---|---|
| [0]：D0 | ワード |
| [1]：D1 | ワード |
| [2]：D2 | ワード |

#### デバイスの監視やデータ変更が可能 (1.1 / 17 / 原本 p.19)

シーケンサモニタユーティリティを利用することで，指定したデバイスの状態の監視やデータ変更が可能です。

【図】デバイス状態チェックのイメージ (1.1 / 17 / 原本 p.19)
- MX Componentで通信経路を設定，接続
- パソコン → シーケンサ: デバイス状態をチェック
- シーケンサ側「X39がON!」→ パソコン側「X39がONしています」

#### インテリジェント機能ユニットのバッファメモリにもアクセス可能 (1.1 / 17 / 原本 p.19)

CPUユニットのデバイスのみでなく，インテリジェント機能ユニットのバッファメモリへアクセスすることもできます。

【図】バッファメモリアクセスのイメージ (1.1 / 17 / 原本 p.19)
- パソコン → シーケンサ: バッファメモリへアクセス
- 図中注記: 接続したインテリジェント機能ユニットのバッファメモリを読出し／書込み可能！

#### CPUユニットの時計データ読出し/書込みが可能 (1.1 / 18 / 原本 p.20)

パソコンと接続したCPUユニットの時計データを読み出す/書き込むことができます。

【図】時計データアクセスのイメージ (1.1 / 18 / 原本 p.20)
- パソコン → シーケンサ: 時計データへアクセス
- 図中注記: 接続したCPUユニットの時計データを読出し/書込み可能！

#### マルチスレッド通信が可能 (1.1 / 18 / 原本 p.20)

複数のスレッドから同時に複数の通信経路に対してアクセスが可能です。

【図】マルチスレッド通信のイメージ (1.1 / 18 / 原本 p.20)
- ユーザプログラム内に「スレッド1(コントロール1)」「スレッド2(コントロール2)」
- 各スレッドのコントロールが，パソコンから別々のシーケンサ(2台)へ同時に接続

#### シミュレーション機能を使用したオフラインでのデバッグが可能 (1.1 / 18 / 原本 p.20)

各種シミュレータ(GX Simulator2，GX Simulator3，MT Simulator2)との通信が可能です。
シミュレーション機能を使用することにより，シーケンサを接続せずに，1台のパソコン上でデバッグできます。

> QSCPUは本機能に対応していません。

【図】シミュレーション機能のイメージ (1.1 / 18 / 原本 p.20)
- パソコン(MX Component)とシーケンサの間の接続に×印
- 図中注記: シーケンサを接続する必要はありません。

#### 多彩なプログラミング言語をサポート (1.1 / 19 / 原本 p.21)

Visual Basic .NET，Visual C++，Visual C#およびVBAをサポートしています。

#### VBAによるデータ収集，モニタリング機能 (1.1 / 19 / 原本 p.21)

VBAでプログラミングを行うことにより，ExcelおよびAccessの機能を利用し，リアルタイムなグラフ表示を行うアプリケーションが作成できます。
シーケンサのデバイスデータをロギングし，リアルタイムにデバイスデータの収集・保存を行うことが可能です。

【図】<Excel> <Access> の画面例 (1.1 / 19 / 原本 p.21)。内容はイメージのみ(原本 p.21 参照)。

#### QCPU(Qモード)のマルチCPUシステムをサポート (1.1 / 19 / 原本 p.21)

通信設定ユーティリティまたはコントロールのプロパティを設定することにより，QCPU(Qモード)のマルチCPUシステムにアクセスできます。

#### ロギングファイルをパソコンに転送可能 (1.1 / 19 / 原本 p.21)

RCPUに装着されているSDメモリカード内のロギングファイルをパソコンに転送できます。
ロギングファイル転送用のコントロールについては下記を参照してください。
☞21ページ Actコントロール(ロギングファイル転送用)

#### GOTのゲートウェイデバイス読出し/書込み可能 (1.1 / 20 / 原本 p.22)

GOTのゲートウェイデバイスを読み出す/書き込むことにより，GOTがモニタしているCPUユニットのデバイスを間接的に読み出す/書き込むことができます。

【図】GOTゲートウェイデバイス通信のイメージ (1.1 / 20 / 原本 p.22)
- パソコン(MX Component)からEthernet経由で3台のGOTに接続
- 各GOTの先に「三菱電機シーケンサ」「A社シーケンサ」「B社シーケンサ」
- 図中注記: MX Component (GOTゲートウェイデバイス通信)でGOTのゲートウェイデバイスを読出し/書き込み可能！
- 図中注記: GOTでCPUユニットのデータを読出し/書込みする。

#### GOTトランスペアレント通信をサポート (1.1 / 20 / 原本 p.22)

GOTのトランスペアレント機能を使用することにより，GOTを経由してCPUユニットにアクセスできます。

【図】GOTトランスペアレント通信の構成 (1.1 / 20 / 原本 p.22)
- パソコン(MX Component) ― GOT ― シーケンサ の直列接続

#### エラー内容検索時間の短縮 (1.1 / 20 / 原本 p.22)

トラブルシュート機能用コントロール「ActSupportMsg」を使用することで，エラーコードを指定するだけで，エラー内容や処置方法をユーザプログラム内に表示できます。
コントロールにてエラーが発生した場合，マニュアルでエラー内容，処置方法を探す必要がありません。

- メッセージボックスにエラー内容，処置方法を表示させた例

【図】メッセージボックス表示例 (1.1 / 20 / 原本 p.22)。タイトル「通信設定ユーティリティ」，表示内容:

## 1.2 コントロールの種類 (1.2 / 21 / 原本 p.23)

MX Componentが提供するコントロールについて説明します。
本コントロールはCPUユニットに対して通信を行うユーザプログラムを作成する際に使用します。これにより，相手先のハードウェア，通信プロトコルを意識することなく通信が可能です。
MX Componentが提供するコントロールには下記の3種類があります。

- Actコントロール
- Actコントロール(ロギングファイル転送用)
- .Netコントロール

各コントロールの一覧を下記に示します。

### コントロール一覧 (1.2 / 21 / 原本 p.23)

#### Actコントロール (1.2 / 21 / 原本 p.23)

Actコントロールは，デバイスおよびグローバルラベルを使用してデータにアクセスできます。グローバルラベルでアクセスする場合は下記を参照してください。
☞22ページ グローバルラベル名を指定したデータ取得
ラベルでアクセスする場合は，.Netコントロールを使用してください。(☞21ページ .Netコントロール)
MX Componentが提供するActiveXコントロールを下記に示します。

| ビット | コントロール名 | 使用用途 | 対応言語 |
|---|---|---|---|
| 32ビット用 | ActUtlType | ユーティリティ設定タイプのコントロールです。<br>通信設定ユーティリティを使用して，ユーザプログラムを作成する場合に使用します。 | Visual C#<br>Visual Basic .NET<br>Visual C++<br>VBA |
| 64ビット用 | ActUtlType64 | (同上) | (同上) |
| 32ビット用 | ActProgType | プログラム設定タイプのコントロールです。*1<br>通信設定ユーティリティを使用しないで，ユーザプログラムを作成する場合に使用します。 | (同上) |
| 64ビット用 | ActProgType64 | (同上) | (同上) |
| 32ビット用 | ActSupportMsg | ユーティリティ設定タイプ，プログラム設定タイプ共通のコントロールです。<br>トラブルシュート機能に使用します。 | (同上) |
| 64ビット用 | ActSupportMsg64 | (同上) | (同上) |

※原本では32ビット用/64ビット用の2行で「使用用途」セルを共有し，「対応言語」セルは表全体(6行)で共有。表記上「(同上)」とした。

> *1 インバータ通信/ロボットコントローラ通信時は使用できません。

#### Actコントロール(ロギングファイル転送用) (1.2 / 21 / 原本 p.23)

MX Componentが提供するロギングファイル転送用のActiveXコントロールを下記に示します。

| ビット | コントロール名 | 使用用途 | 対応言語 |
|---|---|---|---|
| 32ビット用 | ActUtlDataLogging | ユーティリティ設定タイプのコントロールです。<br>ロギングファイルを転送するときに使用します。<br>通信設定ユーティリティを使用して作成した論理局番を用いて動作します。 | Visual C#<br>Visual Basic .NET<br>Visual C++ |
| 64ビット用 | ActUtlDataLogging64 | (同上) | (同上) |

.Netコントロールは，ラベルを使用してデータにアクセスできます。ラベルはラベル管理ユーティリティで作成してください。(☞121ページ ラベル管理ユーティリティを使ったラベルの作成)

| 64ビット用 | DotUtlType64 | (同上) | (同上) |

### グローバルラベル名を指定したデータ取得 (1.3 / 22 / 原本 p.24)

グローバルラベルに対応している機種では，MX ComponentのActコントロールからグローバルラベル名を指定してデータを取得できます。
グローバルラベル名でのデータ取得が可能なActコントロールは下記のとおりです。

- ActUtlType
- ActUtlType64
- ActProgType

##### 読出し点数が2点以上の場合 (1.3 / 24 / 原本 p.26)

読出し点数が2点以上のグローバルラベルを読み出す場合，1つのラベルデータが複数の配列要素に分割されて値が格納されます。
読出し点数が2点のグローバルラベルを読み出した場合，配列要素には下記の値が格納されます。

| 配列要素 | 上位2バイト | 下位2バイト |
|---|---|---|
| iData[0] | 0 | 読み出す値の下位2バイト |
| iData[1] | 0 | 読み出す値の上位2バイト |

**例**

ReadDeviceRandomを使用して，現在値が「0x000F4240」で読出し点数が2点のグローバルラベルを読み出す場合の配列要素の値

- 読出し方法

```c
int iData[2]
ReadDeviceRandom("LABEL",2,iData)
```

- 読み出したデバイス値

```
iData[0]: 0x00004240
iData[1]: 0x0000000F
```

### 管理者権限 (1.4 / 27 / 原本 p.29)

ラベル管理ユーティリティ実行時は，管理者権限で動作します。
通信設定ユーティリティおよびシーケンサモニタユーティリティ実行時は，ユーザーアカウント制御(UAC)の設定により動作が異なります。

#### ユーザーアカウント制御(UAC)が有効の場合 (1.4 / 27 / 原本 p.29)

管理者を含むすべてのユーザが既定で，「標準ユーザ」として動作します。
管理者権限でプログラムを実行するためには，[管理者として実行]を指定してください。

#### ユーザーアカウント制御(UAC)が無効の場合 (1.4 / 27 / 原本 p.29)

ログインユーザの権限でプログラムを実行できます。

#### Windowsで表示される警告メッセージについて (1.4 / 27 / 原本 p.29)
