### MFREE (5-176〜5-178 / 原本 p.778-780)

MFREE メモリカード(CPUメモリ)の空き容量をバイト単位で取得

#### 対応機種 (5-176 / 原本 p.778)

| KV-8000 | KV-7000 | KV-5000/3000 | KV-1000 | KV Nano |
|---|---|---|---|---|
| 有効 | 有効 | 有効 | 有効 | 有効 |

(ポイントに「KV-N14□□/N24□□/N40□□/N60□□では使用できません。」とあります。)

#### 命令一覧 (5-176 / 原本 p.778)

| 命令語 | 記号 | 名称 | 概要 |
|---|---|---|---|
| MFREE | KV-8000/7000シリーズの場合: 上に「MFREE」と書かれた3枠の箱型命令<br>その他のシリーズの場合: 上に「MFREE」と書かれた2枠の箱型命令 | ストレージ容量取得<br>(バイト単位) | メモリカード(CPUメモリ)の空き容量をバイト単位で取得します。 |

#### ラダープログラム (5-176 / 原本 p.778)

- [KV-8000/7000シリーズ] 「実行条件」の a接点を左母線に接続し、箱型命令「MFREE」(左から [n]・[D1]・[D2] の3枠)を経て右母線へ。
- [KV-5000/3000シリーズ] [KV-1000] [KV Nano] 「実行条件」の a接点を左母線に接続し、箱型命令「MFREE」(左から [D1]・[D2] の2枠)を経て右母線へ。

#### 入力方法 (5-176 / 原本 p.778)

| 機種 | 入力方法 |
|---|---|
| [KV-8000/7000シリーズ] | `MFREE␣n␣D1␣D2↵` |
| [KV-5000/3000シリーズ] [KV-1000] [KV Nano] | `MFREE␣D1␣D2↵` |

#### オペランド (5-176 / 原本 p.778)

| オペランド | 説明 | 占有サイズ |
|---|---|---|
| [n] | 空き容量を確認するストレージを指定します。(0:メモリカード、1:CPUメモリ) | 16ビット |
| [D1] | 空き容量の格納先を指定します。※1 | 32ビット |
| [D2] | 通知ビットの格納先を指定します。※2 | 1ビット×2 |

- ※1 ビットデータを指定する場合は、チャンネルの先頭を指定してください。
- ※2 ビットデータを指定した場合、連続する2 ビットを占有します。ワードデータを指定した場合、連続する2ワードのそれぞれ最下位ビットを通知ビットデータとして使用します。最下位ビット以外は変化しません。

> 補足(本ファイル作成者): [n] は KV-8000/7000シリーズのラダー・入力方法にのみ現れるオペランドです(その他のシリーズは [D1]・[D2] の2オペランド)。オペランド表自体に機種ラベルはありません。

**ポイント**

- KV-N14□□/N24□□/N40□□/N60□□では使用できません。
- 空き容量をキロバイト単位で取得する場合はMFREEK命令を使用してください。
  →「MFREEK命令」(5-214ページ)

#### 動作説明 (5-177 / 原本 p.779)

**MFREE**

> 実行条件の立ち上がりで、ストレージの空き容量を[[D1]・[D1]+1]にバイト単位で格納します。
> また、[D2]には完了通知、[D2]+1には異常終了のエラー通知が書き込まれます。
> CM2390にエラーコードが格納されます。
> →「ストレージ命令用エラーコード一覧」

**例**(図): 「ストレージ」アイコンから矢印「空き容量」→ [D1]+1(上位)・[D1](下位)の「32ビットBINデータ」に格納。

| 格納先 | 内容 |
|---|---|
| [D1]+1 / [D1] | 空き容量(32ビットBINデータ) |

**タイミングチャート** 【図】(原本 p.779)

縦軸: スキャン / 実行条件 / MFREE / 取得処理 / 完了通知([D2]) / 空き容量き書込み([D1]・[D1]+1)(原文ママ・要確認: 「空き容量書込み」の誤記か) / CR3214(ストレージ命令実行中)

- 実行条件が OFF→ON に立ち上がったスキャンで、MFREE が「1スキャンだけ実行」される。
- その直後から取得処理(網掛け)が始まり、数スキャン(図では波線で省略)続く。CR3214(ストレージ命令実行中)は取得処理の間 ON。
- 取得処理の終了時に、空き容量が [D1]・[D1]+1 に書き込まれ(短いパルスで表示)、同時に完了通知 [D2] が ON、CR3214 が OFF になる。
- 実行条件はその前に OFF に戻っているが、取得処理は継続している。
- 次に実行条件が立ち上がると、MFREE が再び「1スキャンだけ実行」され、完了通知 [D2] は OFF、CR3214 は ON、取得処理が再び始まる。

#### 通知ビット([D2]:完了通知、[D2]+1:エラー通知) (5-177 / 原本 p.779)

| 項目 | 名称 | 内容 |
|---|---|---|
| [D2] | 完了通知 | 命令実行開始時にOFF、ストレージより空き容量取得処理終了時にONします。命令が正常終了、異常終了のどちらかでもONします。 |
| [D2]+1 | エラー通知 | 命令が正常終了でOFF、異常終了でONします。 |

**ポイント**

- 完了通知、エラー通知は命令実行完了後END処理で結果が書き込まれます。
- 空き容量取得には、数スキャンを要する場合があります。
- 取得処理中に FTP サーバ機能経由でファイル操作をおこなっていた場合や、ロギング機能を使用していた場合、取得した容量は実際の空き容量と異なる場合があります。
- ストレージ命令実行中、CR3214がONしているときは、MFREE命令は実行できません。
  そのため、CR3214を使用して次のように排他制御をおこなう必要があります。
  - (図) RXXXXX の a接点 → CR3214 の b接点 → 「MFREE [D1] [D2]」。(図から書き起こし) `LD RXXXXX` / `ANB CR3214` / `MFREE D1 D2`
- 割り込みプログラムおよび初期化モジュール内では使用できません。

**タイミングチャート** 【図】(原本 p.783)

縦軸: スキャン / 実行条件 / MMKDIR / 作成処理 / 完了通知([D]) / CR3214(ストレージ命令実行中)

- 実行条件が OFF→ON に立ち上がったスキャンで、MMKDIR が「1スキャンだけ実行」される。
- その後、作成処理(網掛け)が数スキャン(波線で省略)続き、その間 CR3214 は ON。
- 作成処理の終了時に完了通知 [D] が ON、CR3214 が OFF になる。実行条件はそれより前に OFF に戻っているが、作成処理は継続している。
- 次に実行条件が立ち上がると、MMKDIR が再び「1スキャンだけ実行」され、完了通知 [D] は OFF、CR3214 は ON、作成処理が再び始まる。

> ※ 作成処理は、プログラムに関係なく実行されます。したがって、あるスキャンで 1 回命令が実行されれば、次のスキャンで入力条件がOFFであっても作成処理は継続実行されます。

#### 通知ビット([D]:完了通知、[D]+1:エラー通知) (5-181 / 原本 p.783)

| 項目 | 名称 | 内容 |
|---|---|---|
| [D] | 完了通知 | 命令実行開始時にOFF、フォルダ作成終了時にONします。<br>命令が正常終了、異常終了のどちらでもONします。 |
| [D]+1 | エラー通知 | 命令が正常終了でOFF、異常終了でONします。 |

**ポイント**

- フォルダ作成には、数スキャンを要する場合があります。
- 通知ビットは命令実行完了後、END処理で結果が書き込まれます。
- 通知ビットに間接指定、インデックス修飾を指定した時の格納先は、実行条件の立ち上がり時点での格納先になります。
- ストレージ命令実行中CR3214がONしているときは、MMKDIR命令は実行できません。
  そのため、CR3214を使用して以下のように排他制御をおこなう必要があります。
  - (図) RXXXXX の a接点 → CR3214 の b接点 → 「MMKDIR [S] [D]」。(図から書き起こし) `LD RXXXXX` / `ANB CR3214` / `MMKDIR S D`
- 割り込みプログラムおよび初期化モジュール内では使用できません。
- KV-8000/7000 シリーズでストレージを指定する場合、¥(バックスラッシュ)がなくても実行できます。

#### [D2]+2:読み出し上限バイト数の設定 (5-195 / 原本 p.797)

#### 通知ビットデータ([D3]～[D3]+3) (5-196 / 原本 p.798)

| 項目 | 名称 | 内容 |
|---|---|---|
| [D3] | 完了通知 | 命令実行開始時にOFF、メモリカードより読み出し処理終了時にONします。<br>命令が正常終了、異常終了のどちらでもONします。 |
| [D3]+1 | エラー通知 | 命令が正常終了でOFF、異常終了でONします。 |
| [D3]+2 | ファイル末端通知 | 1行読み込んだ後にファイルの末端かどうかの判定をおこない、末端の場合はONします。ファイルの末端でない場合はOFFします。 |
| [D3]+3 | 改行文字無し通知 | 読み出し上限バイト数以内に改行文字が無い場合にONします。<br>改行文字がある場合はOFFします。 |

**ポイント**

- 通知ビットデータは、命令実行完了後END処理で結果が書き込まれます。
- 読み出しには、数スキャンを要する場合があります。MREADL命令実行中は、ストレージから読み出したデータ値を指定した格納先の先頭から順に書き込んでいきます。
  そのため、完了通知ビットデータがONする前に、MREADL命令で処理している範囲のデータを読み出さないでください。
  データが一部反映されてない場合があります。これを防ぐために、完了通知またはCR3214(ストレージ命令実行中)を使用して排他制御してください。
- 他のストレージ命令実行中CR3214がON しているときは、MREADL命令は実行できません。そのためCR3214を使用して次のように排他制御をおこなう必要があります。
  - 例(図): RXXXXX の a接点 → CR3214 の b接点 → 「MREADL [S] [D1] [D2] [D3]」。(図から書き起こし) `LD RXXXXX` / `ANB CR3214` / `MREADL S D1 D2 D3`
- 割り込みプログラムおよび初期化モジュール内では使用できません。
- KV-8000/7000 シリーズでストレージを指定する場合、¥(バックスラッシュ)がなくても実行できます。

#### サンプルプログラム (5-197 / 原本 p.799)

> 内部リレーMR000がONすると、メモリカード内のファイル「DATA.csv」の10バイトから改行位置までのデータを読み出して、データメモリDM0～に格納します。読み出しエラー時にR500をONします。

ラダー図: 1行目 MR000 立ち上がり微分(↑)接点 → DW.D #10 DM200、DW #1999 DM202、DW #0 DM203 を並列出力。2行目 MR000 立ち上がり微分(↑)接点 → MREADL "DATA.csv" DM0 DM200 MR100。3行目 MR100 a接点 → MR101 a接点 → R500 (SET)。

〈ニモニックリスト〉

```
LDP MR000
DW.D #10 DM200
CON
DW #1999 DM202
CON
DW #0 DM203
LDP MR000
MREADL "DATA.csv" DM0 DM200 MR100
LD MR100
AND MR101
SET R500
```

> 補足(本ファイル作成者): 設定内容は DM200・DM201(32ビット)=読み出し位置 10、DM202=読み出し上限バイト数 1999、DM203=システム予約 0。通知ビットは MR100(完了)〜MR103(改行文字無し)。
