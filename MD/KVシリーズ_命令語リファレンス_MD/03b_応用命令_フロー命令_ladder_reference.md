| 命令語 | 記号 | 名称 | 概要 |
|---|---|---|---|

| MCR | 右母線側に置く箱型の要素「┤MCR├」 | マスターコントロールリセット | マスターコントロールの範囲の終了を示します。 |

#### ラダープログラム (3-22 / 原本 p.170)

- 1行目: 「実行条件」の a接点を左母線に接続し、右端に MC。
- 2行目(グレー表示。MC〜MCR 間のプログラムの例): a接点 → 出力コイル。この区間の左母線もグレーの破線表示。
- 3行目: 左母線から直接 MCR(接点なし)。

#### 入力方法 (3-22 / 原本 p.170)

機種別の分け書きはなし(全機種共通)。

| 命令語 | 入力方法 | 括弧内の別入力 |
|---|---|---|
| MC | `MC↵` | `IL↵` |
| MCR | `MCR↵` | `ILC↵` |

#### 動作説明 (3-22〜3-23 / 原本 p.170-171)

> マスターコントロールとは、回路の左母線に接点を設け、そのON/OFFで実行するプログラムブロックを切り換える方法です。回路の概念図は次のようになります。

【図】ラダーソフトでの表示 / 概念図 (原本 p.170)
- 左「ラダーソフトでの表示」: R000 a接点 → MC / R001 a接点 → (出力省略の点線) / R002 a接点 → (点線) / (R002 と R003 の行の間の右側に) MCR / R003 a接点 → (点線) / R004 a接点 → (点線)。
- 右「概念図」: 左母線の途中に R000 の接点を設け(MC)、その接点の先の母線に R001 a接点 → R500 出力コイル、R002 a接点 → R501 出力コイルが接続され、MCR で元の母線に戻る。R003 a接点 → R502 出力コイルは元の左母線に接続。
- 概念図の注記: 「入力リレーR000がOFFのとき、この部分はOFFします。」(R500 と R501 の部分を指す)

概念図を書き起こしたニモニック(図から書き起こし):
```
LD R000
MC
LD R001
OUT R500
LD R002
OUT R501
MCR
LD R003
OUT R502
```

> - MC命令は、マスターコントロールの範囲の先頭を示す命令です。
> - MCR命令は、マスターコントロールの範囲の終了を示す命令です。
> - MC命令の実行条件がONのときは、MC～MCR命令間のプログラムを通常(MC～MCR命令の外)のプログラムと同様に実行します。
> - MC命令の実行条件がOFFのときは、MC～MCR命令間の命令を実行条件がOFF状態で実行します。
>   ただし、以下の命令は例外となります。

| 命令語 | 状 態 |
|---|---|
| OUB命令 | OFFします。 |
| OFDL命令 | リセットします。 |
| SHOT命令 | リセットします。 |
| C命令/CTH命令/HSP命令 | 状態保持します。 |
| CJ/NCJ/GOTO命令 | 分岐しません。 |
| MCALL命令 | マクロ実行中はマクロ内の命令を実行条件がOFF状態で1スキャンのみ実行した後、次のスキャンで停止します。マクロ停止中は実行しません。 |
| MSTRT命令 | マクロ実行中はマクロ内の命令を実行条件がOFF状態で1スキャンのみ実行した後、次のスキャンで停止します。マクロ停止中は実行しません。 |

(結合セル展開: 「リセットします。」は OFDL命令・SHOT命令の2行の結合セル、「マクロ実行中は…実行しません。」は MCALL命令・MSTRT命令の2行の結合セル)

> - [KV-8000/7000/5000/3000シリーズ、KV Nanoシリーズ] モニタ時にMC命令の実行条件がOFFのときは、以下のように表示します。

【図】モニタ表示 (原本 p.171)
- R000 a接点 → MC / R001 a接点 → R500 出力コイル / R002 a接点 → R501 出力コイル / MCR / R003 a接点 → R502 出力コイル。
- MC の行の下から MCR の行まで、左母線の内側にもう1本の縦線(ブラケット状の線)が表示され、MC〜MCR 間の回路(R001・R002 の行)はその内側の線に接続された形で表示される。MCR より後(R003 の行)は通常の左母線に接続。

> - 次のように、MC～MCR命令間の出力リレーR500とMC～MCR命令外の出力リレーR500は2重コイルになります。したがって、後に書かれたものが優先されます。

【図】2重コイルの例 (原本 p.171)(図から書き起こし)
```
LD R003
OUT R500
LD R001
MC
LD R002
OUT R500
MCR
```
- 図中、MC〜MCR 間の R500(2番目の OUT R500)に「←こちらが優先されます。」の注記。

> - MC～MCR命令は、別のMC～MCR命令、STP～STE命令、STG～JMP/ENDS命令、CJ/NCJ/GOTO～LABEL命令、FOR～NEXT命令と組み合わせて使用できます。

> **例**
> **STP～STE命令と組み合わせる場合**
> MC～MCR命令の前後に組み合わせる。
> 命令の間にMC～MCR命令を組み込む。
> MC～MCR命令の間に組み込む。
> **別のMC～MCR命令と組み合わせる場合**
> MC～MCR命令の間に別のMC～MCR命令を組み合わせる。
> (ネスティングは15段までできます）。
> 命令の前後に別のMC～MCR命令を組み合わせる。

【図】組み合わせの例 (原本 p.171-172)。各図の右側に対応範囲を示す弧が描かれている。命令の並び(上から順):
- STP～STE命令と組み合わせる場合 / MC～MCR命令の前後に組み合わせる: `STP XXXX` → `STE` → (接点)→`MC` → `MCR`(STP〜STE の後に MC〜MCR が続く。範囲は重ならない)。
- 命令の間にMC～MCR命令を組み込む: `STP XXXX` → (接点)→`MC` → `MCR` → `STE`(STP〜STE の中に MC〜MCR が入る)。
- MC～MCR命令の間に組み込む: (接点)→`MC` → `STP XXXX` → `STE` → `MCR`(MC〜MCR の中に STP〜STE が入る)。
- 別のMC～MCR命令と組み合わせる場合 / MC～MCR命令の間に別のMC～MCR命令を組み合わせる: (接点)→`MC` → (接点)→`MC` → `MCR` → `MCR`(入れ子)。
- 命令の前後に別のMC～MCR命令を組み合わせる: (接点)→`MC` → `MCR` → (接点)→`MC` → `MCR`(直列に2組)。

> **ポイント**
> 次のような使用法では使えません。

【図】使えない例(×印) (原本 p.172)
- 左図: a接点の後で回路を分岐し、上の分岐で MC、下の分岐で a接点 → 出力コイル とする回路(MC を並列分岐の中に置く)。×印。

#### サンプルプログラム (3-25 / 原本 p.173)

> 入力リレーR000と、内部補助リレーR1000が共にONのとき、R001のON/OFFで出力リレーR500がON/OFFします(R001がONするとR500がONし、R001がOFFするとR500もOFFします)。
> R000とR1000のどちらか(あるいは両方)がOFFのときは、R001の状態に関わらず、R500はOFFのままになります(ONしません)。

ラダー: R000 a接点・R1000 a接点(直列) → MC。R001 a接点 → R500 出力コイル。左母線 → MCR。

【図】3段ネスティングの例 (原本 p.181)(図から書き起こし)
```
FOR #5
(接点 → ① → コイル)
FOR #4
(接点 → ② → コイル)
FOR #3
(接点 → ③ → コイル)
NEXT
NEXT
NEXT
(接点 → ④ → コイル)
```
- 範囲の括弧: FOR #3〜1つ目の NEXT が「ネスティング3」、FOR #4〜2つ目の NEXT が「ネスティング2」、FOR #5〜3つ目の NEXT が「ネスティング1」。
- 図中注記: 「この場合、3段のネスティングとなります。」

> - 「ネスティング1」内を5回実行し、プログラム④へ移ります。
>   したがって、プログラム①は、5回実行されます。
> - 「ネスティング1」を1回実行する間に、「ネスティング2」内のプログラム②は4回実行されます。
>   したがって、プログラム②は、計(5×4=)20回実行されることになります。
> - 「ネスティング2」を1回実行する間に、「ネスティング3」内のプログラム③は3回実行されます。
>   したがって、プログラム③は、計(5×4×3=)60回実行されることになります。

> **ポイント**
> - ネスティングが17段以上になると「FOR-NEXTエラー」が発生し、実行できません。
> - 繰り返し回数が多すぎて、スキャンタイムが300ms以上になると「スキャンタイムオーバー」が発生し、実行できません。

| LABEL | 左母線から直接つなぐ箱型の要素「┤LABEL├」 | ラベル | CJ命令、GOTO命令のジャンプ先を設定します。 |

(結合セル展開: 名称「条件分岐」と概要「LABEL命令まで、ジャンプします。」は CJ・NCJ の2行の結合セル)

#### ラダープログラム (3-36 / 原本 p.184)

- 「実行条件」の a接点 → CJ(枠内に [n])。
- 「実行条件」の a接点 → NCJ(枠内に [n])。
- 左母線から直接 GOTO(枠内に [n])。
- 左母線から直接 LABEL(枠内に [n])。

#### 入力方法 (3-36 / 原本 p.184)

| 命令語 | 入力方法 |
|---|---|
| CJ | `CJ␣n↵` |
| NCJ | `NCJ␣n↵` |
| GOTO | `GOTO␣n↵` |
| LABEL | `LABEL␣n↵` |

#### オペランド (3-36 / 原本 p.184)

| オペランド | 説明 | 占有サイズ |
|---|---|---|
| [n] | ラベル番号を指定します。（0～999）※1 | ー |

- ※1 定数、および定数に設定した変数/ラベルのみ指定可能です。

#### 動作説明 (3-36〜3-37 / 原本 p.184-185)

| 命令語 | 動作説明 |
|---|---|
| CJ | 実行条件がONのとき、[n] で指定したLABEL命令のある行までジャンプします。 |
| NCJ | 実行条件がOFFのとき、[n] で指定したLABEL命令のある行までジャンプします。 |
| GOTO | 無条件で [n] で指定したLABEL命令のある行までジャンプします。 |
| LABEL | CJ命令,NCJ命令またはGOTO命令のジャンプ先を指定します。 |

【図】タイミングチャート (原本 p.184) — 信号: スキャン / 実行条件(ON/OFF) / CJ / NCJ
- 実行条件は ON → OFF → ON → OFF と変化。
- CJ: 実行条件が ON の区間(2回とも)で「実 行」。
- NCJ: 実行条件が OFF の区間(2回とも)で「実 行」。

> **例**
> 実行条件がONのとき、CJ命令で指定したLABEL命令#10へジャンプし①→②とプログラムを実行します。
> 実行条件がOFFのとき、GOTO命令で指定したLABEL命令#20へジャンプし②のプログラムを実行します。

【図】例のラダー図 (原本 p.185)(図から書き起こし。実行条件の接点のデバイス名は原本図に記載なし)
```
LD (実行条件)
CJ #10
GOTO #20
LABEL #10
(プログラム①)
LABEL #20
(プログラム②)
```
【図】フローチャート (原本 p.185)
- 「実行条件」の判定: ON → LABEL #10 → ① → LABEL #20 → ②。
- OFF → ① を飛ばして LABEL #20 → ② へ合流。

> **ポイント**
> - 実行されていないCJ命令/NCJ命令/GOTO命令からLABEL命令間はスキャンタイムに影響しません。
> - CJ命令/NCJ命令/GOTO命令で実行中のステップより若いステップへジャンプしたとき、サイクルタイムオーバー(スキャンタイムが300ms以上)にならないように注意が必要です。

【図】若いステップへのジャンプの例 (原本 p.185)(図から書き起こし)
```
LABEL #10
(プログラム①)
LD R000
CJ #20
GOTO #10
LABEL #20
(プログラム②)
```
- GOTO #10 から LABEL #10 へ戻る矢印、CJ #20 から LABEL #20 へ進む矢印。
- 図中注記: 「入力リレーR000がONしない限り①のプログラムから抜け出すことができず、サイクルタイムオーバー異常になります。」

> **ポイント**(続き)
> - CJ命令/NCJ命令/GOTO命令からLABEL命令間に微分実行型命令やタイマ命令、マクロ命令を使用するときは注意が必要です。
>   →「微分実行型命令を使用するときの注意」（1-43ページ）
>   →「マクロ命令」（3-44ページ）
>   使用しているCPUユニットのユーザーズマニュアルの「タイマ命令使用時の注意」もあわせて参照してください。
> - SBN～RET命令をまたがってジャンプできません。
> - モジュールをまたがってジャンプできません。
> - [KV-1000] CJ命令/NCJ命令/GOTO命令とLABEL命令では、必ず一対で使用しなければなりません。
> - FOR～NEXT命令間でCJ命令を使用する場合は、同じFOR～NEXT間にLABEL命令を合わせて記述してください。
