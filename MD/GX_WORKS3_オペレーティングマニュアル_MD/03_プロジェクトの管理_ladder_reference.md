# 3 プロジェクトの管理 (3章冒頭 / 原本 p.110)

プロジェクトの基本操作や管理について説明します。

---

## 3.1 プロジェクトファイルとデータ構成について (3.1 / 原本 p.110-115)

GX Works3で作成したプロジェクトはワークスペース形式，または1ファイル形式で保存して管理します。
プロジェクト内に作成するデータは，ナビゲーションウィンドウに表示されます。

### ファイル形式 (3.1 / 原本 p.110)

#### ワークスペース形式 (3.1 / 原本 p.110)

ワークスペースとは，複数のプロジェクトを一括で管理するためのものです。
複数のCPUユニットで構成されているシステムを構築する場合，CPUユニットごとにプロジェクトファイルを作成する必要があります。
ワークスペース形式で保存することにより，同一システム内の複数のプロジェクトファイルをまとめて管理できます。

【図】＜システム構成例＞と＜GX Works3のプロジェクト管理＞(原本 p.110)
- ＜システム構成例＞: 「A社向け第一期工事」という1つのシステムを，下記の4つの制御単位で構成した例
  - ＜警報処理 A＞ … Ethernet で接続
  - ＜制御 B＞ … CC-Link IEフィールドネットワーク で接続
  - ＜コンベア制御 C＞
  - ＜付帯処理 D＞
- 上記を「ワークスペース形式で一括管理」する
- ＜GX Works3のプロジェクト管理＞のツリー:
  - A社向け第一期工事 … ワークスペース
    - 警報処理 A … プロジェクト
    - 制御 B … プロジェクト
    - コンベア制御 C … プロジェクト

**●構成や名前を編集する場合**

Windowsのエクスプローラーなどを使用して，ワークスペースの構成やプロジェクト名を変更または削除しないでください。"開く"画面などで表示されるプロジェクト一覧に，存在しないプロジェクトが残る場合があります。(存在しないプロジェクトは，[プロジェクト]⇒[削除]で削除できます。)

**●プロジェクトをコピーする場合**

Windowsのエクスプローラーなどを使用してプロジェクトをコピーする場合は，下記のいずれかで操作してください。
ワークスペース/プロジェクトの構成を崩さずコピーできます。

- 保存先フォルダー(上図(1))ごとコピー
- コピー対象のワークスペース名フォルダー(上図(2))と，"workspacelist.xml"(上図(3))をコピー
- 同名のGX Works3プロジェクトファイルをコピー

#### 1ファイル形式 (3.1 / 原本 p.111)

1ファイル形式とは，ワークスペースを作成しない保存形式です。
1ファイル形式で保存すると，フォルダー構成やファイル構成を意識することなくプロジェクトを管理できます。
そのため，Windowsのエクスプローラーなどでプロジェクト名の変更や，プロジェクトのコピー&ペースト，データの受渡しなどを容易に行えます。

### 安全プロジェクトのバックアップについて (3.1 / 原本 p.111)

安全プロジェクトは，必ずシステム管理者がプロジェクトのバックアップを行い，いつでも復元できるようにバックアップデータを大切に保存してください。
プロジェクトのバックアップは，必ずGX Works3の[プロジェクト]⇒[名前を付けて保存]で実行してください。

### 新規作成する (3.2 / 原本 p.116)

プロジェクトを新規作成する方法を説明します。
安全プロジェクトの新規作成時には，ユーザを登録する必要があります。(📖 117ページ 新しいユーザの追加)

#### 注意事項 (3.2 / 原本 p.116)

安全プロジェクトを作成する場合は，Windowsのスクリーンセーバー機能により，一定の時間パソコンを操作しない状態が続いたときに自動的にロックされるようにしておいてください。
詳細は，Windowsのヘルプとサポートを参照してください。

**MXコントローラのプロジェクトを作成する場合**

プロジェクトの新規作成時に，ユーザ認証機能を有効化できます。MXF100Sの場合は有効化する必要があります。
詳細は下記を参照してください。
📖 840ページ MXコントローラのプロジェクトへの不正なアクセスの防止(ユーザ認証)

**RnENCPUのプロジェクトを作成する場合**

RnENCPUは，CPU部とネットワーク部からなる2スロットを占有するCPUユニットです。
新規作成後はCPU部のみが単体で配置されています。
ネットワーク部を，下記のいずれかの方法で配置してください。

- "ユニット構成図"ウィンドウで，CPU拡張ユニット(_RJ71EN71)を配置
- "システムパラメータ"の"I/O割付設定"で，CPU拡張ユニット(_RJ71EN71)を設定

**LHCPUのプロジェクトを作成する場合**

LHCPUのプロジェクトを新規作成すると，"システムパラメータ"の"I/O割付設定"にCPU拡張ユニット(_IO)が自動で設定されます。

**MX-FモデルおよびFX5CPUの詳細な形名を指定する場合**

MX-FモデルおよびFX5CPUの詳細な形名は，"新規作成"画面では指定できません。下記のいずれかの方法で指定してください。

- ユニット構成図でCPUユニットを右クリック⇒ショートカットメニュー [コントローラ形名変更]/[CPU形名変更]を選択
- "システムパラメータ"画面の[I/O割付設定]タブ内の"I/O割付設定"で，CPUユニットの形名を選択

**QCPU(Qモード)，LCPU，またはFXCPUを選択した場合**

QCPU(Qモード)，LCPU，またはFXCPUを選択した場合は，Q/L/FXシリーズ互換モードでGX Works3が起動します。
Version 1.566Q以降のGX Works2がインストールされている場合のみ，自動的に起動します。
インストールされていない場合は，GX Works3のインストールDVD(Disk2)内の"setup.exe"を実行してください。

2. "名前を付けて保存"画面で各項目を設定し，[保存]ボタンをクリックします。

### シーケンサからの新規読出し (3.2 / 原本 p.118)

プロジェクトを新規に作成していない状態でシーケンサからの読出しを実行すると，CPUユニットおよびインテリジェント機能ユニットから読み出したデータでプロジェクトを新規に作成できます。
QCPU(Qモード)，LCPU，またはFXCPUを選択した場合は，Q/L/FXシリーズ互換モードでGX Works3が起動し，プロジェクトを新規作成できます。
また，プロジェクトにユーザ情報が登録されている場合は，ユーザ認証が必要です。詳細は下記を参照してください。
(MXコントローラ: 📖 854ページ MXコントローラへのログオン，RnSFCPUおよびRnPSFCPU: 📖 860ページ CPUユニットへのログオン)

#### 操作手順 (3.2 / 原本 p.118)

2. "シリーズ選択"画面で読み出す対象のシリーズを選択し，[OK]ボタンをクリックします。
3. "接続先指定"画面でCPUユニットとアクセスするための通信経路を設定し，[OK]ボタンをクリックします。
4. "オンラインデータ操作"画面で読出しを実行します。

操作手順

5. 使用しなくなったユニットFBの定義をナビゲーションウィンドウの"M_FBLIB"から削除します。
6. プログラムを変換します。

> - FBインスタンスが登録されているラベルエディタは，文字列検索機能でユニットFBの名称を検索すると確認できます。(📖 566ページ 文字列の検索/置換)

### PX Developer形式プロジェクトを開く (3.2 / 原本 p.125)

PX Developerで作成したPX Developer形式プロジェクト(PX DeveloperプロジェクトおよびGX Works2プロジェクト)をGX Works3で開き，使用できます。
本機能は，下記ユニットのプロジェクトにのみ対応しています。

- ユニバーサルモデルプロセスCPU
- 二重化CPU

変更される機種を示します。

|---|---|
| ユニバーサルモデルプロセスCPU | R120PCPU(プロセスモード) |

PX Developer形式プロジェクトをGX Works3形式プロジェクトとして使用するために必要なデータの置換えの詳細は，下記を参照してください。
📖 1133ページ PX Developer形式プロジェクトからの置換え

なお，本機能を使用するには，最新のPX DeveloperおよびGX Works2がインストールされている必要があります。

#### 操作手順 (3.2 / 原本 p.125)

1. [プロジェクト]⇒[他形式ファイルを開く]⇒[PX Developer形式]⇒[プロジェクトを開く]を選択します。
2. プロジェクトを選択し，[開く]ボタンをクリックします。
3. 表示されるメッセージを確認し，[OK]ボタンをクリックします。
4. 表示されるメッセージを確認し，CPUユニットのサンプルコメントおよびFBプロパティの初期値を読み出すかどうかを選択します。

プロジェクトデータの変更点が"出力"ウィンドウに表示されます。

#### 注意事項 (3.2 / 原本 p.125)

- 下記のプロジェクトがGX Works3で開かれます。
  - 選択したPX Developerプロジェクト
  - 選択したPX Developerプロジェクトと同じフォルダー内に存在するGX Works2プロジェクト(複数存在する場合，PX Developerプロジェクトと同名のプロジェクトのみが開かれます。)

#### コピー&貼り付け (3.3 / 原本 p.137-140)

編集中のプロジェクトや，ほかのプロジェクトのデータを流用できます。
貼り付ける部品と同じ種類のデータが作成可能な場所への貼り付けのみできます。
CPUユニットのシリーズ/機種が異なるプロジェクトには，データを貼り付けられないことがあります。

**操作手順**

1. ナビゲーションウィンドウ内のコピー元のデータを選択します。
2. [プロジェクト]⇒[データ操作]⇒[データコピー]/右クリック⇒ショートカットメニュー [データコピー]を選択します。
3. ナビゲーションウィンドウ内，またはほかのプロジェクトの貼り付け先フォルダー(コピー元データの1つ上の階層)を選択します。
4. [プロジェクト]⇒[データ操作]⇒[データ貼り付け]/右クリック⇒ショートカットメニュー [データ貼り付け]を選択します。
5. 貼り付け先に同じ名前かつ上書きできるデータがある場合は，表示されたメッセージを確認し，[追加]/[上書き]ボタンをクリックします。

表示されたメッセージで[追加]ボタンをクリックした場合，貼り付け後のデータ名は自動で設定されます。
貼り付け先に同じ名前のデータがあり，かつ上書きできないデータである場合も，貼り付け後のデータ名は自動で設定されます。

> **Point** (原本 p.137)
> 本機能でデータを貼り付けられない場合は，各エディタを開き，該当のデータをコピーすることで流用できます。

**注意事項** (原本 p.138)

- 貼り付け後は，未変換状態になります。
- グローバルラベル内で使用されている構造体およびファンクションブロックはコピーされません。
  貼り付け先に同じ名前の構造体およびファンクションブロックが存在しない場合，そのグローバルラベルのデータ型は未定義のデータ型に変更されます。
- グローバルラベルのコピー時に，"ラベル初期値設定"画面で設定した初期値はコピーされません。
  また，プログラムブロックのコピー時に，"ラベル初期値設定"画面で設定したローカルラベル初期値はコピーされません。
  "ラベル初期値設定"画面で設定した初期値を貼り付け先のデータに反映する方法は，下記を参照してください。
  📖 348ページ 初期値の複製
- グローバルラベルのデータ貼り付けを実行したときに，ラベル数の上限(20480)を超えた場合は，データ貼り付けが中断されます。コピー先とコピー元のグローバルラベルのラベル数を修正し，再度実行してください。
- データを上書きした場合，同じ名前のデータは貼り付け先で配置が変更される場合があります。
- データを上書きした場合，プログラムの実行順序が変更される場合があります。下記でプログラムの実行順序を確認してください。
  - ナビゲーションウィンドウの"パラメータ"⇒"(プロジェクトのCPU形名)"⇒"CPUパラメータ"⇒"プログラム設定"⇒"プログラム設定"
  - ナビゲーションウィンドウでプログラムファイルを選択後，右クリック⇒ショートカットメニュー [プログラムファイル設定]
- ファイルおよびフォルダーを上書きした場合，貼り付け先のみに存在するデータは貼り付け後もそのまま残ります。
- ラダープログラムで使用しているファンクションブロック/ファンクションを上書きした場合，それらは未定義のファンクションブロック/ファンクションに変更されます。
- MXコントローラのプロジェクトにマクロ型ファンクションブロックをコピー&貼り付けすると，サブルーチン型ファンクションブロックに変更されます。

  ユニットFBをプロジェクトに取り込んだ後，部品選択ウィンドウからナビゲーションウィンドウにユニットFBをドラッグ&ドロップしてください。(📖 623ページ ユニットFBをプロジェクトに取り込む，📖 626ページ ユニットFBの定義を追加する)

> - [ツール]⇒[オプション]⇒"プロジェクト"⇒"変更履歴"⇒"動作設定"⇒"履歴を登録するかどうかの確認メッセージを表示する"

**登録されている履歴を基に，過去のプロジェクトを復元できます。**

**操作手順**

1. 復元するプロジェクトの履歴を選択し，[復元]ボタンをクリックします。
2. "履歴の復元"画面の[OK]ボタンをクリックします。

**プロジェクトの復元後，手順1で選択した履歴の先頭にマークが表示されます。**

**注意事項** (原本 p.181)

- **プロジェクトを復元する前に，編集中のプロジェクトの履歴を登録してください。登録せずにほかの履歴を基にプロジェクトを復元して上書き保存すると，復元前のプロジェクトが上書きされます。**
- **追加/変更/削除されたユーザ情報は復元されません。**
- **プロジェクトのセキュリティバージョンが"2"の場合は，履歴の復元に時間がかかることがあります。**

#### 履歴の削除 (3.7 / 原本 p.182)

登録されている履歴を削除できます。

**操作手順**

削除する履歴を選択し，[削除]ボタンをクリックします。

#### 履歴の照合 (3.7 / 原本 p.182)

**履歴をほかの履歴または編集中のプロジェクトと照合できます。**

**操作手順**

**履歴を1つ選択した状態で照合すると，編集中のプロジェクトと照合します。履歴同士を照合する場合は，履歴を2つ選択してください。**

## 3.8 プロジェクトバージョン管理 (3.8 / 原本 p.183-204)

**本機能は，バージョン管理システム<sup>*1</sup>を使用してプロジェクトの変更内容を記録することで，プロジェクトの更新履歴をデータ単位で管理できる機能です。(プロジェクト全体の変更内容だけでなく，各データの変更内容を記録できます。)**

> *1 バージョン管理システムとは，パソコン上で作成および編集されるファイルの更新履歴を管理するためのシステムです。

### 概要 (3.8 / 原本 p.183)

**作成したプロジェクトをバージョン管理システムに登録し，システムからそのプロジェクトを取得して編集できます。**
**編集したプロジェクトをシステムに再度登録すると，システムに登録されているプロジェクトが更新され，その変更内容が更新履歴として記録されます。**
**これにより，編集したプロジェクトをシステムに登録されているプロジェクトに自動でマージでき，その更新履歴を管理できます。**
**また，更新履歴を基に過去のデータを復元することもできます。**

#### 特長 (3.8 / 原本 p.183)

本機能の特長を示します。

- **サーバ上のプロジェクトの履歴をデータ単位で管理できます。(データごとに変更内容を記録できます。)**
- **複数の開発者が作成したデータを1つのプロジェクトに自動でマージできます。(特定のデータのみをマージできます。)**
- **データ単位の履歴を基に，特定のデータのみを復元できます。(エラーが発生しているデータのみを元に戻せます。)**

#### 更新履歴 (3.8 / 原本 p.183)

**下記の操作を行うと，データの変更内容が更新履歴として記録されます。**

- プロジェクトをバージョン管理システムに登録(📖 187ページ プロジェクトの登録)
- ローカルプロジェクトのデータをバージョン管理システムに登録(📖 192ページ プロジェクトファイルとデータの登録)

#### マスタプロジェクトとローカルプロジェクト (3.8 / 原本 p.184)

**プロジェクトをバージョン管理システムに登録すると，変更内容を記録できるプロジェクト(フォルダー形式)が作成されます。**
**本マニュアルでは，このプロジェクトを「マスタプロジェクト」と呼びます。**
**また，マスタプロジェクトには下記のプロジェクトをマージできます。**

- **バージョン管理システムに登録したプロジェクト(1ファイル形式)**
- **バージョン管理システムから取得したプロジェクト(1ファイル形式)**

**本マニュアルでは，これらのプロジェクトを「ローカルプロジェクト」と呼びます。**
各操作方法は，下記を参照してください。

**ブロックパスワードを設定しているデータを取得する場合，ローカルプロジェクトのブロックパスワードがマスタプロジェクトのブロックパスワードに上書きされます。**
**また，ブロックパスワードを設定しているデータを登録または照合するとき，ローカルプロジェクトのブロックパスワードがマスタプロジェクトのブロックパスワードと異なる場合，データを登録および照合できません。**
**データの登録または照合時にマスタプロジェクトのブロックパスワードを取得した場合は，ローカルプロジェクトのブロックパスワードがマスタプロジェクトのブロックパスワードに上書きされ，ブロックパスワードの認証が必要になります。**

#### シーケンサからの読出し (3.8 / 原本 p.201)

**ローカルプロジェクトをシーケンサに書き込んだ後，そのプロジェクトをシーケンサから読み出すと，"更新履歴"画面に想定と異なるアイコンが表示される場合があります。**

**例**

**ローカルプロジェクトのデータ(マスタプロジェクトの最新のデータと一致するデータ)をシーケンサに書き込んだ後，そのプロジェクトをシーケンサから読み出すと，"更新履歴"画面の下記データの右側に(過去)が表示されます。また，履歴一覧にマークが表示されません。**

- プログラムブロック
- ユーザフォルダー
- FBフォルダー
- FUNフォルダー
- グローバルラベル
- 構造体
- **データ名の先頭にM+，M_，P+，またはP_が付加されたデータ**

#### シーケンサへの書込み，変換+RUN中書込み (3.8 / 原本 p.201)

ローカルプロジェクトをシーケンサへ書き込んだ後，バージョン管理システムからプロジェクトファイルまたはデータを取得し，そのプロジェクトファイルまたはデータを再度シーケンサへ書き込む場合の注意事項を示します。

- **シーケンサへの書込み: 実行できます。ただし，シーケンサへ書き込む前にプログラムを変換する必要があります。**
- **変換+RUN中書込み: 実行できません。**

#### プロジェクトの変更履歴 (3.8 / 原本 p.201)

**バージョン管理システムからプロジェクトファイルを取得しても，ローカルプロジェクトの変更履歴は削除されません。**

#### Subversionの機能 (3.8 / 原本 p.201)

**プロジェクトバージョン管理機能を使用するため，GX Works3にはSubversion(SVN)が組み込まれています。**
**マスタプロジェクトに対して，Subversionの機能を使用しないでください。**

## 3.9 プロファイルの管理 (3.9 / 原本 p.205)

**プロファイル(CSP+<sup>*1</sup>など)の登録状態を管理します。**
**プロファイルとは，接続機器の情報(形名など)が格納されているデータです。**
**プロファイルを登録/更新/削除する場合は，あらかじめパソコンへは管理者権限のユーザとしてログオンし，プロジェクトを閉じた状態にしてください。**

> *1 CSP+については，CC-Link協会ホームページ(https://www.cc-link.org)を参照してください。

### 登録/更新 (3.9 / 原本 p.205)

**GX Works3にプロファイルを登録します。**
**プロファイルを登録することにより，各ネットワーク構成ウィンドウのユニット一覧に接続機器が追加されます。**
**すでにプロファイルが登録されている場合，プロファイルが更新(上書き)されます。**

#### 操作手順 (3.9 / 原本 p.205)

1. [ツール]⇒[プロファイル管理]⇒[登録]を選択します。
2. "プロファイル登録"画面でファイルを選択し，[登録]ボタンをクリックします。

**追加/更新された接続機器は，次回プロジェクトを開いたときに，各ネットワーク構成ウィンドウのユニット一覧で確認できます。**
**追加/更新された接続機器の情報をプロジェクトに反映するには，プロジェクトを上書き保存してください。**

> **Point** (原本 p.205)
> - **プロファイルはパソコンごとに管理され，GX Works3とその他のMELSOFT製品で共有しています。そのため，GX Works3で登録を行うと，その他のMELSOFT製品にも内容が反映されます。**
> - **プロファイルは，圧縮ファイル(例: *.zip，*.ipar，*.cspp)です。解凍せずに，圧縮ファイルのまま登録してください。**

### 削除 (3.9 / 原本 p.205)

GX Works3に登録されているプロファイルを削除します。

#### 操作手順 (3.9 / 原本 p.205)

1. [ツール]⇒[プロファイル管理]⇒[削除]を選択します。
2. "プロファイル削除"画面で削除する形名にチェックを入れ，[削除]ボタンをクリックします。
