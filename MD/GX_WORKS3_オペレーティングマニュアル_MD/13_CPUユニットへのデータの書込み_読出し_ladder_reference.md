#### 操作手順 (13.1 / 原本 p.704)

1. "オンラインデータ操作"画面の[書込み]タブを選択します。
2. 書き込むデータと書込み先を選択します。
3. [詳細]ボタンをクリックし，書込み範囲などの詳細設定を行います。
4. [実行]ボタンをクリックします。

安全プロジェクトの場合，MXF100S，RnPSFCPU，またはRnSFCPUへ安全プログラムやパラメータを書込み後，安全にご使用いただくうえで使用者に確認いただきたい内容を明示するためにマニュアルが表示されます。

> **Point** (原本 p.704)
> 複数のプログラムを書き込んだ場合，**"実行タイプ指定なし"のプログラムはCPUユニット上で実行されません。** CPUユニットのメモリ削減のため，書込み時に対象からはずすことを推奨します。

### プログラム復元情報 (13.1 / 原本 p.704)

「シーケンサへの書込み」を実行する時に，プログラム復元情報を書き込むかどうかを選択できます。
プログラム復元情報とは，GX Works3プロジェクトをシーケンサから読み出し，復元する際に使用する情報です。プログラムの描画情報や，ローカルラベルの定義情報を含みます。
下記のオプション設定で，プログラム復元情報を書き込むかどうかの選択を"オンラインデータ操作"画面に表示できます。

- [ツール]⇒[オプション]⇒"オンライン"⇒"プログラム復元情報"⇒"動作設定"⇒"プログラム復元情報の書込み有無を設定可能にする"

"オンラインデータ操作"画面の"プログラム復元情報"で"プログラム復元情報を書き込む(書込み対象データ: プログラム復元情報)"を選択すると，プログラム復元情報のみをCPUユニットへ書き込むことができます。
安全プログラム，安全FB，および安全FUNを書き込む場合，"プログラム復元情報"で"プログラム復元情報を書き込まない(書込み対象データ: プログラム)"を選択しても，プログラム復元情報はRnSFCPUへ書き込まれます。
**プログラム復元情報を書き込まずにプログラムを書き込んだ場合，「シーケンサからの読出し」でデータを読み出すことができません。また，「シーケンサとの照合」で，詳細照合結果画面を表示できません。**
なお，本機能に未対応のCPUユニットでは，オプションを設定してもプログラム復元情報の書込み有無を選択できません。

### 変更のないファイルの書込みを省略 (13.1 / 原本 p.705)

データをCPUユニットへ書き込むときに，前回の書込み後，内容が変更されていないデータの書込みを省略できます。これにより，書込みに必要な時間を短縮できます。

#### 操作手順 (13.1 / 原本 p.705)

1. "オンラインデータ操作"画面で[実行]ボタンをクリックします。
2. メッセージを確認し，"変更のないファイルの書込みを省略する。"にチェックを入れます。

#### 注意事項 (13.1 / 原本 p.705)

書込みを省略できないデータを示します。

- デバイスメモリ
- ファイルレジスタ

| FUNファイル | (上記と同一セル) |
| グローバルラベル割付情報 | グローバルラベル設定の書込みが省略されない |

### 二重化システム構成のCPUユニット使用時の動作 (13.1 / 原本 p.706)

RnPCPU(二重化モード)は，運転モードにより動作が異なります。
RnPSFCPUの運転モードはバックアップモードで動作します。

| 運転モード | 動作 |
|---|---|
| セパレートモード | 接続系のCPUユニットに対して実行します。 |
| バックアップモード | 両系(制御系→待機系の順番)に実行します。<br>制御系への書込み中にエラーが発生した場合，待機系への書込みは実行されません。待機系への書込み中にエラーが発生した場合，制御系のデータは書込み前のデータに戻りません。 |

> **Point** (原本 p.706)
> R04CPU，R08CPU，R16CPU，R32CPU，R120CPUのファームウェアバージョン30以前から31以降にアップデートを実行すると，データ配置が変更されます。
> 動作の詳細は，下記を参照してください。
> 📖 MELSEC iQ-R シーケンサCPUユニットユーザーズマニュアル
> 📖 MELSEC iQ-R CPUユニットユーザーズマニュアル(応用編)
>
> そのため，バックアップしたデータをCPUユニットに書き込むと，プログラムメモリの空き容量が足りなくなる場合があります。空き容量が足りなくなった場合は，下記のいずれかの操作後に再度書き込んでください。

#### パラメータの整合性について (13.1 / 原本 p.707)

一部のパラメータを追加で書き込む場合，およびパラメータを変更して書き込む場合は，パラメータ間の整合性を保った運用が必要です。整合性とは，システムパラメータと各パラメータ間でI/O割付設定などの情報(先頭I/O No.，スロットNo.など)を揃えることです。
整合性を保つには，2通りの方法があります。

- システムパラメータと各パラメータを読み出し，変更します。その後，システムパラメータと各パラメータを合わせてCPUユニットへ書き込み，CPUユニットをリセットします。
- 変更する各パラメータを読み出し，プロジェクト内のシステムパラメータと整合性が合うように変更します。その後，変更したパラメータのみCPUユニットへ書き込み，CPUユニットをリセットします。

### 注意事項 (13.4 / 原本 p.733-734)

#### MXコントローラ (13.4 / 原本 p.733)

- RUN中書込みの実行中は，プログラムの実行が中断されます。中断時間は変更内容およびプログラムの実行時間に依存します。
- 割込みプログラムの起動が待たされる場合があります。
- プログラム中に立上り命令，立下り命令，SCJ命令，STMR命令などシグナルフローメモリの前回スキャンの命令実行状態を参照する命令がある場合，RUN中書込みすると正常に動作しないことがあります。
- 同時に複数箇所から同一のプログラムへのRUN中書込みは行わないでください。
- RUN中書込みに失敗した場合，再度RUN中書込みを実行可能とするため，プロジェクトは変換前の状態に戻ります。
- CPUユニット内のパラメータとプロジェクト内のパラメータが一致している状態でRUN中書込みしてください。
- RUN中書込み対象のファイルがCPUユニットに書き込まれている状態でRUN中書込みしてください。
- 交信タイムチェックの指定が90秒以下の場合は，90秒でチェックが行われます。エラーが発生するようであれば接続先指定にて時間を延ばしてください。
- 変換でワーニングが発生した場合でも，RUN中書込みは続行されます。
- 外部機器からアクセスが有効なラベルの名称を変更してRUN中書込みを実行した場合，グローバルラベル割付情報内に変更前のデータが残ります。変更前のデータを削除するためには，グローバルラベル割付情報を"オンラインデータ操作"画面から書き込んでください。
- グローバルラベルを変更した場合，グローバルラベルを使用しているプログラムはRUN中書込み対象となります。
- FBファイル/FUNファイルを変更した場合，FBファイル/FUNファイル内のファンクションブロック/ファンクションを使用しているプログラムはRUN中書込み対象となります。
- レコーディング設定がCPUユニットに存在する場合，RUN中書込みを実行するときにレコーディング設定も書き込んでください。書き込みしない場合，レコーディング開始時にレコーディング設定異常エラーが発生することがあります。

#### RCPU/LHCPU/FX5CPU (13.4 / 原本 p.733-734)

- **RUN中書込みの実行中は，プログラムの実行が中断されます。中断時間は変更ステップ数に依存します。**
- **プログラム中に立上り命令，立下り命令，SCJ命令，STMR命令がある場合にRUN中書込みすると正常に動作しないことがあります。**

- RUN中書込み対象のファイルがCPUユニットに書き込まれている状態でRUN中書込みしてください。
- 交信タイムチェックの指定が90秒以下の場合は，90秒でチェックが行われます。エラーが発生するようであれば接続先指定にて時間を延ばしてください。
- 変換でワーニングが発生した場合でも，RUN中書込みは続行されます。
- 外部機器からアクセスが有効なラベルの名称を変更してRUN中書込みを実行した場合，グローバルラベル割付情報内に変更前のデータが残ります。変更前のデータを削除するためには，グローバルラベル割付情報を"オンラインデータ操作"画面から書き込んでください。
- グローバルラベルを変更した場合，グローバルラベルを使用しているプログラムはRUN中書込み対象となります。
- **構造体定義を編集(追加/削除/変更)した場合，RUN中書込みできません。** CPUユニットへの書込みは"オンラインデータ操作"画面から行ってください。ただし，構造体メンバが存在しない状態でメンバを新規追加した場合，および構造体のすべてのメンバを編集した場合は，RUN中書込みできます。

### ラベル初期値の変換+RUN中書込みについて(Version 1.000A品のみ) (13.4 / 原本 p.737)

また，初期値をすべてクリアする場合は，ラベル初期値ファイルを削除する必要があります。
なお，ブート運転している場合は，ラベル初期値ファイルをSDメモリカードへ書き込む必要があり，すべてクリアする場合は，メモリカードパラメータのブートファイル設定から削除する必要があります。**ラベル初期値ファイルをCPUユニットへ書き込まない，または削除しない場合，CPUユニットの電源OFF→ON時，リセット時，または，STOP→RUN時にエラーになります。**

#### 注意事項 — プログラム復元情報の書込が中断される場合 (13.4 / 原本 p.739)

プログラム復元情報の書込み中に電源断，リセット，または断線が検出されると，処理が中断され，メッセージが表示されます。
電源断およびリセットにより処理が中断された場合，再度シーケンサへの書込みが必要です。
断線により処理が中断された場合，再接続後，メッセージの[再試行]ボタンをクリックしてください。**[キャンセル]ボタンをクリックすると，下記のエラー状態となります。**

- シーケンサに復元情報が書き込まれていないため，シーケンサからの読出し時にエラーが発生し，読み出せません。
- 実行プログラムと復元情報が不一致となるため，シーケンサをリセット後にエラーが発生し，プログラムが実行できません。

**エラー状態から復旧するには，CPUユニットをSTOP状態にし，再度プログラムを書き込んでください。**

**プログラム復元情報を書き込まずにプログラムを書き込んだ場合，「シーケンサからの読出し」でデータを読み出すことができません。また，「シーケンサとの照合」で，詳細照合結果画面を表示できません。**

変換+RUN中書込み機能を使用してFX5CPUにデータを書き込むとき，下記のオプションを"はい"に設定することで，プログラムとプログラム復元情報を分割して書き込めます。

プログラムとプログラム復元情報を分割して書き込むと，**FX5CPUに書き込むデータの容量が書き込める最大の容量を超えたときに発生するエラーが解消される場合があります。**

#### 注意事項 (13.4 / 原本 p.740)

- プログラムとプログラム復元情報を分割して書き込む場合，データの書込みに時間がかかる場合があります。
- **データを書き込むときにプロジェクトが自動で保存されるため，データを書き込む前にプロジェクトの履歴を登録してください。**(📖 179ページ プロジェクトの変更履歴)
- プロジェクトが自動で保存されない場合，データはFX5CPUに書き込まれません。
- 書込みに失敗した場合，FX5CPUの電源を入れ直す，またはリセットした後，STOP状態のFX5CPUにデータを書き込んでください。

## 13.6 すべてのファイルの削除(初期化) (13.6 / 原本 p.746)

- **デバイス/ラベルメモリ**: デバイス/ラベルメモリ内のファイル格納エリアの全ファイルが削除される
- **SDメモリカード**: SDメモリカード内の全フォルダー/全ファイルが削除される

### メモリカードへの書込み/読出し (13.8 / 原本 p.748)

SDメモリカードに対してデータを書き込み/読み出します。
**指定したドライブパスの"$MELPRJ$"フォルダー内に存在するファイルが読み書きの対象です。**

#### 操作手順 (13.8 / 原本 p.748)

1. "メモリカード操作"画面の[書込み]タブ/[読出し]タブを選択します。
2. 書込み先/読出し元のドライブを指定し，[実行]ボタンをクリックします。

### メモリカードからプログラムファイルを読み出す場合の注意事項 (13.8 / 原本 p.748)

SDメモリカードからプログラムファイルを読み出す場合は，下記を実施してください。

#### メモリカードへの書込み時に，プログラムファイルと一緒にパラメータを書き込んでいる場合 (13.8 / 原本 p.748)

プログラムファイルと合わせてパラメータも読み出してください。

#### メモリカードへの書込み時に，プログラムファイルと一緒にパラメータを書き込んでいない場合 (13.8 / 原本 p.748)

- プログラムファイルを読み出す前に，SDメモリカードへの書込み時のプロジェクトを開いておいてください。
- SDメモリカードへの書込み時に使用したパラメータをCPUユニットから読み出しておいてください。
