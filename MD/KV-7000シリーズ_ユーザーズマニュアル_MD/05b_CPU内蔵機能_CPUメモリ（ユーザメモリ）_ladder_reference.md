## 5-3 CPUメモリ（ユーザメモリ） (5-27〜5-49 / 原本 p.349-371)

### CPUメモリ（ユーザメモリ）でできること (5-27〜5-28 / 原本 p.349-350)

> KV-7000シリーズでは、内蔵されたCPUメモリ（ユーザメモリ）領域を使用して、ラダープログラムのロード/セーブやデバイス値のロギング、ラダープログラムからファイルの作成などを実現できます。
>
> - **CPUメモリからCPUユニットへのデータ読み出し**<br>CPUメモリに保存された任意の（プロジェクト）フォルダをアクセスウィンドウで選択して、データを読み出すことができます。<br>データはラダープログラム、デバイス、コメント、ユニット設定情報、ロギング設定情報などのプログラムデータと、DM、EM、W、FM、ZF、CM、R、MR、LR、CRなどのデバイスファイルデータがあります。<br>→ 「プロジェクトデータの保存・読み出し」（5-35ページ）
> - **自動読み出し機能**<br>電源投入時に、「AutoLoad」、または「AtLoad＊＊」（＊＊ : 01～99）という名前の（プロジェクト）フォルダに格納されているデータを自動的にCPU ユニットに読み出します。また「RunLoad」、または「RnLoad＊＊」（＊＊ : 01～99）という名前のフォルダに保存しておくと、PRG→RUN切換時に自動的に読み出します。<br>→ 「オートローディング機能」（5-45ページ）
> - **CPUユニットからCPUメモリへのデータ保存**<br>CPUユニットからCPUメモリへ、プログラムファイル（ラダープログラム、デバイス、コメント、ユニット設定情報、ロギング設定情報）と全領域のデバイスファイル（DM、EM、W、FM、ZF、CM、R、MR、LR、B、CR）を保存できます。保存されたファイルは新規に作成された（プロジェクト）フォルダに格納されます。フォルダ名は自動的につけられ、動作正常終了時にアクセスウィンドウに表示されます。<br>→ 「プロジェクトデータの保存・読み出し」（5-35ページ）
> - **ロギング・トレース機能**<br>記録するデバイスと取り込むタイミング（トリガ）を《KV STUDIO》で登録すれば、CPUメモリにデータを自動的に格納します。CSV形式で保存されますので、Microsoft Excelなどの表計算ソフトに取り込んでそのまま使用することができます。<br>→ 「5-4 ロギング・トレース」5-50ページ

> **ポイント**
> KV-7000シリーズではメモリカードを使用しても同様のことが実現できます。

#### CPUメモリの活用例 (5-28 / 原本 p.350)

> - デバイス値のロギングがメモリカードレスで実現可能。ログから集計し、資料作成が簡単になります。
> - 正常に動作していた時点のプログラムデータを保存しておくことで、変更後にトラブルが発生した場合でも簡単に現状復帰できます。
> - ExcelやWord、PDFなどで作成した設計資料をプログラムと一緒に保存でき、保全作業時に設計と比較して確認できます。
> - デバイスコメントやラベルを格納する領域として活用できます。

【図】活用例のイラスト (原本 p.350)

| 活用例 | 図中の説明 |
|---|---|
| データログの保存 | 「KV STUDIOまたは転送ツールでログを取得。パソコンで集計や資料作成などに。」 |
| プログラムの復元 | 「KV STUDIOまたは転送ツールでCPUメモリに保存」→「正常に動作していた タイミングにまで復元可能」 |
| 設計資料の保存 | トラブルシューティング・配線図(コネクタのピン配置表)を「KV STUDIOまたは転送ツールでCPUメモリに保存」→「プログラムと合わせて読み出し可能」 |
| メモリ構成の変更 | 初期設定「プロジェクト領域｜ユーザメモリ」→ 調整後「プロジェクト領域(拡大)｜ユーザメモリ(縮小)」。「使い方に合わせてメモリ構成と変更可能」 |

### CPUメモリについて (5-29〜5-31 / 原本 p.351-353)

#### 使用できるCPUメモリ領域 (5-29 / 原本 p.351)

> プログラム領域とユーザメモリ領域を足し合わせたものがCPUメモリ領域です。

【図】CPUメモリ = プロジェクト領域 ＋ ユーザメモリ。CPUメモリ容量は KV-7500:64MB、KV-7300:21MB。「領域の境界はCPUメモリ容量設定で変更可能」

(本文は「プログラム領域」、図・表は「プロジェクト領域」。原文ママ)

> 各領域に格納されるデータは以下のとおりです。

| プロジェクト領域 | ユーザメモリ領域 |
|---|---|
| ユニット設定情報 | ファイルレジスタ |
| デバイス初期値設定 | ユーザドキュメント |
| CPUシステム設定 | ロギングデータ |
| プログラム | プロジェクトデータ |
| デバイスコメント | その他 |
| ラベル | |

> ユニット設定/ユニットデータ/アクセスウィンドウ設定などは別領域です。

(表ではユニット設定情報がプロジェクト領域に入っているが、直後の文では「ユニット設定…は別領域」。原文ママ・要確認)

#### 設定方法 (5-29 / 原本 p.351)

> KV STUDIOの【ツール】→【CPUメモリ容量設定】から領域を変更できます。

【図】［CPUメモリ容量設定］ダイアログ (容量設定スライダ: プロジェクト領域 ⇔ ユーザメモリ領域、0kB〜67108864kB 表示。項目 プロジェクト領域 / ユーザメモリ領域 の設定値(kB)と消費状況(現在のプロジェクト / PLC内のプロジェクト)、〔PLC内の消費状況更新〕、プログラム容量の目安「ラダー:1500kステップ / デバイスコメント:224894個」。数値は小さく判読困難のため要確認)

#### CPUメモリ（ユーザメモリ）のデータを読み書きする方法 (5-30〜5-31 / 原本 p.352-353)

> CPUメモリ（ユーザメモリ）のデータを読み書きするには次の3つの方法があります。
> ①ストレージ転送ツールを使用してPLC経由で読み書きを実行する
> ②KV-7500などのFTPサーバ機能を使用してPLC経由で読み書きを実行する
> ③KV STUDIOからPLC転送機能を使用して読み書きを実行する※
> （※ユーザドキュメント、ファイルレジスタ設定のみ）

**①ストレージ転送ツールを使用してPLC経由で読み書きを実行する** (5-30 / 原本 p.352)

> KV STUDIOのメニューの【ツール（T）】→【ストレージ転送ツール】を起動します。

- 別手順: メニュー→すべてのプログラム→KEYENCE Applications→KV STUDIO Ver.8→ツール→ストレージ転送ツール

> CPUメモリ（ユーザメモリ）内のフォルダと、パソコン内のフォルダをバックアップまたはリストアします。
> 全データの一括転送にのみ対応しており、ファイルやフォルダを指定した読み書きには対応していません。
> 詳細な内容については → 『KV STUDIOユーザーズマニュアル』を参照してください。

【図】［ストレージ転送ツール］ダイアログ(PLC側ストレージ種別選択で「1:CPUメモリ（ユーザメモリ領域）」を選択)

**②KV-7500などのFTPサーバ機能を使用してPLC経由で読み書きを実行する** (5-30 / 原本 p.352)

> KV-7500やKV-XLE02などのFTPサーバ機能を使用すると、イーサネットケーブル経由でPLC内のCPUメモリのデータを読み書きできます。
> CPUメモリ内のデータは「1_CPUMEM」フォルダに格納されています。

**③KV STUDIOからPLC転送機能を使用して読み書きを実行する** (5-31 / 原本 p.353)

> PLC転送時にユーザドキュメントとファイルレジスタの設定のみCPUメモリのデータを読み書きできます。

【図】［プログラム転送］ダイアログ (転送項目で「ユーザドキュメント」「ファイルレジスタ設定」にチェック)

> **ポイント**
> PLC転送時にロギングデータやロード･セーブデータなどのデータは転送できません。

#### 使用上の注意事項 (5-31 / 原本 p.353)

> CPUメモリを使用するうえでの一般的な注意事項を以下に記します。

> **注記**
> - 次の場合、CPUメモリに保存したデータが失われる恐れがあります。記録したデータが失われた場合は、弊社は一切その責任を負いかねます。あらかじめご了承ください。
>   - ユーザまたは第三者がCPUメモリを誤った使用方法で使用したとき
>   - CPUメモリが、静電気･電気的ノイズの影響を受けたとき
>   - CPUメモリへの保存回数が1万回を超えたとき(PLC本体エラー143：CPU累積書込回数オーバー　が発生します)

> **ポイント**
> - メモリカードアクセス中にCPUメモリへの書き込みは実行できます。<br>（メモリカードアクセス中のメモリカード書き込み、CPUメモリアクセス中のCPUメモリ書き込みは実行できません。）
> - ユーザメモリに常時書き込みを実行する場合、書き込み速度に制限がかかります。高速での読み書きが必要になる場合、RAM上にファイルを作成し、電源断の直前に書き込みを行うことで高速に書き込みができます。→ 「RAMモード」（5-47ページ）
> - 「隠しファイル属性」や「読み取り専用属性」がついたファイル/フォルダをユーザメモリに書き込んだ場合、これらの属性は解除されます。

### オートローディング機能 (5-45〜5-46 / 原本 p.367-368)

> 電源投入時やPRG→RUN時にCPUメモリに保存されているプロジェクトデータを自動的に読み出します。
> コントロールメモリ（CM）を使用して、複数のフォルダから読み出すフォルダを選択することができます。

#### 電源投入時に読み出す (5-45 / 原本 p.367)

1. 《KV STUDIO》を使用して、「AutoLoad」、または「AtLoad＊＊」（＊＊ : 01～99）のフォルダ名称でプロジェクトデータを作成します。ストレージ転送ツールやFTPサーバ機能などを使用して、CPUメモリ（ユーザメモリ）にプロジェクトデータを書き込みます。<br>→ 「ラダープログラムなど（デバイスファイル以外）」（5-44ページ）
2. 《KV-7000シリーズ》の電源をOFFします。
3. 《KV-7500/7300》の電源を投入します。<br>自動的にデータが読み出されます。

**読み出すフォルダの指定方法**

> 読み出すフォルダを指定する場合は、あらかじめCM1790に数値を格納します。
> - CM1790の値が0の場合<br>フォルダ名「AutoLoad」が読み出されます。<br>「AutoLoad」フォルダがCPUメモリ（ユーザメモリ）に存在しない場合は、オートロードされません。電源投入前のプログラムで動作します。エラーは発生しません。
> - CM1790の値が01～99の場合<br>フォルダ名「AtLoad＊＊」（＊＊ : CM1790の値（01～99））が読み出されます。

**フォルダ番号の指定手順**

1. 電源投入している状態で、タッチパネルなどの外部機器からCM1790に数値を格納します。
2. 電源を切ります。
3. 電源を投入します。
4. CM1790で指定したフォルダが読み出されます。
5. 読み出し完了後、CM1790に0が格納され、CM1792に読み出したフォルダ番号が格納されます。

> **参考**
> オートロード完了後、CM1790に0が格納されるので、次回電源投入時、同じフォルダ番号は読み出されません。ただし、CM1790に0が格納されている状態でメモリカードに「AutoLoad」フォルダがあると、次回電源投入時に読み出されるので注意してください。

(CPUメモリの節だが「メモリカードに「AutoLoad」フォルダがあると」と記載。原文ママ)

> **ポイント**
> - 《KV STUDIO》のCPUシステム設定でライトプロテクトされている場合はエラー（オートローディング失敗）が発生し、PRGモードになります。エラークリア後、RUNモードで動作するとオートロード実行前のプログラムで動作します。
>
> 以下の場合はエラー（オートロードフォルダ）が発生し、PRGモードになります。
> - CM1790の値が100以上の場合
> - CM1790で指定したフォルダがCPUメモリ（ユーザメモリ）にない場合
> - PLC本体に格納されているプロジェクトの機能バージョンと転送するプロジェクトの機能バージョンが異なる場合、CPUのオールクリアが必要になります。

(エラー名が 5-2 では「オートローディング失敗」、本節では「オートロードフォルダ」。原文ママ・要確認)

#### PRG→RUN時に読み出す (5-46 / 原本 p.368)

1. 《KV STUDIO》を使用して、「RunLoad」、または「RnLoad＊＊」（＊＊ : 01～99）のフォルダ名称でCPUメモリ（ユーザメモリ）にプロジェクトデータを書き込みます。<br>→ 「ラダープログラムなど（デバイスファイル以外）」（5-44ページ）
2. 《KV-7500/7300》をPRG→RUNに切り換えます。<br>自動的にデータが読み出され、運転を開始します。

**読み出すフォルダの指定方法**

> 読み出すフォルダを指定する場合は、あらかじめCM1794に数値を格納します。
> - CM1794の値が0の場合<br>フォルダ名「RunLoad」が読み出されます。<br>「RunLoad」フォルダがCPUメモリに存在しない場合は、オートロードされません。PRG→RUN前のプログラムで動作します。エラーは発生しません。
> - CM1794の値が01～99の場合<br>フォルダ名「RnLoad＊＊」（＊＊はCM1794の値01～99）が読み出されます。

**フォルダ番号の指定手順**

1. タッチパネルなどの外部機器からCM1794に数値を格納します。
2. PRG→RUNに切り換えます。
3. CM1794で指定したフォルダが読み出されます。
4. 読み出し完了後、CM1794に0が格納され、CM1796に読み出したフォルダ番号が格納されます。

> **参考**
> オートロード完了後、CM1794に0が格納されるので、次回電源投入時、同じフォルダ番号は読み出されません。ただし、CM1790に0が格納されている状態でCPUメモリ（ユーザメモリ）に「RunLoad」フォルダがあると次回PRG→RUNすると読み出されるので注意してください。

(原文ママ・要確認: ランロードの説明なので「CM1790」は CM1794、「次回電源投入時」は「次回PRG→RUN時」と思われる)

> **ポイント**

### RAMモード (5-47〜5-48 / 原本 p.369-370)

> RAMモードとはKV-7000シリーズでCPUメモリにファイル保存する際に、一度RAMにファイルを作成し、完成したファイルをまとめて1回で保存することで、CPUメモリに対して、高速でファイル保存する機能です。

> **ポイント**
> - RAMモードで使用するRAMは電源をOFFするとクリアされます。<br>電源をOFFする前に、CPUメモリ保存処理を実行してください。

【図】RAMモード未使用時 / 使用時 (原本 p.369)

| 状態 | 構成 | 図中の説明 |
|---|---|---|
| RAMモード未使用時 | CPUユニット → CPUメモリ(ユーザメモリ) に直接書き込み(多数の書き込みに×印) | 高速で書き込みを実行すると、CPUメモリの書き込み回数制限に短期間で到達するため、書き込み速度を制限 |
| RAMモード使用時 | CPUユニット → RAM（揮発） → CPUメモリ(ユーザメモリ) | RAM上でファイル作成するため、CPUメモリへの書き込み回数を抑えることができる |

> **ポイント**
> - ファイルレジスタ命令またはストレージ命令でCPUメモリにアクセスする場合は、命令語RAMモード動作リレー(CR3207)をONしてRAMモードに切り換えます。
> - ロギングを使用してCPUメモリにアクセスする場合はロギング/トレース設定のオプションで、「不揮発メモリへのファイル保存を行う」のチェックを外すとRAMモードで動作します。
> - KV-7000シリーズでは、CPUメモリへの書き込み超過によるメモリの劣化を防止するため、CPUメモリへの書き込み速度を制限しています。

#### 設定方法 (5-48 / 原本 p.370)

> ラダープログラム中でCPUメモリ命令語RAMモードリレー（CR3207）をONします。
> CPUメモリに書き込む際には、CPUメモリ保存処理要求リレー（CR3200）をONします。

**タイムチャート** (原本 p.370 の図を表化)

| 信号 | ① | ② | ③ | ④ |
|---|---|---|---|---|
| CPUメモリ命令語RAMモード(CR3207) | OFF→ON | ON | ON | ON(その後 OFF) |
| (ストレージ命令など) | 実行中 → 完了 | | | |
| CPUメモリ保存処理要求(CR3200) | OFF | OFF→ON(パルス) | ON→OFF | OFF |
| CPUメモリ保存処理中(CR3201) | OFF | OFF | OFF→ON | ON→OFF |
| CPUメモリ保存処理完了(CR3202) | (前回の状態。点線で ON) | | ON→OFF | OFF→ON |

> ①CPUメモリ命令語RAMモードリレー（CR3207）をONし、ストレージ命令などを実行します。（ラダー）
> ②ストレージ命令の実行が完了し、保存が必要になったタイミングで、CPUメモリ保存処理要求リレー（CR3200）をONします。（ラダー）
> ③CPUメモリの保存を開始するとCPUメモリ保存処理中リレー（CR3201）がONします。CPUメモリ保存処理完了リレー（CR3202）がONしていた場合はOFFします。（CPU）
> ④CPUメモリ保存処理が完了するとCPUメモリ保存処理中リレーがOFFし、CPUメモリ保存処理完了がONします。（CPU）

(図では CR3200 が ON 後すぐ OFF(パルス)になっているが、SET 命令で ON した要求を誰が OFF するかは本文に記載なし。要確認)
