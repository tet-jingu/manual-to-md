## 4-10 ローカルデバイス (4-150〜4-155 / 原本 p.248-253)

> 従来、PLCで扱うデバイスはプロジェクト全体で共通の存在でした。そのため、プログラム中に使用する全てのデバイスをユーザ側で管理する必要がありました。
> 《KV STUDIO》では、プログラムごとに独立したデバイスとして使用可能なローカルデバイスを扱えます。別のプログラムで同じ番号のローカルデバイスを使用しても、別のデバイスとして扱われるため、モジュール内やマクロ内のみで使用するデバイスの割り付けが簡単に管理できます。
> 各プログラム内のみで有効なローカルデバイスに対して、プロジェクト全体で共通して扱うデバイスをグローバルデバイスと呼びます。

【図】従来とKV STUDIOのデバイス構成 (原本 p.248)

| 区分 | 構成 |
|---|---|
| ＜従来＞ | プロジェクト内に「プログラム」と「(グローバル)デバイス」が1つずつ存在する。 |
| ＜KV STUDIOでは＞ | プロジェクト内の モジュールA / モジュールB / マクロC がそれぞれ「プログラム」と「ローカルデバイス」を持ち、さらにプロジェクト全体で「グローバルデバイス」を共有する。 |

### ローカルデバイスの記述方法 (4-150 / 原本 p.248)

> ローカルデバイスの指定は、デバイス名の先頭に「@」を付けて記述します。

例

| ＜グローバルデバイス＞ | ＜ローカルデバイス＞ |
|---|---|
| EM0 | @EM0 |
| MR0 | @MR0 |

> **ポイント**
> タイマ・カウンタ命令のオペランドとしてデバイス番号を指定する場合のみ、「@＋（デバイス番号）」と記述します。
> （ニモニック入力例 :　TMR @0 #100）

### ローカルデバイス一覧 (4-151 / 原本 p.249)

> プロジェクト作成時に確保されるローカルデバイス/グローバルデバイスの個数･範囲の初期値を下記に示します。ローカルデバイスの予約個数は、[ワークスペース]上の[CPUシステム設定]→[ローカル全体割付設定]で変更できます。

| デバイス名※1 | ローカルデバイス<br>プロジェクト全体での予約個数※2 | グローバルデバイス<br>個数･範囲 | 合計個数 |
|---|---|---|---|
| リレー（R）※3 | なし | 32000 点（2000ch）<br>R000 ～ R199915 | 32000 点（2000ch） |
| 内部補助リレー（MR）※3 | 32000 点（2000ch） | 32000 点（2000ch）<br>MR000 ～ MR199915 | 64000 点（4000ch） |
| ラッチリレー（LR）※3 | 8000 点（500ch） | 8000 点（500ch）<br>LR000 ～ LR49915 | 16000 点（1000ch） |
| タイマ（T）※4 | 1500 点 | 2500 点<br>T0 ～ T2499 | 4000 点 |
| カウンタ（C）※4 | 1500 点 | 2500 点<br>C0 ～ C2499 | 4000 点 |
| データメモリ（DM） | 25000 点 | 40535 点<br>DM0 ～ DM40534 | 65535 点 |
| 拡張データメモリ（EM） | 45000 点 | 20535 点<br>EM0 ～ EM20534 | 65535 点 |
| テンポラリデータメモリ（TM） | なし | 512 点<br>TM0 ～ TM511 | 512 点 |

- ※1 リンクリレー（B）、リンクレジスタ（W）、ファイルレジスタ（ZF）、コントロールリレー（CR）、コントロールメモリ（CM）、インデックスレジスタ（Z）は、ローカルデバイスとして使用できません。<br>@FMxxxを使用した場合、ワーク領域をローカルデバイスとして消費します。
- ※2 プロジェクト新規作成時に、ローカルデバイスとして使用可能なデバイスの領域を一括で確保します。<br>（モジュールを10個使用して、マクロを50回呼び出すと想定して計算しています。）各デバイスの予約個数は任意に変更できます。
- ※3 チャンネル（ch）単位で使用個数を設定します。
- ※4 タイマ･カウンタ命令のオペランドとしてデバイス番号を指定する場合のみ、「@＋（デバイス番号）」と記述します。（ニモニック入力例：　TMR @0 #100）。

> 補足(本ファイル作成者): 各行とも「ローカル予約個数＋グローバル個数＝合計個数」で整合しています(例: EM 45000＋20535＝65535)。

> **ポイント**
> - リレー（R）とテンポラリデータメモリ（TM）をローカルデバイスとして使用する場合は、使用個数を設定する必要があります。
> - 以下のデバイスは、グローバルデバイスとして扱う必要があります。
>   - CPUユニットや拡張ユニットに割り当てられているデバイス
>   - タッチパネルなどの外部接続機器で参照するデバイス
>   - プロジェクト全体で共通して使用するデバイス
>   - モジュール間でデータの受け渡しが必要なデバイス
> - ローカルデバイスは、0番を先頭にできるだけ詰めて使用してください。
> - RやDMはユニットに割り当てられるため、グローバルデバイスとして使用する領域が必要です。ローカルデバイスは、MRやEMを優先して使用してください。
> - 使用可能範囲外でローカルデバイス/グローバルデバイスを使用すると、変換エラーになります。
> - オペランドに先頭デバイスを指定する各命令語、インデックス修飾、間接指定を使用する場合は、ローカルデバイス/グローバルデバイスの使用可能範囲を超えないようにしてください。

(「リレー（R）…をローカルデバイスとして使用する場合は、使用個数を設定する必要があります」と、表の R ローカル予約個数「なし」は、初期値では R のローカル予約が0であることを示すと読める。原文ママ)

### ローカルデバイスの割付 (4-152 / 原本 p.250)

> ローカルデバイスは変換時、デバイスの種類ごとにあらかじめ用意されている予約領域に自動的に割り付けられます。

【図】ローカルデバイスの割付 (原本 p.250)

| デバイス領域(先頭→最後) | 内容 |
|---|---|
| 先頭側 | プロジェクト1のグローバルデバイス |
| ローカルデバイスの予約領域 | モジュールAのローカルデバイス ← (変換) プロジェクト1内 モジュールAのローカルデバイス |
| 〃 | モジュールBのローカルデバイス ← (変換) モジュールBのローカルデバイス |
| 〃 | マクロCのローカルデバイス ← (変換) マクロCのローカルデバイス |
| 〃(最後側) | 未使用 |

> **ポイント**
> ファンクションブロック、マクロの場合、プロジェクト内で呼び出す回数分のローカルデバイスを割り付けます。
> ファンクションブロックの種類がファンクションの場合、実体は常に1つになるため、複数回呼び出しても、1つ分のみのローカルデバイスを割り付けます。

> **参考**
> ローカルデバイスには、グローバルデバイスと同様にデバイスコメントを使用できます。

### 全体割付設定 (4-153 / 原本 p.251)

> プロジェクト内で使用するローカルデバイスの予約個数はあらかじめ設定されていますが、デバイスの種別ごとに変更可能です。また、変更した設定は《KV STUDIO》に保存されるため、プロジェクトを新規作成するたびに設定する必要はありません。
> [ワークスペース]上の[CPUシステム設定]を開いて、[ローカル全体割付設定]を選択します。

【図】CPUシステム設定 ローカル全体割付設定 画面 (原本 p.251 / スクリーンショットのため省略)

### プログラム別デバイス設定 (4-153 / 原本 p.251)

> プログラム別に使用するローカルデバイスの予約個数を、デバイスの種別ごとに設定できます。デフォルトは[自動]に設定されており、プログラム内で使用したローカルデバイスの個数が自動的に設定されますので、通常は意識する必要はありません。
> [ワークスペース]上の[CPUシステム設定]を開いて、[プログラム別デバイス設定]を選択します。

【図】CPUシステム設定 プログラム別デバイス設定 画面 (原本 p.251 / スクリーンショットのため省略)

> 自動設定にせず、手動で設定している場合のみエラーになる可能性があります。
> ［プログラム別ローカルデバイス設定］ダイアログの表記を確認してください。

例

【図】プログラム別割付: 設定範囲 @DM0～@DM1999 に対して、範囲外の @DM3000 を使用している状態がエラーとなる。

> ［ローカルデバイスの全体割付設定］ダイアログの［ローカルデバイス割付状況表示］で、使用個数などが赤色表記されているデバイスを確認してください。該当するデバイスの予約個数を増やすか、各プログラム別に設定されているローカルデバイスの個数を減らして、使用可能個数（ローカル予約個数）が使用個数より多くなるように設定してください。

## 4-11 割り込み (4-156〜4-175 / 原本 p.254-273)

### 概要 (4-156〜4-157 / 原本 p.254-255)

> 通常PLCは、入力処理→プログラムの実行→出力処理を繰り返すことで、ラダーシーケンスが進んでいきます。したがって、スキャンタイムより短い信号は入力できません。
> 割り込み処理機能を使えば、スキャンタイムに依存せずに、割り込みが発生した時点で処理ができます。
> 割り込みが発生すると、プログラム実行中でもその場で一旦処理を中断し、割り込み要因に応じた割り込みプログラムを実行します。割り込みプログラムが終了すると、中断していたプログラムの処理を再開します。

【図】割り込み処理の流れ (原本 p.254)

| 項目 | 内容 |
|---|---|
| スキャンタイム | 入力処理 → プログラム実行 → 出力処理 → (入力処理へ戻る) |
| 割り込み要因の発生 | プログラム実行中に割り込み要因が発生すると、割り込みプログラム実行へ移る |
| 復帰 | 割り込みプログラム終了後、割り込み発生の次の命令に戻る |
| 割り込みプログラム実行中 | ダイレクト入力機能・ダイレクト出力機能が使用可能(点線で接続) |

#### 割り込み要因の種類 (4-156 / 原本 p.254)

> プログラムにより設定できる割り込み要因には、拡張ユニットからの割り込み（64個まで）と定周期モジュール（4個まで）、ユニット間同期モジュールがあります。
> - → 「定周期モジュール」（4-83ページ）

#### デバイスの処理について (4-157 / 原本 p.255)

> 割り込み時のデバイスの処理は以下のとおりです。
> 入出力処理の詳細については、→ 「割り込み時の入出力処理」（4-162ページ）を参照してください。

【図】出力処理・入力処理 → メインルーチン … (①割り込み要因発生) … プログラム → 出力処理・入力処理。割り込み要因発生時点でメインルーチンプログラムを中断し、割り込みプログラム（出力処理）を実行して元の位置に戻る。

**①割り込みプログラムの開始時/終了時の処理**

> 割り込みプログラムの開始時に、内部レジスタ、演算フラグ、TM0～TM3、Z11～Z12の値をシステム内に記憶し、割り込みプログラム終了時に記憶した値に戻します。
> 割り込み中にこれらの値を変更してもメインルーチンプログラムには影響しません。変更した値は、割り込みプログラム中のみ有効になります。
> その他のデバイスは、割り込みプログラム中に変更した値が、割り込みプログラム終了後、メインルーチンプログラムに反映されます。

> **ポイント**
> インデックスレジスタZ1～Z10は、CPUシステム設定の「ユーザ割り込み設定」で退避/復帰処理をするように設定できます。

> **参考**
> 自動的にリフレッシュされないデバイス値を最新の状態に更新するには、以下のように処理してください。
> - 「DR」で入出力リレーを記述します。
> - 「RFSX/RFSY」命令を記述します。
>
> → 「ダイレクト処理について」（4-63ページ）

(図中では割り込みプログラムに「（出力処理）」と付記されているが、p.261 本文では「割り込みプログラムには出力処理がありません」とある。原文ママ・要確認)

#### 処理時間 (4-157 / 原本 p.255)

> 以下の条件をすべて満たす場合、割り込みプログラム開始までの時間は15µs以内（TYP.4µs）になります。
> - 〔CPUシステム設定〕の〔ユーザ割り込み設定〕で、「命令実行中に割り込み許可する」をチェックしている場合
> - その割り込みプログラムより優先度の高い割り込みプログラムを使用していない
> - KV-5000/3000シリーズ用拡張ユニットを使用していない（使用した場合は最大+14µs）
> - ユニット間同期の入力リフレッシュ、もしくは出力リフレッシュにて大量のデバイスをリフレッシュ対象にしていない
>
> なお、割り込みプログラムの起動/終了処理（各デバイスのリフレッシュ/退避/復帰）時間は合計2.5µsです。

> **参考**
> 割込み開始までの処理時間は上記のとおりですが、割り込みプログラムの先頭でKV-5000/3000シリーズ用拡張ユニットに対してダイレクト処理命令を実行した場合、処理完了までの時間がかかることがあります。
> - KL-N20V, KV-CL20, KV-DN20, KV-H20, KV-H20S, KV-H40S使用時：115µs
> - 上記以外のKV-5000/3000シリーズ用の拡張ユニット使用時：55µs

### 割り込みプログラムの実行方法 (4-158 / 原本 p.256)

> 以下のようにプログラムを記述することで、割り込み処理が可能になります。

割り込みプログラムの例 (図から書き起こし・ニモニックは本ファイル作成者による・要確認)

```
LD CR2008
EI
LD CR2008
IEDGE #1 #0 #1      ; ユニット番号#1(KV-SIR32XT) 入力番号#0 検出条件#1
  ～(メインルーチン)～
END
INT #1 #0           ; ユニット番号#1 割込要因#0
  ～(割り込みプログラム)～
RETI
ENDH
```

| 範囲 | 説明(原本の図中注記) |
|---|---|
| メインルーチンプログラム(先頭〜END) | EI命令を実行しないと割り込みプログラムは実行できません<br>※KV-SIR32XTの入力状態で割り込みを実施する場合は、IEDGE命令を使用して割り込み検出条件を設定します。 |
| 割り込みプログラム(INT〜RETI) | 割り込みプログラムは、「END」、「ENDH」間に記入します。 |

#### 割り込み許可（EI）命令 (4-158 / 原本 p.256)

> 運転開始時は、割り込みが禁止状態になっています。
> 割り込みプログラムを実行するには、割り込み許可（EI）命令を実行する必要があります。
> メインルーチンプログラム内に、EI命令を記述してください。

> **参考**
> - 割り込みを禁止する場合は、割り込み禁止（DI/DIC）命令を使用します。
> - 割り込み禁止時に割り込みが発生しても、次に割り込みを許可されるまで処理を保留します。
> - 割り込みプログラムの開始時は、割り込み許可状態です。
> - 割り込み許可（EI）命令を実行していない場合でも周辺処理実行によるシステム割り込みは実行されます。

> → 「EI命令」4-168ページ
> → 「DI命令」4-168ページ、「DIC命令」4-170ページ

#### INT/RETI命令 (4-158 / 原本 p.256)

> END/ENDH命令の間に、割り込み要因をオペランドにしてINT命令を記述します。
> INT命令の後に割り込み処理内容をプログラムして、最後にRETI命令を記述します。

> **ポイント**
> - 1つの割り込み要因に対してINT命令は1回のみ記述できます。
> - 割り込みプログラム内では、使用できない命令語があります。<br>→ 「割り込みプログラムで使用できない命令語」（4-160ページ）を参照してください。
> - KV-SIR32XTを使用して割り込み実行時に、割り込み応答を高速にする場合は、ユニットエディタの設定で入力時定数を小さく設定してください（初期値：10µs）。

> → 「INT/RETI命令」（4-172ページ）

### 割り込みの優先度 (4-159 / 原本 p.257)

> 複数の割り込み要因が同時に発生した場合の優先度を設定できます。
> 《KV STUDIO》のワークスペースから[CPUシステム設定]を開いて、[プログラムの設定]の[定周期実行とユーザ割り込み設定]で設定します。

【図】CPUシステム設定 定周期実行とユーザ割り込み設定 画面 (原本 p.257)

| 画面内の項目 | 画面の表示例 |
|---|---|
| 定周期／ユニット間同期モジュールの設定 (モジュール名 / 周期 / 単位 / 運転開始時に実行状態にする) | Interrupt / 0.05 / ms / ✓<br>Sampling / 10.00 / s / ✓ |
| 割り込み優先度の設定 (項目 / 割込要因 / 優先度) | Interrupt / (空欄) / 高<br>Sampling / (空欄) / 中 |
| チェックボックス | ☑ 命令実行中に割り込み許可する(N)<br>☐ 割り込みプログラム起動時にZ1～Z10を退避し、完了時に復元する(Z) |

> 優先度は「高/中/低」で設定できます。割り込みプログラム実行中は、自身より高い優先度の割り込みは受け付けますが、同じか低い優先度の割り込みは実行中の割り込みプログラムが終了するまで保留されます。
> また、「命令実行中に割り込み許可する」にチェックを付けると、処理時間の長い命令語の実行途中に割り込めるため、割り込み応答時間のばらつきを抑制できます。
> 割り込みプログラム実行中に別の割り込みが発生した場合、優先度の設定により動作が異なります。以下の表を参考にしてください。

| 実行中割り込みプログラム（A）の優先度 | 発生した割り込みプログラム（B）の優先度: 高 | 中 | 低 |
|---|---|---|---|
| 高 | 保留 | 保留 | 保留 |
| 中 | 即実行 | 保留 | 保留 |
| 低 | 即実行 | 即実行 | 保留 |

> 保留　：現在実行中の割り込みプログラム（A）終了後に、発生した割り込みプログラム（B）を実行します。
> 即実行：現在実行中の割り込みプログラム（A）を中断し、発生した割り込みプログラム（B）を実行します。
> 　　　　割り込みプログラム（B）の実行が終了した後、割り込みプログラム（A）が再開します。

### 割り込み時の入出力処理 (4-162〜4-163 / 原本 p.260-261)

#### 入力処理 (4-162 / 原本 p.260)

> 割り込みプログラム開始時、そのスキャンの入力処理（I/Oリフレッシュ）で取得した状態です。
> 割り込みプログラム内で、その時点の入力リレーの状態を取得するため、DRでリレー番号を指定する、またはダイレクトリフレッシュ命令（RFSX命令）を使用してリフレッシュを行う必要があります。

例 【図】タイミングチャート (原本 p.260)

| 時点 | R30000 | R30001 | R30002 | 備考 |
|---|---|---|---|---|
| 入力処理(1回目) | OFF | OFF | OFF | 取り込み値 R30001:OFF / R30002:OFF |
| メインルーチン実行中 | OFF | OFF→ON | OFF→ON | R30001・R30002 は入力処理後に ON |
| 割り込み要因発生 | OFF→ON | ON | ON | R30000 の立ち上がりで割り込みプログラム実行 |
| 入力処理(2回目) | ON | ON | ON | 取り込み値 R30001:ON / R30002:ON |

| ラダー上の接点 | メインルーチン(割り込み前) | 割り込みプログラム内 | メインルーチン(割り込み後) | 次スキャン |
|---|---|---|---|---|
| R30001 / DR30001 | R30001: OFF | DR30001: ON | DR30001: ON | R30001: ON |
| R30002 | OFF | OFF | OFF | ON |

> 上記のような割り込みプログラムが実行されると、
> ①メインルーチンプログラムの入力処理　→ R30001 : OFF　　R30002 : OFF
> ②割り込みプログラムの入力処理　　　　→ R30001 : ON　　 R30002 : OFF
> になります。
> 入力リレーDR30001はダイレクト入力なので、割り込みプログラム実行時の状態が取り込めます。
> 入力リレーR30002は割り込みプログラム中でも、メインルーチンプログラムの入力処理の状態で扱われます。
> メインルーチンプログラムでは割り込みプログラム内でダイレクトリフレッシュをしているので、割り込みプログラム内の状態（ON）になります。

#### 出力処理 (4-163 / 原本 p.261)

> 割り込みプログラムには出力処理がありません。割り込みプログラム終了後、メインルーチンプログラムの出力処理（自動リフレッシュ）で外部に出力します。
> ただし、出力リレーをDRと記述すると（DR30200など）、プログラムが実行されると、直ちに外部に出力されます。（ダイレクト出力）

例 (図から書き起こし・ニモニックは本ファイル作成者による・要確認)

```
LD CR2002        ; ①
SET DR30200
LD CR2002        ; ②
SET R30201
```

【図】割り込みプログラム①の実行時点で R30200:出力、②の R30201 は割り込みプログラム内では出力されず、次の出力処理で R30201:出力。

> 上記のような割り込みプログラムが実行されると、
> - ①行目で、出力リレーDR30200はダイレクト出力リレーなので、直ちに外部に出力します。
> - ②行目で、出力リレーR30201は内部処理ではONしますが、ダイレクト出力リレーではないのでメインルーチンプログラムの出力処理で外部に出力されます。

例

> **割り込みプログラム内でダイレクト出力したい場合は、出力リレーにDRを使用してください。**

> **参考**
> 自動的にリフレッシュされないデバイス値を最新の状態に更新するには、以下のように処理してください。
> - 「DR」で入出力リレーを記述します。
> - 「RFSX/RFSY」命令を記述します。
> - 「UREAD/UWRIT」命令などダイレクトリフレッシュ命令を記述します。
> - ユニット専用命令を記述します。
>
> → 「ダイレクト処理について」（4-63ページ）

(図中の①部分には「R30200:出力」、②部分には「R30201:出力」と付記されている。本文では②R30201は割り込み中には出力されないとあるため、図の②の付記は内部処理を示すものと思われる。原文ママ・要確認)

### サンプルプログラム (4-164〜4-166 / 原本 p.262-264)

#### 信号変換器を使用した割り込みの応用例 (4-164 / 原本 p.262)

> 割り込み処理を使用した微小パルスを一定の幅のパルスに変換して出力します。
> - 入力リレーR30000で入力した微小パルスを、出力リレーR30200からON幅1秒のパルスに変換します。
> - 入力リレーR30000の立ち上がりから1秒間、出力リレーR30200がONします。

【図】タイミングチャート: 入力リレーR30000 の微小パルス(スキャン周期より短い)の立ち上がりごとに、出力リレーR30200 が1秒間 ON する(3回分図示)。

```

EI
LD CR2008
IEDGE #1 #0 #0
LD R30200
MPS
TMR #0 #10
MPP
AND T0
RES R30200
END
INT #1 #0
LD CR2002
SET DR30200
RETI
ENDH
```
