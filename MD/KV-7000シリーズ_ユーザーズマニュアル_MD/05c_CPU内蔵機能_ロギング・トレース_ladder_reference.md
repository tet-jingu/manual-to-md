## 5-4 ロギング・トレース (5-50〜5-76 / 原本 p.372-398)

### ロギング機能/トレース機能の概要 (5-50〜5-51 / 原本 p.372-373)

#### ロギング機能 (5-50 / 原本 p.372)

> 《KV-7500/7300》のロギング機能は、指定したデバイスの状態や値を任意のタイミング（トリガ）で取り込みます。取り込んだデータは、CSVファイル形式でメモリカードまたはCPUメモリ(ユーザメモリ）に自動保存されます。取り込むデバイスやトリガなどは《KV STUDIO》で簡単に設定できます。
> ロギング･トレースデータはCSV形式で保存されるため、Microsoft Excelなどの表計算ソフトでそのまま使用できます。CSV形式で保存されたデータは以下の方法で読み出せます。
> - メモリカードを抜き出してパソコンで読み出す
> - ストレージ転送ツールや、FTP機能を使用してPLC経由で読み出す
> - リアルタイムチャートモニタを使用して読み出す

【図】KV-7500/7300 の PLCデバイスデータ →(ロギング)→ メモリカード(→「メモリカード」（5-4ページ）) / CPUメモリ(→「CPUメモリ（ユーザメモリ）」（5-27ページ）) →(読み出し)→ パソコン(Microsoft Excelなど)

**ロギングのタイムチャート** (原本 p.372 の図を表化)

| 信号 | ロギング開始(LOGE命令実行) | ロギング中 | ロギング終了(LOGD命令実行) |
|---|---|---|---|
| ロギング開始 LOGE命令実行 | パルス | | |
| ロギングトリガ | | パルスが繰り返し発生 | |
| 実行リレー | OFF→ON | ON | ON→OFF |
| 動作中リレー | OFF→ON | ON | ON→OFF |
| 任意ロギング動作中リレー | OFF→ON | ON | ON→OFF |
| メモリカード使用中リレー | OFF→ON(ファイルオープン) | ON | ON→OFF(ファイルクローズ) |
| ロギング終了 LOGD命令実行 | | | パルス |

- ※オプション設定により各リレーの挙動は変わります。

> **参考**
> - ファイルが存在しない状態でロギング･トレースを開始すると自動でファイルを新規作成します。
> - ロギング･トレース機能とストレージ命令は同時使用可能です。優先順位はストレージ命令 > ロギング･トレース機能となります。

#### トレース機能 (5-51 / 原本 p.373)

> ロギング機能と同様にデバイスの状態や値をバッファメモリ上に記憶します。ファイル保存のタイミングで、その前後の指定したデータ数のみを抽出してメモリカードやCPUメモリ（ユーザメモリ）、または内部メモリに記録します。
> 例えば、装置の異常時にファイル保存するようにトリガ設定すると、異常発生前後のみのデータが自動保存されるので、異常解析に役立ちます。

【図】トレースの仕組み (原本 p.373): SRAM のバッファに「日付 時刻 DM11 DM12 DM13」の行を常時ロギング(時間の経過とともに下へ)。「ファイル保存トリガ」発生位置の前後(トリガ前データ／トリガ後データ)を抽出し、メモリカード(CSVファイルとして自動保存)、CPUメモリ（ユーザメモリ）(「CVSファイルとして自動保存」)、内部メモリ(※データのみ記録)へ保存。

(図中「CVSファイル」は原文ママ。CSV の誤植)

> **参考**
> ファイル保存先を「内部メモリ」にして保存したデータは、《KV STUDIO》の「リアルタイムチャートモニタ」上に読み出すことができます。

|---|---|---|---|---|---|---|
| トレース開始 LOGE命令実行 | パルス | | | | | |
| ロギングトリガ | | パルス繰り返し | パルス繰り返し | パルス繰り返し | | |
| 実行リレー | OFF→ON | ON | ON | ON | ON | ON→OFF |
| 動作中リレー | OFF→ON | ON | ON | ON | ON | ON→OFF |
| ファイル書き込み完了 | OFF | OFF | OFF | OFF | OFF | OFF→ON |
| ファイル保存トリガ | | | パルス | | | |
| ファイル保存トリガモニタ | OFF | OFF | OFF→ON | ON | ON | ON |
| データ取得完了 | OFF | OFF | OFF | OFF | OFF→ON | ON |
| トレース終了 LOGD命令実行 | | | | | | パルス |

(トリガ前データはファイル保存トリガ以前、トリガ後データはファイル保存トリガ以降の範囲として図示)

> **ポイント**
> トレース機能で取得したデータをメモリカードに保存する場合はデータ取得完了をトリガにしてLOGD命令を実行してください。
> データ取得完了前にLOGD命令を実行してもファイルは生成されません。

### 設定 (5-53〜5-62 / 原本 p.375-384)

> ロギング･トレース機能を使用するための設定は《KV STUDIO》でおこないます。
> ロギング･トレース機能を使用するには、以下の設定が必要です。
> - データ保存先
> - 保存するファイル名の設定
> - 機能（ロギング/トレース）の選択
> - ロギング･トレースするデバイスの設定
> - トリガの設定
> - オプション設定
> - トレース詳細設定（トレース機能選択時のみ）
>
> ロギング･トレース機能は最大10個まで作成でき、ロギング/トレースID（0～9）で区別します。
> ロギング/トレースIDごとにファイル名、デバイス、トリガ設定します。

#### ファイル名 (5-55〜5-56 / 原本 p.377-378)

> 保存するファイルに関する設定をおこないます。
> ロギング･トレースIDごとに保存するフォルダ名が決められています。（LOG0～LOG9）

> **参考**
> データ保存先が「内部メモリ」の場合、「ファイル名」の各項目は設定できません。

【図】〔ロギング/トレース設定 (ID:0)〕［ファイル名］タブ (画面例: ファイル番号 自動連番、番号上限 99、開始時の動作 ファイル新規作成、空き番号がない場合 古いファイルから上書き、ファイルパスプレビュー LOG0¥LOG000。注意書き「本体ではロギングIDとファイル番号でファイルを識別します。(ファイル番号までが同じであれば同一ファイルとして扱われます。)」)

```
        │        ├─ LOG001_FGHIJ0706271820.csv
        │        └─ LOG002_FGHIJ0706271920.csv
        │           :
        ├─ LOG2
        │  :
        └─ LOG9
```

> 　命令実行後、IDごとのロギング･トレース実行リレーがリセットされ、ロギング･トレースが停止します。それまでのロギング内容がメモリカードまたはCPUメモリに出力されます。

#### 各デバイスの詳細 (5-71〜5-73 / 原本 p.393-395)

**ロギング･トレース実行リレー**

> ロギング･トレース実行の許可、禁止を行います。ロギング･トレース命令（LOGE）実行時、またはKV STUDIOでロギング･トレースを開始時にセットされますので、通常は直接操作する必要はありません。
> このリレーがONすると、同じロギング/トレースIDのすべての状態リレーを一度OFFします。
> エラーが発生した場合、リセットします。

**ロギング･トレース動作中リレー**

> 実際にロギング･トレースが実行している間ONします。

**ロギング･トレースファイル書き込み完了リレー**

> ロギング使用時 : ファイル毎に指定したファイル容量上限値のデータを書き終えたときにONします。
> トレース使用時 : ファイルまたは内部メモリにデータを書き終えたときにONします。
> このリレーがONした場合ロギング･トレースは終了し、ロギング･トレース実行リレーがOFFします。
> ロギング･トレースファイル書き込み完了リレーは、次回のLOGE命令実行時にOFFします。
> → 「ファイル容量上限設定オーバー時の処理について」（5-76ページ）

(デバイス一覧(p.392)では名称「ロギング･トレースファイル書き込み終了」。原文ママ)

**ロギングバッファ50%未満警告リレー**

> トリガ発生の頻度がファイル書き込み速度よりも速いために、バッファの空き容量が50%未満になったときにONします。ファイル毎に指定したファイル容量上限値のデータを書き終えたときにONします。

(後半の「ファイル毎に指定したファイル容量上限値のデータを書き終えたときにONします。」は、直前のファイル書き込み完了リレーの説明と同文。混入と思われる。原文ママ・要確認)

**バッファオーバーフローリレー**

> メモリカードまたはCPUメモリへのデータの書き込みが追いつかず、ロギング･トレース用のバッファがオーバーフローしたことを示します。
> このリレーがONしたときは、データの取りこぼしが発生しています。データ番号を見れば、いつデータを取りこぼしたか確認できます。
> オーバーフローが発生しても、メモリカードへの書き込みは継続されます。
> バッファオーバーフローが発生するときは、
> - メモリカードまたはCPUメモリへのアクセスを減らす
> - データ量やトリガの頻度を下げる
> - スキャンタイムを長くすることで軽減できます。

**ロギング･トレース実行中RUN中書込みありリレー**

> ロギング･トレース実行中にRUN中書き込みがあったときONします。
> RUN中書き込み時、ロギング･トレースは動作を続けますが、メモリカードまたはCPUメモリへの書き込みが遅くなるため、バッファオーバーフローが発生しやすくなります。

**ロギング･トレースエラーリレー**

> ロギング･トレースが、メモリカードのエラーで終了したとき、ONしロギング･トレースは終了します。
> 各種エラーリレーがONしていないか確認してください。このときバッファに残っているデータは無くなります。エラークリアは次回の「LOGE命令」実行時に行われます。

**メモリ容量なしエラーリレー** (5-72 / 原本 p.394)

> メモリカードまたはCPUメモリに十分な空き容量がないときにONします。
> このリレーがONしたときは、ロギング･トレースは終了します。ロギング･トレースエラーリレーがONし、ロギング･トレース実行リレーがOFFします。このときバッファに残っているデータは無くなり、ロギングファイルは作成されません。エラークリアは次回の「LOGE命令」で行われます。

**デバイス･トリガ設定異常リレー**

> ロギング･トレースのデバイス設定、トリガ設定、その他設定が異常な場合にONします。
> このリレーがONしたときは、ロギング･トレースが終了します。ロギング･トレースエラーリレーがONし、ロギング･トレース実行リレーがOFFします。

**トレースファイル保存トリガモニタリレー**

> トレース機能使用時に、ファイル保存トリガが発生するとONします。
> 次回のLOGE命令実行時にOFFします。

**トレースデータ取得完了リレー**

> トレース機能使用時に、ファイル保存トリガ後データ量で設定されたデータ量を取得し終わるとONします。
> 次回のLOGE命令実行時にOFFします。

**バッファ空き容量（Kbyte単位）**

> 現在のバッファの空き容量がKbyte単位で格納されています。KV-7000シリーズのバッファ容量は2048Kbyteです。
> ロギング使用時 : バッファの余裕度合いが把握できます。値が小さくなると、バッファオーバーフローが発生する可能性が高くなります。
> トレース使用時 : ファイル保存トリガ発生前は、バッファ全体の容量を表します。ファイル保存トリガ発生後は、トレース完了までに取得する残りのデータ量を表します。

**ファイル保存カウンタ**

> ファイル保存が実行される度に1ずつインクリメントします。
> 0～65535の範囲でカウントされ、65535の次は0になります。電源断時も保存されます。
> ファイル保存カウンタをリセットする場合は0を格納してください。LOGE命令実行時に自動的に0になりません。

> **ポイント**
> CPUシステムプログラムバージョン2.1以前では、0を書きこんでもリセットされません。

**任意ロギング･トレース動作中リレー**

> ロギング･トレースID0～9のいずれか1つ以上のロギング･トレースが、メモリカードに対して動作しているときONします。
> 他の機能を使用するときに、メモリカードへのロギング･トレースが動作しているかどうか確認するために用います。

**メモリカード使用中リレー** (5-73 / 原本 p.395)

> メモリカードを使用しているときにONします。ロギング･トレース機能に限らず何らかの機能がメモリカードを使用している間ONします。

**メモリカード認識完了リレー**

> メモリカードが挿入され、メモリカードスロットカバーが閉まっており、かつ初期化が完了し利用可能な状態になっているときにONします。

**メモリカードありリレー**

> メモリカードが挿入されており、かつメモリカードスロットカバーが閉まっている場合にONします。

**メモリカードライトプロテクトリレー**

> メモリカードが挿入されており、かつライトプロテクトがかかっている場合にONします。

**ストレージアクセス中電源OFF**

> ストレージアクセス中に電源がOFFするとエラーになり、0以外の値が格納されます。
> 値は自動的にクリアされません。

**内部バッファオーバーフローリレー**

> 内部で使用しているバッファ領域がオーバーフローした場合にONします。ロギング･トレース･リアルタイムチャートモニタ機能使用時に、大量のデバイスを高頻度で収集した場合などにONします。
> 収集しているデバイス数、またはサンプリング頻度を減らすことで軽減できます。

### ロギング･トレース機能の注意事項 (5-74〜5-76 / 原本 p.396-398)

> ロギング･トレース機能を使用する上での注意事項を以下に示します。
> → 「KV-7500/7300で使用する」（5-8ページ）、 → 「使用上の注意事項」（5-9ページ）もあわせてお読みください。

#### 保存速度 (5-74 / 原本 p.396)

> - ロギング･トレース実行時のスキャンタイムは、最大で20µs×使用しているIDの数まで延びます。
> - 複数のトリガが同時に発生する場合、メモリカードやCPUメモリに対するアクセス量が多くなるためスキャンタイムが延びたり、バッファオーバーフローが発生しやすくなります。

#### ストレージへのアクセスの優先順位 (5-74 / 原本 p.396)

> - ロギング･トレース中、ストレージへのアクセスの優先順位は、以下の通りです。<br>ストレージ命令 ＞ ロギング･トレース命令 ＞ FTPサーバ機能、FTPクライアント機能、アクセスウィンドウのファイル操作<br>このため、ロギング･トレースのトリガが大量に発生している場合、他の機能がストレージを使用できないことがあります。

#### 電源断、カード抜き差し (5-74 / 原本 p.396)

> メモリカードは、本体の電源をONしたまま、メモリカードアンマウント要求リレーをONし、メモリカード認識完了リレーがOFFになるのを確認して取り出してください。ロギング･トレース実行時は、この手順でメモリカードを取り出さないとデータが保存されません。

**メモリカードスロットカバーの扱い**

> - メモリカードスロットカバーが閉まっていないときは、ロギング･トレースは開始されません。
> - メモリカードスロットカバーを開くと、実行中の処理は継続されますが、それ以後の処理はメモリカードの処理を受け付けません。

**電源断時、カードの抜き差しの注意**

> - メモリカードアクセス中LEDが点灯中（カードへのデータの読み込み･書き込み）は、絶対にカードを抜いたり、本体の電源を切らないでください。カード内のデータが破壊されることがあります。
> - ロギング･トレース実行中に電源がOFFした場合、データはメモリカードに保存されません。
> - CPUメモリアンマウント要求リレーONし、CPUメモリ認識完了リレーがOFFするのを待って電源をOFFしてください。アンマウントとは、メモリカードを安全に取り外し可能な状態にすることです。
> - RAMモードで使用している場合、必要なデータは電源断を実行する前にCPUメモリ保存要求リレーをONし、CPUメモリ保存完了リレーがONになったのを確認して電源をOFFしてください。

**カードの交換**

> - カード交換は、必ず手順にそって行ってください。<br>→ 「KV-7500/7300で使用する」（5-8ページ）
> - 《KV STUDIO》のロギング･トレース設定で「メモリカード挿入によるロギング･トレース自動再開」を設定すると、ロギング･トレース実行中にメモリカードを抜いた場合、次回メモリカードを挿入するまで本体バッファにロギング･トレースデータを蓄積し、メモリカードが挿入されると、蓄積していたデータをメモリカードに書き込みます。このとき、ロギング･トレースエラーリレーはONしません。メモリカード挿入までの時間が長かったり、トリガ発生回数が多かったりすると、バッファオーバーフローが発生してデータが欠落することがあります。<br>「メモリカード挿入によるロギング･トレース自動再開」を設定していない場合、ロギング･トレース実行中にメモリカードを絶対に抜かないでください。カード内のデータが破壊されることがあります。

> **参考**
> データの取りこぼしが発生する場合に、一定スキャンタイム運転やEND処理時間の設定を使用して改善することができます。
> → 「一定スキャンタイム運転」（4-70ページ）
> → 「END処理時間の設定」（4-72ページ）

#### RUN中書き換え中の動作 (5-75 / 原本 p.397)

> - RUN中書換えを行っているとき、ロギング･トレースの実行が非常に遅くなります。このため、バッファオーバーフローが発生しやすくなります。
> - ロギング･トレース設定をRUN中書き込みできますが、設定が有効になるのは次回ロギング･トレース動作開始時です。

#### RUN/PRGモード切換時の動作 (5-75 / 原本 p.397)

> - ロギング･トレース機能はRUN状態のときのみ動作します。RUN→PRG切換を行うとすべてのロギング･トレースが停止します。<br>LOGD命令が実行された場合と同様、それまでのロギング･トレース内容がメモリカード（またはCPUメモリ）に出力されます。<br>また、PRG→RUN切換したときには、ロギング･トレースはすべて停止状態なので、開始するためにLOGE命令を実行する必要があります。

#### ロギング･トレース開始時の処理について (5-75 / 原本 p.397)

> 電源を投入してロギング･トレース許可されたとき、指定されたファイル番号がすでに存在していると次のような動作になります。

**ファイル番号の指定方法が「自動連番」のとき**

> - 「ファイル新規作成」で空き番号が無い場合の動作は「ファイル容量上限設定オーバー時の処理について」を参照してください
> - 「最新のファイルに追記」で最新のファイルがファイル容量上限設定で設定した上限値を超えた場合 :<br>次の空き番号のファイルを使用します。空き番号が無い場合の動作は「ファイル容量上限設定オーバー時の処理について」を参照してください。<br>ファイル容量上限設定をしていない場合は追記し続けます。
>
> 「ファイル容量上限設定オーバー時の処理について」は次ページを参照してください。

**ファイル番号の指定方法が「固定/デバイス値」のとき**

> - 「同一ファイル存在時」に「古いファイルを上書き」を選択している場合 :<br>古いデータを削除し、同一ファイル名で上書きします。
> - 「同一ファイル存在時」に「追記」を選択している場合 :<br>指定されたファイルにデータを追記します。存在するファイルがすでにファイル容量上限設定で設定した上限値を超えているときにロギング･トレースを開始すると、ロギング･トレースエラーリレーがONし、ロギング･トレースを停止します。
>
> → 「ロギング･トレース用デバイス一覧」（5-70ページ）

#### ファイル容量上限設定オーバー時の処理について (5-76 / 原本 p.398)

> ファイル容量の上限値を超えたときの動作は、ファイル番号の指定方法によって異なります。
> ファイル容量上限値設定については、→ 「オプション」（5-59ページ）参照

**ファイル番号の指定方法が「自動連番」のとき**

> ファイル番号に空きがある場合は、次のファイル番号で新たなファイルを作成します。
> ファイル番号がすべて使用済みの状態で、最後のファイルが容量オーバーしたとき
> - 「空き番号がない場合」に「古いファイルから上書き」を選択している場合 :<br>最も古いデータを削除し、同一ファイル番号でファイルを新規作成します。
> - 「空き番号がない場合」に「ロギング･トレース停止」を選択している場合 :<br>ロギング･トレース開始時にロギング･トレースエラーリレーがONし、ロギング･トレースを停止します。

**ファイル番号の指定方法が「固定/デバイス」のとき**

> 「同一ファイル存在時」に「古いファイルを上書き/追記」どちらを選択している場合も、ロギング･トレースを停止します。

> **参考**
> FTPクライアント機能で「ロギング/トレース転送設定」を設定している場合、LOGD命令を実行していなくても、ファイル容量上限設定オーバーで生成されたファイルは都度FTPアップロードされます。
