## 4-1 シーケンス制御とは (4-2〜4-4 / 原本 p.100-102)

> 下図のような自動車の組立工程では、機械や装置の各動作、順序および条件を制御装置にあらかじめ記憶させておきます。運転を開始すると、機械や装置の状態・条件に従って一連の目的動作が順次実行され、自動車が組み立てられていきます。このような制御をシーケンス制御と呼びます。
> シーケンス制御のための装置に、《KV-7000シリーズ》のようなPLC（Programable Logic Controller）が使われます。

【図】＜自動車工場の車体組立工程＞のイラスト (4-2 / 原本 p.100)

> **参考**
> - JIS（日本工業規格）には、「シーケンス制御とは、あらかじめ定められた順序、または、一定の論理によって定められた順序に従って制御の各段階を逐次進めていく制御」と定義されています。
> - PLCの制御には、シーケンス制御の他にフィードバック制御があります。
>   フィードバック制御は、対象から検出した現在値と目標値を比較した結果が一致するまで制御を繰り返します。
>   （例）温度制御、圧力制御、速度制御

(「Programable」は原文ママ)

### シーケンス制御の例 (4-3 / 原本 p.101)

> シーケンス制御について、全自動洗濯機を例にして具体的に見てみましょう。
> 全自動洗濯機はスタートボタンを押すと、あらかじめ定められた順序に従って、洗濯工程が自動的に進行していきます。この洗濯工程の制御は、次のようになります。

【図】全自動洗濯機の工程フロー (4-3 / 原本 p.101)。開始 → 給水Ⅰ → 洗濯 → 排水Ⅰ → 脱水Ⅰ → 給水Ⅱ → すすぎ → 排水Ⅱ → 脱水Ⅱ → 完了。洗濯・脱水Ⅰ・すすぎ・脱水Ⅱ の各工程で「蓋が開いたら」→ 一時停止(カチッ)、「蓋が閉じたら」→ 元の工程へ戻る。

| 工程 | 説明 |
|---|---|
| 開始 | ①洗濯物を投入し、スタートボタンを押します。 |
| 給水Ⅰ | ②スタートボタンが押されたら、洗剤を投入して給水バルブを開けます。 |
| 洗濯 | ③規定の給水量（水位）へ達したことを検出したら、給水バルブを閉じて洗濯用モータを起動します。 |
| 排水Ⅰ | ④規定の時間が経過したら、洗濯用モータを止めて排水バルブを開けます。 |
| 脱水Ⅰ | ⑤排水完了（水位が0）を検出したら、排水バルブを閉じて脱水用モータを起動します。 |
| 給水Ⅱ | ⑥規定の時間が経過したことを検出したら、脱水用モータを止めて給水バルブを開けます。 |
| すすぎ | ⑦規定の給水量（水位）へ達したことを検出したら、給水バルブを閉じて洗濯用モータを起動します。 |
| 排水Ⅱ | ⑧規定の時間が経過したことを検出したら、洗濯用モータを止めて排水バルブを開けます。 |
| 脱水Ⅱ | ⑨排水完了（水位が0）を検出したら、排水バルブを閉じて脱水用モータを起動します。 |
| 完了 | ⑩規定の時間が経過したことを検出したら、脱水用モータを止めます。<br>洗濯完了を表示して、音で通知します。 |

### シーケンス制御の種類 (4-4 / 原本 p.102)

> 基本的なシーケンス制御は、主に「順序制御」「条件制御」「時限制御」の3種類に分けられます。これらの制御を組み合わせて、目的とする制御回路を設計します。

#### 順序制御 (4-4 / 原本 p.102)

> 順序制御は、検出器など、外部からの信号によって動作終了を確認し、あらかじめ定められた順序に従って、次の動作を開始する制御です。
> 〔全自動洗濯機のシーケンス制御における順序制御〕
> 「②給水Ⅰ」→給水が完了→「③洗濯（洗濯用モータの起動）」
> 「④排水Ⅰ」→排水が完了→「⑤脱水Ⅰ（脱水用モータの起動）」

> **参考**
> 順序制御で使用する代表的なラダー命令語・・・「STG」「JMP」など

#### 条件制御 (4-4 / 原本 p.102)

> 条件制御は、制御対象の状態信号を組み合わせて、あらかじめ定められた条件が満足された時に動作させる制御です。
> 〔全自動洗濯機のシーケンス制御における条件制御〕
> 「③洗濯」→洗濯槽の蓋が開けられたら→「一時停止」→蓋が閉じられたら→「③洗濯」
> 「⑤脱水Ⅰ」→洗濯槽の蓋が開けられたら→「一時停止」→蓋が閉じられたら→「⑤脱水Ⅰ」

> **参考**
> 条件制御で使用する代表的なラダー命令語・・・「STP」「STE」「CJ」「NCJ」「LABEL」など

#### 時限制御 (4-4 / 原本 p.102)

> 時限制御は、制御対象への動作指令がタイマなどを使った時間経過や時刻によって終了し、あらかじめ定められた順序に従って、次の動作を開始する制御です。
> 〔全自動洗濯機のシーケンス制御における時限制御〕
> 「③洗濯」→規定時間の経過を検出→「④排水Ⅰ」
> 「⑤脱水Ⅰ」→規定時間の経過を検出→「⑥給水Ⅱ」

> **参考**
> 時限制御で使用する代表的なラダー命令語・・・「TMR」「LDWK」など

## 4-2 プログラミング言語 (4-5〜4-8 / 原本 p.103-106)

> 《KV STUDIO》では、「ラダープログラム」と「KVスクリプト」を使用してプログラムを作成できます。
> 作成したプログラムを《KV-7000シリーズ》で動作させるための言語として、「ニモニック」が使用されます。また、16ビット/32ビットや符号付き/符号なしなどは命令語ではなく、サフィックスを使用して使い分けます。

### ラダープログラム (4-5 / 原本 p.103)

> ラダー回路とは、実体配線図を図式化したもので、《KV STUDIO》で書かれたラダー回路をラダープログラムといいます。
> 《KV STUDIO》では、汎用のスイッチやランプの他に、ON時間、OFF時間を制御する便利な命令語や、PID制御なども命令語として用意しており、組み合わせて記述することで、シーケンス制御を簡単に記述できます。

【図】ラダー回路の例 (4-5 / 原本 p.103)。図から書き起こし(タイマの設定値は図に記載なし):

```
LD   R000
OUT  T1        (タイマ T1。設定値は図に表示なし)
LD   T1
AND  R001
OUT  R500
LD   T1
AND  R002
OUT  T2        (タイマ T2。設定値は図に表示なし)
LD   T2
AND  R003
OUT  R501
```

> さらに、《KV STUDIO》では、拡張ラダーモードが使用でき、ラダーの行数を削減したり、処理順序を明確にしたりできるので、視認性が向上できます。
> → 「拡張ラダーモード」（4-206ページ）

> 補足(本ファイル作成者): 図のタイマは「T1」「T2」のコイル記号(`―| T1 |―`)のみで、命令語(TMR 等)と設定値は描かれていない。上のニモニックは構造を示すための書き起こしで、そのまま《KV STUDIO》に入力できる形ではない(要確認 原本 p.103)。

### KVスクリプト (4-6 / 原本 p.104)

> ラダープログラムは、シーケンス制御の記述に適している一方、数値を扱う複雑な演算処理や文字列を扱う処理については、記述が複雑になり、デバッグやメンテナンスも困難になりがちです。
> KVスクリプトは、これらラダープログラムの問題点を補うために開発されたプログラミング言語です。ラダープログラムでは記述が複雑になる部分をスクリプトで代替記述して、効率よくプログラムを作成できます。
> → 『KV-8000/7000/5000/3000/1000シリーズ・KV Nanoシリーズ スクリプトプログラミングマニュアル』

【図】KVスクリプトの画面例 (4-6 / 原本 p.104)。吹き出し:
- 制御文が記述できるのでプログラムの流れがわかりやすくなります。
- 演算処理も内部レジスタを意識しなくても数学式のように記述できます。
- ラダーと混在でき、スクリプトの行ごとにコメントが記述できます。

> **ポイント**
> スクリプトプログラムはラダープログラムに変換されてから実行されます。
> スクリプトプログラムの動作確認などは、変換されたラダープログラムでモニタする事ができます。

### ニモニック (4-7 / 原本 p.105)

> ニモニックは、作成したラダープログラムを《KV-7000シリーズ》で動作させるための言語です。
> 拡張ラダーは、ニモニックをシンボル化することによって、視覚的にわかりやすく表現したものです。
> 拡張ラダーで作成したプログラムは、《KV-7000シリーズ》への転送時にニモニックリストへ変換されます。
> ニモニックリストは《KV STUDIO》上で編集できますが、通常のラダープログラム作成時に意識する必要はありません。

【図】ラダーとニモニックリストの対応例 (4-7 / 原本 p.105):

```
LD   R000
OUT  R500
LD   R002
OUT  R501
LD   R003
OUT  R502
```

> **参考**
> - ニモニックリストを編集するには、メニューから【編集（E）】→【リスト編集（L）】を選択します。
>   別手順: Ctrl ＋ D
> - 本マニュアル内では、CPU 内蔵機能や命令語のサンプルプログラムにニモニックリストを記載しています。このニモニックリストを使用すると、サンプルプログラムを簡単に入力できます。
>   → 「ニモニックリストの使い方」（17ページ）
> - 拡張ラダーでプログラムを作成する時に、各命令をニモニックで入力することでプログラム作成工数を短縮できます。
>   → 「ニモニック入力」4-188ページ

### サフィックス (4-8 / 原本 p.106)

> サフィックスとは命令語やデバイスの接尾語としてつくもので、使用すると、デバイスのデータ型の扱いを変更できます。以下の6種類があります。

□.U　□.S　□.D　□.L　□.F　□.DF

- ※ □にはサフィックス対応の命令語が入ります。

> **例**
> ADD（.U）　MOV.（U）
> ADD.S　　MOV.S
> ADD.D　　MOV.D
> ADD.L　　MOV.L
> ADD.F　　MOV.F
> ADD.DF　 MOV.DF

(「MOV.（U）」は原文ママ)

| サフィックス | 扱い | 範囲 |
|---|---|---|
| □.U | 16ビット符号無しBINデータとして扱います。 | （0～65535） |
| □.S | 16ビット符号付きBINデータとして扱います。 | （－32768～＋32767） |
| □.D | 32ビット符号無しBINデータとして扱います。 | （0～4294967295） |
| □.L | 32ビット符号付きBINデータとして扱います。 | （－2147483648～＋2147483647） |
| □.F | 単精度浮動小数点型実数データとして扱います。 | －3.4E＋38≦ N ≦－1.4E－45<br>N ＝ 0<br>＋1.4E－45≦ N ≦＋3.4E＋38<br>（有効桁数 : 約7桁） |
| □.DF | 倍精度浮動小数点型実数データとして扱います。 | －1.79E＋308≦ N≦－2.23E－308<br>N ＝ 0<br>＋2.23E－308≦ N≦＋1.79E＋308<br>（有効桁数 : 約16桁） |

> □.Uは、《KV STUDIO》上では表示が省略されます。また、サフィックスを持たない命令は、16ビット符号無しBINデータとして扱います。
> サフィックス対応命令は、BINデータをサフィックスに応じた10進表現の値で実行します。
> したがってBINデータが同じでもサフィックスが異なることにより、実行命令結果が異なることがあります。

## 4-3 プロジェクト (4-9〜4-16 / 原本 p.107-114)

### プロジェクトの構成 (4-9〜4-10 / 原本 p.107-108)

#### プロジェクトとは (4-9 / 原本 p.107)

> プログラムや各ユニット設定など、《KV-7000シリーズ》を運転するために必要な全ての情報をプロジェクトという単位で管理します。

【図】プロジェクトの構成 (4-9 / 原本 p.107)。プロジェクト ＝ プログラム(モジュール ×複数、ファンクションブロック、マクロ ×複数) ＋ ユニット設定 ＋ デバイスコメント ＋ ラベル ＋ CPUシステム設定 ＋ ユーザドキュメント ＋ ロギング・トレース設定 ＋ デバイス初期値設定 ＋ ファイルレジスタ設定

### プロジェクトのプロテクト設定 (4-13〜4-16 / 原本 p.111-114)

#### プロテクト設定の概要 (4-13 / 原本 p.111)

> 《KV-7000シリーズ》ではプロジェクトをプロテクト設定できます。
> プロテクト設定は《KV STUDIO》の「CPUシステム設定」で設定してください。

| 項目 | 説明 |
|---|---|
| ライトプロテクト | CPUユニットに格納されているラダープログラムがライトプロテクト（書き込み時に確認ダイアログを表示）されます。誤って上書きすることを防止できます。 |
| リードプロテクト | CPUユニットに格納されているラダープログラムがリードプロテクト（読み出し不可）されます。プログラム資産の流出を防止できます。 |
| プロジェクトパスワード | CPUユニットに格納されているラダープログラムを読み出す際にパスワード入力ダイアログが表示されます。<br>※リードプロテクト設定時は、パスワード入力ダイアログも表示されず、読み出しできません。 |
| プログラムパスワード | プロジェクト編集時に、プログラムを表示しようとすると、[パスワード解除]ダイアログが表示されます。 |

【図】操作の経路 (4-13 / 原本 p.111)。パソコン(KV STUDIO) ⇔ ファイル: 「ファイルを開く」「保存」「プログラムを開く」、パソコン → CPU: 「PLC転送」、CPU → パソコン: 「PLC読出」、CPU ⇔ SDカード: 「ロード」「セーブ」。

##### プロジェクトをパソコン上で編集する場合 (4-13 / 原本 p.111)

- ファイルを開く場合<br>プロテクト設定はできません。
- ファイルを保存する場合<br>プロテクト設定はできません。
- プログラムを開く場合<br>プログラムパスワードを設定して、開く際に、[パスワード解除]ダイアログを表示できます。

##### プロジェクトをパソコンからCPUユニットに読み書きする場合 (4-14 / 原本 p.112)

- 読み出しを実行する場合1<br>リードプロテクトを設定して読み出しを禁止できます。<br>プロジェクトパスワード設定時も、確認ダイアログは表示されません。
- 読み出しを実行する場合2<br>プロジェクトパスワードを設定して[パスワード解除]ダイアログを表示できます。
- 書き込みを実行する場合<br>ライトプロテクトを設定して上書き時に[確認]ダイアログを表示できます。

【図】ダイアログ「KV STUDIO」: 「PLC本体はライトプロテクトされています。強行しますか？」〔はい(Y)〕〔いいえ(N)〕(4-14 / 原本 p.112)

> **参考**
> プロジェクトパスワード設定時は、パスワード認証に失敗すると、次回読み出しが可能になるまでに一定時間待つ必要があります。また待ち時間は認証失敗のたびに延長されます。パスワード認証に失敗したため、読み出し認証ができない場合、プロジェクトパスワード認証禁止状態リレー（CR2314）がONしています。
> パスワード認証に連続で失敗した回数、および累積の回数は、プロジェクトパスワード連続認証失敗回数（CM1658）とプロジェクトパスワード累積認証失敗回数（CM1659）に格納されます。プロジェクトパスワード連続認証失敗回数は、認証成功時、プログラム転送正常終了時、オールクリア実行時にクリアされ、プロジェクトパスワード累積認証失敗回数は、オールクリア実行時のみクリアされます。

##### メモリカードを使用してロード/セーブする場合 (4-14 / 原本 p.112)

- ロードする場合<br>ライトプロテクトを設定している場合は、ロード前に確認できます。

【図】アクセスウィンドウの表示例(3言語)(4-14 / 原本 p.112)。「ロード ライトプロテクトされています 強行しますか？」/「Load Write protected Force Load?」/「加载 写保护 是否强制执行?」(テキスト抽出では文字化けするため画像から転記)

- セーブする場合<br>リードプロテクトおよびプロジェクトパスワードを設定すると、セーブは実行できますが、デバイスの値のみセーブし、ラダープログラムはセーブされません。

#### プロジェクトのパスワード (4-15 / 原本 p.113)

> プロジェクトにパスワードを設定して、《KV-7000シリーズ》からの読み出しに制限をかけることができます。
> 次の手順でパスワードを設定します。

1. ［ワークスペース］を選択します。
2. 右クリックして表示されるメニューから［プロジェクトプロパティ（F）］を選択します。
   - 別手順: メニューから【ファイル（F）】→【プロジェクトプロパティ（F）】を選択します。
   - ［プロジェクトプロパティ］ダイアログが表示されます。
3. 〔パスワード設定〕ボタンを押します。
   - ［パスワード設定］ダイアログが表示されます。
4. パスワードとパスワードの確認を入力して、〔OK〕ボタンを押します。
   - パスワード(半角英数字32文字以内)

【図】ワークスペースの右クリックメニュー、［プロジェクトプロパティ］ダイアログ、［パスワード設定］ダイアログの画面例 (4-15 / 原本 p.113)

> パスワード設定後、パスワード設定したプロジェクトを《KV-7000シリーズ》から読み出す時、［パスワード解除］ダイアログが表示されます。
> パスワードを入力しないと、プロジェクトを《KV-7000シリーズ》から読み出せません。
> また、パスワードが異なるプロジェクトをPLC転送するときも、PLC内のプロジェクトを保護するため、パスワードを入力するか、全項目を転送する必要があります。

#### プロジェクトのライト/リードプロテクト (4-16 / 原本 p.114)

> プロジェクトにプロテクト設定をして、《KV-7000シリーズ》本体への書き込みや読み出しに制限をかけることができます。
> プロテクト設定は、ワークスペースから【CPUシステム設定】→【プロテクト設定】を選択します。
> それぞれチェックを入れて《KV-7000シリーズ》に転送することで、プロテクト設定が有効になります。

【図】CPUシステム設定のプロテクト設定画面 (4-16 / 原本 p.114)

> **ポイント**
> リードプロテクトをかけた状態で《KV-7000シリーズ》に転送すると、その後ラダープログラムの実行状態はモニタできません。
> デバッグ完了後にリードプロテクトをかけて、PLC転送を実行してください。
> パスワード設定とリードプロテクトを両方使用した場合、パスワード確認ダイアログは表示されず、プロジェクトの読み出しはできません。

> **参考**
> プログラムパスワードについては、→ 「モジュールパスワード」（4-94ページ）、→ 「ファンクションブロックのパスワード設定」（4-116ページ）、→ 「マクロパスワード」（4-141ページ）を参照してください。
