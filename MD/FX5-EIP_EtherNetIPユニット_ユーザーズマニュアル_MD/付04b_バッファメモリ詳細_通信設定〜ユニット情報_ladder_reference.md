##### 最大コネクション数 (付4 / 印刷 p.231 / 原本 p.233)

###### 最大コネクション数(Un￥G224) (付4 / 印刷 p.231 / 原本 p.233)

パラメータ設定のʼ最大コネクション数設定ʼで選択したパラメータに応じた値が格納されます。
- 64: 64コネクションが設定されている
- 128: 128コネクションが設定されている

##### 自動リフレッシュ処理 (付4 / 印刷 p.231 / 原本 p.233)

###### 自動リフレッシュ状態(Un￥G228) (付4 / 印刷 p.231 / 原本 p.233)

サイクリック通信の入力データや出力データに対する，自動リフレッシュの設定有無が格納されます。
入力データに対する自動リフレッシュ /出力データに対する自動リフレッシュが，1 コネクションでも設定されている場合，"設定されている”(0 以外)になります。
- 入力データに対する自動リフレッシュ : ネットワークユニット→CPU ユニットへ転送されるデータ
- 出力データに対する自動リフレッシュ : CPU ユニット→ネットワークユニットへ転送されるデータ

| アドレス | 値 | 内容 |
|---|---|---|
| Un￥G228 | 0 | 自動リフレッシュが設定されていません。 |
| Un￥G228 | 1 | 出力データにのみ自動リフレッシュが設定されています。 |
| Un￥G228 | 2 | 入力データにのみ自動リフレッシュが設定されています。 |
| Un￥G228 | 3 | 出力データ/入力データの両方に自動リフレッシュが設定されています。 |

##### 入出力データのデータ保証 (付4 / 印刷 p.231 / 原本 p.233)

###### コネクション単位ブロック保証指定(Un￥G232) (付4 / 印刷 p.231 / 原本 p.233)

サイクリック通信/メッセージ通信で使用する入力データや出力データに対して，データ保証する/しないを設定します。
ʻEtherNet/IP通信起動要求ʼ(Un￥G272)の"0: 停止要求”→”0 以外: 起動要求”時に設定が反映されます。
☞ 79ページ 入出力データのデータ保証
- 0(0H): 保証しない
- 16(10H): 保証する

###### コネクション単位ブロック保証状態(Un￥G233) (付4 / 印刷 p.231 / 原本 p.233)

現在実行中のサイクリック通信/メッセージ通信の入力データや出力データに対して，データ保証状態が格納されます。
ʻEtherNet/IP通信起動要求ʼ(Un￥G272)の"0: 停止要求”→”0 以外: 起動要求”時に設定が反映されます。
- 0: EtherNet/IP通信が停止中
- 1: データ保証していない
- 2: データ保証している

##### PINGテスト要求エリア (付4 / 印刷 p.232 / 原本 p.234)

###### 交信タイムチェック(Un￥G240) (付4 / 印刷 p.232 / 原本 p.234)

PING テストの完了待ち時間を設定します。
- 0: 1 秒で動作します。
- 1~5: 設定した秒数で動作します。
- 6以上: 5秒で動作します。

###### 送信回数(Un￥G241) (付4 / 印刷 p.232 / 原本 p.234)

送信回数を設定します。
- 0: 1 回送信します。
- 1~10: 設定した回数で送信します。
- 11以上: 10回送信します。

###### IP Address(Un￥G242~Un￥G243) (付4 / 印刷 p.232 / 原本 p.234)

PING テスト対象機器のIP アドレスを設定します。

| アドレス | 内容 |
|---|---|
| Un￥G242 | 第3オクテット，第4オクテット |
| Un￥G243 | 第1オクテット，第2オクテット |

**例**
IPアドレスが192.1.0.254の場合: Un￥G242=H00FE，Un￥G243=HC001

> **注意事項**
> 下記IP アドレスは設定できません。
> - 自ノードのIPアドレス
> - 自ノードが属するネットワークのネットワークアドレス(IPアドレスのホスト部*1のビットがすべて0のIP アドレス)
> - 自ノードが属するネットワークのブロードキャストアドレス(IPアドレスのホスト部*1のビットがすべて1のIP アドレス)
>
> *1 サブネットマスクが0になっているビット部分を指します。サブネットマスクが未設定の場合，FX5-EIPのIPアドレスが属するクラスによって下記のサブネットマスクを設定しているとして扱われます。
> - クラスA(IP アドレスの先頭ビット列が0)→サブネットマスク: 255.0.0.0
> - クラスB(IP アドレスの先頭ビット列が10)→サブネットマスク: 255.255.0.0
> - クラスC(IP アドレスの先頭ビット列が110)→サブネットマスク: 255.255.255.0
>
> **例**
> 自ノードのIP アドレス: 192.168.3.4，サブネットマスク :255.255.0.0の場合，下記のアドレスは設定できません。
> - 自ノードのIP アドレス: 192.168.3.4
> - ネットワークアドレス: 192.168.0.0
> - ブロードキャストアドレス: 192.168.255.255

##### EtherNet/IP通信制御 (付4 / 印刷 p.233 / 原本 p.235)

###### EtherNet/IP通信起動要求(Un￥G272) (付4 / 印刷 p.233 / 原本 p.235)

EtherNet/IP通信の起動を要求します。
- 0: 停止要求
- 0以外: 起動要求

> **Point**
> ʻEtherNet/IP通信起動要求ʼ(Un￥G272)に0以外の値を設定してEtherNet/IP通信を起動する場合，ʼサイクリック通信一時停止指定ʼ(Un￥G1360~Un￥G1367)をすべて0 にしてください。
> ʻサイクリック通信一時停止指定ʼ(Un￥G1360~Un￥G1367)がすべて0ではない場合，ʼEtherNet/IP通信起動要求ʼ(Un￥G272)に0 以外の値を設定しても，EtherNet/IP通信は起動しません。
> この場合，ʼEtherNet/IP通信起動状態ʼ(Un￥G273)に2(起動不可)が格納されます。

###### EtherNet/IP通信起動状態(Un￥G273) (付4 / 印刷 p.233 / 原本 p.235)

EtherNet/IP通信の起動状態を表すモニタ用エリアです。
- 0: 停止中
- 1: 起動中
- 2: 起動不可(ʻサイクリック通信一時停止指定ʼ(Un￥G1360~Un￥G1367)のいずれかのbit をON した状態で，EtherNet/IP通信の起動を要求した場合)

###### EtherNet/IP通信継続指定要求(Un￥G274) (付4 / 印刷 p.233 / 原本 p.235)

CPUユニットの動作状態をRUN→STOP にしたとき，またはCPUユニットが停止エラーになったときに，EtherNet/IP通信を継続するか停止するかを決定します。
ʻEtherNet/IP通信起動要求ʼの起動要求時に設定が反映されます。
- 0: 停止する
- 16(10H): 継続する

###### EtherNet/IP通信継続指定状態(Un￥G275) (付4 / 印刷 p.233 / 原本 p.235)

ʻEtherNet/IP通信継続指定要求ʼ(Un￥G274)の設定状態が格納されます。
EtherNet/IP通信起動要求の起動要求時に設定が格納されます。
- 1: “継続する”で動作中
- 2: “停止する”で動作中

###### EtherNet/IP通信起動要求(Un￥G272)の動作タイミング (付4 / 印刷 p.234 / 原本 p.236)

ʼEtherNet/IP通信起動要求ʼ(Un￥G272)のONによるEtherNet/IP通信の動作タイミングを示します。

- EtherNet/IP通信が起動した場合(正常時)

【図】EtherNet/IP通信が起動した場合(正常時)のタイミングチャート（原本 p.236 上段）
- 凡例: 破線矢印 = FX5-EIPにて実施、実線矢印 = プログラムにて実施
- 'EtherNet/IP通信起動要求'(Un￥G272): プログラムで「EtherNet/IP通信起動要求に0以外を設定」→ 0以外の期間 → プログラムで「EtherNet/IP通信起動要求に0を設定」
- 0以外を設定すると、FX5-EIPが'入出力データバッファメモリアドレス'(Un￥G560~Un￥G1071)に入出力データバッファメモリアドレスを格納し、同じタイミングで'サイクリック通信 予約ノード'(Un￥G1344~Un￥G1351)/'メッセージ通信 予約ノード'(Un￥G4640~Un￥G4647)が「予約状態」になり、'コネクションエラー状態' サイクリック通信コネクション(Un￥G1392~Un￥G1903)が 0 になる
- 続いて「EtherNet/IP通信の起動および停止」で「EtherNet/IP通信起動」が行われ、完了時点で'EtherNet/IP通信起動状態'(Un￥G273)が「0: 停止中」→「1: 起動中」（正常起動）
- 1: 起動中 になった時点から「EtherNet/IP通信中」となり、'サイクリック通信データリンク状態'(Un￥G1328~Un￥G1335)が「通信状態」、'入力データエリア'(64 コネクション設定時: Un￥G16944~Un￥G63151 / 128 コネクション設定時: Un￥G32560~Un￥G70959)に「入力データ」、'出力/メッセージ通信(サーバ)データエリア'(64 コネクション設定時: Un￥G63152~Un￥G109359 / 128 コネクション設定時: Un￥G70960~Un￥G109359)に「出力データ」
- 起動要求に0を設定すると「EtherNet/IP通信停止」が行われ、完了時点で起動状態(Un￥G273)が「0: 停止中」、予約ノード(Un￥G1344~Un￥G1351, Un￥G4640~Un￥G4647)は 0、サイクリック通信データリンク状態(Un￥G1328~Un￥G1335)は 0 になる
- 停止後も'入出力データバッファメモリアドレス'の値、入力データエリア・出力データエリアの値、コネクションエラー状態(0)は図上で変化なし（線が継続）

- EtherNet/IP通信が起動しない場合(異常時)

【図】EtherNet/IP通信が起動しない場合(異常時)のタイミングチャート（原本 p.236 下段）
- 凡例: 破線矢印 = FX5-EIPにて実施、実線矢印 = プログラムにて実施
- 'EtherNet/IP通信起動要求'(Un￥G272)にプログラムで0以外を設定すると、FX5-EIPが'コネクションエラー状態'(Un￥G1392~Un￥G1903)に「エラーコード」を格納し、続いて'ユニットエラー状態'(Un￥G34.b14)がON
- その後、'EtherNet/IP通信起動状態'(Un￥G273)は「0: 停止中」→「1: 起動中」になる
- 起動要求に0を設定すると、起動状態(Un￥G273)が「0: 停止中」に戻る。'ユニットエラー状態'(Un￥G34.b14)のONとコネクションエラー状態のエラーコードは図の終端まで保持されたまま

###### EtherNet/IP通信継続指定状態による通信制御 (付4 / 印刷 p.235 / 原本 p.237)

ʼEtherNet/IP通信継続指定状態ʼ(Un￥G275)の状態によってEtherNet/IP通信可能状態の制御が異なります。
ʻ通信継続指定状態ʼ(Un￥G275)が”2: 停止する”で動作中の場合，CPUユニットがRUN→STOP に変化した場合，またはCPUユニットに停止エラーが起きた場合に，EtherNet/IP通信が停止します。(ʼEtherNet/IP通信起動要求ʼ(Un￥G272)がOFF します)
ʻ通信継続指定状態ʼ(Un￥G275)が”1: 継続する”で動作中の場合，CPUユニットがRUN→STOP に変化した場合，またはCPU に停止エラーが起きた場合でも，EtherNet/IP通信は継続します。
ʻコネクション単位ブロック保証状態ʻ(Un￥G233) が”2：データ保証している”で動作中の場合，EtherNet/IP通信は継続しますが，入出力データは更新されません。

- EtherNet/IP通信継続指定状態”2: 停止する”で動作中の場合

【図】継続指定状態”2: 停止する”で動作中の場合のタイミングチャート（原本 p.237 上段）
- 凡例: 破線矢印 = FX5-EIPにて実施、実線矢印 = プログラムにて実施
- 'EtherNet/IP通信継続指定要求'(Un￥G274): 「EtherNet/IP通信起動要求に0を設定」の状態でプログラムが「0: (停止指定要求)」を設定
- 'EtherNet/IP通信起動要求'(Un￥G272)にプログラムで0以外を設定 → FX5-EIPが「EtherNet/IP通信可能」にし、'EtherNet/IP通信継続指定状態'(Un￥G275)が「2: (停止指定状態)」、'EtherNet/IP通信起動状態'(Un￥G273)が「0: 停止中」→「1: 起動中」
- 「CPUユニットの動作状態がRUN→STOP またはCPUユニットが停止エラー」が発生すると起動要求(Un￥G272)がOFF（0）になり、EtherNet/IP通信可能が終了し、起動状態(Un￥G273)が「0: 停止中」

- EtherNet/IP通信継続指定状態”1: 継続する”で動作中の場合

【図】継続指定状態”1: 継続する”で動作中の場合のタイミングチャート（原本 p.237 下段）
- 凡例: 破線矢印 = FX5-EIPにて実施、実線矢印 = プログラムにて実施
- 'EtherNet/IP通信継続指定要求'(Un￥G274): 「EtherNet/IP通信起動要求に0を設定」の状態でプログラムが「16: (継続指定要求)」を設定
- 'EtherNet/IP通信起動要求'(Un￥G272)にプログラムで0以外を設定 → FX5-EIPが「EtherNet/IP通信可能」にし、'EtherNet/IP通信継続指定状態'(Un￥G275)が「1: (継続指定状態)」、'EtherNet/IP通信起動状態'(Un￥G273)が「0: 停止中」→「1: 起動中」
- 「CPUユニットの動作状態がRUN→STOP またはCPUユニットが停止エラー」が発生しても起動要求(Un￥G272)は0以外のまま、起動状態は「1: 起動中」、EtherNet/IP通信可能が継続

##### 消費コネクション数 (付4 / 印刷 p.249 / 原本 p.251)

###### Class1/Class3通信用(Un￥G110116) (付4 / 印刷 p.249 / 原本 p.251)

現在の消費コネクション数を表示します。消費コネクション数は下記のコネクションの合計となります。(最大: 128)
- Class1通信(インスタンス/タグ)のオリジネータとして”EtherNet/IP構成”に設定されたコネクション*1
- Class3通信(インスタンス/タグ)のクライアントとして”EtherNet/IP構成”に設定されたコネクション*1
- Class1通信(インスタンス/タグ)のターゲットとして通信中のコネクション*2*3
- Class3通信(インスタンス/タグ)のサーバとして，他のEtherNet/IP機器と通信中のコネクション*3*4

最大数である128 を超えると接続できません。
Class1通信(インスタンス/タグ)のターゲットとして，通信中のオリジネータ機器がケーブル断や通信異常によって通信できなくなった場合は，カウントダウンします。

*1 通信が開始していない状態でも消費コネクションの対象になります。
*2 オリジネータからの要求を受け通信が開始した場合，消費コネクションの対象になります。
ターゲットとして設定されたコネクションに複数のオリジネータがマルチキャストで接続した場合，接続されたオリジネータの数だけ消費コネクション数が加算されます。
*3 “EtherNet/IP構成”にて設定したClass1通信(インスタンス/タグ)のターゲット設定や，Class3/UCMMタグ通信のタグを設定しただけでは加算されません。オリジネータ/クライアントからのコネクション確立要求を受け付けてから，コネクションが解放されるまでが，消費コネクション数の加算条件になります。
*4 Class3インスタンス通信のサーバ機能は，”EtherNet/IP構成”にて設定を行わなくても，クライアントからの要求があればサーバとして動作し，コネクション確立要求を受け付けます。その際，コネクション数が加算されます。
