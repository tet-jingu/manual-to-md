## 4 機能 (4 / 印刷 p.38 / 原本 p.40)

### 4.2 サイクリック通信機能（続き） (4.2 / 印刷 p.38-56 / 原本 p.40-58)

#### Class1インスタンス通信 (4.2 / 印刷 p.38 / 原本 p.40)

相手機器のIPアドレスとインスタンスIDを使用してオープンするコネクションを管理し，オリジネータとターゲット間で定期的にデータ通信を行います。
下記にFX5-EIPをオリジネータおよびターゲットとした場合の，アプリケーションタイプがExclusive Ownerのデータ通信を示します。

【図】Class1インスタンス通信(Exclusive Owner)のデータ通信シーケンス（原本 p.40）
- 左: FX5-EIP（オリジネータ）、右: FX5-EIP（ターゲット）
- ❶ 両側に「Class1インスタンス通信のコネクション設定を書き込みます。」
- ❷ 両側のライフラインに「'EtherNet/IP通信起動状態'(Un￥G273)が1(起動中)になります。」
- ❸ オリジネータ→ターゲットへ「コネクションオープン」、ターゲット→オリジネータへ「レスポンス(正常)」（コネクションが確立します。）
- ❹ データの送受信: オリジネータは'出力/メッセージ通信(サーバ)データエリア'(Un￥G63152~またはUn￥G70960~)のデータを「送信データ」としてRPIの間隔で送信し、ターゲットはそれを「受信データ」として'入力データエリア'(Un￥G16944~またはUn￥G32560~)に格納する
- ターゲットは'出力/メッセージ通信(サーバ)データエリア'(Un￥G63152~またはUn￥G70960~)のデータをRPIの間隔でオリジネータに送信し、オリジネータは'入力データエリア'(Un￥G16944~またはUn￥G32560~)に格納する
- オリジネータ側RPIとターゲット側RPIはそれぞれ独立。吹き出し「送受信されるタイミングは同期しない」

❶ Class1インスタンス通信のコネクション設定を書き込みます。
❷ 'EtherNet/IP通信起動状態'(Un￥G273)が1(起動中)になります。
❸ コネクションが確立します。
❹ データを送受信します。

> **Point**
> オリジネータとターゲットではデータを送信するタイミングが異なるため，データが送受信されるタイミングは同期しません。また，コネクション単位でRPIを管理するため，同じRPIを設定した場合でもコネクションごとのデータの送信タイミングは同期しません。

##### データ通信の手順 (4.2 / 印刷 p.39 / 原本 p.41)

###### オリジネータとして動作する場合 (4.2 / 印刷 p.39 / 原本 p.41)

1. コネクション設定
   "EtherNet/IP構成"からコネクション設定を行います。(→ 105ページ EtherNet/IP構成画面)
2. コネクションの確立
   下記のタイミングで'EtherNet/IP通信起動状態'(Un￥G273)が1(起動中)となり，コネクションのオープンを開始します。
   - 'EtherNet/IP通信起動要求'(Un￥G272)に0以外の値を設定した。
   - EtherNet/IP通信の自動起動が有効時，CPUユニットがSTOP→RUNした。
3. データの送受信
   正常にコネクションがオープンした場合，RPIの間隔で下記のデータを送受信します。(コネクションNo.が1の場合)
   - ターゲットから送信されたデータを'入力データエリア'(Un￥G16944~またはUn￥G32560~)に格納します。
   - オリジネータの'出力/メッセージ通信(サーバ)データエリア'(Un￥G63152~またはUn￥G70960~)に設定されたデータをターゲットに送信します。

###### ターゲットとして動作する場合 (4.2 / 印刷 p.39 / 原本 p.41)

1. コネクション設定
   "EtherNet/IP構成"からコネクション設定を行います。(→ 105ページ EtherNet/IP構成画面)
2. コネクションの確立
   下記のタイミングで'EtherNet/IP通信起動状態'(Un￥G273)が1(起動中)となり，コネクションのオープンを開始します。
   - 'EtherNet/IP通信起動要求'(Un￥G272)に0以外の値を設定した。
   - EtherNet/IP通信の自動起動が有効時，CPUユニットがSTOP→RUNした。
3. データの送受信
   正常にコネクションがオープンした場合，RPIの間隔で下記のデータを送受信します。(コネクションNo.が1の場合)
   - オリジネータから送信されたデータを'入力データエリア'(Un￥G16944~またはUn￥G32560~)に格納します。
   - ターゲットの'出力/メッセージ通信(サーバ)データエリア'(Un￥G63152~またはUn￥G70960~)に設定されたデータをオリジネータに送信します。

> **Point**
> バッファメモリの詳細については，→ 105ページ EtherNet/IP構成画面を参照してください。

##### コネクション設定 (4.2 / 印刷 p.40 / 原本 p.42)

###### FX5-EIPをオリジネータとしてインスタンス通信を行う場合 (4.2 / 印刷 p.40 / 原本 p.42)

FX5-EIPをオリジネータとしてインスタンス通信を行う場合，下記の設定が必要です。
- ターゲットに設定されたインスタンスIDを確認します。設定および確認方法については，相手機器のマニュアルを参照してください。機器によっては，EDSファイルにて固定値が指定されるため，マニュアルに記載がない場合があります。
- "EtherNet/IP構成"を使用して，ターゲットに設定されたインスタンスIDを元にFX5-EIPの"スキャナ設定"を行います。FX5-EIPの設定方法は，→ 105ページ EtherNet/IP構成画面を参照してください。

###### FX5-EIPをターゲットとしてインスタンス通信を行う場合 (4.2 / 印刷 p.40 / 原本 p.42)

FX5-EIPをターゲットとしてインスタンス通信を行う場合，下記の設定が必要です。
- "EtherNet/IP構成"を使用して，FX5-EIPの"アダプタ設定"を行います。FX5-EIPの設定方法は，下記を参照してください。
  → 105ページ EtherNet/IP構成画面
- オリジネータ機器に，"アダプタ設定"に合わせたインスタンスID に対して通信を行うよう設定します。設定方法については，相手機器のマニュアルを参照してください。

FX5-EIPをターゲットとして使用する場合のインスタンスIDについては，下記を参照してください。
→ 34ページ インスタンスIDとタグ名

##### 注意事項 (4.2 / 印刷 p.40 / 原本 p.42)

'EtherNet/IP通信起動要求'(Un￥G272)に0以外の値を設定してEtherNet/IP通信を起動する場合，'サイクリック通信一時停止指定'(Un￥G1360~)をすべて0にしてください。
'サイクリック通信一時停止指定'(Un￥G1360~)がすべて0ではない場合，'EtherNet/IP通信起動要求'(Un￥G272)に0以外の値を設定しても，EtherNet/IP通信は起動しません。
この場合，'EtherNet/IP通信起動状態'(Un￥G273)に2(起動不可)が格納されます。

- ターゲット1台とオリジネータA・B・Cの3台。各オリジネータとターゲットの間に双方向矢印(1)(2)(3)
- ❶ は(1)の接続を指し、❷ は(2)(3)の接続を指す

(2) オリジネータBとターゲットは，コネクションNo.1(Input Only(Class1インスタンス通信))で接続
(3) オリジネータCとターゲットは，コネクションNo.1(Input Only(Class1インスタンス通信))で接続
❶ ターゲット→オリジネータのインスタンスIDを768，オリジネータ→ターゲットのインスタンスIDを1024に設定

【図】通信中のデータの流れ（原本 p.51）
- ターゲット内に「コネクションNo.1 受信データ」と「コネクションNo.1 送信データ」の2エリア
- (1) オリジネータA→ターゲットの「コネクションNo.1 受信データ」へ矢印
- (2) 受信データエリアへの格納を示す矢印
- ❶ 「コネクションNo.1 送信データ」への格納を示す矢印
- ❷ 送信データからオリジネータA・B・Cへ分岐する経路（マルチキャスト）
- ❸ 各オリジネータA・B・Cの受信

(1) オリジネータAがターゲットに対してデータを送信
(2) オリジネータAから受信したデータを'入力データエリア'(Un￥G16944~またはUn￥G32560~)(コネクションNo.1)に格納
❶ ターゲットから各オリジネータに送信するデータを'出力/メッセージ通信(サーバ)データエリア'(Un￥G63152~またはUn￥G70960~)(コネクションNo.1)に格納

#### Class1タグ通信 (4.2 / 印刷 p.50 / 原本 p.52)

相手機器のIPアドレスとタグ名を用いてオープンするコネクションを管理する通信です。
同じタグ名および同じデータサイズのタグ同士でコネクションをオープンし，定期的にデータ通信を行います。
タグ通信では，ターゲットが設定するタグから，オリジネータが設定するタグに対する単方向のデータ通信のみ可能です。
双方向でデータ通信したい場合は，お互いがオリジネータになる必要があります。
またコネクション単位でRPIを管理するため，複数のターゲットが同一のタグと通信した場合でも，データの送信タイミングは同期しません。

【図】Class1タグ通信の構成（原本 p.52）
- 2台のFX5-EIP搭載システムがEthernetで接続
- 上段: FX5-EIP (ターゲット) の Tag「タグ名: Class1_Data1 / データサイズ: 8」、バッファメモリ'出力/メッセージ通信(サーバ)データエリア'(Un￥G63152~またはUn￥G70960~) → FX5-EIP (オリジネータ) の Tag「タグ名: Class1_Data1 / データサイズ: 8」、バッファメモリ'入力データエリア'(Un￥G16944~またはUn￥G32560~)
- 下段: FX5-EIP (ターゲット) の Tag「タグ名: Class1_Data2 / データサイズ: 8」、'出力/メッセージ通信(サーバ)データエリア'(Un￥G63152~またはUn￥G70960~) → FX5-EIP (オリジネータ) の Tag「タグ名: Class1_Data2 / データサイズ: 8」、'入力データエリア'(Un￥G16944~またはUn￥G32560~)（下段は図の右側がターゲット、左側がオリジネータ）
- すなわち、それぞれの方向にオリジネータを置くことで双方向通信を構成している

| 種類 | 内容 |
|---|---|
| ターゲット側のタグ | 通信相手となるオリジネータからコネクションオープンの要求を受け，同名のタグに対してデータを送信します。 |
| オリジネータ側のタグ | 通信相手となるターゲットにコネクションオープンの要求を行い，同名のタグからデータを受信します。 |

下記にFX5-EIPをオリジネータおよびターゲットとした場合の，タグ通信のデータの流れを示します。

【図】Class1タグ通信のデータの流れ（原本 p.53）
- 左: FX5-EIP（オリジネータ）、右: FX5-EIP（ターゲット）
- ❶ 両側で「オリジネータのタグ設定」「ターゲットのタグ設定」を書き込む
- ❷ オリジネータ→ターゲットへ「コネクションオープン」、ターゲットがタグ設定と照合し、ターゲット→オリジネータへ「レスポンス(正常)」
- ❸ ターゲットの'出力/メッセージ通信(サーバ)データエリア'(Un￥G63152~またはUn￥G70960~)のデータをRPIの間隔で繰り返しオリジネータへ送信し、オリジネータは'入力データエリア'(Un￥G16944~またはUn￥G32560~)に格納（ターゲット→オリジネータの単方向）

❶ Class1タグ通信のコネクション設定を書き込みます。
❷ ターゲット側のタグとオリジネータ側のタグのタグ名とデータサイズが一致するとコネクションがオープンします。
❸ ターゲット側で格納しているデータをRPIの間隔で送信します。

##### データ通信の手順 (4.2 / 印刷 p.51 / 原本 p.53)

###### オリジネータとして動作する場合 (4.2 / 印刷 p.51 / 原本 p.53)

1. コネクション設定
   "EtherNet/IP構成"からコネクション設定を行います。(→ 105ページ EtherNet/IP構成画面)
2. コネクションの確立
   下記のタイミングで'EtherNet/IP通信起動状態'(Un￥G273)が1(起動中)となり，コネクションのオープンを開始します。
   - 'EtherNet/IP通信起動要求'(Un￥G272)に0以外の値を設定した。
   - EtherNet/IP通信の自動起動が有効時，CPUユニットがSTOP→RUNした。
3. データの送受信
   正常にコネクションがオープンした場合，RPIの間隔で下記のデータを送受信します。(コネクションNo.が1の場合)
   - ターゲットから送信されたデータを'入力データエリア'(Un￥G16944~またはUn￥G32560~)に格納します。

###### ターゲットとして動作する場合 (4.2 / 印刷 p.51 / 原本 p.53)

1. コネクション設定
   "EtherNet/IP構成"からコネクション設定を行います。(→ 105ページ EtherNet/IP構成画面)
2. コネクションの確立
   下記のタイミングで'EtherNet/IP通信起動状態'(Un￥G273)が1(起動中)となり，コネクションのオープンを開始します。
   - 'EtherNet/IP通信起動要求'(Un￥G272)に0以外の値を設定した。
   - EtherNet/IP通信の自動起動が有効時，CPUユニットがSTOP→RUNした。
3. データの送受信
   正常にコネクションがオープンした場合，RPIの間隔で下記のデータを送受信します。(コネクションNo.が1の場合)
   - ターゲットの'出力/メッセージ通信(サーバ)データエリア'(Un￥G63152~またはUn￥G70960~)に設定されたデータをオリジネータに送信します。

#### サイクリック通信の停止と再開 (4.2 / 印刷 p.55 / 原本 p.57)

コネクションごとにサイクリック通信の停止と再開が'サイクリック通信一時停止指定'(Un￥G1360~)を使用することで可能になります。
停止させるコネクションNo.に対応したビットをONすることでサイクリック通信が停止し，OFFすることでサイクリック通信が再開します。
'サイクリック通信一時停止指定'(Un￥G1360～)のいずれかのビットがONした状態で，'EtherNet/IP通信起動要求'(Un￥G272)を0以外にしてもEtherNet/IP通信を起動することはできません。
サイクリック通信の停止と再開は下記のバッファメモリを使用します。

| 'EtherNet/IP通信起動要求'(Un￥G272) | 'サイクリック通信一時停止指定'(Un￥G1360~)の該当ビット | サイクリック通信状態 |
|---|---|---|
| 0(停止要求) | OFF: 一時停止指定なし | すべてのサイクリック通信が停止 |
| 0以外(起動要求) | OFF: 一時停止指定なし | サイクリック通信が開始 |
| 0以外(起動要求) | ON: 一時停止指定あり | サイクリック通信が一時停止 |

'EtherNet/IP通信起動要求'(Un￥G272)を0以外→0にしても，'サイクリック通信一時停止指定'(Un￥G1360~)はクリアされません。そのため，'EtherNet/IP通信起動要求'(Un￥G272)を0以外→0→0以外にしても，EtherNet/IP通信は再度起動しません。'サイクリック通信一時停止指定'(Un￥G1360～)のいずれかのビットがONした状態でEtherNet/IP通信を起動する場合は，'サイクリック通信一時停止指定'(Un￥G1360~)をクリアしてから'EtherNet/IP通信起動要求'(Un￥G272)を0以外にしてください。

【図】起動要求と一時停止指定の状態遷移（原本 p.57）
- オリジネータ側の'EtherNet/IP通信起動要求'(Un￥G272)が 0以外(起動要求) → 0(停止要求) → 0以外(起動要求) と変化する3段階を上から順に図示
- 各段階とも、コネクションNo.1 は「停止指示なし」、コネクションNo.2 は「停止指示」
- 1段階目（0以外）: (1) No.1 はターゲットと双方向矢印（通信中）、(2) No.2 は矢印なし（停止中）
- 2段階目（0）: (3) No.1 停止中、(4) No.2 停止中
- 3段階目（0以外に戻す）: (5) No.1 停止中のまま、(6) No.2 停止中のまま（No.2 の一時停止指定が残っているため起動しない）

(1) コネクションNo.1: 通信中
(2) コネクションNo.2: 停止中
(3) コネクションNo.1: 停止中(停止中に移行)
(4) コネクションNo.2: 停止中
(5) コネクションNo.1: 停止中(停止中のまま)→EtherNet/IP通信は起動しません。
(6) コネクションNo.2: 停止中(停止中のまま)

> **Point**
> サイクリック通信を停止させた場合，下記の動作となります。
> - オリジネータ側はコネクションクローズ処理を行い，サイクリック通信を停止します。ターゲット側ではコネクションタイムアウトは発生しません。
> - ターゲット側はサイクリック通信を停止するのみです。オリジネータ側ではコネクションタイムアウトが発生します。
