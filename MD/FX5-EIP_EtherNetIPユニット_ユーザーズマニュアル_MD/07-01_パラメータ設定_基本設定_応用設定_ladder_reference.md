## 7 パラメータ設定 (7 / 印刷 p.87 / 原本 p.89)

FX5-EIPでEtherNet/IPおよび汎用Ethernet通信を行うために必要なパラメータ設定について説明します。
GX Works3の各操作の詳細は，GX Works3オペレーティングマニュアルを参照してください。

### 7.1 パラメータ設定手順 (7.1 / 印刷 p.87 / 原本 p.89)

1. エンジニアリングツールに”情報ユニット(FX5-EIP)”を追加します。*1
   - 操作: ナビゲーションウィンドウ⇨[パラメータ]⇨[ユニット情報]⇨右クリック⇨[新規ユニット追加]
2. パラメータを設定します。(☞ 88ページ 基本設定，95ページ 応用設定)
   - 操作: ナビゲーションウィンドウ⇨[パラメータ]⇨[ユニット情報]⇨[FX5-EIP]⇨[ユニットパラメータ]
3. ”EtherNet/IP構成”から，EtherNet/IPの通信パラメータを設定します。(☞ 97ページ EtherNet/IP構成)
   - 操作: ナビゲーションウィンドウ⇨[パラメータ]⇨[ユニット情報]⇨[EtherNet/IP構成(ユニット拡張パラメータ])]
4. エンジニアリングツールで，パラメータをCPUユニットに書き込みます。
   - 操作: [オンライン]⇨[シーケンサへの書込み]
5. CPUユニットのリセット，または電源OFF→ONでパラメータ設定が反映されます。

*1 ユニット構成図からもFX5-EIPをGX Works3に追加することができます。

### 7.2 基本設定 (7.2 / 印刷 p.88 / 原本 p.90)

FX5-EIPのIPアドレス，各種機能の設定をします。

- 操作: ナビゲーションウィンドウ⇨[パラメータ]⇨[ユニット情報]⇨[FX5-EIP]⇨[ユニットパラメータ]⇨[基本設定]

【図】GX Works3「1[U1]:FX5-EIP ユニットパラメータ」画面（基本設定）（原本 p.90）
- 設定項目一覧ツリー: 基本設定（自ノード設定 / EtherNet/IP設定 / 相手機器接続構成設定）、応用設定
- 自ノード設定 > IPアドレス設定 > IPアドレス: `192 . 168 . 3 . 251`、サブネットマスク: 空白、デフォルトゲートウェイ: 空白
- 交信データコード: バイナリ / オープン方法の設定: プログラムでOPENしない
- EtherNet/IP設定 > 最大コネクション数設定: 64コネクション / リフレッシュ設定: <詳細設定> / EtherNet/IP自動起動設定: 起動しない
- 相手機器接続構成設定: <詳細設定>
- 説明欄: 「自ノードに関するIPアドレス等を設定します。」 ボタン: チェック(K) / デフォルトに戻す(U) / 適用(A)

#### 自ノード設定 (7.2 / 印刷 p.88 / 原本 p.90)

FX5-EIPのIPアドレス，交信データコード，オープン方法の設定をします。

| 項目 | 項目(詳細) | 内容 | 設定範囲 |
|---|---|---|---|
| IPアドレス設定 | IPアドレス | FX5-EIPのIPアドレスを設定します。*1<br>FX5-EIPと交信するEtherNet/IP機器が同じクラス，サブネットアドレスになるように設定します。 | • 空白(デフォルト)<br>• 0.0.0.1~223.255.255.254*2 |
| IPアドレス設定 | サブネットマスク | FX5-EIPのサブネットマスクを設定します。<br>デフォルトゲートウェイのIPアドレスを設定した場合で，ルータを介して，他ネットワークのEtherNet/IP機器と交信する場合に，デフォルトゲートウェイのサブネットマスクパターンを設定します。同じサブネットワーク上のすべての機器は，共通のサブネットマスクを持つ必要があります。<br>単一ネットワークで通信を行う場合は設定不要です。 | • 空白(デフォルト)<br>• 0.0.0.1~255.255.255.255*3 |
| IPアドレス設定 | デフォルトゲートウェイ | FX5-EIPのデフォルトゲートウェイを設定します。<br>他ネットワークのEtherNet/IP機器へアクセスする場合に経由する機器(デフォルトゲートウェイ)のIPアドレスを設定します。<br>■設定条件<br>• IPアドレスのクラスは，クラスA，B，Cのいずれかである<br>• デフォルトゲートウェイのサブネットアドレスがFX5-EIPのサブネットアドレスと同じである<br>• ホストアドレスが，すべて”0”またはすべて”1”でない | • 空白(デフォルト)<br>• 0.0.0.1~223.255.255.254 |
| 交信データコード | — | 交信時に使用するデータの形式を選択します。 | • バイナリ(デフォルト)<br>• ASCII(X,Y 8進)<br>• ASCII(X,Y 16進) |
| オープン方法の設定 | — | コネクションをオープンする方法を選択します。<br>• プログラムでOPENしない: 相手機器でオープン処理を実行して，コネクションをオープンします。オープン/クローズ処理用のプログラムは不要です。<br>• プログラムでOPENする: プログラムでオープン/クローズ処理を実行し，コネクションをオープン/クローズします。 | • プログラムでOPENしない(デフォルト)<br>• プログラムでOPENする |

*1 IPアドレスを設定しない状態(空白のまま)でパラメータを書き込むと，下記のアドレスが設定されます。
192.168.3.251
*2 第1オクテットが0または127の場合，パラメータ異常となります。
*3 128.0.0.0~255.255.255.252以外の範囲を入力した場合，パラメータ異常となります。

##### 最大コネクション数設定 (7.2 / 印刷 p.89 / 原本 p.91)

EtherNet/IP通信で使用可能なコネクション数(コネクションNo.)の最大値を設定します。
コネクション数の最大値により，通信データサイズの最大値が変化します。
設定値ごとの各通信の最大データサイズは下記です。

| 項目 | 通信 | 種別 | 64コネクション | 128コネクション |
|---|---|---|---|---|
| 通信データサイズ(バイト) | Class1通信 | インスタンス通信 | 1444 | 600 |
| 通信データサイズ(バイト) | Class1通信 | タグ通信 | 1444 | 600 |
| 通信データサイズ(バイト) | Class3通信 | インスタンス通信 | 1404 | 600 |
| 通信データサイズ(バイト) | Class3通信 | タグ通信 | 496 | 496 |
| 通信データサイズ(バイト) | UCMM通信 | インスタンス通信*1 | 504 | 504 |
| 通信データサイズ(バイト) | UCMM通信 | タグ通信 | 498 | 498 |

（原本の列見出し: 項目 / 設定（64コネクション，128コネクション））

*1 データサイズにヘッダを含みます。

> 最大コネクション数設定を変更する場合，必要に応じて”リフレッシュ設定”や”EtherNet/IP構成(ユニット拡張パラメータ)”を見直してください。
> ☞ 90ページ リフレッシュ設定
> ☞ 97ページ EtherNet/IP構成
> また，データエリアのアドレスも変化するため，バッファメモリのアドレスをプログラムから直接参照している場合はプログラムも見直してください。
> ☞ 221ページ バッファメモリ

##### リフレッシュ設定 (7.2 / 印刷 p.90 / 原本 p.92)

バッファメモリとCPUユニットのデバイス間におけるリフレッシュを設定します。

【図】リフレッシュ設定画面（原本 p.92）
- 上部: リフレッシュ先 = 指定デバイス（プルダウン）、ツールボックスアイコン、右側に「ネットワークユニットへ転送」「CPUユニットへ転送」の切替
- 表の列: 項目 / 設定 > CPU側 > 自動リフレッシュ / デバイス名 / 点数 / 先頭 / 最終
- 「ネットワークユニットへ転送」行: 「指定したデバイスのデータをバッファメモリに転送します」
- コネクションNo.1〜No.10 が表示され、各行の自動リフレッシュはすべて「無効」（デバイス名以降はグレーアウト）

リフレッシュ設定を起動して，リフレッシュ先を設定します。
- リフレッシュ先が”指定デバイス”の場合: リフレッシュするコネクションの”自動リフレッシュ ”を有効にし，各項目を設定します。
- リフレッシュ先が”自動リフレッシュを使用しない”の場合: ”自動リフレッシュ ”はすべて無効となり，ほかの項目は設定しません。

###### ■設定項目(ネットワークユニットへ転送/CPUユニットへ転送) (7.2 / 印刷 p.90 / 原本 p.92)

| 設定項目（コネクションNo.1~128*1） | 内容 | 範囲 |
|---|---|---|
| 自動リフレッシュ | 指定した領域をCPUユニットと自動リフレッシュするかどうかを選択します。 | • 無効(デフォルト)<br>• 有効 |
| デバイス名 | リフレッシュ対象とするCPUデバイスを設定します。 | ■ネットワークユニットへ転送<br>• 空白(デフォルト)<br>• Y，M，L，B，D，W，R<br>■CPUユニットへ転送<br>• 空白(デフォルト)<br>• X，M，L，B，D，W，R |
| 点数 | リフレッシュする点数を10進数で設定します。<br>(デバイス割付方法*3を先頭/最終にて選択している場合は，リフレッシュ点数が10 進数で表示されます。) | CPUパラメータのデバイス設定に従う |
| 先頭*2 | リフレッシュ範囲の先頭となるCPUデバイスのデバイスNo.を設定します。 | CPUパラメータのデバイス設定に従う |
| 最終*2 | リフレッシュ範囲の最後となるCPUデバイスのデバイスNo.を設定します。<br>(デバイス割付方法を点数/先頭にて選択している場合は，リフレッシュ範囲の最終が表示されます。) | CPUパラメータのデバイス設定に従う |

*1 ”最大コネクション数設定”が64コネクションの場合，コネクションNo.65~128は設定できません。
*2 表示進数はCPUの種別，およびCPUデバイスの種類によって異なります。
FX5 CPUの場合: M，L，D，Rは10進数表示。X，Yは8進数表示。B，Wは16進数表示。
MXコントローラ(MX-Fモデル)の場合: M，L，D，Rは10進数表示。X，Y，B，Wは16進数表示。
*3 設定画面で右クリックし，リンクデバイスの割付け方法を選択します。
・先頭/最終: リンクデバイスの先頭番号と最終番号を入力して設定します。
・点数/先頭: リンクデバイスの点数と先頭番号を入力して設定します。

###### 注意事項 (7.2 / 印刷 p.91 / 原本 p.93)

> **注意事項**
> - リフレッシュ設定で設定するCPUユニットのデバイスは，FX5-EIP以外のユニットのリフレッシュ設定で使用するデバイス，および入出力ユニットやインテリジェント機能ユニットで使用している入出力番号と重複しないように設定してください。
> - リフレッシュ設定で設定するデバイスの点数は，”EtherNet/IP構成”で設定したデータサイズと合わせてください。設定したデバイスの点数がデータサイズ未満の場合，送受信データの泣き別れを防止できません。設定したデバイスの点数がデータサイズを超えた場合，受信データ以外のデータをデバイスに読み込む可能性やデバイスに書き込んだデータが送信されない可能性があります。
> - リフレッシュを有効にしている場合，リフレッシュ先の値が有効となり，バッファメモリはリフレッシュ先の値で上書きされます。リフレッシュ対象のバッファメモリの値を変更する場合は，リフレッシュ先のユニットラベルやデバイスの値を変更するようにプログラムを作成してください。
> - 自動リフレッシュ処理はサイクリック通信を対象とした機能のため，サイクリック通信に設定したコネクション以外のコネクションNo.に対してリフレッシュ設定しないでください。メッセージ通信のコネクションをリフレッシュ設定した場合，誤ったデータが転送されます。

> **Point**
> ”自動リフレッシュ ”を使用すると，送受信データの泣き別れを防止できます。

###### ■自動リフレッシュ処理時間 (7.2 / 印刷 p.91 / 原本 p.93)

自動リフレッシュ処理時間は，CPUユニット側の性能に依存します。
全コネクションのデータサイズを128バイト*1とした場合のスキャンタイムの最大伸び時間の目安は，150μs×コネクション数になります。

*1 ExclusiveOwnerで、T→O, O→Tの双方をリフレッシュした場合です。

> **注意事項**
> CPUユニットへ転送する場合，該当コネクションの入力データが前回から変化がない時は，リフレッシュ処理が行われません。そのため，入力データの更新頻度によってリフレッシュ処理時間が増減することがあります。スキャンタイムを一定に保ちたい場合はコンスタントスキャンを設定してください。

###### ■自動リフレッシュ一括設定と点数一括設定を使用したリフレッシュ設定 (7.2 / 印刷 p.92-93 / 原本 p.94-95)

”自動リフレッシュ ”を使用すると，送受信データの泣き別れを防止できます。
設定方法を下記に示します。

1. リフレッシュ先が”指定デバイス”の状態で，ツールボックスから［自動リフレッシュ一括設定］を選択します。
   - 【図】（原本 p.94）ツールボックスのメニュー「自動リフレッシュ一括設定(A)」「点数一括設定(O)」のうち、自動リフレッシュ一括設定(A)を選択。コネクションNo.1〜5はすべて「無効」
2. 確認ダイアログが表示されるので［はい］を選択します。
   - 【図】（原本 p.94）MELSOFT GX Works3 確認ダイアログ:「ユニット拡張パラメータを自動リフレッシュへ反映します。反映後、自動リフレッシュが「無効」となる場合、編集済みのデータを削除します。反映を実行してよろしいですか？」 ボタン: はい(Y) / いいえ(N)
3. ”自動リフレッシュ一括設定”を使用すると，”EtherNet/IP構成”から自動リフレッシュ可能なコネクションデータが読み出され”自動リフレッシュ ”に反映されます。
   - 【図】（原本 p.94）反映後の画面例: コネクションNo.1〜3 = 有効、No.4〜5 = 無効
4. ”デバイス名”を設定し，ツールボックスから［点数一括設定］を選択します。
   - 【図】（原本 p.94）デバイス名の設定例: コネクションNo.1 = Y、No.2 = M、No.3 = W（No.4〜5は無効）。ツールボックスで「点数一括設定(O)」を選択
5. 確認ダイアログが表示されるので［はい］を選択します。
   - 【図】（原本 p.94）MELSOFT GX Works3 確認ダイアログ:「自動リフレッシュが「有効」となっている行に対して、点数をコネクションのデータサイズから計算して反映します。点数を反映するため、デバイス割付方法を「点数／先頭」に変更します。反映を実行してよろしいですか？」 ボタン: はい(Y) / いいえ(N)
6. ”点数一括設定”を使用すると，"EtherNet/IP構成"から自動リフレッシュが有効となっているコネクションデータが読み出され，”点数”に反映されます。
   - 【図】（原本 p.95）反映後の画面例: コネクションNo.1 = 有効 / Y / 点数16、No.2 = 有効 / M / 点数16、No.3 = 有効 / W / 点数1、No.4〜5 = 無効。先頭は空欄、最終はグレー表示
7. ”先頭”を入力し，本設定を完了してください。

> **Point**
> - ”先頭”を指定してから”点数一括設定”を使用した場合，”点数”だけでなく”最終”にもコネクションデータが反映されます。
> - ”点数一括設定”を使用すると，デバイスの設定方法が”先頭”/”最終”から”点数”/”先頭”に変更されます。
